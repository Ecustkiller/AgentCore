## 详细发现

### F1 · 真·多模型辩手：文档称「透传链已核验」但代码注释禁用（headline 卖点静默失效）

- **严重度**：P1
- **类别**：DRIFT / SEAM
- **证据**：
  - **代码禁用**：`tools/builtin/debate/prompt.py:171-174`——把 `payload["model"] = side.model` 整段**注释掉**，注释写明「MVP 全链路统一用户 model，per-side override 在 debater_task 中忽略」。`test_debate_tool.py:392-412`（`test_side_model_parsed_but_not_injected_into_debater_task`）**锁死**该禁用行为（断言 `"model" not in t_a`）。
  - **schema 仍向 CEO 承诺功能**：`schema.py:103-111` 的 `model` 参数描述「指定该方辩手使用的模型，实现【真·多模型辩论】……用 `provider/model` 前缀路由到不同厂商」——主动教 LLM 使用一个 no-op 参数。`parse_sides` 仍解析入库（`schema.py:170-178`）。
  - **事件仍把 model 发给前端**：`types.py:529`（`to_event_payload` 的 sides「`"model": s.model`」）——CEO 一旦设了 model，前端会渲染「正方=豆包 / 反方=DeepSeek」徽章，但后端各方实际全跑同一默认模型。
  - **权威文档称已落地**：`docs/03-AI核心/辩论编排设计.md` 头部 line 19「真·多模型辩手…as-built 见 §7.5（**透传链已核验**、⏳ 端到端真跑待验）」；§7.5（line 311-313）逐段写「`sides[].model`…→ **`debater_task` 注入** → `RunSpec.model` → 执行器覆写…」——而 `debater_task` 恰恰**不注入**。
- **影响**：辩论「谁更聪明」这一 headline 卖点在被点名使用时**静默失效**（各方同模型自导自演）+ 前端徽章与实际不符 + schema 主动误导 LLM 用无效参数、浪费其决策注意力。更关键：**权威现状文档 §7.5 的「透传链已核验」是错误陈述**（信它者会据此推进 / 宣传一个不工作的能力）。行为本身是有意为之（有测试锁定），故根因是「文档 + schema + 事件三处对外承诺，唯独执行落点被禁用」。
- **对照 03 分册 F1**：`reasoning_effort` 也是「schema 声明、执行不读」但被判 P2——差异在那里**权威文档如实标注了 MVP 限制**（`编排器与CEO主Agent.md §2.1`「MVP 不发」），只是 schema 措辞超前；此处**权威文档反过来称「已核验」**，属重大漂移，故升一档 P1。若人评估认为「opt-in 且实验性」可对齐 P2，但「已核验」的错误陈述需无论如何修正。
- **修复方向**：二选一——① 恢复 `debater_task` 注入并做端到端跨厂商验证，兑现文档；② 把 §7.5 改写为「per-side model MVP 暂未启用（全链路统一模型）」、从 `schema.py` model 描述撤下「路由到不同厂商」承诺、`to_event_payload` 暂不发 `model`（或前端明确不渲染），三处口径与「已禁用」对齐。

### F2 · 质询解析：JSON 数组元素非 dict 时静默丢答、不回退启发式（记分被误扣）

- **严重度**：P2
- **类别**：BUG
- **证据**：
  - `cross_exam_parse.py:45-54`：`parse_cross_exam_response` 一旦 `_extract_json_array` 返回**非 None** 就直接走 JSON 路径、**不再回退**启发式。
  - `cross_exam_parse.py:57-78`：`_extract_json_array` 只要首`[`末`]`间能 `json.loads` 成非空 list 即返回——**不校验元素是否为 dict**。
  - `cross_exam_parse.py:81-96`：`_exchanges_from_json_items` 对每个 `not isinstance(raw, dict)` 的元素 `continue`，默认列表 `[CrossExamQa(answer="", ok=False) …]` 原样返回。
  - **触发形态**：辩手把作答写成 JSON 数组**但元素是字符串**（`["答案一","答案二"]`，是「要求输出 JSON 数组」下颇常见的少一层 wrapper 畸形），或 prose 里夹一个可解析的标量数组（如「p99 降到 `[120, 800]` ms」）→ 全部 exchange 变成 `answer="" / ok=False`。
  - **无测试覆盖**：`test_cross_exam_parse.py` 只测 dict 数组 / 纯 prose，未覆盖非 dict 数组。
- **影响**：辩手其实作答了却被判「全部未正面作答」→ 裁判 `engagement` 记分被误扣、逐条 A 摘要为空（全文仍随 `answer_run_id` 走、不丢，但 `ok`/摘要失真会带偏 verdict 与 leaning）。属畸形输入下的边界正确性缺口。
- **修复方向**：JSON 路径产出 0 条有效映射时回退 `build_cross_exam_exchanges`（启发式）；或对标量数组按位置映射为 `answer`。

### F3 · 质询 runner 的后端落地 glue（`make_cross_exam_runner`）无测试驱动

- **严重度**：P2
- **类别**：TEST
- **证据**：
  - `rounds.py:258-357`（`make_cross_exam_runner`）承载质询回合 P1 的真实执行：并行 `continue_run` 作答 → `parse_cross_exam_response`（339）→ 构 `CrossExamExchange` → 失败兜底 `build_cross_exam_exchanges`（327,351）→ 折账 / 留人 / recall_count。
  - 无任何测试驱动它跑通：`test_debate_tool.py` 的 `_DebateLLM.complete`（67-87）对 `cross_exam` 步**无分支**、落到 `return LLMResponse(content="{}")` → `_cross_exam_questions` 拿不到问题 → runner **从不被调**；`test_debate_moderator.py` 用**假** `_RecordingCrossExam`；`test_cross_exam_parse.py` 只测纯解析函数。
- **影响**：质询回合是「让辩论像真人」的 P1 支柱，但其后端 glue（continue_run + 解析 + 落 exchange + 失败兜底 + session 续写）属未测路径，回归（如 F2 的解析变更、continue_run 契约变更）会静默漏过。
- **修复方向**：加一条集成测试——假 provider 对 `cross_exam` 步吐 `{"questions": {...}}`、`stream` 产结构化 JSON 作答，驱动真实 `run_cross_exam` 跑通并断言 exchange 落进 `RoundResult.cross_exam` + 失败方兜底 not-ok。

### F4 · 代码注释引用的决策文档 `开放主流AI模型接入 §4.7` 不存在（悬空引用）

- **严重度**：P3
- **类别**：DRIFT
- **证据**：`prompt.py:172` 以「（开放主流AI模型接入 §4.7）」作为「忽略 per-side model」的决策依据；但 `docs/` 下 glob `*模型接入*.md` 命中 **0**（该文档不存在；全仓另有多处 `开放主流AI模型接入 §4.5/§4.7` 悬空引用）。且该「决策来源」与 in-scope 权威文档 `辩论编排设计.md §7.5`（称已核验）**直接冲突**——即 F1 的一体两面：决策指向一个不存在的文档。
- **影响**：读者无法据注释追到真实决策；与权威文档口径打架，加深 F1 的混乱。
- **修复方向**：随 F1 一并修——把「per-side model MVP 暂不启用」的决策落到真实存在的文档并统一引用。

### F5 · 记分 / decisive 未按形态门控：圆桌简报可能被「裁胜负」带偏（NEEDS-VERIFY）

- **严重度**：P3
- **类别**：DESIGN
- **证据**：质询回合（`moderator.py:620-625`）与结辩（627-632）都按「`thorough` + 对抗形态」门控，**唯记分未门控**——`_judge_and_summarize` 对**所有形态**都索取 `scores`（756-785）、`_brief` 对所有形态都注入 `_scores_block` 且要求「decisive / leaning 须与累计记分一致」（876-884）；但圆桌的 `_brief_form_hint`（179-183）又要求「不强行裁谁对谁错、出观点地图」。二者对多方圆桌存在张力。
- **影响**：圆桌本为「铺光谱、非争胜负」，若记分驱动的 decisive/leaning 压过 form hint，简报可能不当地「裁出赢家」。需真模型跑一场圆桌确认是否真被带偏（form hint 也可能抵消），故标 **NEEDS-VERIFY**。
- **修复方向**：圆桌跳过 `decisive` / 记分对齐要求（或明确记分对圆桌仅作 momentum 展示、不驱动 leaning）。

### F6 · cross_exam 解析启发式 nit：`overall_ok` 在 JSON 路径被忽略 + 行首数字误切段

- **严重度**：P3
- **类别**：BUG（低）
- **证据**：
  - `cross_exam_parse.py:31-54`：`parse_cross_exam_response(overall_ok=…)` 只把 `overall_ok` 透给启发式降级，**JSON 主路径不用**（`ok` 全由 `directly_addressed`/`ok`/`bool(answer)` 推）。真实调用恒 `overall_ok=True`（`rounds.py:339`），故无实际后果，但签名有误导性。
  - `cross_exam_parse.py:19-26,176-187`：`_SECTION_RE` 的 `\d+[.、)]` 在**行首**匹配——作答某行以「3.5 倍……」开头会被误当第 3 段切分（启发式降级路径的边界，非主路径）。
- **影响**：均为畸形 / 降级路径下的低概率失真，不影响主路径。
- **修复方向**：文档化或在 JSON 路径也纳入 `overall_ok` 语义；`_SECTION_RE` 数字分段要求其后跟非数字，避免小数误切。
