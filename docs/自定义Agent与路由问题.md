# 自定义 Agent 与路由问题

> **状态**：核心方向已确定（不预制角色 + 统一编排器路由）
> **创建时间**：2026-06-13
> **更新时间**：2026-06-14

---

## 核心问题

在 Multi-Agent First 产品中，是否需要支持用户自定义 Agent？如果支持，当用户的请求与所有自定义 Agent 都不匹配时，应该委派给谁？

这是 Multi-Agent 系统路由层的根本性挑战。

---

## 一、是否需要自定义 Agent？

### 支持自定义的理由

1. **长尾需求无法穷举** — 无法为每个行业/场景预建 Agent（律师、量化交易、学术写作…）
2. **差异化** — 如果所有 Agent 都是预设的、不可定制的，产品退化成「更花哨的 ChatGPT」
3. **用户粘性** — 用户投入时间定制的 Agent 团队 = 迁移成本 = 留存率
4. **生态飞轮** — 自定义 Agent 可以演化为 Agent 市场，用户互相分享/交易

### 自定义带来的问题

1. **路由困难** — 核心难题，见下文
2. **质量不可控** — 用户自建 Agent 可能效果很差
3. **安全风险** — prompt 注入、数据泄露
4. **用户门槛** — 普通用户不知道怎么"设计"一个 Agent

---

## 二、路由「不匹配」难题的三种场景

| 场景 | 示例 | 本质 |
|------|------|------|
| **A. 有合适的 Agent 但路由未匹配** | 用户问财务问题，有「财务分析 Agent」但路由器没正确匹配 | 路由器智能度不足 |
| **B. 完全没有合适的 Agent** | 用户问量子物理，团队里全是编程和设计 Agent | 能力覆盖缺口 |
| **C. 多个 Agent 都沾边但都不专业** | 用户要写技术博客，研究员和开发者都能做一部分 | 协作编排问题 |

## 三、曾讨论的设计方向

以下方向在早期探索中考虑过，最终采纳了方向 4（动态 Agent 生成），融入编排器统一架构：

### 方向 1：通用 Agent 兜底

- 系统内置一个不可删除的 General Agent，使用最强基础模型
- 当没有专业 Agent 匹配时，General Agent 处理
- **优点**：简单可靠，永远有出口
- **问题**：跟单 Agent 产品有什么区别？用户可能永远依赖 General Agent

### 方向 2：智能路由器 + Agent 自评

- 路由器分析用户意图，与所有 Agent 的能力描述做语义匹配
- 候选 Agent 对任务进行置信度自评（0-1），选最高的
- **优点**：更精准的匹配
- **问题**：自评可靠吗？自评本身消耗额外 LLM 调用，延迟和成本

### 方向 3：用户主导路由

- 让用户直接选择或建议把任务分配给谁
- **优点**：最准确，用户最了解自己的意图
- **问题**：增加用户操作负担，违背"智能"的初衷

### 方向 4：动态 Agent 生成

- 当没有匹配时，系统根据用户需求自动创建一个临时 Agent
- **优点**：完全消除覆盖缺口
- **问题**：临时 Agent 的质量？创建的延迟？与自定义 Agent 的关系？

### 方向 5：混合方案

- 组合以上多种方式
- **问题**：复杂度如何控制？用户心智模型是否清晰？

## 四、更深层的问题

1. **自定义 Agent 的"定义"是什么？** 是一段 system prompt？是一组约束？是工具集合？还是完整的工作流？不同的定义会影响路由方式。

2. **路由的粒度** — 是整个对话路由到一个 Agent，还是每条消息独立路由？还是一个任务可以在 Agent 之间流转？

3. **路由失败的用户体验** — 当系统不确定时，应该：
   - 默默兜底？（用户可能不知道用的不是最优 Agent）
   - 明确告知用户？（增加认知负担）
   - 让 Agent 们"竞标"？（有趣但可能混乱）

4. **自定义 Agent 的生命周期** — 创建、测试、迭代、分享、归档的完整流程

---

## 五、已确定的决策

以下决策已写入 DECISIONS.md：

1. **不做预制 Agent 角色**，采用动态角色分配 + 用户可选行为模板（[§5](DECISIONS.md#5-agent-角色策略)）
2. **统一编排器路由**，所有任务经过编排器，无前置分类器（[§14](DECISIONS.md#14-简单任务处理策略)）
3. **自适应 UI**，单 Agent 时为聊天形态，多 Agent 时展开协作面板

### 上述决策如何回应本文的路由难题

| 场景 | 解决方式 |
|------|---------|
| A. 路由未匹配 | 不存在此问题——无预制角色，编排器动态分配 |
| B. 完全没有合适的 Agent | 编排器为任意任务生成临时角色，等效方向 4（动态 Agent 生成） |
| C. 多个 Agent 都沾边 | 编排器决定 Agent 数量和分工，等效协作编排 |
