# 项目结构

> **状态**：✅ 已确定

---

## 一、总览

Monorepo 布局，前后端统一管理：`apps/server`（Python/FastAPI）、`apps/desktop`（Electron + React）、`apps/mobile`（Vite SPA + Capacitor，Bearer 鉴权）、`apps/admin`（独立运营控制台，详见 [`管理员后台.md`](/docs/05-平台与运维/管理员后台.md)）；根级 `packages/`（跨端规范与契约，非业务实现）；`deploy/` 为 compose 与环境模板；`docs/` 为设计文档。

→ 见代码：`apps/server/agentcore/`、`apps/desktop/src/`、`apps/mobile/src/`、`packages/`。OpenAPI / SSE 类型同步 → 见 [本地开发.md](/docs/02-架构/本地开发.md)。

本文只记录目录树看不出来的**分层边界**与非显然依赖。

## 二、后端分层（apps/server/agentcore）

> 目录与文件清单 → 见代码：`apps/server/agentcore/`。模块体系与 runtime 子包见 [`后端架构.md`](/docs/02-架构/后端架构.md)。下表只记录**非显然依赖约束**。

> **约束的粒度**：硬约束守的是「调用方向不反转 + 入口层不干执行层的活」，**不是**「禁止 import 任何符号」。共享**类型/事件/常量/目录**不算违反（它们本就是上层要消费的数据）。真正的护栏是「不在路由里构建/调用 LLM、不在路由里驱动 runtime 执行；叶子工具不依赖业务模块」。落地由 import 边界测试守（见 `apps/server/tests/test_arch_boundaries.py`）。

| 模块 | 不依赖（硬约束） | 例外 / 说明 |
|------|------------------|-------------|
| `api/` | **不在路由内构建/调用 LLM provider、不驱动 runtime 执行** | 路由薄层：业务经 `service`（`conversation`/`assist`/…）+ `schemas`。**允许** import `runtime`/`llm`/`tools` 的类型·事件·常量·目录（`runtime.events`、`llm.protocol.TokenUsage`、`llm.pricing` 常量、`tools.catalog`、投影纯函数如 `journal.runs_from_entries`）；**禁止**在 handler 里 `build_provider`/调 provider/驱动 pipeline——这类逻辑下沉 service（如 `assist.rewrite`） |
| `runtime/` | conversation, api | 执行核心不回依入口层 |
| `llm/` 网关本体 | 所有业务模块 + db | `factory`/`deepseek`/provider 保持**纯网关、db-free**（凭据由调用方传入） |
| `llm/` 凭据服务 | — | `key_service`/`byok` 按职责桥接 `db`（读用户 BYOK 密钥仓储 + 解密）；与网关本体区分，**不属违规** |
| `tools/` 叶子工具 | 所有业务模块 | web/file_ops/grep/code_execute 等纯工具 ⊥ runtime/llm |
| `tools/builtin/` 编排原语 | — | delegate/debate/ask_user/escalate/revise 等**经 tool-calling 触发的编排原语**，按职责依赖 `runtime`/`llm`（与 [`后端架构.md §三`](/docs/02-架构/后端架构.md) 「编排原语与 runtime 同构」一致） |
| `memory/` | db, runtime（记忆维护走文件 + llm，不经 runtime 回路） | |
| `db/` | 所有其他业务模块 | |
| `core/` | 所有业务模块（共享类型，零向上依赖） | `config` 视为 core 之下的**配置地基**，可被 core 依赖（settings 非业务模块） |

### 调用链路

→ 见代码：`conversation/service.py`（`stream_chat` 入口）+ `runtime/pipeline/`。

## 三、跨端共享包（packages/）

pnpm workspace 纳入 `packages/*`、`apps/desktop`、`apps/mobile`、`apps/admin`（→ 见根 `pnpm-workspace.yaml`）。**共享的是规范 / 契约，非业务实现**（各端 stores / services / fold / 组件各自全新建）。

| 包 | 职责 |
|---|---|
| `protocol-conformance` | SSE 测试向量 + golden harness + `ProjectedTurn` schema |
| `contract-types` | SSE 事件判别联合（`events.ts`）；理想态后端 schema 生成 |
| `contract-rest-types` | OpenAPI 生成 REST 类型（desktop / admin / mobile 共享单一源） |
| `design-tokens` | 跨端语义色 token |

协议 fold 对账：根目录 `pnpm conformance`；后端 golden 重导 `python -m agentcore.conformance.export`。→ 见 [`前端技术与架构.md` §十二](/docs/04-前端/前端技术与架构.md)、`.cursor/rules/protocol-conformance.mdc`。

## 四、手机端（apps/mobile）

独立 Vite + React 应用：自有 stores / services / 协议 fold / 组件；鉴权走 Bearer（非 cookie）。Capacitor 8 套壳（Android 工程已 scaffold）；web 版已部署 Cloudflare Pages。→ 产品减法与跨端策略见 [`前端技术与架构.md` §七](/docs/04-前端/前端技术与架构.md)；原生壳 / 商店余项 → [`远期规划`](/docs/06-规划/远期规划.md) §3.2。

## 七、包管理与工具链

根级 **pnpm workspace**（`packages/*` + `apps/desktop` + `apps/mobile` + `apps/admin`）；后端 **uv**。跨端门禁 `pnpm conformance`（CI mobile job + 本地可串桌面 vitest）。REST 类型单一源：根 `pnpm gen:types` → `@agentcore/contract-rest-types`（desktop/admin/mobile 经 shim re-export）。其余工具链见各包 manifest 与 CI（Biome / Ruff / Vitest / pytest / Alembic 等）。
