## 一、总览

Monorepo 布局，前后端统一管理。类型同步：后端 `scripts/dump_openapi.py` 导出 committed `apps/server/openapi.json` → 前端 `pnpm gen:api`（`openapi-typescript`）生成 `apps/desktop/src/renderer/types/api.generated.ts`（gitignore，`postinstall` 自动重生成）。

```
AgentCore/
├── docs/                          # 设计文档
├── apps/
│   ├── server/                    # Python 后端（FastAPI；scripts/dump_openapi.py 导出 OpenAPI spec）
│   └── desktop/                   # Electron + React 前端（pnpm gen:api 生成 TS 类型）
├── deploy/                        # 部署配置（compose / searxng / 环境模板 / init-db）
├── .github/workflows/             # CI/CD
└── README.md                      # 仓库首页指针 → docs/索引.md
```

完整目录树以代码为准 → 见代码：`apps/server/agentcore/`、`apps/desktop/src/`。本文只记录目录树看不出来的**分层边界**与**调用链**。

## 二、后端分层（apps/server/agentcore）

> 目录与文件清单 → 见代码：`apps/server/agentcore/`。模块体系与 runtime 子包见 [`后端架构.md`](/docs/02-架构/后端架构.md)。下表只记录**非显然依赖约束**。

| 模块 | 不依赖（硬约束） |
|------|------------------|
| `api/` | runtime, llm, tools（HTTP 入口只经 schemas + service） |
| `runtime/` | conversation, api |
| `llm/` | 所有其他业务模块 |
| `tools/` | 所有其他业务模块 |
| `memory/` | db, runtime（记忆维护走文件 + llm，不经 runtime 回路） |
| `db/` | 所有其他业务模块 |
| `core/` | 所有其他模块（共享类型，零向上依赖） |

### 调用链路

→ 见代码：`conversation/service.py`（`stream_chat` 入口）+ `runtime/pipeline.py`（Prepare → Execute CEO/`delegate` → Finalize 持久化/SSE）

抽象链：`POST …/messages` → `conversation.service` 持久化用户消息 → `run_chat_pipeline`（载入记忆/prompt/工具 → CEO `react_loop` → 按需 `delegate`/`WaveScheduler` → SSE）→ 落库助手消息 + 标题/记忆维护。

## 三、前端组织原则（apps/desktop/src）

> 目录与文件清单 → 见代码：`apps/desktop/src/`（`main/` 主进程、`preload/` 安全桥、`shared/` 三端共享契约、`renderer/` React 渲染层）。下表为代码看不出的组织判据。

1. **页面级布局（pages/ + router）**：全局只有 AppShell（侧栏 + Outlet），各页面自定义布局（对齐 [前端UX设计.md](/docs/04-前端/前端UX设计.md)）
2. **components/ 按业务域分目录**：chat / graph / files / sidebar / layout，组件就近组织
3. **stores/ 集中管理**：多页面共享状态（如 execution 被 chat 与 graph 同时消费）；单测就近放 `stores/__tests__/`
4. **shared/ipc-contract.ts**：主/preload/renderer 三端共享的 IPC 契约单一真相源（本地文件系统）
5. **types/ 自动生成** ✅：`api.generated.ts` 由后端 OpenAPI 经 `pnpm gen:api` 生成，不手动编辑
6. **shadcn/ui** ✅ 已部分落地：`components/ui/`（dialog、tooltip、popover 等基础组件），其余按需添加

## 四、部署结构（deploy/）

```
deploy/
├── docker-compose.dev.yml         # 本地开发（PG + Redis + SearXNG）
├── docker-compose.server.yml      # 生产基础设施（infra-only；应用在宿主机以 uv/systemd 运行）
├── config/production.env.example  # 生产环境变量模板（真实 production.env 被 .gitignore 忽略）
├── searxng/settings.yml           # SearXNG 引擎配置（dev/prod 共用）
└── scripts/init-db.sh             # DB 初始化
```

> 后端 Dockerfile、生产应用容器化 compose、Nginx / Cloudflare 配置源、`deploy-server.sh` 自动部署**尚未纳入仓库**（详见 [`../05-平台与运维/部署与运维.md` §三](/docs/05-平台与运维/部署与运维.md)）。
