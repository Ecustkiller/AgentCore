# 双模式工作区（云 + 本地）

> **定位**：给每次协作一个持久项目空间；云与本地**平等**——**不给用户云/本地开关**，模式跟着「文件在哪」走。
>
> **边界**：Backend / 绑定 / Sidecar / 共享空间 / 约定文档目录。记忆注入 → [记忆系统](/docs/03-AI核心/Agent记忆与知识系统.md)；文件树 UX → [前端 UX §九](/docs/04-前端/前端UX设计.md)。
>
> → 见代码: `apps/server/agentcore/workspace/`

---

## 一、两种模式平等

- **内核**：多 Agent 在同一张「桌子」上靠文件协作；「在不在本地磁盘」是第二层偏好。
- **云** = 零前提起点（打开即用、可隔离协作）；**本地** = 平等的另一种（开发者内环改真实仓）。
- **无开关**：模式由绑定自动决定；「云优先 / 本地优先」只是构建顺序。
- **G3 远程**：云工作区可从产品 UI 浅克隆 http(s) 仓；私仓用账户级 PAT（设置 · Git 凭据）。Local 不代持密码——继承 OS credential helper / `gh auth`。→ [工具 · G3](/docs/03-AI核心/工具与能力系统.md#git-闭环)

## 二、三正交轴与拒绝实时同步

| 轴 | 取值 |
|---|---|
| 轴1 执行位置 | server / local |
| 轴2 文件源头 | server dir / local dir |
| 轴3 持久化 | S3 快照 / 仅本地盘 / ~~实时同步~~ |

「云 / 本地模式」= 轴1+轴2 一整套。所谓「本地默认云储存」= `local + local + cloud`——**不是第三种模式**，而是 LOCAL 的存储策略：

- ✅ 接受快照 / 交接（git-push 式）：本地唯一真相源，按需经 `StorageProvider` 快照到 S3。
- ✅ / ⏳ **云沙箱工作副本 + 显式合回**：交接放大为「云上改副本 → 人确认再写回本机」——MVP 第一档见 §7.6；仍非双向同步。
- ❌ **拒绝实时双向同步**（Dropbox 式）：双真相源 + 冲突，在并行 Agent 并发写下尤其致命。

## 三、`WorkspaceBackend` 抽象原则

沿用 Protocol + 实现 + 工厂（同 `LLMProvider` / `SandboxProvider`）。引擎与工具只对接口编程。

- **护栏·瘦接口**：持久化（snapshot/restore）**不进 backend**——属轴3，归独立 `StorageProvider`。backend 只管「文件 + 执行」这对必须同源的能力。
- **为何 P0 引入**：本地是已承诺路线；接口先行使加 `LocalWorkspace` 时工具/引擎零改动。
- **唯一接缝**：`ToolContext.workspace_dir` → `backend: WorkspaceBackend`；`code_execute` 收编进 `backend.execute`（与文件同目录）。

→ 见代码: `apps/server/agentcore/workspace/`

`ServerWorkspace`：服务端目录 + 同进程沙箱。`LocalWorkspace`：用户真实本地目录 + 桌面执行；传输不另造——把审批门「挂起 + HTTP 回填」泛化为 `WorkspaceChannel`。Sidecar 文件 op 直连本机（不经 channel），但后台进程仍交主进程代持（sidecar 生命周期短于 dev server）。

## 四、约定文档目录约定

多幕协作副产物落工作区约定目录。**否决**另建「会话级团队约定文档」实体——复用既有项目/工作区文件心智。全部挂在 `AgentCore/文档/`（产品心智 = AI 文档统一入口；**不**进 `<rules>` 注入）。

| 目录 | 谁写 | 谁读 |
|---|---|---|
| `AgentCore/文档/research/` | MLR / 自由讨论 / 竞品笔记（`form=files`） | 后续辩论 + 主持人索引 |
| `AgentCore/文档/debate/` | 辩论收场机制 | 用户 / 后续回合按需读 |
| `AgentCore/文档/reviews/` | 审查类 `form=files` | CEO 汇总 / 用户按需 |
| `AgentCore/文档/项目/` | 厚约定文档（闸清后/普通回合按需；**探索 pending 不写**） | 用户 / 后续回合按需读 |

落盘与 handoff 摘要正交：结构化 handoff 走委派通道；完整报告叠加写文件。`<workspace_context>` 只陈述布局，不注入正文。约定文档类委派由运行时按 `stage_dirs` 填默认 `artifact_dir`（brief 仅引用约定文档路径、或业务 `artifacts` / `repair_code` 等跳过约定文档默认时不自动绑）。`文档/项目/` 常量 → `stage_dirs.PROJECT_DOCS_DIR`。

**向用户报路径（✅ 提示约束）**：收口列出落盘文件时，须用工作区相对完整路径（与上表约定文档前缀一致），以 `file_write` 回执 / `artifacts` / 交付对账为准；禁止裸写 `reviews/…` 或同一清单混用两套前缀。→ CEO `【产物路径】` · `<workspace_context>` 约定文档边界

**约定文档文件命名（✅）**：柜名 / 抽屉目录不动；规范柜内文件名。

| 规则 | 约定 |
|---|---|
| 类型前缀 | 英文小写 + 连字符（机器友好）；可读短名可中文 |
| 权威默认名 | 只在一处常量；playbook 文案 / 验收 / 技能须引用，禁第三种默认名 |
| `reviews/` 代码审计 | `code-audit-{slot}-{slug}.md`（slot=`0/1/2…`，**禁止** `audit_0` 叠进文件名）；汇总 `code-audit-summary.md`；台账同名 `.audit.json` |
| `reviews/` 日复盘 | `{YYYY-MM-DD}.md`（保持） |
| `research/` 成篇主文件 | 权威默认 `报告.md`（`output_path` 可覆盖；验收只认主路径） |
| `research/` 单角调研中间产物 | `调研要点.md`（**勿**与主文件抢名） |
| `research/` 多角 / 透镜 | `{短名}调研报告.md` / `{短名}透镜报告.md`；汇总 `汇总与命题卡.md`（辩论依赖，保持） |
| `research/` 审校 | `AgentCore/文档/reviews/审校报告.md`（本轮保持中文名） |
| `debate/` | 机制落盘名保持（本轮不动） |

旧 dogfood 产物不自动迁移。生成端 → `playbooks/audit.py` · `research_quality.DEFAULT_RESEARCH_REPORT_ARTIFACT` · `playbooks/research.py`。

**写路径扁平（✅）**：上表四个约定文档前缀下，写工具（含 `file_batch`）把前缀之后的嵌套 `/` `\` 压成 `_` 成单文件名（例 `reviews/audit-ai/01.md` → `reviews/audit-ai_01.md`）；派 `artifacts` / 约定路径时用平铺名，勿再 move「改回」斜杠子路径。→ `workspace/_paths.sanitize_write_relpath`

同树旁路（仍系统噪音，对 AI / 用户文件 UI 都隐藏；**不**注入）：`AgentCore/{index,trash,baselines}/`（code_search · 软删 · 回合基线）。与可见 `规则/` · `记忆/` · `文档/` 同根；路径感知忽略（禁止全局忽略裸名 `index` 等）。**勿与**容器路径 `~/Documents/AgentCore/` 混淆。常量 → `stage_dirs.{INDEX,TRASH,BASELINES}_REL`。

**否决**：约定文档与 `AgentCore/{规则,记忆}`「两根并存」——改为统一挂 `AgentCore/文档/`；规则/记忆仍仅 documents 注入。否决独立隐藏根 `.agentcore/`（已并入约定根旁路）。

机制 → [编排器 · MLR](/docs/03-AI核心/编排器与CEO主Agent.md)、[辩论编排](/docs/03-AI核心/辩论编排设计.md)；根夹 → [记忆 §5.0](/docs/03-AI核心/Agent记忆与知识系统.md)。

## 五、绑定：项目即工作区 · 裸聊默认云

- **项目 = 工作区**：Folder 必声明 `mode`；**项目**绑定创建后不可改；会话归入项目则继承该项目为**默认桌**与原始上下文。
- **会话归属中途不改挂**（旧称「出生定终身」的正确半边）：创建时绑定项目或明确无项目；**禁止**事后改写本会话 `folder_id` / 把对话移入另一项目。要换心智 → 新开对话。「打开项目」= 建/复用 Folder + **新会话**挂 `folder_id`，禁止 auto-promote 裸聊。
- **可达多桌（✅）**：归属不改 ≠ 手只能碰默认桌。同对话内 `delegate` 任务可带已解析的 `target_folder_id`，worker 在该项目根写盘且记忆跟目标桌；有出生未点名 → 仍坐会话默认桌；无出生未点名 → 禁默写 `conv:` scratch。同指挥面可 `create_project`（云）/ `register_local_project`（本地登记、resume 本对话）；与 `open_local_project`（打开当出生=新会话）分流。**多 local 同回合可并行**（每目标一 LocalWorkspace + channel）。→ 见代码: `tools/builtin/projects.py` · `runtime/delegate/target_desktop.py`
- **打开文件夹 = 本地项目**：所选目录 → `mode=local`、`local_subpath` 空、根=该目录；建/复用 Folder + **新会话**挂 `folder_id`。
- **`bind_local_folder` ≠ 打开项目**：仅把裸聊 scratch 绑到本机执行环境（`conversations/<id>`）；文案与产品心智不得冒充「打开仓库 / 打开项目」。
- **裸聊**：默认云 `conv:<id>` scratch；桌面新建默认云执行；显式「本机草稿」才用容器根下 `conversations/<id>/`（**仅落盘位置**，≠本机引擎、≠打开项目；执行默认仍过桥）。亦可作跨项目指挥面（先建/登记/点名再派）。
- **路由**：读生效绑定 → Local / Server；无云/本地开关。异桌 worker 另建目标 folder 的 backend，**不**改会话绑定。
- **用户心智**：「默认在你打开的项目（或裸聊 scratch）里干活；同一对话也可以派团队去改别的已有项目——对话归属不变。」

**裸聊默认云的理由**：① 关桌面任务停是 Multi-Agent 长任务硬伤（云可续跑）；② 大众交付形态是「云预览 + 一键导出」；③ 多端可见；④ 混合态下对话正文回写云，隐私论点不支持 local-first。开发者「指着本地文件干活」由**打开本地项目**完整保留；本会话临时要本机跑通仍可用 bind；跨项目指挥用登记/派工，不必为每个目标新开对话。

**否决**：auto-promote 裸聊为 Folder；会话中途改 folder；桌面裸聊 local-first（被默认云替代，容器根与显式本地绑定仍保留）；用改会话挂载冒充跨项目（须走 `target_folder_id`）；用 `open_local_project` 冒充同对话先建后干。

云 scratch 产物导出 = 预览 + 一键导出（git-pull 式单向 checkout，与 §二 快照语义对称）。平台代付**不为云执行新增配额维**——推理 `quota_*` 天然封顶；真实负载后再议。

## 六、关键边界

| 项 | 约束 |
|---|---|
| 路径 | 相对工作区根 POSIX；裸 `/` 与 `\` → `.`；其它绝对路径拒。禁止工具私有 `if path=="/"` |
| 归属变更 | **不支持**事后改挂本会话到另一项目（要换心智→新开对话）。**不**禁止同对话委派 worker 到其他项目根（`target_folder_id`）；文件搬运仍是显式动作 |
| 删除 | 软删可逆分轨：云端/sidecar → `AgentCore/trash/`（`GET|POST …/trash` 一键 list/restore，保留期对齐 `workspace_retention_days`）；本地默认 → 系统回收站（**不**承诺产品一键还原）。无系统回收站时桌面兜底仍写 `AgentCore/trash`，可由桌面 IPC 还原。硬删旁路仅针对同树内部区 `AgentCore/{index,trash,baselines}`。删**含 trash 的祖先**（含裸 `AgentCore`）→ **按子项展开**（先硬清三 zone，再逐项软删可见子树），禁止整树移入自身回收区；`WorkspaceIOError` → API 422。删规则/记忆/文档仍可逆 |
| 脚本/shell 破坏可回滚 | Local：`code_execute`/`terminal`/`host_shell` 命中破坏性删启发时，须有本回合 zip 基线（`AgentCore/baselines/`）否则 `FORCE_APPROVAL`；顶层整项目树另窄闸（白名单清 `node_modules`/`.venv` 等不误拦）。桌面通道 Local 经 `ensure_turn_baseline` 落盘/探测非空 zip（gate 问 ready，不给服务端假 `Path.root`）；Sidecar `ServerWorkspace(location=local)` 仍走 Path zip。普通回合基线仍 best-effort、失败不阻断。还原 = overlay 尽力（有体积/忽略目录门），非完整镜像。UI：有基线即可进「改动」恢复，不依赖 `file_*` 产物。无 git 时上下文软提示 `git.init_baseline`（不硬拦派工）。→ `destructive_fs` · `turn_baseline` · `safety_breaker` |
| 本地并行团队 | 同回合多本地根（不同 `root_id`）✅ 经每目标一 `WorkspaceChannel` 并行；sidecar 进程内多根仍 ⏳ C2。单通道容量有限时仍可 snapshot 交接云端放大并行 |
| 引用区外文件 | 单文件仍优先复制进 `attachments/`。对话级区外目录挂载（`external/<别名>/…`）与绑定 / 打开项目 **正交**：桌面在线即可（云 scratch 亦可），不改 binding。**只读**：工具 `external_mount_readonly`（`approval=never`）按 path 与/或 `well_known`+`target_name` 静默挂载——无授权决策卡、grant 链**无**系统选文件夹；成功后同回合热挂载（云 backend）；模型面日常仍走 `external/`，**禁止**把 abs 当 `file_*` 日常路径。**整理/写回**：`ask_user`+`grant_organize_folder` 仍须用户确认（卡上展示 `display_label`，非完整 abs）；只读挂过 ≠ 已授写。找不到 → 明确失败，不弹 picker。**登记**：服务端只存 alias/root_id/mode；持久 abs 只在桌面（`fs-session-grants.json`）；mount 工具参数可含 path（运输例外，与用户原文同级）。**可见/可撤**：工作区面板列本对话挂载并可撤销。⏳ 本地引擎（sidecar）mid-turn 热推 `externalMounts` 未齐——下回合/resume 注入仍可用 |
| ⏳ 本机 Host | 与工作区绑定**正交**的第三能力面（观测/开系统面板/受控动作）；运输同属桌面回填通道族；云 scratch 亦可装配。→ [工具与能力 · Host](/docs/03-AI核心/工具与能力系统.md) |
| 多 worker | 锁/审批门/通道/handoff 现为进程内态；多机需 Redis + durable queue ⏳ |

HTTP / `ws_id`（`folder:` / `conv:` / `shared:`）→ 见代码: OpenAPI + `workspace/locate.py`。本地 `location=="local"` 时 REST 写/索引返回 409；只读 snapshot list/download 放行。

## 七、Sidecar（本地引擎）与执行路径

比 `LocalWorkspace`（云端引擎 + `WorkspaceChannel` 遥控桌面）更深一层：引擎本体可搬到桌面子进程跑同一 `run_chat_pipeline`，工作区直连本地盘。**产品心智上须与「工作区是否本地」拆开**——见下。

### 7.1 三层勿混（已确认）

| 层 | 用户在选什么 | 示例文案 |
|---|---|---|
| **工作区** | 文件在本机还是云 | 「AgentCore · 本地」= 项目文件夹在本机，**不是**选了本机引擎 |
| **执行路径** | Agent 循环跑在哪 | 云端过桥 = 云上跑引擎、经通道读写本机盘；本地引擎 = 本机子进程跑引擎、直连盘 |
| **模型 / 计费** | 推理从哪出 | 今天两条执行路径下推理仍多经云代理；**不得**把「本地引擎」卖成离线或「数据不出本机」 |

Composer：**用户只选工作区**（本地项目 / 云项目）；**否决**大众面并排「本地引擎 / 云端过桥」当可选项（易与「· 本地」混淆）。执行路径失败降级用轻 toast，不靠常驻引擎 chip 抢注意力。→ [前端 UX · 模型与自主度](/docs/04-前端/前端UX设计.md)

### 7.2 产品路由定案（✅ 默认全过桥观察）

**已落地**：大众路径 **默认全部走云端过桥**（绑本地文件夹亦然 → `location=local` + `via=cloud`）；用真实负载观察轻～中是否可接受、重读盘差多少。

| 项 | 定案 |
|---|---|
| 默认执行 | **云端过桥**（`SIDECAR_DEFAULT_ENABLED=false`；不默认拉起 sidecar） |
| 产品面 | **取消「本地引擎」作为用户概念**（Composer 无引擎 chip；设置高级「允许本机执行」默认关） |
| 代码资产 | sidecar **暂留、默认不走**；效果不可接受或完全离线/本机一体私有化再评估加回 |
| 高级 | 「允许本机执行」= 偏好显式 `on`，走旧 sidecar |
| 续跑 | **路由意向 ≠ 恢复事实**：已有 `origin=sidecar` / 本机活回合续跑跟本地事实，忽略大众默认关 |
| Toast | 默认云路径**静默**；禁止常态「本地引擎已关闭」推回大众面 |
| 否决（本阶段） | 以「静默默认 sidecar」冒充产品取消；继续让用户二选一引擎 |

机制能力（stdio JSON-RPC、降级规则、窄票、outbox 等）仍以下文为准；**默认路由以本表为准**。

### 7.3 本地引擎相对过桥：不可等价替代什么

- **不可被过桥「做成一样」的**：引擎与本机盘同侧 → 文件工具循环无「云下指令 → 桌面再读盘」往返；重读盘/多工具更不易把 `WorkspaceChannel` 挤死。过桥只能少跳、跳得稳，不能变零跳（除非引擎也在本机，或盘改到云上）。
- **今天并不交付的**：真正离线、数据不出本机（对话回写云、推理出网）。断线产品档仍是 **断线只读**（不能发送/改文件/跑 AI）。
- **轻～中负载**：过桥体感往往接近「差一点」；**本机大仓 + 多 Agent 狂读写**：差别可以很大——默认全过桥是**观察试验**，不是断言无感。

### 7.4 与完全离线 / 私有化

- **完全离线** ⏳（本机推理 + 本机消息库 + 本机执行）：需要「本机运行时」形态；**打开今天的 sidecar ≠ 离线**。保留代码资产降低以后重做成本；详细提案不在公开仓。
- **私有化**：私有云只部署服务端 → **不依赖**桌面 sidecar；本机/内网一体、断网可用 → 依赖本机（或内网）运行时，与 sidecar 同类而非必须原开关。

### 7.5 同 folder 多对话（云端）

✅ **定案 A′**：同项目多对话应可并行跑 prepare / LLM / 读；**写盘与 snapshot manifest RMW 单层串行**（`workspace_lock`，禁止同 key 嵌套）。已撤云端整回合握锁（避免第二对话静默排队假「思考中」）。写锁短等须诚实等待态（如「等待工作区…」），禁止空 Thinking 冒充。Sidecar 路径本就不握该整回合锁。→ 见代码: `workspace/locks.py` · `ServerWorkspace` mutation / `execute` · `workspace/snapshots.py`

### 7.6 云沙箱工作副本 + 显式合回

相对「过桥逐步改本机盘」：重任务可先在**云临时副本**上改，结束后**显式合回**本机——跑中不保证与本机实时一致。非从零发明：第一档入口 = 桌面本地项目 Composer **「后台云端」**（handoff 作业），不是另造开关。

| 项 | 定案 |
|---|---|
| 与过桥关系 | **并行两档**：轻～中续过桥观察（§7.2）；用户勾选「后台云端」走本路径。**否决**现阶段用云副本一口替换过桥 |
| 副本寿命 | **按任务临时**（合回或放弃后可收；未处理前按工作区保留窗可 Diff）。**否决**项目级常驻远程盘 |
| 写回默认 | **② Diff 合入本机**（文件级预览，勾选/整包；三方冲突须提示，禁静默覆盖） |
| 写回旁路 | ⏳ **① 仅产物**；⏳ **③ 合回=开 PR**（Git 工具可开 PR ≠ 本路径写回选项） |
| 用户心智 | 「AI 在云拷贝上改；我点了才进本机文件夹」——禁止暗示已自动双向同步 |
| 入口 | 桌面本地模式「后台云端」；聊天/画布指挥台卡「查看改动并合回」；手机无本机盘 → 无此面 |
| 否决 | Dropbox 式实时双向同步（与 §二同）；主回合并排「过桥\|云副本」执行档（本阶段）；把「云副本」卖成离线或数据不出本机 |

**MVP 第一档**

| 切片 | 状态 |
|---|---|
| 本机快照 → 云团队跑 → Diff 合入本机（机制） | ✅ → `conversation/handoff_jobs.py` · 桌面 `BackgroundTaskCard` / `BackgroundTaskReview`；三壳分工 → [后端架构 · 后台派活](/docs/02-架构/后端架构.md#后台派活三壳) |
| 文案/心智对齐（拷贝 ≠ 直改本机；完成可发现合回） | ✅ 与本切片一并（桌面 tip/卡/CTA） |
| 结束可收（合回或 discard 后回收云 host；保留窗内可 Diff） | ✅ 与本切片一并（服务端 job 态） |
| 主回合选执行档；① 仅产物；③ 合回开 PR；大仓破 ARCHIVE 硬顶 | ⏳ |

验收（第一档）：用户能区分过桥直改本机 vs 后台云拷贝+点合回；合回或放弃后云副本可收，未处理前不偷偷删光。

**下一阶段（狗粮观察 · 先于再开 ⏳）**

用真实本地项目开「后台云端」若干次，记摩擦后再决定是否开工 ① / 「建议开后台」提示 / ③ / 破硬顶。**本阶段禁止**未观察就做主回合选档或一口替换过桥。

| 试什么 | 记什么 |
|---|---|
| 小改动任务：开后台 → 待合回 → 合回本机 | tip/卡是否一眼懂「拷贝 ≠ 本机」；合回是否好找 |
| 同一任务路径：放弃结果 | 「已丢弃」是否清楚；是否误以为已写本机 |
| 空变更 / 与本机已一致 | 是否收成「已合回」而非一直「待合回」 |
| 偏大仓（近 ARCHIVE 上限） | 截断/失败文案是否诚实；是否误以为完整同步 |
| 多对话 + 过桥对照 | 何时想开后台、何时过桥更省事（供后续「建议开」启发式） |

本地：dev 重启服务端即 `alembic upgrade head`（含 `applied`/`discarded`）；桌面需新构建/热更后的文案与放弃按钮。观察结论够用后再开下一刀（默认候选：① 仅产物，或轻量「建议后台云端」——以摩擦为准）。

### 7.7 机制约束（实现）

- **路由（机制能力；默认以 §7.2 为准）**：历史上绑本机可走 sidecar（打开本地项目 / `bind_local_folder` scratch）；裸聊未绑 / 云项目 / 带附件 / 点名走云。启动失败（出输出前）可降级云；中途失败不降级。**bind ≠ 打开项目**——前者只换本会话执行环境，后者建/复用 Folder + 新会话。
- **健康 ≠ 绑定判定**：健康只决定「要不要拉起」，**不掺进绑定判定**——否则污染续跑 / 列暂停帧。
- **Office 文档能力（云 = 本地）**：附件分流预解析（docx/pdf/pptx 等 → 可读 `*.md`）与工作区 `file_read` **透明抽取**（同一 markitdown 桶；读时默认不写旁路，若已有 `path.md` 可优先读）以及确定性 `md_to_docx` / `md_to_pdf`（fpdf2，禁 Playwright 主路径以免破 sidecar 同能力），在云 API 与 sidecar **同能力**。xlsx/csv 等不抽文本，仍走 `code_execute`。依赖在 `pyproject` 主依赖与 `[project.optional-dependencies].sidecar` 对齐；`bundle:sidecar` 冒烟校验 `docx` / `fpdf2` + markitdown 抽取 + md→docx/pdf。**否决**为瘦身砍掉 Office 却仍跑同一管线（缺库 → 整轮 `PIPELINE_ERROR`）。预解析 / 透明抽取失败仍不阻塞回合（路径提示回落；office/PDF 勿一律教 `code_execute`）——那是解析语义，不是「平面缺依赖」。
- **岔路 B（否决 A）**：平台 key 不下放；推理经云代理；计费权威在云、不从客户端上报。名册同构：桌面铸 **folders 窄票**（`POST /v1/folders/token`）注入 sidecar；`list/resolve/create_project` 与换桌 binding 问云 `GET/POST /v1/folders`（及 `GET /{id}`），**不**打本机 PG、**不**把 access 塞进引擎。对话日志 + 规则/记忆同构：桌面铸 **account 窄票**（`POST /v1/account/token`）注入 `accountAuth: {baseUrl, apiKey}`（`baseUrl`=`…/v1/account`）；`search_conversations` / `read_conversation` 问云 `POST …/conversations/search|read`；`assemble_turn_rules` / `remember` / `DocumentMemoryStore`（consult / update_project_profile 经同一 store）问云 `POST …/rules/*` 与 `…/memory/*`——仅 account（或 access）可调、引擎最小面，**不**把 UI 对话/文档/记忆编辑器 CRUD 对窄票敞开。无票仍走本机 DB。开回合另注入 `folderId` + 本地绑定（`localRootId`/`localSubpath`）供记忆 workspace key，避免为归属/钥匙硬连本机库。
- **持久化**：sidecar → 本机 outbox → 主进程回写云；Renderer 退出回写职责。混合态下对话正文全量回写云——**不得承诺「数据不出本机」**。大众不装 Docker/本机 PG；开发 compose 仅开发者联调。
- **挂起帧**：settlement 预写即消费帧（决策即事实，不还帧）。**否决**：保留帧 + journal 对账改写 paused[]（双真相源对账 = 补丁绊线禁止形态）。挂起帧与 outbox **不并同一状态机**。
- **恢复面**：默认路由变更须重估双面恢复；路由意向 ≠ 恢复事实——刷新后无条件并行查本地+云。
- **契约 α（本地回合恢复）**：刷新 = **双面恢复**（云消息投影 ∥ 本地 recovery/attach）；resume 中靠本地 attach 续活态，**勿只信云薄壳**；outbox 是活态缓冲；终局投影权威 = writeback → `local-turns` → `turn_journal`。不冲 β；不放宽 hydrate、不透传 unsynced journal（掉帧/审计员另案）。→ `outbox.py` / `outbox-writeback.ts`；水合 → [前端技术 · 打开对话水合](/docs/04-前端/前端技术与架构.md)。
- **产品对外（档 A · 断线只读）**：断网/服务不可用时可浏览已缓存对话与本机文件（只读）；不能发送、改文件、跑 AI。完全离线 ⏳ 见 §7.4。

→ 见代码: `apps/server/agentcore/sidecar/`；打包 `apps/desktop/scripts/bundle-sidecar.mjs`；预解析 / 透明抽取核 `workspace/attachment_parse.py`；挂载点 `tools/builtin/file_ops.py`（`FileReadTool`）。

## 八、共享空间 vs 项目工作区

跨用户云端共享文件空间（成员制协作），与「公开分享」（对话只读快照）是两回事；与项目（Folder）**平行、独立实体**。

| | 项目工作区 `folder:` | 共享空间 `shared:` |
|---|---|---|
| 本质 | 会话分组 + 记忆 + 工作区三合一 | 只有「文件」一个面 |
| 归属 | owner 独占 | 成员制（viewer / editor / owner） |
| 挂载 | 会话继承项目绑定 | 会话级挂载为云端第二根 `shared/<别名>/` |
| 本地 | 可绑本地 | **仅云**（否决本地共享 / 双向同步） |

**否决 Folder+成员**：鉴权面圈死在新模块，免在「owner 独占」不变量上开洞；免每个 Folder 功能都要答「成员可见吗」。重启条件：若做「成员对话进项目、共享记忆」的完整项目协作，再交 `folder_members` 治理税。

其它边界：仅定向邀请（不做链接加入）；可编辑成员的 Agent 可直写（角色即授权，不加第二道门）；**仅云执行对话可挂载**（sidecar 无跨运行时双根）。v1 不做：公开文件链接、实时协同、成员对话/共享记忆、组织概念。
