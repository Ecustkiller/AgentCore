# 双模式工作区（云 + 本地）

> **状态**：✅ 已落地——**文件夹即工作区**（工作区 = 文件夹；裸聊无空间、首次产文件懒建文件夹迁入）+ `WorkspaceBackend` 抽象 + `ServerWorkspace`（云）+ `LocalWorkspace`（本地）+ 绑定路由（模式跟着文件走）+ 文件进出 / 快照 / `git clone` / 附件驻留 / 保留期清理 + 本地→云 snapshot 交接（三段式，前后端齐全）。⏳ 仅余多 worker 化：锁 / 审批门 / 工具执行通道 / handoff 作业现为**进程内态**，多机需前置 Redis + durable queue。
>
> **定位**：让「AI 对话能选文件夹、并在该文件夹工作」，一套分层同时支撑**云**与**本地**两种**平等**模式——**不给用户云/本地开关，模式跟着「文件在哪」自动走**（§六）。
>
> → 见代码：`apps/server/agentcore/workspace/`

---

## 一、需求推导结论：两种模式平等

- **内核需求**：给每次协作一个**持久、可累积的项目空间**——多 Agent 在同一张「桌子」上靠文件协作。「在不在本地磁盘」是第二层偏好，非内核。
- **云模式（服务端托管）= 零前提的起点**：打开即用、不暴露整块磁盘；并行团队同台协作，天然可观测、可隔离。
- **本地模式（桌面执行，对标 Cursor）= 平等的另一种，后做**：开发者内环（改真实本地仓）。
- **不给用户云/本地开关**——模式跟着「文件在哪」自动走（§六）；「云优先 / 本地优先」只是构建顺序。

## 二、`WorkspaceBackend` 抽象

沿用项目「Protocol + 实现 + 工厂」同构范式（同 `LLMProvider` / `SandboxProvider` / `SearchBackend`），引擎与工具只对接口编程：

- **接口**：`read / write / list / replace / grep / execute` + `location`(server·local) + `root_label`（相对路径渲染、不暴露绝对路径）。
- **签名一次到位**：P0 即钉死结构化结果类型（`DirEntry` / `ReplaceOutcome` / `GrepResult` 等），失败走类型化异常 `WorkspaceError` 子类（`OutsideWorkspace` / `PathNotFound` / `NotAFile` / `NotUTF8` / `AmbiguousMatch` …），工具层捕获后映射回原报错文案（用户侧报错零变化）。
- **护栏 1·瘦接口**：持久化（snapshot/restore）**不进 backend**——是回合级存储策略（轴3），归独立 `StorageProvider`，由 service 在 run 前后调（§三、§四）。backend 只管「文件 + 执行」这对**必须同源**的能力（一个 backend = 一个执行平台）。
- **为何 P0 就引入抽象**：本地模式（B）是**已承诺、必然建完**的路线；接口先行（项目 house style）使新增 `LocalWorkspace` 时工具与引擎零改动。
- **唯一接缝**：`ToolContext.workspace_dir: Path` → `ToolContext.backend: WorkspaceBackend`，6 个工具（`file_ops` 4 个 + `grep` + `code_execute`）与引擎退化薄壳。`code_execute` 收编进 `backend.execute`（`ServerWorkspace` 内委托 `SandboxProvider` + 带 cwd），顺修「代码与文件不在同一目录」的潜伏 bug。

## 三、三正交轴与「本地默认云储存」判定

| 轴 | 取值 |
|---|---|
| 轴1 执行位置 | server / local |
| 轴2 文件源头 | server dir / local dir |
| 轴3 持久化 | S3 快照 / 仅本地盘 / 实时同步 |

「云 / 本地模式」是在**轴1+轴2** 选一整套。用户提的「本地默认云储存」= `轴1=local、轴2=local、轴3=cloud`——**不是第三种模式，而是 LOCAL backend 的存储策略**：

- ✅ **接受**快照 / 交接语义（git-push 式）：本地是唯一真相源，按需经 `StorageProvider` 快照到 S3，用于备份 / 跨设备 / 把活交给云端团队。
- ❌ **拒绝**实时双向同步（Dropbox 式）：双真相源 + 冲突地狱，在「并行 Agent 团队并发写」下尤其致命。

## 四、两个 Backend 实现

| Backend | 文件在哪 | 执行在哪 | 模式 | 传输 |
|---|---|---|---|---|
| `ServerWorkspace` | 服务端 `<data_dir>/workspaces/<user_id>/<folder_id>/`（文件夹即工作区）；handoff 作业 / 裸聊瞬态用内部 `…/conv/<id>/` | 服务端（复用 `SubprocessSandbox`） | 云 | 同进程 |
| `LocalWorkspace` | 用户真实本地目录 | 桌面端（op 路由到 Electron） | 本地 | 泛化审批门接缝 |

`LocalWorkspace` 的传输**不另造**：把 `runtime/approvals.py` 的「服务端挂起 `asyncio.Future` + 客户端 HTTP 回填」泛化成一条工具执行通道（`WorkspaceChannel`）——服务端挂起 + `workspace_op_required` SSE + `POST …/interactions/{id}`（kind=client_tool，§18.2 统一挂起原语）resolve 回填；桌面 `fs-service.ts` 处理全 op、渲染端 `workspaceOps.ts` 收 SSE→IPC→回填。每个 op 串行路由、回传结构化结果或同款 `WorkspaceError`，故工具 / 引擎不动。

## 五、落地能力现状

| 能力 | 现状 |
|---|---|
| **接缝 + 云模式** ✅ | `WorkspaceBackend` + `ServerWorkspace`；`ToolContext.backend`；6 工具改薄壳；`StorageProvider` 快照/恢复/下载；文件进出 + `git clone` + 附件驻留 + 保留期清理 |
| **本地模式** ✅ | `LocalWorkspace` 经 `WorkspaceChannel` 全 op 路由桌面；`local_root_id` 绑定 API + 模式条 UI；worker 审批门透传（P2d） |
| **本地→云交接** ✅ | 三段式：打包上传 → 云端 autonomous 跑团队 → diff/三方判定/回写（`HandoffJob` 专表） |
| **多 worker** ⏳ | 锁 / 审批门 / 通道 / handoff 作业为进程内态；多机需 Redis + durable queue |

> **本地真实编辑 = 正交模型的一个配置**：= 轴1 `server` + 轴2 `local_dir`，仅在「服务端 = 用户机器的可信自托管」下成立——`resolve_safe_path` 仍管越界，但允许把 `local_dir` 喂给工作区根。与「云端杜绝用户传任意服务端路径」不矛盾（前者可信运维配置，后者不可信多租户默认）。

## 六、绑定模型与「模式跟着文件走」

- **文件夹即工作区**：工作区 **就是** 文件夹（= 项目），不另设「对话工作区」概念（对标 Cursor）。顺现有 `folder_id` 模型——`folder_id` 即「在哪个工作区」。
- **裸聊懒建**：未分组对话（裸聊）**没有工作区**，零成本（随手问答不建目录 / 不进中枢）。首次真正产文件时——团队首次写（`DeferredWorkspace`）、用户上传 / `clone`、或绑本地文件夹——才**懒建一个文件夹并迁入**（命名取对话标题），此后即该文件夹工作区。
- **无云/本地开关**：路由判定（`workspace/locate.py`）——文件夹有 `local binding`（`Folder.local_root_id`，绑定只在文件夹）→ `LocalWorkspace`，否则 `ServerWorkspace`；裸聊永远是云（无工作区即无绑定）。直接聊 / 上传 / 手机端 → 云；桌面绑本地文件夹 → 本地（裸聊绑本地先懒建文件夹再绑）。
- **跨设备**：云项目跨设备同步；本地项目仅在那台机器；手机无本地文件夹概念，自动走云。
- **注入路径**：`conversation/service.py` 解析 `conversation →（文件夹空间 / 裸聊无空间）→（文件夹有绑定则本地、否则云）` → `_build_turn_backend` 构造 `WorkspaceBackend`（裸聊得 `DeferredWorkspace`，首写时懒建文件夹并迁入，回合末快照落到新文件夹）→ 经 `run_chat_pipeline` 注入 `base_tool_context.backend`；worker 经 `replace(...)` 自动继承。

## 七、风险与边界

| 项 | 处理 |
|---|---|
| 路径越界 | `resolve_safe_path` 下沉 `ServerWorkspace`；服务端目录由 user/folder 生成，杜绝用户传任意服务端路径 |
| 裸聊（未分组会话） | 无工作区（零成本随手聊）；首次产文件 / 上传 / 绑本地时懒建文件夹迁入（`DeferredWorkspace`）→ 即成文件夹工作区 |
| 已开始对话跨文件夹移动 | 禁止——有消息后锁定归属（前端隐入口 + 后端 409） |
| folder / 会话删除后文件 | 与软删对齐：软删原样保留可恢复；超保留期（默认 30 天，可配）物理清目录 + 记录 + OSS 备份；「彻底删除」立即清。文件归项目（文件夹）所有 |
| 同 folder 跨会话并发写 | 文件夹级锁（`workspace/locks.py`，进程内，多机再 Redis）；任务内并行小队不受限 |
| `LocalWorkspace` 下并行团队 | 单桌面通道是瓶颈；正解 = 本地内环 + snapshot 到云由云端跑并行团队（交接 e2，呼应 §三 快照语义） |
| 本地 worker 直接执行 | 本地模式被委派 worker 共用 CEO 同一回合审批门（仅 `backend.location=="local"` 透传 `ApprovalGate`）；云模式不下发门（沙箱隔离） |
| execute 通道传输期限 | 代码执行 = 代码自身超时 + 余量（默认 30s）；文件 op 走扁平期限（默认 60s）——避免长但合法的执行被传输层提前丢弃 |
| 多 worker 进程态 | 审批门 / 通道 / 锁 / handoff 作业现为单进程内存态，多 worker 需前置 Redis + durable queue |

## 八、关键决策（已定）

1. **P0 引入 `WorkspaceBackend` 抽象**：B 为已承诺路线，接口先行（§二）。
2. **不给用户云/本地开关**：模式跟着「文件在哪」自动走；直接聊 / 手机端走云（§六）。
3. **文件进出：先上传**（人人可用、结果可下载）；**`git clone` 紧随**（公开仓先、私有令牌后）。
4. **云存储 = 阿里云 OSS**（通用 S3 接口，dev MinIO，客户端库 `boto3`）；**快照 = 改过文件的任务结束后后台备份 + 手动留版本 + 随时下载**（非每写必存）。
5. **P2e 本地→云交接 = 三段式 + 派发式云作业**：`HandoffJob` 专表 + 隐藏 `mode="handoff"` 作业对话；云作业 autonomous 免审批（区别于 P2d 交互门）；冲突判定服务端权威；完成通知 MVP=轮询，作业为进程内态（重启丢在飞作业，MVP 可接受，后续前置 durable queue）。
6. **工作区升一等可寻址资源 `/v1/workspaces/{ws_id=folder:<id>}`**：@ 提及云索引 / 按文件夹浏览需直接寻址工作区，而旧契约只能「借一个对话」访问。对话级路由解析「对话 → 其文件夹」后调同一服务层（无重复逻辑）。
7. **「添加文件夹 = 建本地绑定项目」一步到位**（F2）：选 OS 目录即 `POST /v1/folders` 带 `local_root_id` 单条 insert 建项目+绑定，免 create-then-bind；否决「只浏览不建项目」的游离根（心智割裂）。
8. **@ 提及覆盖云端工作区**（F4）：云端工作区文件也能被 `@`，与本地根同进一套索引（前端 `FileSource` 抽象见 [`前端技术与架构.md` §8.7](/docs/04-前端/前端技术与架构.md)）。裸聊无云工作区，只索引本地根。
9. **文件夹即工作区（推倒「对话工作区」）**：工作区 = 文件夹，不再有面向用户的 `conv:` 工作区；裸聊无空间、首次产文件懒建文件夹迁入（`DeferredWorkspace`）。**根因**：旧设计无「工作区」一等概念——文件挂对话、又打「文件夹共享」补丁，被迫造全局文件页把两套拍平，导致「两处翻文件、同份双列、空态自指」。否决「全局文件视图 + 对话/文件夹双份浏览」；删 `Conversation.local_root_id`（绑定只在文件夹）、删全局 Files 页，对标 Cursor「打开的就是一个文件夹/工作区」。

## 九、工作区一等资源（HTTP 契约）

工作区（=文件夹）需可独立寻址（@ 提及云索引、按文件夹浏览），非只能「借一个对话」访问，故升为一等可寻址资源。完整 REST 路由 → 见 OpenAPI（`apps/server/openapi.json`）。

**`ws_id` 编码**：`ws_id = folder:<folder_id>`（**工作区即文件夹**）——分隔符 `:`（UUID 不含、单段 URL 安全），`parse_workspace_id` 在 `workspace/locate.py`（纯函数，DB 无关）。`conv:` 仅 `_workspace_relpath` 内部保留给 handoff 作业 / 裸聊瞬态目录，公开 `/v1/workspaces` 既不产出也不接受（解析到非 `folder` → 404）。

**云/本地闸**：本地工作区文件走桌面 IPC、不走 REST——故 `location=="local"` 时 file/dir/move/clone + snapshot create/restore + **file-index** 返回 **409**；只读 snapshot list/download 放行（对象存储按 ws 键，本地项目也能列历史）。

**F2 建本地绑定项目**（文件夹路由非 ws 路由）：`POST /v1/folders` 可选 `local_root_id` → `FolderRepository.create` 单条 insert 写 `folder.local_root_id`；该文件夹随即以 `folder:<id>` + `location=="local"` 出现在枚举，前端走 IPC。沿用 §六 folder=共享项目空间语义。

**F4 @ 扁平文件列**：`GET …/file-index` → `{ data:[posix_path…], total, truncated }`。`ServerWorkspace.index_files` 用 `os.walk` 剪 `IGNORED_DIRS`（node_modules/.git…）+ 只收文件 + 上限 5000，**对齐桌面 `fsApi.listFiles`** 的忽略+上限语义，故 @ 不分云/本地一致（前端聚合见 [`前端技术与架构.md` §8.7](/docs/04-前端/前端技术与架构.md)）。

- **枚举**（`WorkspaceSummary`）：`{ ws_id, name, location: "cloud"|"local", root_id, has_files }`。**仅列文件夹**（工作区即文件夹）——裸聊无工作区故不列；本地文件夹恒列（服务端看不到其文件，`has_files` 恒真），云文件夹带 `has_files`。
- **鉴权**：`ws_id` 解析出 `folder_id` → 复用 owner 校验；非属主 / 坏 id / 任何 `conv:` 寻址（对话不是工作区）→ 一律 404。
- **对话级路由**（`/conversations/{id}/workspace/…`）：前端对话面板的工作区入口——解析「对话 → 其文件夹」后调同一 `workspace.files`/`snapshots`/`git` 服务层，无重复逻辑。裸聊（无文件夹）：读类（list/download）返回空 / 404（绝不在磁盘建幻影目录），写类（upload/dirs/clone）先懒建文件夹再写。@ 提及索引走该文件夹的 `folder:<id>` ws 路由。
