## 一、Agent 运行时模型 ✅ 已确定

分层设计：Agent 逻辑和工具执行采用不同的运行时模型。

| 层 | 运行时 | 说明 |
|---|---|---|
| Agent 逻辑 | asyncio 协程 | 纯 I/O 密集型，用协程最轻量 |
| 普通工具 | 同进程异步 | 文件读写、搜索等安全操作 |
| 代码执行 | 受限 subprocess（MVP，`SandboxProvider` 抽象预留） | 当前仅 timeout + tempdir 隔离；Docker/gVisor 升级后置 |

### 沙箱架构原则

- 设计抽象沙箱接口，后端实现可插拔
- 默认禁止出站流量、凭证不进沙箱、文件系统边界严格、全量审计日志

> 沙箱安全的完整设计见 [`../05-平台与运维/安全权限与治理.md`](../05-平台与运维/安全权限与治理.md)。

## 二、LLM 接入策略 ✅ 已确定

MVP 只接入 DeepSeek V4，用 Flash + Pro 双模型覆盖所有场景：编排器 / 单聊 / worker 按角色分思考档位，标题与记忆维护走非思考。开发期统一 `high` / `max` 两档有效思考强度——worker 的 `fast` / `strong` 同为 `high`，靠回合预算区分，`max` 由 per-agent 覆盖按需解锁（只升不降）。

> **档位与思考强度以 `llm.mdc` §思考强度按角色分档 为权威**；轮数预算与模型映射见 [`../03-AI核心/执行引擎架构设计.md` §十六](../03-AI核心/执行引擎架构设计.md)，运行参数单一真相源是 `apps/server/agentcore/llm/config.py` 的 `PROFILES`。DeepSeek V4 API 细节见 [`../06-参考/DeepSeek-V4-API参考.md`](../06-参考/DeepSeek-V4-API参考.md)。

## 三、数据存储 ✅ 已确定

最小组件策略：用尽量少的组件覆盖所有存储需求。

| 组件 | 覆盖的数据 | 说明 |
|------|----------|------|
| PostgreSQL + pgvector | 结构化数据 + 向量检索 | 用户/账户、Agent 配置、会话历史、Agent 记忆 |
| Redis | 实时状态、缓存 | Agent 运行状态、任务进度、热数据缓存 |
| S3 兼容存储 | 大文件 | 代码执行结果、上传文件、工具输出 |

> **实现现状**：开发 compose（`deploy/docker-compose.dev.yml`）起 PostgreSQL 16 + Redis；**pgvector 扩展、S3/MinIO 对象存储、向量检索均未接入**，server 代码当前不读写 Redis / S3（`config.redis_url` 已配置未用）。数据模型与建模约定见 [`核心接口定义.md` §六](核心接口定义.md)。

## 六、候选架构演进方向（待决策）

> 来自对一个更成熟的同源参考实现的探索（2026-06）。以下 3 项**超出当前设计、属架构选型级**，暂记于此待决策，落地前不写入对应专题文档。其余借鉴项（统一 Run 模型 / WaveScheduler / `delegate` / Turn Journal 投影 / Interaction 挂起 / ContextComposer 等）均是我方**既有设计**（见 [`../03-AI核心/执行引擎架构设计.md` §十八](../03-AI核心/执行引擎架构设计.md)）的落地，参考实现只是其可运行样板，不在此列。

| 方向 | 是什么 | 价值 / 代价 | 倾向 |
|---|---|---|---|
| 客户端工具执行 + 本地优先 folder | 工具带 `client_exec`：运行时发事件 → 桌面在本机执行 fs/exec → 回传解阻塞；云端只持不透明 `root_id` + 相对路径，绝对路径不出桌面 | **对「桌面优先 + 真碰本地文件」差异化收益最高**（Cursor 式体验）；需 Electron IPC + 授权根模型 + 前后端单一真相源 | 建议近-中期优先讨论 |
| Sidecar 可迁移核 | 桌面 spawn `python -m agentcore.sidecar` 跑**同一 `RuntimeEngine`**，stdio JSON-RPC 通信，仅把宿主端口（§18.6）换为本地实现（SQLite/内存/in-proc），离线可降级 | 本地执行 / 离线 / 隐私基础，云与本地同一引擎；但宿主端口面大、双实现维护成本高 | 中长期；新代码按「引擎面向宿主端口」组织留缝 |
| JSON-RPC 2.0 运行时协议 | 用 JSON-RPC 承载整轮运行时（initialize/startTurn/resume/pause/cancel/respond…），事件映射为 notification，传输可换 stdio（sidecar）/ WS（云）；**注意非 MCP**（MCP 仍用于 Agent↔外部工具） | 云/桌面/UI 一套代码，pause/resume/交互回值天然统一；需把 SSE+HTTP 重构为协议层 | 与 Sidecar 绑定决策；否则暂缓 |
