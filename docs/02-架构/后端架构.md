## 一、五层分层

每个业务模块遵循 `models → schemas → repository → service → router`，调用方向严格单向、不可反转：

| 层 | 职责 | 约束 |
|----|------|------|
| **models** | ORM 定义 | → 见 [核心接口定义.md §6.2](/docs/02-架构/核心接口定义.md)（无 ORM FK、软删除、文件单表等建模约定） |
| **schemas** | Pydantic request/response | 严格区分 request / detail / list item 等分层 |
| **repository** | 纯数据访问 | 接收 AsyncSession；不含业务逻辑 |
| **service** | 业务逻辑 | 构造注入 AsyncSession，内部实例化 repository，组合多 repo |
| **router** | HTTP 端点 | 薄层委托 service，用 DI 别名 |

> **service 层的边界（务实约定）**：service 是**有真业务逻辑**（多 repo 组合、编排、跨副作用、外部调用）时才设的层，**不是**每条路由的强制透传。**简单 CRUD 路由允许经 DI 直接注入 repository** 在 handler 里增删改查（如 `routes/folders.py`）——给纯 CRUD 套一层 `service.create()→repo.create()` 是仪式而非架构。判据：handler 里只有"取 repo→调一两个 repo 方法→返回"就直用 repo；一旦出现条件分支/多 repo/调 llm/外部副作用，抽 service。

## 三、runtime 子包结构

`runtime/` 是执行核心，按运行时关注点分子包（engine / runs / journal / resolve / events / host …）→ 见代码 `apps/server/agentcore/runtime/`（目录即关注点）。**与目录不一一对应的例外**：

- **memory ⏳ 无独立子包**：工作记忆注入散在 `runs/executor_context.py` + `runtime/context/`；长期记忆在 `agentcore/memory/`。
- **suspend 非独立子包**：持久暂停/恢复在 `runtime/suspension*.py`。
- **sandbox 不在 runtime**：代码执行沙箱后端在 `tools/sandbox/`。
- **CEO 内置编排原语**（`delegate` / `ask_user` / `debate`）在 `tools/builtin/`，与 `runtime/` 子包同构——按变更原因拆目录。

## 四、垂直能力开关（feature flags）

平台核心行业无关；垂直 / 实验能力用**编译期 feature flag**（`config/features.py` 的 `FeatureSettings` 布尔字段）分层叠加——现状是最简机制，**不是**插件贡献点契约或约定式扫描。

| 开关 | 默认 | 关闭时行为 |
|---|---|---|
| `simulation_enabled`（AI Town 模拟） | `True` | simulation REST 路由返 404 |
| `legal_vertical_enabled`（法律垂直 v0） | `False` | 法律域 Skills 不注册进 CEO 系统 Skill 注册表、不出现在能力目录 |

- **注册方式**：所有路由在 `main.py` 里**无条件** `include_router`（含 `simulation`）；「启停」发生在**处理层**（关 → 404）或**注册层**（Skill 不进目录），而非按开关决定是否挂载路由。
- **依赖方向**：垂直代码（`simulation/` 等）可依赖核心，核心不反依赖垂直。
- **边界**：这是 v0 权宜（法律 Skills 待迁移到 per-agent 市场绑定）。「6 贡献点契约 / 约定扫描 / 白名单」式插件化**尚未实现**；若要做属架构提案，走 `06-规划`，不在此预写。

→ 见代码：`config/features.py`、`main.py`（`include_router` 段）。

## 五、评估体系（L0 契约硬门 ✅ / L1 结果评分 ✅ / L2 协作质量 ⏳ / L3 轨迹回流 ⏳）

> **设计立场（为什么是这个形态，代码看不出来）**：评测以「**任务结果**」为中心，而非「执行轨迹机制」。2026-06 方向评审否决了旧体系的根本假设——旧体系把 `Delegated`/`RosterMatches`/`MaxRounds` 这些**手段**当门禁、在回归测试作者自己的编排理论（按 [`dev-process.mdc`](/.cursor/rules/dev-process.mdc) 属「实现冒充需求」），且**投资倒置**（per-PR 硬门禁守最便宜最低价值的「JSON 能否解析 / 有没有调某工具」，唯一衡量用户价值的质量裁判却软门禁、从不阻断）。新体系把投资从「下重上轻」翻为「**中间重**」：L0 只兜安全 / 契约不变量，**L1 结果质量是被守的主轴**。

> **开发期提醒**：本体系当前跑在合成 `core` + milestone 用例上，**无任何真实运行数据**（真实对话 / 线上 pass_rate / 质量分都不存在）。基于这些跑分讨论或优化质量时，须先声明「目前无真实数据，以下为假设」（见 [`dev-process.mdc`](/.cursor/rules/dev-process.mdc)）。

骨架落地于 `agentcore/evals/`（离线 CLI：`python -m agentcore.evals`），四层 L0–L3：

| 层 | 判定对象 | 何时跑 | 门禁性质 | 落地 |
|---|---|---|---|---|
| **L0 契约 / 安全硬门** | 不崩、引用可解析、不编造工具调用、schema 合法、成本 / 延迟预算 | per-PR | **硬门禁（零 LLM）** | ✅ `checks.py` 不变量子集 |
| **L1 结果评分** | 用户要的拿到没有（端到端、结果维） | per-PR 小集 + nightly 大集 | **可门禁**（baseline 回归） | ✅ rubric 裁判 + milestone + pass^k |
| **L2 体验 / 信任 + 协作质量** | 可读性、诚实度、延迟、该追问是否追问；团队 milestone / 协作 | nightly | 信息性 → 逐步可门禁 | ⏳ → [`远期规划.md §2.4`](/docs/06-规划/远期规划.md) |
| **L3 轨迹回流 + 诊断** | 真实轨迹聚类找失败；团队 vs 单体「值不值」 | 现挖 / 上线后在线 | 喂数据，不直接门禁 | ⏳ → [`远期规划.md §2.4`](/docs/06-规划/远期规划.md) |

**L0 契约硬门（轨迹形状降级为诊断）**：保留不变量子集 `FinishReason`(错误态) / `NonEmpty` / `ToolArgsValid` / `HasCitations`(可解析) / `NoFabricationMarker` / `Max*`(成本·延迟预算)；`Delegated` / `NotDelegated` / `RosterMatches`(轨迹形状)**降级为诊断**——仍注册仍跑仍报告，但 `gating=False` 不计 pass/fail（→ `checks.py` `DIAGNOSTIC_CHECKS`、`runner.apply_checks`）。过度编排不再用 `NotDelegated` 标签判，改由「个体贡献=0 + L0 成本预算」度量。

**L1 结果评分（裁判从「接口位、永不阻断」扶正为主轴）**：
- **rubric 绝对裁判** `judge.LLMJudge` + `build_default_judge`（Pro 评 Flash）。
- **milestone 结构化覆盖** `LLMMilestoneJudge`：把任务子目标写成可逐条判定清单，一次结构化打分返回逐项布尔，覆盖率=加权命中比，≥阈值且无编造即过（→ `types.py` milestone/`outcome` 字段、`seed_lint.py` 结构校验）。
- **baseline 回归门**：分数落盘 + `--update-baseline`，只有**跌破** baseline 超阈才红（区别旧「全过才绿」）（→ `report.baseline_regression` + CLI `--baseline`/`--update-baseline`）。
- **pass^k**：看 k 次重跑的一致成功率，非单次。

**裁判可信工程（DeepSeek-only 适配）**：裁判是测量仪器，先校准再用。
- **校准回路**：生产裁判过人工 gold-set → 算 **Cohen's kappa** / 加权 kappa·Spearman（**不用 exact-match**，会高估 33–41pp）→ **kappa>0.6 才准上门禁** → 读分歧改 rubric/prompt 重跑；重校触发=月度 + 改 rubric / 换模型 / 判↔人分歧 >20–25%（→ `calibration.py` 纯统计零依赖 + CLI `--calibrate`；gold-set schema 见 `cases/gold/labels.example.json`）。
- **消偏**：位置偏差走 swap-and-aggregate（`LLMPairwiseJudge`，诊断用）；长度偏差 rubric 明写「不奖励长度、惩罚注水」；同家族自偏好用 **Pro 评 Flash** + 持续监测 kappa（**已知、被监测**的限制）；CoT 先理由后给分。
- **成本纪律**：裁判成本控在生产 LLM 的 **10–15%** 内。**反模式**：100% 通过=eval 太水的警报，不是胜利。

**多 Agent：milestone KPI 取代轨迹标签**：评测问题从「团队比单体好吗（研究问题）」转为「团队这一跑**交付目标了吗 + 协作得当吗**（产品质量）」——**milestone 覆盖**（结果维，不管谁干的）+ **协作质量分**（5 点 LLM：子产出有没有被 CEO 真整合）+ **个体贡献**（派了但零贡献=浪费，这才是「过度编排」的正确度量）；`team_quality` 只在 team 路径跑。`comparison.py`（等算力 `matched_single` 臂 + best-of-N 擂台 + 思考-token 对齐）**降为偶发诊断**（要做路由引擎前 / 季度手动跑，协议保留备查），不再当核心 nightly 回归。

**门禁分层**：

| 闸 | 内容 | 红线 |
|---|---|---|
| **per-PR** | L0 全部(硬) + L1 小集(廉价裁判档) + baseline 回归 | L0 任一不变量破→红；L1 跌破 baseline 超阈→红 |
| **nightly** | L1 大集 + L2 + L3 诊断 + 切片分析 | 信息性为主，回归显著才告警 |

per-PR CI 仅跑零-LLM 自测（假 provider）；真模型评测见 `evals-nightly.yml`。切片分析按 intent / 质量档 / 路径分段出均值 + 置信区间 + **分布**（防双峰被均值掩盖），CI 宽于 delta 时不宣布胜利。

**评测基建（确定性 plumbing，零真模型即可单测）**：以下三件都守「**零侵入复用 harness、不改 `pipeline`/`engine` 签名**」铁律——确定性算术 + 用例结构可零 LLM 单测，但**出数都需真模型回合**（故度量仍挂上文 L1 + 远期 §2.4 主线）。

- **提示词变体注入** `runtime/resolve/profile.py`：静态片段（`base`/`ceo_core`/`citation`/`ceo_visualization`）经 **contextvar 解析器** `resolve(key, 原常量)` 取文案——**选 contextvar 而非穿参，正是为守零侵入铁律**；无活跃变体（生产恒态）→ 逐字节不变 → **前缀缓存零影响**；变体走「空串覆盖即移除块」的**消融式**（不编造新文案）。配 `EvalCase.prompt_profile` 字段 + 注册表 `evals/prompt_profiles.py`。这是「先能 A/B 比较提示词、再谈优化」的 plumbing 前置。
- **路由准确率探针** `routing.py`：观测信号复用 `TurnOutcome.delegated`、标签即用例 `Delegated`/`NotDelegated` check（**不引新 schema 字段**；`seed_lint` 保证 `category="routing"` 用例恰好声明其一），出混淆矩阵 + 两类业务错误率（过度编排率 `FP/(FP+TN)` / 组队不足率 `FN/(TP+FN)`，正类=应当委派）。CLI `--routing`，诊断用。
- **anti-slop 风格 linter** `style_lint.py`：零 LLM 锚定检测三类 `<output_style>` 禁项（套话开场锚首句 / 客套收尾看末句 / 未授权 emoji 走 Unicode 块，**刻意排除箭头·数学符号避免误报**）；两用法 `StyleCleanCheck`(就地断言零 slop) + `style_metrics`(违规率聚合 + 逐条 offender)。

**现有代码模块处置**：`checks.py`(不变量子集 + 轨迹形状降诊断)、`judge.py`(rubric 绝对裁判 + 成对诊断裁判)、`calibration.py`(gold-set kappa 校准，新增)、`comparison.py`(降季度诊断 CLI)、`harness.py`/`types.py`/`runner.py`/`report.py`(复用 + 扩 milestone / 协作 / 体验 / 切片字段)、`routing.py`(路由准确率混淆矩阵暂留诊断，等路由引擎再定)、`cases/`(`core` 改结果 milestone、`comparison` 留诊断、新增真实轨迹回流分桶集 ⏳)、`style_lint.py`(并入 L0/L2)。

> **未落地（数据 / 上线依赖）→ 远期**：真实轨迹回流挖掘（gold-set 数据采集 + intent 分桶集）、L2 体验 / 协作轴 nightly 深化、L3 在线采样闭环、评估→路由反馈——均见 [`远期规划.md §2.4`](/docs/06-规划/远期规划.md)。**校准门依赖**：baseline 硬门禁吃 `LLMJudge` 的 pass_rate，上线前须先有 100–200 条人工 gold-set 过 kappa≥0.6 校准门——人工标注是唯一人力前置（工具已就绪）。

> 工程门禁（棘轮 / 类型债 / 结构治理 / 跨端契约门禁）见 [`部署与运维.md` §九](/docs/05-平台与运维/部署与运维.md)。

## 日志系统规范

## 架构

渲染按「输出目标 × 环境」分发（`ProcessorFormatter` 给每个 handler 各自的 renderer，见 `core/logging.py`）：

| 输出目标 | dev (`DEBUG=true`) | prod |
|---|---|---|
| stdout | ConsoleRenderer（彩色可读） | JSONRenderer |
| `LOG_FILE` | **JSONRenderer（JSONL）** | JSONRenderer（JSONL） |

- **文件输出始终是 JSON Lines**（一行一个 JSON、无 ANSI），与环境无关——便于工具/AI 逐行 `json.loads` / `jq` 解析。
- 外部库日志（uvicorn / sqlalchemy）经同一 `foreign_pre_chain` 渲染，格式统一。
- SQL 全量回显是独立开关 `DB_ECHO`（`db/base.py`），**不挂在 `DEBUG` 上**——开 DEBUG 不会刷屏 SQL。

## 环境变量

- `LOG_LEVEL`：debug / info / warning / error（默认 info）。
- `LOG_FILE`：日志文件路径（相对路径对仓库根解析），空=仅 stdout。**开发设 `logs/dev.jsonl`**。文件 handler 带**大小轮转**（20MB × 5 备份 `dev.jsonl.1…5`，见 `core/logging.py`）——`trace_id` 已落库，轮转不丢定位；分析脚本默认合并读备份。
- `LOG_LLM_BODIES`：是否抓取 LLM prompt/回复正文（`llm.request`/`llm.response`）。**开发默认开**、**单开关即可**（emit 在 info 级，无需再调 `LOG_LEVEL=debug`）；始终**截断+脱敏**（铁律：永不落 BYOK key / 完整正文）。**生产默认关**（正文大且敏感）。

## Logger 获取

```python
from agentcore.core.logging import get_logger

logger = get_logger(__name__)
logger.info("component.action", key=value)        # 事件名第一参数，数据用 kwargs
logger.error("component.action", error=str(e), exc_info=True)
```

- 始终用 `get_logger`，**禁止** `logging.getLogger` / `structlog.get_logger`（否则脱离统一渲染与关联上下文）。
- 不在日志里记敏感信息（BYOK key、密码、token）；消息正文只记 preview，不落完整体/文件内容。
- **代码锚定**：每条 app 日志自动带 `logger`（模块）+ `func_name` + `lineno`（`core/logging.py` 的 `CallsiteParameterAdder`，只加在 app 链、不加在 foreign 链）——`module.func:line` 直接从一行日志跳到埋点源码，无需 grep 事件名。foreign（uvicorn/sqlalchemy）行不带（它们自带 stdlib callsite）。

## 事件命名

格式 `组件.动作`（动作用 snake_case），如 `chat.turn_start`。全仓库已统一此式，**新增日志必须遵循**——禁止裸名（`pipeline_error` 这类无组件前缀的旧风格）。

## 关键事件词表（权威源：代码）

| 组件 | 关键事件 | 含义 / 排查价值 |
|---|---|---|

## Context 注入（Trace 关联）

`structlog.contextvars` 的字段由 `merge_contextvars` 自动并进**每一行**日志。封装在 `core/log_context.py`（`new_trace_id` / `bind_log_context` / `clear_log_context` / `log_context` 作用域版 / `get_log_value`），**勿直接调 `structlog.contextvars`**。

| 键 | 含义 | 绑定点 |
|---|---|---|
| `trace_id` | **一次用户交互全生命周期**（唯一关联键） | `conversation/service.py` 回合起点铸造 |
| `conversation_id` `turn_id` `user_id` `agent_id` | 会话 / 回合 / 用户 / 当前 Agent | 同上 |
| `run_id` `depth` | 委派 / DAG 子节点 | 用 `log_context(...)` 作用域绑定，退出自动还原 |
| `traffic` | **合成流量标记**：`eval`（评测跑批）/ `test`（pytest）；**真实流量不绑此键**（缺省即真实） | `evals/__main__.py`、`evals/spikes/sim/__main__.py` 入口；`tests/conftest.py` autouse fixture |

> AgentCore 是**进程内 asyncio**：委派 worker 是子 task，`contextvars` 在建 task 时拷贝——`trace_id` 自动随 worker 日志传播，无需像跨进程方案那样手工串 payload。

> **`trace_id` 已落库**（DB↔日志 join 键）：`messages` / `cost_events` / `run_sessions` 各带可空 `trace_id` 列——assistant 回复与该回合的落账行写本回合 trace，recoverable worker 写其**首次**生成回合的 trace（续写不覆盖）；user 消息与 handoff 任务为 `NULL`（无 trace 作用域）。于是可从一条持久化回复/落账行反查整条日志链，日志轮转后仍能定位。写值点：`conversation/service.py`（本地变量回传，因落库在 `log_context` 退出之后）、`runtime/session_persistence.py`（读 contextvar）。

调试：`grep trace_id=<id>` 拉一次交互全链路；`conversation_id` 关整会话；`run_id` 下钻单个委派节点。分析工具与排查方法 → [对话日志分析指南](/docs/05-平台与运维/对话日志分析指南.md)。
