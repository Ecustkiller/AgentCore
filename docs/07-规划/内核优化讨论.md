## 一、已达到 / 超过行业线（先 codify，避免重复造轮子）

这一节是**结论而非待办**：把 AgentCore 已对齐或领先的部分钉下来，防止后续把已解的题当缺口重提。

| 行业原语（LangGraph / Anthropic / 2026） | AgentCore 对应 | 评价 |
|---|---|---|
| StateGraph：执行形状是图 | `delegate.depends_on` + `WaveScheduler`，「形状是数据不是模式」 | 对等，且更贴「团队」心智 |
| `interrupt()` + `Command(resume)` 人在环 | `InteractionRegistry` 统一挂起原语（approval / ask_user / plan_review / client_tool 四 kind 同构，单一 resolve 端点） | 对等甚至更统一 |
| Supervisor / Swarm 预制编排 | CEO 主 Agent + 协调者工具边界（只读归 CEO、变更全委派） | 对等 |
| Subagent 上下文隔离（Anthropic 实测 +90.2%，价值在隔离非并行） | worker 隔离上下文、产物经调度器中转、结果回 CEO；worker 不直达用户 | 完全对齐 |
| Subgraph 嵌套 | `can_delegate` + `MAX_DELEGATION_DEPTH=2`（默认关、显式开） | 对等且更克制 |
| 上下文工程 Write / Select / Isolate | 共享工作区 + 依赖预算水填充 + 递指针不递全文 + 队友产物清单 + 兄弟感知 | **超过多数框架** |
| Agent 间结构化契约 | `requires_files` 确定性后置条件门（工具调用计数，非纯提示词） | 比「押 worker 听话」更硬 |
| best-of-N / 辩论 | `RunPolicy.candidates` / 跨轮 `depends_on`，不另起子系统 | 优雅，守「形状是数据」 |
| 收敛 / 防空转 | `LoopController` 滑窗检测三类机械循环 → 两段式 NUDGE / FINALIZE | 业界少见地做进代码（非纯 prompt） |

> 已**明确否决**直接用 LangGraph / CrewAI（见 [编排器与 CEO §实现方案](/docs/03-AI核心/编排器与CEO主Agent.md)：编排是核心壁垒、要完全掌控、避免框架锁定）。本文全部是「**借其原语补自研内核**」，不重开此决策。

## 二、缺口与优化项（按杠杆分档）

### A. 架构杠杆（一动解多题）

#### A1. Turn Journal：展示级 → 执行级事件溯源 ★最高杠杆（已在远期规划，本文只定优先级）

- **现状**：`turn_journal` 已是唯一事实源，但仍是**展示级**——`run_completed` 只发摘要、CEO transcript 不入流，故 journal 无法重建 LLM 窗口 / 暂停 plan，resume 仍靠 `paused_turns.frame` 旁路。
- **行业线**：LangGraph 在每个 super-step 落「序列化 channel 值 + 版本」，checkpoint 可在**任意机器 / 任意时间**恢复、不依赖进程存活；Temporal 同理（全事件历史 + replay）。
- **判断**：这是**地基级根因**——执行级 journal 一旦落地，同时解锁 真·窗口重建 / 跨进程暂停 / Sidecar 本地引擎 / time-travel 调试 四件事。
- **指针**：技术细节（要补 `llm_call` / `message_final` / 全文 content 三类事实、受阻于现 journal 展示级）已在 [`远期规划.md §1.1`](/docs/07-规划/远期规划.md)「未启动子项·执行级 journal 事实」。**本文新增的只是定位：把它列为优化序列的 P1。**
- **落地设计**（2026-06 启动，开发期/无兼容层/直奔单一真相源）：→ 见 [`执行级事件溯源落地设计.md`](/docs/07-规划/执行级事件溯源落地设计.md)（九类事实 schema + 两投影 + Phase1 无损/Phase2 删 frame + conformance golden 闸）。

#### A2. 长对话上下文压缩（compaction）✅ 已落地 · 本条退役

- 决策通过并落地（token 触发的滚动摘要 + recency 窗口，off-turn、水位线幂等、缓存安全；附带修掉「历史取最旧 N 条」的 recency bug）。行为契约迁入 → 见 [执行引擎 §十三 长对话压缩](/docs/03-AI核心/执行引擎架构设计.md)。
- **定性修正（落地复盘）**：A2 真实价值不是「防溢出」（1M 不溢出）、也不是「省稳态成本」（exact-prefix 缓存已软化），而是治 **context rot + 缓存失效成本**——故定为质量项、P3 非紧急。

### B. 健壮性（已散见 ⏳，但有真实事故面，建议提级）

#### B1. 工具超时 + 取消传播 ✅ 已落地

- **落地**：`engine._run_one` 用 `asyncio.wait_for` 按 `ToolCategory` 分级兜底（默认 60s / 执行类 90s，`ToolSchema.timeout_seconds` 可逐工具覆盖；orchestration/interaction 豁免），超时回喂模型并计入 `LoopController` 失败；子进程做 cancel-safe（超时/取消均 kill、不留孤儿）。取消本就经 `producer.cancel()` → `gather` 协作传播到在飞 await，未引入显式 `CancellationToken`（无消费方）。
- **行为契约 → 见** [执行引擎 §十四](/docs/03-AI核心/执行引擎架构设计.md) 收敛表「工具超时 / 协作取消」两行（单一真相源）。
- **评估后否决（L2 节点级墙钟超时）**：叶子 worker 硬墙钟与 `profile.max_rounds`（轮预算）+ L1（每次工具调用上限）三重重叠，固定阈值会误杀正经重活叶子（节点超时即 `FAILED`、在飞产物无打捞）；真正的挂死 / 失控向量已被 L1（卡死工具）+ 取消传播（用户停 / 断连）覆盖。如日后确需每叶子硬墙钟，做成**配置驱动 + 可关闭 + 宽松**（落 `wave._run_node`、仅对 `not spec.can_delegate` 生效），而非硬编码 240s。

#### B2. 收敛治理补全 ✅ 已落地

- **落地**：在 `loop_controller.py` 三类机械循环检测 + 两段式干预之上补齐——空响应 degraded + 引擎级 fallback 升档、**工具失败熔断**（按工具累计失败 2 次劝阻 / 3 次本回合停用，与按签名的「重复失败检测」互补）、**无产出早停**（连续全失败且无正文 → 强制收口为 `FinishReason.UNPRODUCTIVE`）、**反思注入**（第 4 轮起每 3 轮按节奏注入「进度复盘」prompt，区别于事件驱动的 NUDGE）。阈值均进 `settings`（`engine_empty_response_threshold` / `engine_tool_failure_warn` / `engine_tool_failure_disable` / `engine_unproductive_threshold` / `engine_reflection_start_round` / `engine_reflection_interval`）。
- **行为契约 → 见** [执行引擎 §十四](/docs/03-AI核心/执行引擎架构设计.md) 收敛表「空响应 / Fallback 模型 / 工具失败熔断 / 无产出早停 / 反思注入」五行（单一真相源）。
- **刻意未做**：裁剪 system prompt（升 Pro 更对症、裁剪有丢指令风险）、LLM 异常路径 fallback（异常路径仍走现有 error 兜底）；仅剩结构化 `RoundOutcome`/`LoopDirective` 协议仍为目标态（§十四 最后一项 ⏳）。
