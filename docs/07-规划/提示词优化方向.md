> **定位**：盘点 AgentCore「提示词架构 + 相关功能」当前可优化的方向。先立一个核心判断（高杠杆在「先装方向盘、再精修少数高错率行为」，而非再加注入侧架构），再给五个方向（各带现状指针 / 机会 / 代价 / 依赖与触发）与明确「不重开」项。讨论底稿，供「AI 提案 → 人确认」。
>
> **治理**：本目录仅 `07-规划`；🗂️ = 讨论中、未承诺落地。本文只立**判断 + 方向 + 排序**，不重述各机制实现细节——装配栈 / evals / 收敛治理 / 交付前核验的细节单一真相源在 `01`–`06` 与代码，本文只留指针。多个方向与既有 07 提案相邻，一律交叉引用、不复制。决策通过、开始落地后，对应内容迁入正式文档、本条退役。
>
> **来源**：2026-06 一次「优化 AI 提示词架构与功能」的讨论 + 基于代码现状（`runtime/resolve/prompt.py`、`runtime/skills.py`、`runtime/context/`、`runs/executor_context.py`、`runtime/pipeline/run.py`、`runtime/loop_controller.py`、`agentcore/evals/`）的核验。

## 一、核心判断：缺的是「方向盘」，不是更多架构

注入侧的提示词架构已相当成熟，且**克制得对**：声明式装配（`runtime/context/` 的 `ContextAssembler` + `PromptContributor` + `SectionOrder`，稳定前缀护 DeepSeek 前缀缓存）、渐进披露（CEO 常驻只留路由核心，进阶 HOW 经 `consult_skill` 按需拉，见 [`工具与能力系统 §二`](/docs/03-AI核心/工具与能力系统.md)）、角色分层（CEO / worker 各自叠加）、去重纪律（路由判断只在 CEO core 说一次，机制在工具描述，HOW 在 Skill）。是否该统一为 `ContextProvider` 也已在 [`上下文注入统一性讨论`](/docs/07-规划/上下文注入统一性讨论.md) 里正确地判为「现在不建」。

所以高杠杆不在再加机器，而在两步：**先能量化好坏，再精修少数高错率行为。** 当前改 prompt 全凭手感——[`远期规划 §2.4 支一`](/docs/07-规划/远期规划.md) 自陈「不做则改动好坏全凭手感、防不住回归」。本判断把它从「评估体系待办」升格为**任何提示词优化的前置条件**：方向① 是闸门，②③④ 的收益必须经它验证才敢动（尤其涉及共享缓存前缀的改动）。

## 二、五个方向（按建议落地序）

### 方向①（前置）·提示词质量量化闭环 + 变体注入

- **现状指针**：成对裁判 + 团队/单体对比 harness、绝对分 `LLMJudge` + milestone 裁判 + baseline 回归门 + kappa 校准回路的 **plumbing 均已落地**（[`后端架构 §五`](/docs/02-架构/后端架构.md)、`evals/judge.py`/`calibration.py`/`__main__.py`，与 [`远期规划 §2.4`](/docs/07-规划/远期规划.md) 一致）。真正仍缺的是**裁判校准 gold-set 人工标注**（仓里仅 `evals/cases/gold/labels.example.json` 4 条演示、无真 `labels.json`，`--calibrate` 跑不起来）+ 真模型出数。
- **变体注入 plumbing 已落地（2026-06，经「提案→人确认」）**：contextvar 解析器让 eval 能 A/B 两套文案，零侵入（不改 pipeline/engine 签名）+ 无活跃变体时逐字节不变（前缀缓存零影响）→ **实现与决策理由见** [`后端架构 §五·评测基建`](/docs/02-架构/后端架构.md) + 代码 `runtime/prompt_profile.py`。
- **度量边界 / 本方向仍缺**：变体「能注入」是确定性的、已落地；但「**哪个变体更好**」需两变体各跑真模型 CEO 回合 + 裁判对比（成本 + 非确定，思考模型不吃 temperature、靠多采样压方差）。绝对分 `LLMJudge` + baseline 回归门的 **plumbing 已落地**；仍缺的是 gold-set 人工标注（校准门 kappa≥0.6 的人力前置）+ 真模型出数，挂 [`§2.4`](/docs/07-规划/远期规划.md) 真跑主线。

### 方向②·按角色 right-size（终端声音指引下沉）

- **首切已落地（2026-06）·CEO→ 方向**：详细画图 HOW（选型 + mermaid/markmap/vega-lite 语法 + 先取数再画 + 克制）已从共享 `<output_style>` base 下沉为 CEO 专属 `<visualization>` 块（base 仅留一行「…与图表，在恰当处可用」affordance）→ 见代码 `runtime/prompt._CEO_VISUALIZATION_HINT` + `SectionOrder.CEO_VISUALIZATION`（700，落在稳定前缀内）。CEO 行为逐字不变；worker 掉 HOW、留 affordance。
- **二切已落地（2026-06）·worker→ 反向**：`<tool_safety>`（写/删/移/执行需确认 + 破坏性操作谨慎）从共享 base 下沉为 **worker 专属**（`runtime/runs/executor_identities._WORKER_TOOL_SAFETY_POLICY`，嵌 leaf + captain 身份）——协调者 CEO 只持只读工具（`build_ceo_tool_registry`），这段对它是惰性文字。与画图下沉**对称但反向**（那是 CEO-only 内容下沉、worker 不背；这是 worker-only 内容下沉、CEO 不背）：CEO 省约百来 token、worker 内容逐字不变，**近零行为风险**（比画图刀更低、基本不依赖① 回测）。`test_prompt.py`/`test_identities.py` 守「base/CEO 无、worker 有」。
- **现状指针（base 已基本到位）**：扫完共享 base——`output_style`/`tool_use`/诚实/语言 均属真共享（worker 散文也对用户可见，须共享防 slop）；CEO→ 能下沉的只有画图 HOW（已切）、worker→ 能下沉的只有 `<tool_safety>`（已切）。base 已基本 right-size 到位，不再硬凑切口；后续若有右尺寸切口仍应接方向① 验证。
- **代价 / 已知缺口**：base 是共享缓存前缀，动它有 prefix-cache 风险（见 `runtime/resolve/prompt.py` 内缓存注释与 [`记忆系统 §5.5–5.6`](/docs/03-AI核心/Agent记忆与知识系统.md)）——实测为「上线一次性 re-cache、无持续抖动」。**此首切在方向① 量化网之前落地，worker 写 .md 交付物是否因此画图退化暂未度量**；若退化，回退不是还原全段，而是给 worker base 加**一行精简画图提示**。后续右尺寸切口仍应接方向① 验证。

### 方向③·路由准确率可度量 + few-shot 强化（产品命门）

- **现状指针**：「自己做 vs 交团队」的判断是产品最核心差异，权威在 [`编排器与CEO主Agent`](/docs/03-AI核心/编排器与CEO主Agent.md) 与 CEO core / `team_orchestration_advanced` skill；几乎是纯规则陈述，仅一对正反例。
- **缺口**：没有任何指标度量**这一轮 CEO 的路由决策对不对**（该委派却自己做 / 过度委派 trivial 活）。[`远期规划 §2.4 支二`](/docs/07-规划/远期规划.md) 的对比闭环测的是「团队 vs 单体产出谁好」，**不测路由决策本身**——两者正交。
- **确定性 plumbing 已落地（2026-06）**：路由探针零侵入复用评估栈（混淆矩阵 + 过度编排率 / 组队不足率，CLI `--routing`，另 5 条 seed 边界用例）→ **实现与设计理由见** [`后端架构 §五·评测基建`](/docs/02-架构/后端架构.md) + 代码 `evals/routing.py`。
- **度量边界（需真模型，属已延后主线）**：上述全是「跑完之后怎么算」的纯算术 + 用例结构，可零 LLM 单测；但要**产生**每条 `outcome.delegated`，须把用例跑过真实 `run_chat_pipeline`（真模型 CEO 回合）——故出数仍依赖 [`远期规划 §2.4`](/docs/07-规划/远期规划.md) 已延后的真跑评测，且 5 条 seed 的**标签需人工评审**后再扩为有统计意义的套件。
- **机会（仍开）**：拿到首批混淆矩阵后，针对高错边界加 2–3 对精准 few-shot——few-shot 对这种细腻判断通常比加规则有效，还可能替换掉部分冗长规则反而瘦身（与方向② 协同）。

### 方向④·输出风格的确定性护栏（先可观测）

- **现状指针**：anti-slop（无 emoji / 无套话开场 / 格式克制）纯靠 `<output_style>` 指令；确定性轻层 `finish_guard`（见代码 `runtime/verify.py`，背景 [`执行引擎 §四·交付前核验`](/docs/03-AI核心/执行引擎架构设计.md)）覆盖造引用 + 代码围栏结构完整性。
- **区分**：交付前核验管的是**交付物正确性**（引用 / 规格）；本方向管的是**风格遵守度的度量**，二者不同关注点。
- **确定性 plumbing 已落地（2026-06）**：零 LLM anti-slop linter（三类 AI 腔检测 + `StyleCleanCheck` 就地断言 + 违规率聚合，CLI `--style`）→ **实现与设计理由见** [`后端架构 §五·评测基建`](/docs/02-架构/后端架构.md) + 代码 `evals/style_lint.py`。
- **度量边界（需真模型，属已延后主线）**：linter 规则纯函数、可零 LLM 单测；但要**产生**被检 `outcome.content` 仍需真模型回合，故违规率出数依赖 [`远期规划 §2.4`](/docs/07-规划/远期规划.md) 的真跑评测。密度类启发式（过度加粗 / 滥用列表）噪声大、需真实语料校准阈值，列为 v2 未做。
- **机会（仍开）**：拿到首批违规率后即可回答「`<output_style>` 那段到底有没有用、能否瘦」——与方向①②形成闭环（瘦身后用违规率守不回归）。

### 方向⑤（功能向）·consult_rule：项目/用户级规则的渐进披露

- **现状指针**：[`上下文注入统一性讨论 §四–五`](/docs/07-规划/上下文注入统一性讨论.md) 明确 `consult_rule` / rules on_demand「全仓无实现」，Skills 是唯一完整的「目录 + 按需取」。
- **机会**：若产品要支持用户/项目自定义 agent 行为（类 Cursor rules），现无承载；它正好复用 Skills 的 `Consultable` 形态，也正是该讨论里说的**扳机 A**（第 3 个真「目录+按需取」源落地时才抽 `Consultable` 协议，而非大一统 Provider）。
- **触发**：产品确定要做「用户自定义规则 / 自定义 agent 行为」这一能力。优先级取决于产品决策，非提示词内部优化。

## 三、不重开（尊重已有决策）

- **统一 `ContextProvider`**：复杂度在写侧 / 执行侧、不在注入侧 → 见 [`上下文注入统一性讨论 §三–四`](/docs/07-规划/上下文注入统一性讨论.md)。
- **向量 RAG 注入**：已取消，实时工作区概览 + agentic 检索已够 → 见 [`记忆系统 §5.6`](/docs/03-AI核心/Agent记忆与知识系统.md)。
- **再造一套 delegate guidance**：去重纪律已在（机制 / 判断 / HOW 三层各说一次）→ 见代码 `tools/builtin/delegate/schema.py` 注释。

## 四、建议落地序与依赖

**方向① 是闸门**：先有「能比较提示词改动」的量化方向盘，②③④ 才从手感变成有证据的优化（②动共享缓存前缀尤其依赖它）。其中**方向③ 的路由准确率**是最值得投入的产品向工作——它把「真正的 Agent 团队协作」从口号变成可度量、可调的回路。方向⑤ 独立、由产品是否要「自定义规则」驱动。

落地序：① →（②｜③｜④）→ ⑤ 按产品驱动随时插入。任一方向启动、决策通过后，对应内容迁入正式文档（`01`–`06`）、本条相应段落退役；全部未启动 → 本文 no-op，仅作 🗂️ 判断与方向留档。

**进度**：方向② 首切（画图 HOW 下沉 → CEO `<visualization>`）+ 二切·反向（`<tool_safety>` 下沉 → worker 身份，CEO 只读工具无需此 caution）+ 同类低风险去重下沉（CEO core 与 `team_orchestration_advanced` skill 间「约束 vs 方案」正反例、「广度调查归团队」HOW 从常驻 core 收敛为「判断 + 指针」，完整版仅 `consult_skill` 披露）已先于① 落地（按产品负责人决定，常驻前缀再省约 200 字、路由判断逐字保留，`test_prompt.py` 守 `专业方案`/`填字员`/`调研`/`探路`），CEO→ 与 worker→ 两向切口均已切净、base 基本到位；净收益待① 量化网回测（二切近零行为风险、依赖度最低）。方向①（变体注入 + 绝对分裁判 + baseline 门 + kappa 校准）/③（路由探针）/④（anti-slop linter）的**确定性 plumbing 均已落地**，实现见 [`后端架构 §五·评测基建`](/docs/02-架构/后端架构.md)；但**出数都需真模型回合**（③ 另需人工评审 seed 标签），度量仍挂 **gold-set 人工标注 + 真跑出数**（即 [`远期规划 §2.4`](/docs/07-规划/远期规划.md) 真跑评测主线）。方向⑤（consult_rule）未启动。
