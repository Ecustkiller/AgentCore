# 前端 UX 目标态（未落地 UI 规格）🗂️

> **定位**：仅存**未落地**的前端 UX 目标设计。已落地部分全部迁回现状专题文档（[`04-前端/前端UX设计.md`](/docs/04-前端/前端UX设计.md) / [`前端技术与架构.md`](/docs/04-前端/前端技术与架构.md)），对应条目随落地从本文退役（含原「详情面板/任务卡片/辩论展示/图视图交互/侧栏分组」诸节，及已否决的 Slash 命令、Agent/Team 选择器、气泡内工具卡、各类输入框 pill、工具点节点、拖拽移动对话——否决理由已就地写入现状文档）。当前仅剩：**信息层次模型（蓝图）+ 三项 ⏳ Phase 2 前端增量（均后端先行）**。

---

## 一、信息层次模型（Layer 0–4）

设计模型：单 Agent 回合默认只见输出（Layer 0）；多 Agent 回合的状态/进度/协作由内嵌图承担（Layer 1–3）；点节点把单 run 全文下钻到面板（Layer 4）。其他文档以「目标态 §一」指向此处。

> 落地形态（内嵌协作图 / `SidePanel` 下钻）已是现状 → 见 [`前端UX设计.md` §一 / §三 / §十](/docs/04-前端/前端UX设计.md)。

---

## 二、`checkpoint_after` 结构化挂起（⏳ Phase 2）

DAG `checkpoint_after` 按 step 结构化挂起——与已落地的 CEO 主动 `ask_user` 检查点（会话流卡片 `CheckpointCard`）是**不同机制**：前者是调度器按 plan 预声明的挂起点，后者是 CEO 运行中临时拍板。边界、为何 defer、现状如何用 `ask_user` + CEO 批次覆盖替代，见 [`编排器与CEO主Agent.md` §四](/docs/03-AI核心/编排器与CEO主Agent.md)。

**后端先行**：统一 Interaction 原语本身**已落地**（进程内 `InteractionRegistry`，收编审批 / `ask_user` / 本地工具，见 [`执行引擎架构设计.md` §18.2](/docs/03-AI核心/执行引擎架构设计.md)），但本节所需的**结构化挂起**——调度器按 plan 预声明的检查点（`kind=plan_review`、`checkpoint_after`）——尚未承载；后端不出这类数据，前端无 UI 可落。前端形态（结构化挂起卡片 + 图上检查点节点）见 §四。

---

## 三、结构化辩论 Arena（⏳ Phase 2，排最后）

真·结构化辩论：阶段轮转 / 多轮来回交锋 / 独立 `arena` SSE / 状态机——区别于已落地的**轻量辩论展示**（普通并行 DAG + `stance`/`group` 打标差异化呈现，见 [`前端UX设计.md` §四](/docs/04-前端/前端UX设计.md)）。独有价值（多轮交锋）、与轻量版的架构关系、为何排 Phase 2 最后，见 [`Agent协作模式.md` §7.4](/docs/03-AI核心/Agent协作模式.md)。

**后端先行**：后端 Arena 阶段机 / 独立 SSE 不落地即无数据可画。前端形态（arena 图节点）见 §四。

---

## 四、图视图增量节点（⏳：arena / 检查点节点）

随上游后端落地的两类新图节点（其余图视图交互——端点节点 / 嵌套子团队分组 / 粒子边 / 回放 / 右键菜单 / 布局切换等——均已是现状，见 [`前端UX设计.md` §五](/docs/04-前端/前端UX设计.md)）：

- **arena 节点**：随 §三 Arena 后端落地、排最后。
- **检查点节点**：随 §二 `checkpoint_after` 后端落地；区别于已落地的 `ask_user` `CheckpointCard` 会话流卡片（挂在消息下、非图节点）。

两类**无独立前端决策**——上游后端不动即无数据可画，故随各自后端一并落地。性能约束（≤50 节点、≥60fps）见现状 [`前端UX设计.md` §八](/docs/04-前端/前端UX设计.md)。
