### 1.1 Sidecar 可迁移核（中长期）

桌面 spawn `python -m agentcore.sidecar` 跑**同一 `RuntimeEngine`**，stdio JSON-RPC 通信，仅把宿主端口（[执行引擎 §18.6](/docs/03-AI核心/执行引擎架构设计.md)）换为本地实现（SQLite / 内存 / in-proc），离线可降级。

- **价值**：本地执行 / 离线 / 隐私基础，云与本地同一引擎。
- **代价**：宿主端口面大、双实现维护成本高。
- **就绪度**：§18.6 的 10 个宿主端口当前 3 个 Protocol 化（`EventSink` / `ClientRequestBridge` / `Journal`），其余 7 个仍为具体实现；**`Journal` 地基已落地**（`turn_journal` 表 + `TurnJournalRepository` + `runs` 投影，唯一事实源；暂停的 journal-so-far 亦落 `turn_journal`、`paused_turns.frame` 仅余 resume 控制态，见 [执行引擎 §18.3](/docs/03-AI核心/执行引擎架构设计.md)），`SnapshotStore` 已被 Journal 吸收。
- **未启动子项（绑定本初创）·执行级 journal 事实**：把暂停帧的 plan/completed/transcript 也折叠进 journal（`round_boundary.fold`，最终删 `paused_turns.frame`）+ LLM 窗口投影——**受阻于现 journal 为「展示级」**：`run_completed` 只发 `summarize(content)`（resume 要全文回灌）、CEO `transcript` 来自实时态根本不入流、系统提示亦非事实。须先加**执行级事实**（`llm_call` / `message_final` / 全文 content，即 §18.3 九类事实里尚未 emit 的几类），属 emit 路径 + journal schema + 重验全部 resume 路径的多层改造。**触发条件**：Sidecar/本地执行真正需要 frame 消失时随本初创启动；当前展示级 journal 上硬折叠会静默损坏 resume，故不做。
- **倾向**：中长期；新代码按「引擎面向宿主端口」组织**留缝**（低风险铺路，不引入第二实现）。

### 1.2 JSON-RPC 2.0 运行时协议（与 Sidecar 绑定）

用 JSON-RPC 承载整轮运行时（initialize / startTurn / resume / pause / cancel / respond…），事件映射为 notification，传输可换 stdio（sidecar）/ WS（云）。**注意非 MCP**（MCP 仍用于 Agent↔外部工具）。

- **价值**：云 / 桌面 / UI 一套代码，pause/resume/交互回值天然统一。
- **代价**：需把现有 SSE + HTTP（[执行引擎 §十二](/docs/03-AI核心/执行引擎架构设计.md)，事件契约已稳定对齐）重构为协议层。
- **倾向**：**与 §1.1 Sidecar 绑定**——Sidecar 不做则本项暂缓（SSE 无独立收益时重构纯亏）。

## 二、平台能力演进（抽象已预留、第二实现待启）

> 共性：抽象接口（Protocol + 工厂）或机制扩展点在 MVP 即预留、首实现 / 首模式满足发布；第二实现 / 强制模式属**发布后**增强，出现明确驱动力才启动——与 §一 Sidecar 同范式（「抽象先行、第二实现留缝」的能力域版）。

### 2.1 真实沙箱（SandboxProvider 第二实现）

代码执行当前走受限 `SubprocessSandbox`；第二实现把执行搬进**真隔离运行时**（gVisor / Firecracker 等），抽象 `SandboxProvider` 已预留。

- **价值**：不可信代码安全执行、多租户隔离。
- **启动触发**：放开不可信代码执行 / 多租户共享执行 / 代码执行成为高频能力。

**Post-MVP 目标架构细节**（从安全文档迁出）：

| 方案 | 结论 |
|---|---|
| gVisor（用户态内核拦截） | Post-MVP 升级目标——不挑硬件、强度足够 |
| 独立小虚拟机（Firecracker） | 换带 KVM 机器后平滑升级 |
| 独立 Worker + NATS | API 永不接触 Docker；代码执行经 NATS request 转发到 worker 容器 |

gVisor 执行模型锁死项：默认禁止联网、只读根文件系统、内存/CPU/pids 上限、非 root。资源限额默认：256MB 内存 / 1 CPU / 128 pids / 默认禁网 / 并发 2。

→ 见 [`../05-平台与运维/安全权限与治理.md` §五](/docs/05-平台与运维/安全权限与治理.md)

### 2.2 多 LLM Provider（LLMProvider 第二实现）

当前单一 `DeepSeekProvider`（Flash + Pro）；第二实现接入其他模型家族（海外 / 本地 / 其他厂商），抽象 `LLMProvider` + `llm/factory.build_provider` 已预留。

- **价值**：出海与多模型选择、客户指定模型、对冲单一供应商的可用性 / 成本风险。
- **代价**：各家 API 差异（工具调用 / 思考模式 / 流式增量）需在 provider 层抹平；定价表与计费每接一家加一份。
- **就绪度**：`LLMProvider` 抽象 + 首实现 `DeepSeekProvider` 已落地；BYOK「一轮一网关」凭据传播原则已定（[执行引擎 §18.7](/docs/03-AI核心/执行引擎架构设计.md)）；第二家 provider 未接。
- **启动触发**：出海需要海外模型 / 客户要求指定模型 / 对冲单一供应商风险。

### 2.3 治理强制检查点层（结构化挂起的强制模式）

> **来源**：原 07 草稿《结构化挂起后端落地设计》§4.7「治理强制注入层」**已退役删除**；该蓝图 2a/2b 全落地迁入正式文档后，唯一延后项迁出至此。

结构化挂起底座（`WaveScheduler.on_checkpoint` + `InteractionRegistry` 的 `plan_review` kind + 回合级 `paused_turns` 落盘 + `POST /resume`）已全落地，**首模式 = CEO 自声明** `checkpoint_after`（CEO 自愿在高危 step 后标记，用户 continue/adjust/stop，软挂起 timeout=continue 放行，已满足发布）；**第二模式 = 治理策略强制**：检查点由策略强制注入（非 CEO 自愿声明）、声明即必停（不可被 CEO / 用户跳过）、挂起点可审计留痕、超时取 `halt`（而非软挂起的 `continue`）。

- **价值**：合规 / 企业治理场景的「保证闸门」——某些高危 / 不可逆步骤必须由人确认，不依赖 CEO 自觉；审计留痕满足审查要求。
- **代价**：调度器 / 计费 / 事件层需区分「自声明 vs 强制」两类挂起；timeout 语义按类分流（软 = continue、强制 = halt）；强制注入规则的策略面与配置。
- **就绪度**：机制底座 + 首模式（CEO 自声明）已全落地（见 [`../03-AI核心/执行引擎架构设计.md` §暂停与恢复](/docs/03-AI核心/执行引擎架构设计.md)）；仅缺「强制注入 + 必停 + halt 超时 + 审计」这层策略。
- **启动触发**：出现明确的合规 / 企业治理需求（某类客户或审查要求强制人工闸门）。

## 四、产品形态演进

> 发布后才考虑的产品形态方向在此累积，按 §一/§二 格式（价值 / 代价 / 就绪度 / 启动触发）。

### 4.1 人 + AI 混合群（消息页差异化形态）

消息页 IM 群聊里 `@` 唤起 agent → 接 CEO 编排，让 AI 作为群成员参与人类群聊（区别于对话页的纯 AI 团队群）。是消息页相对对话页的差异化卖点；数据层 `chat_messages.sender_type=agent` 已为此预留。

- **价值**：把 AI 团队能力带进人类社交 / 协作群——群里 `@` 某 agent 即可让它响应、查资料、执行任务，人与 AI 同会话协作。
- **代价**：要打通两套当前解耦的栈——IM（`messaging` service / `chat_messages` / firehose）↔ AI 执行引擎（CEO 编排 / `RuntimeEngine` / 事件流）。需处理：群消息识别 `@agent` → 转一次编排 run → agent 输出回写为 `chat_message`（`sender_type=agent`）→ 计费 / 限流归属 → 权限（谁能 `@`、agent 可见多少群历史）。
- **就绪度**：数据层 `sender_type=agent` 已留；IM transport（全员群 / 成员 / 实时 fan-out）与 CEO 编排引擎均已落地；**缺两栈之间的桥**（IM 消息 ↔ 编排 run）。
- **启动触发**：内测群验证人群聊价值后出现「群里直接调 AI」的明确诉求；或需把消息页做成区别于对话页的协作场景。

> **来源**：原 [`../05-平台与运维/消息IM.md`](/docs/05-平台与运维/消息IM.md) §七 P2 ⏳ 项，按文档治理迁入。
