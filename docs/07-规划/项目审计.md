# 项目审计（首轮：全栈健康体检）

> **状态**：🗂️ 首轮已收尾（2026-06-29，见 §十一 结案）的工作文档（审计计划 + 问题登记册）。非现状蓝图，剩余 P3 各自走 `dev-process` 决策流程立项。
>
> **本文是什么**：一份**可执行的审计计划**——先定清楚「审什么 / 怎么判 / 按什么序 / 产出什么」，再据此一步步审。审计**只发现与登记问题，不在本轮顺手改代码**（改动各自立项，契约级改动须人确认）。
>
> **不止静态**：除了"代码看着对不对"，本轮还要求**每个功能端到端跑得通**（见 §二 D 维度）——审计输出既有「问题登记册」，也有「功能清单 + E2E 证据」。

## 一、目标与边界

### 锁定的方向（2026-06-29 决策）

| 维度 | 选择 |
|---|---|
| 套餐 | **全栈健康体检** = 架构一致性 + 代码健康 + 文档漂移 + **功能端到端验证（E2E 可用性）** |
| 范围 | **全 monorepo**：`apps/server` + `apps/desktop` + `apps/mobile` + `apps/admin` + `packages/`（+ `website`/`promo` 轻扫） |
| 节奏 | **广度优先 → 先建「问题登记册 + 功能清单」→ 按优先级深挖** |
| E2E 彻底度 | **逐个功能手动实跑（穷尽，非分层），"慢慢来"** |

> **E2E 彻底度（2026-06-29 补充决策）**：每个功能都要给出实跑结论，不止登记盲区。节奏放慢可接受；但仍**先跑现成自动证据 / 零-LLM** 再人肉补，真模型旅程**省着花**（决策：零-LLM/假 provider/Flash 优先、每条只跑一次）。两类成本区分见 §二 D。决策齐全，已进入执行。

### 不在首轮范围（避免发散，后续可单独立轮）

- 安全深挖（认证/会话/IDOR/BYOK 密钥/沙箱逃逸）——仅在体检中顺手记**显眼**风险，不做系统性渗透式审查。
- 成本/性能 profiling（token/计费路径/热点）。
- 产品完整度矩阵（MVP 6 模块 + 垂直 vs 实际）。
- 补测（**不写新自动化测试**；E2E 验证靠跑现有测试/向量 + 手动 happy path 实跑，缺口只**标注**不补）。

### 锚定与免责

- 审计锚定**当前 main 工作树状态**。本仓多 Agent 并行开发、大量 WIP 未提交（白板 / 辩论 / vision / board 等）；正在动的区域会在登记册标注「⚠️ WIP，可能很快变化」。
- 自检读代码用 **Read**，不与 `git status`/`git diff` 对账（见 `.cursor/rules/git-workflow.mdc`）。

## 二、审计维度与判定标准

四条镜头，每条给「查什么 + 判定依据（锚到蓝图/规则）+ 怎么查」。前三条是静态（读代码/对蓝图），第四条 D 是动态（功能真的跑得通）。

### A. 架构一致性（代码 vs 蓝图）

| 检查项 | 判定依据 | 方法 |
|---|---|---|
| 后端五层单向调用 | `后端架构.md §一`：`models→schemas→repository→service→router` 不可反转（router 不直接碰 DB、repository 无业务逻辑） | 抽查各模块 `routes/`、`repositories/`、`service` |
| 模块依赖硬约束 | `项目结构.md §二`：`api` 不依赖 runtime/llm/tools；`runtime` 不依赖 conversation/api；`core/db/llm/tools` 零向上依赖 | 按表逐条 grep import 反向引用 |
| runtime 子包边界 | `后端架构.md §三`：engine/runs/journal/interactions/events/resolve… 关注点不串味 | 抽查跨子包 import |
| 垂直插件反向依赖 | `后端架构.md §四`：核心不得 import 任何垂直（`legal_*` 等）；白名单为空可独立启动 | grep 核心→垂直 import |
| 契约漂移 | `protocol-conformance.mdc`：两端 fold 行为对齐；OpenAPI 单一源 | 跑 `pnpm conformance`、查 `openapi.json` 与 schemas 是否同步 |
| 「实现冒充需求」 | `dev-process.mdc`：是否有为复用旧实现而裁剪的需求、用「技术方便」反推的设计 | 阅读 + 对照 docs 设计意图 |

### B. 代码健康

| 检查项 | 信号 | 方法 |
|---|---|---|
| 补丁绊线味道 | `dev-process.mdc` 绊线：兜底/对账/自愈/特例类逻辑；同一根因改 ≥2 层；同一接缝第 3 次打补丁 | grep `fallback`/`workaround`/`HACK`/`兜底`/`特例` + 阅读热点 |
| 死代码 / 未用导出 | 无引用的函数/模块/导出 | grep 引用计数、`ruff F401` 等 |
| 重复实现 | 多处近似逻辑（各端本应分叉的除外） | 语义检索同义实现 |
| 超大模块 / 函数 | 单文件/单函数过长、圈复杂度高 | 按行数排序定位热点后阅读 |
| Lint / 类型债 | `ruff`（E/F/W/I/N/UP/B/A/SIM）、`biome`、`tsc --noEmit` | 跑工具收基线 |
| 错误处理完整性 | 生产级要求：完整错误处理、合理日志（`dev-process.mdc`） | 抽查关键路径 try/except、SSE/IPC 边界 |
| TODO/FIXME 债 | 标注未决 | grep `TODO`/`FIXME`/`XXX` |

### C. 文档漂移

| 检查项 | 判定依据 | 方法 |
|---|---|---|
| ✅/⏳ 标注 vs 实际 | `doc-governance.mdc`：标 ⏳ 但已实现=文档滞后；标 ✅ 但缺失=虚标 | 抽样蓝图断言回代码核对 |
| `code:`/`→ 见代码` 指针有效性 | frontmatter `code:` 与正文指针应指向真实路径 | 校验路径存在 |
| 契约文档 vs 代码 | `核心接口定义.md` REST/SSE/DB 形状 vs 实现 | 抽查高频契约 |
| 索引/路由准确性 | `docs/索引.md` 任务路由表链接有效 | 校验链接 |

### D. 功能端到端验证（E2E 可用性）

目标：不止"代码看着对"，而是**功能从用户入口到结果回显真的跑得通**。先建**功能清单**（§四之二），逐条判定 E2E 证据与结论。

**证据分层（按成本/可靠性，优先用现成的）**：

| 层 | 证据来源 | 说明 |
|---|---|---|
| L1 自动 E2E | `tests/integration/`、`pnpm conformance` 向量、`evals`(L0/L1)、前端 vitest + fold、preview 回放向量 | 已有自动证据 → 直接采信，跑一遍看绿 |
| L2 实跑 happy path | 终端已在跑后端(`uv run python -m agentcore`) + `pnpm dev`；对关键旅程手动走一遍 | 缺自动证据时，用运行环境实证主路径 |
| L3 盲区 | 既无自动证据也难手动复现 | 记为 finding（维度=E2E、标"E2E 盲区"），给补法建议 |

**判定结论**：✅ 通过 / ❌ 失败（附现象） / ⚠️ 盲区（无证据）。失败按 §三 定级（核心功能不可用 = P0/P1）。

> **彻底度（决策：逐个功能实跑、慢慢来）**：每个功能最终都要 ✅/❌ 结论，L3 盲区只是"还没验"的中间态，不是终点。
>
> **两类成本要分清**：
>
> | 成本 | 是什么 | 谁买单 |
> |---|---|---|
> | Cursor AI（我） | 驱动每个 E2E、读输出、记结果的时间/用量 | Cursor 用量 |
> | 产品 AI（DeepSeek） | 跑到真模型的功能（聊天/派单/辩论/vision）每次真实 API 调用 | 项目 DeepSeek/BYOK 账单 |
>
> **省钱策略**：能用 L1（零-LLM/假 provider/集成测试/conformance）验的就不碰真模型；纯后端/前端功能（文件/认证/工作区/admin 等）压根不调 LLM；真模型旅程优先 Flash、每条只跑一次。真正烧 DeepSeek 的只有 AI 核心那几类。

## 三、严重度分级

| 级别 | 含义 | 例 |
|---|---|---|
| **P0 阻断** | 破坏不变量 / 契约 / 安全；线上会出事 | 分层硬约束被破、契约漂移致两端 fold 不一致、密钥泄漏路径 |

| **P2 中** | 应改善，不紧急 | 重复实现、超大模块、文档 ⏳/✅ 误标 |
| **P3 低** | 轻噪音 / 清理项 | 死代码、TODO 债、lint 噪声、失效链接 |

### 四之二 功能清单（E2E）

每个功能一行，回答"它真的跑得通吗"：

| 字段 | 说明 |
|---|---|
| 功能 | 用户可感知的能力（如"辩论编排""派单 delegate""工作区文件读写""登录刷新"） |
| 入口→结果 | 端到端路径一句话（前端入口 → 后端 → LLM/存储 → 回显） |

| 证据指针 | 测试/向量/eval 路径，或实跑步骤 |
| 结论 | ✅ 通过 / ❌ 失败 / ⚠️ 盲区 |
| 关联 | 失败/盲区对应的 `AUD-NNN`（如有） |

**E2E 实跑（D 维度）**：

| 目标 | 命令 / 入口 |
|---|---|
| 后端集成 E2E | `uv run pytest apps/server/tests/integration` |
