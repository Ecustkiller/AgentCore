## 一、视角：认知层同构，执行层异构

讨论的起点：从技术实现看，Tool / Skill / Agent / 记忆等概念，对模型而言**都是"模型 + 注入的上下文（token）"**。这个判断在**认知层成立**——模型只有一条感知通道（上下文 token），Skill / 工具描述 / persona / 记忆 / A2A 消息都是变成 token 进窗口。[`Agent记忆与知识系统.md` §5.2](/docs/03-AI核心/Agent记忆与知识系统.md) 已逐字写明"注入进 prompt 后一切都是文本"。

但它在**执行层异构**：

| 概念 | 边界另一侧发生什么 |
|---|---|
| **Skill** | 纯只读上下文，零副作用 |
| **Tool** | 上下文（schema）+ 真实副作用执行（走 function-calling 通道） |
| **Agent** | 上下文（persona）+ 自治循环 + 持久状态 |

一句话：**提示词决定"想做什么"，运行时决定"真能做什么"。**

## 二、抽象命名：Provider / Assembler

若只看认知层（注入侧），它可塌缩成两个原语：

- **Provider**：一切上下文片段源的统一形状——`目录()` + `按需取(name)`，或 `预算装配()`。
- **Assembler**：收集片段 → 选择 / 排序 / 裁剪 → 在预算内拼出最终 prompt。

注入侧的核心工程问题只有一个：**避免提示词爆炸**——真正的目标函数不是"塞得下"，而是"对的时间、最少 token、最相关上下文"（成本 / 延迟 / 质量三者受害，质量最致命）。原则：**默认不放，按需才拉（渐进式披露）。**

### 可调度的五个杠杆（均已有实现归属，本文只做指针汇总）

| 杠杆 | 做法 | 实现归属 |
|---|---|---|
| 选择 | 检索 / 路由，只注入相关片段 | [`记忆 §5.6`](/docs/03-AI核心/Agent记忆与知识系统.md) 实时概览 + agentic 检索（向量 RAG 已取消、降扳机后手）；[`执行引擎 Phase1`](/docs/03-AI核心/执行引擎架构设计.md) CEO 只读 / 检索子集 |
| 时机 | 渐进式披露：菜单常驻、正文按需读 | [`工具与能力 §二`](/docs/03-AI核心/工具与能力系统.md) Skill 目录模式 + `consult_skill` |
| 压缩 | 历史 compaction、工具输出截断 | [`执行引擎 §三`](/docs/03-AI核心/执行引擎架构设计.md) 长对话压缩 |
| 外置 | 文件系统当溢出区、递指针 | [`记忆 §四`](/docs/03-AI核心/Agent记忆与知识系统.md) Agentic Recall / `recall(id)` |
| 分治 | 子 Agent 各持任务上下文、回传蒸馏结果 | worker 隔离上下文（Anthropic 实测 +90.2%），见 [`Agent协作模式`](/docs/03-AI核心/Agent协作模式.md) |

"谁来拉"已决：**模型自选**（[`工具与能力 §二`](/docs/03-AI核心/工具与能力系统.md) 否决 embedding / LLM 预筛，选 `consult` 模型自取）。

## 三、守恒律：复杂度不会因统一而消失

统一只发生在注入侧；它对**输出侧**（执行副作用、控制循环、状态生命周期、失败 / 重放）一字未说。复杂度搬家、不消灭：

- → Assembler 的"选什么 / 何时 / 排序 / 淘汰"策略（注入侧唯一难点）
- → 工具 / 记忆写入运行时、[`执行引擎 §8.5`](/docs/03-AI核心/执行引擎架构设计.md) 引擎纯化、`§八` ports

**接口很简单，策略很难；输入统一了，输出没有。**

## 四、判断：现在不建统一 ContextProvider

核验代码现状（2026-06 快照，权威以代码为准）：5 套机制虽多已落地，但**真正的"目录 + 按需取"只有 Skills 一个**——其余要么不同源、要么 blob / 实时套标签、要么还没建——

| 机制 | 代码现状 |
|---|---|
| Skills | ✅ `SkillRegistry` + `consult_skill`，唯一完整"目录 + 按需取" |
| Tools | ✅ `ToolRegistry`，但走 function-calling 通道 + 带执行（不同源） |
| Memory→`<rules>` | ✅ 但注入侧只是 blob 套标签（`assemble_system_prompt`），复杂度在写侧 |
| Rules on_demand / `consult_rule` | ⏳ 全仓无实现 |
| Workspace `<workspace_context>` | ✅ 实时概览（`runtime/context/workspace_overview.py`）+ agentic 文件工具；**向量 RAG 已取消**、语义检索降为扳机后手（详见 [记忆 §5.6](/docs/03-AI核心/Agent记忆与知识系统.md)） |

四条理由（现在不建）：

1. **真"目录 + 按需取"只有 Skills 一个**：Tools 不同源、Memory 与 Workspace 概览是 blob / 实时套标签、Rules on_demand 还没建；给尚未成形的 consultable 源设计统一接口，落地必漏必改。
2. **唯一真同构已消化**：`skills.py` 明写"mirrors ToolRegistry"——刻意选"照抄、不共享基类"。按"第 3 次真实重复才抽"的纪律，现在真实重复 = 2。
3. **复杂度不在注入侧**（守恒律）：注入侧最便宜；难点在记忆写侧 / 工具执行侧 / 还没建的预算侧。统一接口只罩最便宜那块。
4. **家已点名**：`assemble_system_prompt` docstring 自述"Full version will support skills, rules, workspace context"——真要收敛就长它（装配主干已照此长成 `runtime/context/assembler.py`（`ContextAssembler`），见扳机 B），不必新立门派。

## 五、两个触发扳机（满足才动）

- **扳机 A（抽接口）**：第 3 个**真**"目录 + 按需取"源落地（市场 Skill / rules on_demand / pgvector 知识库）→ 从 `SkillRegistry` 抽一个小 `Consultable` 协议（3 个真实例撑）。**不是**大一统 Provider。
- **扳机 B（建预算）**：拼出的 prompt **真的**溢出 / 裁错 / 打穿缓存 → 把装配长成带预算 + 优先级的真 Assembler。**装配主干 + 常驻源插件化已落地**：`runtime/context/assembler.py`（`ContextAssembler`） 统一收集 / 排序片段，每个常驻源（base / runtime context / 记忆 / CEO core / 技能目录 / citation / 工作区概览 / 附件）皆为 `PromptContributor` 插件、渲染序由 `SectionOrder` 声明（稳定前缀逐字节一致护缓存）；`budget` 字段已预留**唯一读取点**，但**预算 / 裁剪 / 降级逻辑仍未建**——按需才长。方案见 [`执行引擎 §七`](/docs/03-AI核心/执行引擎架构设计.md)"降级模式"（DeepSeek 1M 未逼到，见 [`记忆 §六`](/docs/03-AI核心/Agent记忆与知识系统.md)）。

A、B 均未触发 → **no-op**。

## 六、文档结论

代码不统一 → 文档**维持按子系统 split**，不建统一权威文档（合并文档应是合并代码的结果、非前提：代码维持 5 套则文档维持 split；若日后建统一模块，再让 move + delete 跟代码一起走）。本文仅作 🗂️ 视角 + 判断留档。
