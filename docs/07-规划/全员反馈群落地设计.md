## 一、目标与定位（✅ 已与产品确认）

- **目标**：内测期收集反馈 + 建立社区粘性，靠**一个全员群**把分散的反馈/求助/讨论收口到一处，创始团队可见、可即时响应。
- **形态**：`type='group'`，**人人能发言**（区别于被否的「官方号单向广播」）。
- **默认进群**：内测期所有用户（存量 + 新注册）默认成为该群成员，无需手动加入。

## 二、关键判断：大部分 transport 已免费可用

现有 IM（P0 单聊）的后端与前端**几乎全部按 `chat_id` 泛型**，群聊可直接复用，无需重写：

| 能力 | 现状 | 群是否可用 |
|---|---|---|
| 会话列表 | `list_memberships(user_id)` 按成员关系查，任意 `type` | ✅ 群自动出现在列表 |
| 发消息 + fan-out | `send_message` 已 `list_members` → `events.publish` 给**全体成员** | ✅ 群发即全员推送 |
| 收消息 / 分页 / 已读 / 未读 | `list_messages`/`mark_read`/`unread_counts` 全按 `chat_id`，`unread_counts` 已处理 NULL sender | ✅ 直接可用 |
| 实时通道 | hub 按 `user_id` fan-out 到每人每连接 | ✅ 群成员都能实时收到 |
| 前端 store/列表/线程/气泡 | `messaging.ts` store + `ChatList`/`ChatThread`/`ChatBubble` 均泛型 | ✅ 群能渲染收发 |
| 显示名 | `chatDisplayName` 已写 `group → title || "群聊"` | ✅ 已就绪 |

**结论**：群聊不是从零，缺的是「建群 + 默认进群 + 群成员 API + 群形态 UI 的几处补丁」。

## 四、数据模型增量

新增一列，**不新建表**（沿用 `chats`/`chat_members`/`chat_messages`）：

| 改动 | 内容 | 理由 |
|---|---|---|
| `chats.auto_join` `bool default false` | 标记「新用户默认加入」的会话 | 比硬编码 `beta_group_id` 更通用——日后官方号广播也可 `auto_join=true` 复用同一入群路径 |

- 默认全员群 = 一条 `type='group'`、`auto_join=true`、`created_by=NULL`（系统所有）、`title` 固定的 `chats` 行，由迁移创建。
- 成员 `role='member'`、`state='accepted'`（群成员不走单聊的 `pending` 消息请求门）。
- **被否**：① 单独 `beta_group` 表——一行配置不值得建表；② 配置项存 `beta_group_id` UUID——`auto_join` 列自描述、可扩展、查询直接。
- **Stage 3 增量**：`chat_members.muted_by_admin bool default false`（admin 禁言态，被禁言者可读不可发；与用户自静音 `muted` 区分）。迁移 `c4f8b1d6e9a2`。

## 五、默认进群机制（核心）

三个触发点，全部**幂等**（`chat_members` 主键 `chat_id+user_id`，`on_conflict_do_nothing`）：

1. **建群 + 存量回填（一次性迁移）**：插入群行 → `INSERT chat_members SELECT user_id FROM users ... ON CONFLICT DO NOTHING`。内测体量小，迁移内回填可接受。
2. **新用户注册即入群**：注册 service 成功建用户后，把该用户加入所有 `auto_join=true` 的会话（state=accepted）。→ 接入点 `auth`/register service。
3. **不在每次登录重灌**：自动入群**只在注册时触发**，登录不重加——否则「退群」永远无效。这是「可退群」语义的前提（见 §十一·待拍板）。

## 六、后端 API 增量

`/v1/messages` 下新增（薄路由 → `MessagingService` → `ChatRepository`，权限在 service 层）：

| 端点 | 用途 | 备注 |
|---|---|---|
| `GET /chats/{id}/members` ✅ | 群成员列表（→ 前端 roster：解析发送者名 + 信息面板） | 仅成员可读（非成员 404，IDOR） |
| `POST /chats/{id}/leave` ✅ | 退群 | service 删 `chat_members` 行；单聊 422（不可退）；系统群无群主，最后一人退群不特判 |
| `PATCH /chats/{id}/membership` ✅ | 静音 `muted` / 置顶 `pinned`（每人会话态） | 部分更新（省略字段不变），返回更新后的 `ChatSummary` |
| `DELETE /chats/{id}/members/{uid}` ✅ | admin 踢人（发系统提示） | 平台 admin 门控（`AdminUser`）；单聊 422、非成员 404、不能踢管理员 403 |
| `POST /chats/{id}/members/{uid}/mute` ✅ | admin 禁言 / 解禁（toggle `{muted}`） | 同上门控；被禁言者发消息 403。原设计 `POST .../ban` 改名 `mute` 做开关（禁/解一端点） |
| `POST /chats/{id}/announce` ✅ | admin 公告（system_card 居中胶囊） | 同上门控；NULL sender=official，fan-out 全员 |

Repo 侧补 `add_member` / `remove_member` / `add_members_bulk`（回填用）/ `list_members`（已有）。

**Schema**：`ChatSummary` 已含 `type/title/avatar_url/pinned/muted` 足够；新增 `ChatMembersResponse`（`data: list[ChatParticipant]`）。改 schema 后按 `api.mdc`：`dump_openapi.py` → `pnpm gen:api`。

## 七、实时与规模

- 复用进程内 hub：群发 → `list_members` → fan-out 给全体在线连接。
- **全员一个大群是 fan-out 最坏情况**（1 条 × N 成员 × 每人多连接）。内测**几十～低百人**单进程可接受；队列有背压丢弃 + 重连按 `last_read_message_id` 补偿，掉帧可恢复。
- **规模上限/触发**：成员数上千、或上多 worker 时，`ChatEventPublisher` seam 换 Redis/NATS（`消息IM.md` §四已留）。届时 `send_message` 每次 `list_members` 取 fan-out 目标也需优化（缓存/分片）。**本设计不提前做**，仅留缝。

## 九、隐私 / 反滥用 / 审核

| 维度 | 处理 |
|---|---|
| 成员互相可见 | 群内通过 roster 暴露成员显示名——内测社区可接受；注意 `discoverable=false` 的隐身**不掩盖已在群内的身份**（产品需知会用户） |
| 限流 | 发消息复用按用户限流（`conversation/rate_limit.py`，已接在 `send_chat_message`） |
| 拉黑 | 现 `is_blocked_between` 仅 gate 单聊；**群内被拉黑者消息 MVP 仍可见**（客户端按 blocklist 过滤为后续可选项），本设计不做 |
| 审核 ✅ | 平台 admin 踢人 + 禁言（`muted_by_admin`，与用户自静音 `muted` 区分）；管理员互相豁免（不能被踢/禁） |
| 系统提示 ✅ | **公告 + 踢人**用 `content_type='system_card'`（NULL sender=official）居中胶囊；入群/退群/禁言**不发**全群提示（降噪；禁言走被禁言者发言时 403） |

## 十二、产品决策（✅ 已确认，按默认拍板）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | **可退群 vs 强制常驻** | ✅ **可退 + 可静音**，自动入群只在注册时触发（退群不被重灌）。退群/静音 UI 属 Stage 2 |
| 2 | 群名 / 头像 | ✅ `title="AgentCore 内测群"`，头像后配 |
| 3 | 审核是否进 MVP | ✅ **否**——MVP 靠信任 + 全局限流；踢人/禁言放 Stage 3 |
| 4 | 富消息 / @AI 是否进 MVP | ✅ **否**——MVP 纯文本人群；富消息/@AI 放 Stage 4 |
| 5 | 自动入群是否默认置顶 | ✅ **是**（`pinned=true`，用户可取消）——已落地（`add_member(pinned=True)` + pinned-first 排序） |
| 6 | **治理权来源**（Stage 3） | ✅ **平台 admin（`users.role='admin'`，即创始团队）**，非群级 `chat_members.role`——内测群无群主、零迁移、前端 `user.role==='admin'` 免扩 schema 即可门控；群级 role 列保留给 Stage 4 用户自建群。被否：内测群指定群主/群管（多一次成员迁移 + 前端需新增 role 字段才能门控） |

| 8 | **系统提示范围**（Stage 3） | ✅ 只发**公告 + 踢人**；入群/退群/禁言**不发**全群 system_card（全员群每次注册自动入群会刷屏；禁言改为发言时 403 toast）。原 `POST .../ban` 改名 `POST .../mute` 做 toggle |
