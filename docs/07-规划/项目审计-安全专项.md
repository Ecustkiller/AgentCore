## 一、范围与边界

**套餐**：后端为主的安全体检——认证授权 / 多租隔离(IDOR) / 密钥与机密 / 注入 / 沙箱与命令执行 / SSRF / 速率与滥用。

**锚定**：当前 main 工作树；多 Agent 并行 WIP 区标注「⚠️ WIP」。自检用 Read，不与 git 对账。

**不在本轮**（避免发散）：

- 渗透式攻击实操（本轮仅**静态阅读 + 逻辑推演**，不真打）。
- 提示注入（prompt injection）对抗——属 AI 安全，另轮。
- 前端 XSS 深挖（Electron 桌面 + 纯 web mobile/admin），单独轮。
- 依赖 CVE 全量扫描（仅顺手记**显眼**的老版本/已知问题）。

### 七之二 · 共性主题

1. **「守卫已建、未全覆盖」**——SEC-006（SSRF 守卫漏接 git）、SEC-002（owner 作用域可选）、SEC-003（CSRF 塌缩到 CORS）：防护机制都已就位，缺口是个别路径漏接 / 依赖调用方约定而非结构强制。修复多为「复用既有守卫 + 让其成为结构默认」，成本低。

3. **纯防御纵深**——SEC-001 / 004 / 007：今日影响低。SEC-001/004 已低成本补上（脱敏正则扩前缀、登录跑 dummy verify）；SEC-007（DNS rebinding）需 pinned-IP transport，非低成本→另立项。

### 七之三 · 处置建议（优先级）

- **3 条 P2 全部已修**（都是小改、复用既有机制）：✅ **SEC-006**（`clone_repo` 前过 `classify_url` + 4 回归测试）；✅ **SEC-003**（CSRF 仅在无 access cookie 时才豁免 bearer + 2 回归测试）；✅ **SEC-005**（方案 A 务实硬守卫：非 debug 开 cloud 但无 `code_execute_cloud_unsafe_ack` 即拒启动 + docstring 据实改 + 4 回归测试；真沙箱另立项）。

- 各修复按 `dev-process`：契约级**真沙箱**（容器/gVisor/nsjail）与 SEC-002/SEC-007 作为独立项另起；本轮所有已修项均为纯加固 / 复用既有守卫的小改，已直接落地。
