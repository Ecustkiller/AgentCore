# 手机端落地设计（桌面端减能力层 · 各端全新建实现 + 协议一致性巡检 · 为 AI 开发设计）🗂️

> **定位**：把产品从「桌面唯一客户端」扩展到**手机端**。产品心智：**手机端 = 桌面端 − 手机物理做不到的能力层**（黑名单减法，非白名单新设计）。
>
> **实现策略（关键）**：**各端全新建实现**——桌面与手机各自拥有完整 stores / services / 协议 fold / 组件，**零共享业务实现**；唯一共享的是**协议一致性规范**（测试向量 / golden / 事件类型，非实现）+ 设计 token。代码层不是「共享核」，而是「**双实现 + 漂移巡检**」。
>
> **为何这样**：见 §二（全新建在 AI 开发下的真实收益）+ §六（协议巡检如何兜住双实现的唯一硬伤 drift）。
>
> **关键约束 · 项目主要由 AI 开发**：第一判据是「最适合多 Agent 并行 + 有界上下文的 AI 开发」，非单纯工程审美。
>
> **状态**：🗂️ 提案，**部分已落地**。P0 巡检地基（pnpm workspace + `packages/` 三包 + conformance harness）已建起；**P1 手机端 web 骨架的客户端功能已基本落地**（聊天/流式、多 Agent 团队视图、进度/审批、停止生成、断线重连续看、结构化挂起恢复、会话管理+搜索、云端文件、成本呈现、历史上翻分页——逐项实现位置见 §十）；**安全存储已落地**（OS Keychain/Keystore 原生适配器 + 注入），**Capacitor 8 壳与 Android 工程已 scaffold**；**后端推送已落地**（FCM 下发 + `/v1/devices` 端点 + durable pause 触发），**移动端推送接入代码已落地**（待 Firebase 项目 + 真机验证）；后端 golden 导出口已落地（`conformance/export.py`，oracle 投影 + 一键重导）；P2 余项（iOS 工程需 macOS、商店打包/签名）、从真实 turn pipeline 抓向量仍 ⏳。全部落地后现状回写 [`前端技术与架构.md`](/docs/04-前端/前端技术与架构.md) §七/§九/§十、退役本稿。本目录仅 `07-规划`。

## 二、为何「全新建实现 + 巡检」而非「共享实现核」

**选定 = 各端全新建**（原 C 的形态），配协议一致性巡检消除 C 唯一硬伤（drift）。

**全新建在 AI 开发下的真实收益：**

- **爆炸半径收束**：手机件全在 `apps/mobile`，agent 改手机**物理上动不了**桌面。共享核相反——一改可能两端都炸。
- **上下文局部**：agent 载一个手机纵向切片即可干活，不追进共享包、不理解桌面怎么用。
- **零协调 / 最大并行**：无「共享实现核」这个序列化协调点，两端 agent 几乎零碰撞。
- **重写成本 AI 付得起**：传统「别重复」主要靠「人写码贵」，AI 削弱了这条。

drift（原 B 靠零重复换来的优势）由 §六 巡检找回。

> **被否决 · 共享实现核（原 B）**：共享 = 耦合 = 爆炸半径跨两 app；对有界上下文 AI，**跨 app blast radius 比 drift 更难控**；共享核还是并行 agent 的协调点（序列化）。
>
> **被否决 · 一棵树降级（原 A）**：分支税 + 手机沦为压扁的桌面。
>
> **诚实代价**：选二**不消除**双实现维护（契约一变仍改两套 fold）；巡检 harness 成本 ≈ 直接共享那层薄 fold（原 B）的成本，且还多付双实现。**所以选二的理由必须是上述收益（爆炸半径 / 上下文局部 / 独立演进），不能是省事。**

## 六、三支柱漂移巡检（选二的安全网 · 核心机制）

**核心洞察**：协议层是纯函数 `fold(events[]) → ProjectedTurn`。drift = 两端 fold 对同一事件序列产出不同 state，**机械可测**，前提 = 共享向量 + 中立裁判。思路：**后端做输入（向量）与期望输出（oracle）的单一源，两端都对后端对帐。**

### 支柱 1 · 后端权威向量 + golden oracle（共享测试向量）

- **向量** = 后端导出的**真实 SSE 事件序列**（代表性场景：单聊回合 / 多 Agent `delegate` / 审批 pause-resume / 错误 / 跨回合）。✅ 已落地：`conformance/export.py` 经 oracle（`projection.py`）投影导出向量 + golden；向量目前由真实 event builder（`vectors.py`）策划，⏳ 从 turn pipeline / [`turn_journal`](/docs/03-AI核心/执行引擎架构设计.md) 抓真实运行序列仍待建。
- **golden** = 后端对每条向量投影出的**期望规范化 state**。后端知道语义真相 → 它当裁判。这解决「两端不一致时谁对」：都对 oracle，不是互相对。
- **schema** `ProjectedTurn{ messages, runs(树), status, pendingInteraction, cost }`，平台无关、可序列化。每端实现 `fold → ProjectedTurn` 暴露测试快照（内部 store 形状可不同）。
- 放 `packages/protocol-conformance/`。**共享的是规范(spec)、不是实现**——和「实现各写」不冲突（多实现共用一套一致性测试是经典模式，如浏览器 WPT）。

> **落地现状 · ✅ 两端已钉同一 golden**：后端 oracle（[`projection.py`](/apps/server/agentcore/conformance/projection.py)）+ **13 条向量**导出 golden（单聊 文本/工具/错误/citations、多 Agent delegate/worker 工具/辩论 stance·round/定向唤回续写/多批 delegate、审批与 plan_review 挂起-放行）；**手机** fold（生产同款）+ **桌面** `conformanceFold` 适配器各 13/13 过 conformance（注入一字符漂移即红、`exit 1`，证「够响」）。
> **桌面适配器的真实性边界**：团队图（runs 树 / 进度 / 状态 / 挂起——最易漂、最难肉眼核的部分）**复用桌面真实的 `projectExecution`**（非拷贝）；单聊 **process 时间线**（思考·正文·工具 coalesce）已抽出 [`@/lib/processTimeline`](/apps/desktop/src/renderer/lib/processTimeline.ts)，**生产渲染（`conversation` store）与 conformance 适配器共用同一组纯函数**（杜绝两份 coalesce 规则漂移，且顺带修正了前端 `display:null` 与后端 oracle「无值不写」的旧形状差异）；仅回合级薄标量（正文 / 思考字串 / 引用 / 挂起门 / 总账）在适配器内直接累计以拼出 `ProjectedTurn`。`ProjectedTurn` 类型**已 import 共享 [`@agentcore/protocol-conformance`](/packages/protocol-conformance)**（桌面已入 workspace，经 `./projectedTurn` 纯类型子入口避免拽入 harness 的 node 依赖）；真正的契约仍是被对账的 golden JSON。

### 支柱 2 · 共享类型 + 穷尽性（契约一致性检查）

- 两端 import **同一套**事件类型：单一源在 [`@agentcore/contract-types`](/packages/contract-types) 的 `SSEEventType` 判别联合（约 30 个类型）；桌面 [`types/events.ts`](/apps/desktop/src/renderer/types/events.ts) 已改为 `export type *` 透传本包 + 仅留 4 个桌面独有富渲染类型。⏳ 理想态仍是后端 schema 生成。
- 每端 fold 用判别联合 `switch` + `assertNever` 兜底。后端加一个事件类型 → 重生成 → 两端 fold **编译失败**直到处理。
- 最便宜最响的绊线：**编译错 > 红测 > 静默**。

### 支柱 3 · AI 可操作层（让 AI 拓两端偏差）

- 一条命令 `pnpm conformance` 跑两端：`pnpm -r run conformance`（手机 tsx runner）+ `pnpm -C apps/desktop run conformance`（桌面 vitest）——桌面经自身 vitest 串联（已入 workspace），单一红绿；CI 门禁。
- 失败输出**为 AI 设计**：打 `ProjectedTurn` diff（golden vs 各端 actual），精确指到分叉的字段 / run / status——agent 不用加载另一端就能定位。
- **巡检 agent 任务**：跑 conformance，红了就把落后那端对齐到 golden（oracle 已指明谁错 → agent 能自主修）。
- **rule**（[`protocol-conformance.mdc`](/.cursor/rules/protocol-conformance.mdc)）：动了一端协议 fold → 必跑 conformance；后端契约变了要更新向量；CI 卡。并行 agent 被强制过闸。

### 让漂移结构上不可能静默

后端是震中：一处拥有（a）事件类型（b）向量（c）golden。契约一变 → 两端编译错（类型）+ 红测（向量 / golden）→ **drift 永远是「响」的**。这正是项目评估体系「黄金集 + harness + CI」的同款哲学（见 [`后端架构.md §五 评估体系`](/docs/02-架构/后端架构.md)）。

## 九、传输与打包

| 路线 | 结论 |
|---|---|
| **web SPA → Capacitor 套壳** | **选定**：同一套 web 代码打 iOS/Android 原生包，拿到上架 + 原生推送（FCM/APNs），近零重写 |
| 纯响应式 web（手机浏览器） | P1 验证可用；但**无可靠原生推送**（iOS PWA 推送残缺），不能作终态 |
| React Native | **否决**：UI 要重写、用不了 DOM 渲染叶子；与「web→Capacitor」目标冲突 |

## 十二、风险与边界

| 风险 | 缓解 |
|---|---|
| 未覆盖的 drift（向量没覆盖到的边角） | 后端真实场景导出 + 发现协议 bug 就加一条复现向量（棘轮） |

| 巡检 harness 成本 ≈ 共享薄核 | 已知（见 §二诚实代价）；选二理由是别的收益、非省事 |
| 设计两端漂移 | token 共享兜底（[`color-tokens.mdc`](/.cursor/rules/color-tokens.mdc)）；**手机端仅浅色、暂不做暗色**（无 `.dark`，少一个漂移面） |
| 范围蔓延（手机想做本地能力） | 守「减法」边界：手机不实现即没有；要做须重新决策 |
