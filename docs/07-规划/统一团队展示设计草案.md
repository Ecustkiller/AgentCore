# 统一团队展示设计草案（内嵌协作图）🗂️

> **定位**：前端「多 Agent 团队展示」收口草案。回答「今天团队信息散在三个面——对话内 `TaskCard` / 右侧 `DetailPanel` / 全屏协作图——彼此抢戏，且历史回合的团队视图会丢」这一问题，统一到**一张内嵌进 AI 回复消息的协作图**。代码未落地，落地前以本文为蓝图；落地后取代 [`前端UX目标态.md`](前端UX目标态.md) §一/§三/§五 与 [`前端UX设计.md`](../04-前端/前端UX设计.md) §十 的旧模型，成本归宿更新 [`前端成本呈现.md`](../04-前端/前端成本呈现.md) §7.3A/B。

---

## 一、现状：一份数据，三个抢戏的面

| 面 | 在哪 | 独占、图装不下的职责 | 代码 |
|---|---|---|---|
| `TaskCard` | 对话流末尾**单例**（只跟最新回合） | 状态信号 + 救火（停止/重试/调整/放弃 + 部分失败提示）+ **回合成本合计** | `components/chat/TaskCard.tsx` |
| `DetailPanel` | 会话右侧可拖拽栏 | run-detail **下钻全文**（输出/思考/工具/错误/资源）+ **团队工资单** + 进度/协作图 tab | `components/chat/DetailPanel.tsx`、`detail/RunDetailBody.tsx`、`detail/AgentRoster.tsx` |
| `GraphView` 全屏 overlay | `graphOpen` 门控 | DAG 大画布 + **回放 Timeline** + 节点详情侧栏 | `components/graph/GraphView.tsx`、`GraphOverlay.tsx` |

**关键事实（已勘明）**：

- 三面都读同一个 `useProjectedExecution()`（`stores/execution.ts`）——**一份数据三种画法**，统一不会有数据打架。
- 执行 store 同时只存**一个** execution，回合间 `clearExecution`——**历史回合无团队视图，刷新即丢**（`Message` 只持久化 content/reasoning/citations/cost，**不带 runs**）。
- **节点根本不显钱**：`GraphView` 组装 flowNodes 时喂了 model/durationMs/realTokens，**唯独没喂 `run.cost`**；钱只活在 `TaskCard`（回合合计 §7.3A）+ `AgentRoster`（工资单 §7.3B）。
- 图本就支持内嵌：`GraphView` 的 `embedded` prop（已用于面板 task-graph tab，丢 Timeline + 侧栏、节点点击交给 `onNodeSelect`）——**内嵌不是从零造**。

## 二、目标形态：内嵌协作图 = 多 Agent 回合的主团队界面

「只留图」的可落地解读 = **以内嵌图为枢纽，把另外两面的必要职责折进图，只删冗余导航**（不是真把能力删掉）。

| 旧 | 新去向 |
|---|---|
| `TaskCard` 卡片 | 折进内嵌图**边框**：图顶状态条「状态 · N agents · M/M · 用时 · ¥合计」 |
| `TaskCard` 救火行 + 部分失败提示 | 状态条下挂救火行（失败/停止时出现，**绝不藏错误**） |
| `TaskCard` 双入口（图标进全屏 / 查看团队详情进面板） | 删——图已在消息里 |
| `AgentRoster` 工资单（合计 + 占比条） | 节点补 `run.cost` **直接显钱**；回合合计进状态条 |
| `DetailPanel` 进度 tab | 删——被图顶状态条取代 |
| `DetailPanel` 协作图 tab | 删——图已在消息里 |
| `DetailPanel` run-detail tab | **保留**：面板降级为**纯下钻目标**，点节点 → 右侧滑出 `RunDetailBody`（决定 A） |
| 全屏 `GraphOverlay`（常驻第三面） | 删常驻入口；改为内嵌图右上角「最大化 → 临时全屏」（含回放 Timeline + 大画布） |
| 单 Agent 回合 | **不变**：纯气泡 + 淡成本 caption，不出图（零噪音） |

**一句话**：屏上从「卡片 + 右栏 + 全屏」三面，收成「**消息里的图（主）** + **右侧被动下钻**（点节点才出） + **临时全屏**（要大图/回放才进）」。

## 三、数据前提：连历史（决定 2）

要让**每条 AI 消息内嵌它那次的图、刷新后仍在**，需补 per-message runs：

- **后端**：回合结束（`message_end`）把该回合的 plan + runs 快照按消息持久化（git 里 `add_messages_runs_column` 迁移像已在铺这条路，落地前确认）。
- **API**：`GET /conversations/{id}/messages` 随消息下发 runs 快照。
- **前端**：`Message` 增 `runs` 字段；按消息重建投影——`projectExecution(plan, frames, status)` 是**纯函数，直接复用**：live 回合用实时 store、历史回合用消息快照喂同一个 fold，**两条路不分叉**（呼应目标态 §一「实时 `byMessage` 优先，回落 `message.runs` 快照」）。

## 四、落地分层

> P0–P2 用户已确认**全做**；分层只定施工顺序，不是范围裁剪。

| 阶段 | 内容 | 产出 |
|---|---|---|
| **P0 内嵌图（live）** | 多 Agent 回合的助手消息位渲入图块；状态条折进图边框（吃掉 `TaskCard`）；节点补 ¥；点节点 → 面板 run-detail（面板退成纯下钻）；删 `TaskCard` 双入口 | 当前回合「图即主界面」成立 |
| **P1 临时全屏** | 内嵌图右上「最大化」→ 临时全屏（复用现 `GraphView` 非 embedded 形态：Timeline 回放 + `NodeDetail` 大画布）；删常驻 `GraphOverlay` 入口 | 大图/回放不丢 |
| **P2 连历史** | 后端按消息持久化 runs + API 下发 + 前端 `Message.runs` + 按消息投影；历史/刷新后每条多 Agent 消息内嵌自己的图 | 历史团队视图成立 |
| **P3 收尾** | 删 `TaskCard.tsx` / `GraphOverlay.tsx` / `ProgressTab` / `AgentRoster`（职责已迁）；成本 §7.3A/B 文档同步；目标态/现状旧模型替换为单指针 | 三面收一面 |

## 五、性能与边界

| 项 | 处理 |
|---|---|
| 一页多张内嵌图（历史长对话） | 默认渲**静态快照**（轻量 DOM/SVG，不挂 ReactFlow），仅当前/展开那张挂交互式 ReactFlow；目标态 §五「≤50 节点 ≥60fps」是**单图**预算，靠此守住 |
| 896px 主列偏窄 | 内嵌图块用对话内容宽（`max-w-4xl` 内）；复杂 DAG 一键临时全屏；节点信息密度沿用现 `AgentNode` |
| 下钻长文挤压对话 | 走 A：详情在右侧宽栏（`RunDetailBody` 现成），不顶对话流 |
| 回放 Timeline | 内嵌块不放（保持简报感），收进临时全屏 |
| 失败/停止可操作性 | **绝不藏**：状态条转红 + 下挂救火行，与现 `TaskCard` 同等可操作 |

## 六、关键决策（已定）

1. **下钻走 A**：右侧 `DetailPanel` 降级为纯 run-detail 下钻目标，删进度/协作图 tab。
2. **连历史**：按消息持久化 runs + 按消息重建投影，历史/刷新后每条多 Agent 消息内嵌自己的图。
3. **删常驻全屏 overlay，保留内嵌图「临时全屏（含回放 Timeline + 大画布）」**。
4. **先落文档（本文）再改码**。
5. **单 Agent 回合不变**：纯气泡 + 淡成本 caption，不出图。

## 七、顺路优化清单（开发期可积极重构，无需兼容层）

> 借「三面收一面」的爆破半径顺手清掉的复杂度。分级：**必做**（统一的内在要求，不做即半成品/有 bug）/ **建议**（半径内、显著降复杂度）/ **可选**（相邻、中低价值）。

**必做**

1. **图布局状态：全局单例 → 按图 id keyed**（`stores/graph.ts`）：`positions`/`edges` 现为**全局单例**（假设同时只一张图）；连历史后一页多张内嵌图会互相覆盖 → 改成**按图 id keyed 的实例化状态**（live = execution id、内嵌历史 = message id），`layoutKind` 用户偏好仍留全局。**keyed 是 global 的超集**：global 单例只能存一张图，keyed 能存 N 张；未来「跨会话/项目图」只是再加一个 key（如 folder id），无需回炉。**P2 必做（正确性前提，且天然向后兼容跨会话图）**。
2. **删 `graphOpen` 全局态 + `GraphOverlay`**（`stores/ui.ts`、`pages/ConversationPage.tsx`）：`graphOpen` 只是「overlay 是否开」的模态布尔，临时全屏改内嵌图局部状态/轻量 portal，清理 `openGraph`/`closeGraph` 的 9 处调用。未来「跨会话图」宜做成**独立路由/页面**（持久项目产物，非 per-turn 弹层），不复用这个模态标志——故删它不损未来。**P1**。
3. **`DetailPanel` 瘦身**（`stores/detailPanel.ts`，240 行）：删 `task-progress`/`task-graph` tab kind、`PROGRESS_TAB`/`GRAPH_TAB`、`openProgress`/`openGraphTab`、`autoOpenForPlan` 的 progress 逻辑；保留多 `run-detail` 并存对比（目标态已定「否决每次覆盖」）。**P0**。

**建议（顺手）**

4. **`GraphView` 拆 core/variants**（490 行）：抽纯展示 `<CollaborationGraph>`（nodes/edges/layout/点击）+ 内嵌壳（状态条 + 临时全屏钮）+ 全屏壳（`Timeline` + `NodeDetail` + 全右键菜单）；现有 `embedded` prop 那条缝即此拆分。**P1**。
5. **focus 模型收一**（`stores/execution.ts`）：`focusedRunId` + `focusedAgentId` 双字段是「图与卡/面板异屏桥接」的产物；统一后收成单一 `selectedRunId`（runless agent 高亮随 `AgentRoster` 于 P3 删一起清）。
6. **去重「找最后一条 assistant 的 cost」**：`TaskCard` 与 `AgentRoster` 各写了一遍**同样**的倒序扫描 `messages`；统一后只剩状态条一处，抽成 selector。`lib/cost.ts`（`splitPayroll`/`resolveTurnCost`）本身干净，**保留复用**（状态条总额 + 节点 ¥）。

**可选（相邻，中低）**

7. `messageFocus`（conversation store：图 synthesis 节点 → 滚到本回合最终答案）：图已在消息里，桥可能冗余，评估删。
8. `AgentNode` 补 ¥ 后，hover tooltip 顺手并入 ¥，避免信息两处。

**明确不碰（防 scope creep）**：后端 runtime/调度/记账（除 P2 必需的「按消息持久化 runs + API 下发」）；`lib/elk-layout.ts` / `StepEdge` 粒子边 / `AgentNode` 视觉（能用不动）；已被并行 worktree 删除的 `CheckpointCard`/`TeamPreviewCard`/`resolveCheckpoint` 等（非本职）。
