## 一、目标与定位

- **目标**：一支 30 秒、可投官网首页 / 社媒的产品宣传片，让人 10 秒内 get 到 AgentCore 是什么、强在哪。
- **内容主线**：紧扣产品心智——**「真正的 Agent 团队协作」**，而非「单 Agent + 子任务派发」（见 [`/docs/01-产品/产品定位与品牌.md`](/docs/01-产品/产品定位与品牌.md)）。让观众**亲眼看到一支 Agent 团队实时并行协作**——这是全片的钩子，也是对标 Cursor / Claude 的差异点。
- **硬约束**：画面必须与真实产品**像素完全一致**。不接受 AI 文生图 / 手绘 mockup（给不了一致性），**只能渲染真实 UI**。
- **输出规格**：1920×1080、16:9、30s、30fps、**仅横屏（不出竖屏）**；**亮色主题** + **桌面端外壳**（含应用 `TitleBar`）。字幕由本片产出，BGM 用户后续自加。

## 二、为什么选「全 Remotion 复用真实组件」（全 B）

两条能做到「真实像素」的路径，取舍如下：

| 方案 | 本质 | 像素一致 | 卡点控制 | 改版成本 | 真实性背书 |
|---|---|---|---|---|---|
| A · 截真机（Playwright） | 脚本驱动真实应用录屏 / 逐帧截图 | ★ 天然 100% | 弱：实时录，难做帧级定格 / 缓动 | 高：改一次常要重跑 + 重录 + 重剪 | ★ 最硬（就是产品本体） |
| **B · Remotion 复用真组件** ✅ | React 视频框架 `import` 真组件 + 同套 token 逐帧渲染成 MP4 | 同源（chrome 需忠实重建） | ★ 逐帧时间轴，卡点 / 缓动 / 变速随意 | ★ 改个 prop 重渲，确定性输出 | 真组件，但属「复刻」 |

**决策 ＝ 全 B**。理由：宣传片必然反复改版（换文案 / 换主题 / 出竖屏 / 出英文），且 30s 的生死在「帧级卡点」；B 在这两点压倒性占优，并且全程 100% 代码、一条管线、版本可控。B 的唯一代价（忠实重建 chrome + 一次像素核对）已在落地时消除。

> 被否：**全 A**（真实性最硬，但帧级卡点难、改版贵、需额外做 mock SSE 演出 harness + 另开剪辑器）；**A 截图仅降级为「像素标尺」**（落地时用来比对，不进成片）。

## 三、全 B 落地的 5 个关键点

1. **共享同一套样式层（根基）**：Remotion 工程 `@import` 真实 [`apps/desktop/src/renderer/styles/globals.css`](/apps/desktop/src/renderer/styles/globals.css)（Tailwind v4 + `@xyflow/react` 样式 + OKLCH `:root`/`.dark` token，品牌色 hue 255）+ 镜像 Tailwind 配置。颜色 / 间距 / 圆角 / 阴影全部同源。
2. **叶子组件直接复用**：`AgentNode` / `EndpointNode` / `StepEdge` / 消息气泡 / `ConversationItem` / 各徽章都是 `data`/props 驱动的纯展示件，像素从真组件来（§四清单）。
3. **chrome 重「搭脚手架」而非「启整页」**：`GraphView` / `Sidebar` / `ChatView` 这些容器读了一堆 zustand store / react-query / 路由 / IPC（`window.fsApi`、`window.windowApi`），直接搬整页会被依赖绊住。做法：**外层 flex 脚手架（几个 Tailwind `div`）按原样重述** + **内容填真叶子组件**——脚手架除 border/bg token 外无独有像素，重述零风险。
4. **ELK 布局预计算成常量**：[`computeLayout`](/apps/desktop/src/renderer/lib/elk-layout.ts) 是异步的；demo 数据固定，故把节点坐标算一次写成常量（或用 `delayRender` 等 ELK 完成）→ 渲染零异步、完全确定。
5. **运动从「帧钟」重驱（唯一真成本）**：产品动画是 CSS 壁钟动画（节点入场 `graph-node-enter`、running `animate-pulse`、完成 `graph-node-flash`、`StepEdge` 粒子流、打字光标 `▋`），在 Remotion 里不能靠壁钟（不跟帧同步、渲染不确定）。要改成由 `useCurrentFrame()` 驱动：每节点按帧错峰入场、`status` 按帧翻转、粒子位置 / 流式文字按帧切片。**复用组件的「长相」，重编排它的「运动」**——这正是换来帧级卡点的代价。

**唯一会「漂移」的点 ＝ 字体**：产品用系统字体（`-apple-system … Noto Sans SC`），无头渲染时机器字体不同会致字形差异。解法：**内嵌固定 webfont**（把 Noto Sans SC / Inter 打进工程，`delayRender` 等字体加载完再渲），每次渲染像素相同。

## 五、30 秒分镜（横屏，真实产品演示）

核心钩子＝**「一支真正并行协作的团队，实时可见」**。11–20s 是全片灵魂，而那些动画（节点级联入场、running 脉冲、粒子流入边、完成绿闪）**产品里本来就有**，全 B 只是把它们在 30s 时间轴上重新编排。

> 全程基线：**亮色主题** + **桌面端外壳**（含应用 `TitleBar` + 侧栏）；BGM 用户后续自加。
>
> **字幕叙事线**＝全片不做功能描述，而是用品牌核心理念「协作，是更高级的智能」的完整论证链作为字幕：哲学开题（人类文明靠协作）→ 类比 AI → 画面论证（团队并行跑起来）→ 品牌锁定。**字幕讲"为什么"，画面演"是什么"**。

| 时间 | 画面（全真实 UI） | 复用件 | 字幕（「协作智能」叙事线） |
|---|---|---|---|
| 0–3s | 应用淡入：侧栏 + 干净对话页，空状态「今天想解决什么问题？」 | `Sidebar` + `ChatView` 空态 | 人类文明的突破，从来不靠某一个人 |
| 3–7s | 输入框逐字打字「做个完整的产品规划，正反两面论证后定方案」→ 回车 | `MessageInput` + 用户气泡 | 而是靠分工与协作 |
| 7–11s | `run_plan` → 8 节点 4 层 DAG 级联入场：L1 调研×3 → L2 辩论正反方 → L3 策略定稿 → L4 产出×2；委派虚线 + depends_on 实线 + 辩论修订点线同时可见 | `EndpointNode` + `AgentNode`(pending) + `StepEdge`(delegate/depends/revision) | AI 也一样 |
| 11–20s | **高潮 4 层波次执行**（见下方详细编排）：L1 并行→L2 辩论对射→L3 裁决→L4 再并行 | `AgentNode`(running/completed) + `StepEdge`(粒子双向流) | 单个模型有天花板，协作没有 |
| 20–24s | CEO 汇聚点点亮，最终答案流式写入对话气泡 | `EndpointNode`(captain) + `MessageBubble`(流式) | 结果，自动汇聚为一个答案 |
| 24–27s | 快切 3 张真实场景图：并行扇出 / 辩论正反 / 嵌套小队 | `ScenarioGraph` × 3 | 并行 · 辩论 · 嵌套，一张图 |
| 27–30s | Logo + slogan（**无 CTA 落点**） | 品牌件 | AgentCore · 协作，是更高级的智能 |

### Demo DAG 结构（8 Worker 节点，4 层）

```
Layer 1（并行调研）       Layer 2（辩论对抗）       Layer 3（裁决）    Layer 4（并行产出）

  [用户调研] ─┐
              ├─→ [激进方案·正] ←─→ [稳健方案·反] ─→ [策略定稿] ─┬→ [产品需求]
  [竞品分析] ─┤         ↕ 辩论修订                               └→ [技术方案]
              │
  [技术趋势] ─┘
```

- 「激进方案」depends_on: [用户调研, 竞品分析]（从痛点+竞品空白出发）
- 「稳健方案」depends_on: [竞品分析, 技术趋势]（从技术现实+竞品出发）
- 辩论正反方之间：修订点线（双向粒子流，2–3 个来回）
- 「策略定稿」depends_on: [激进方案, 稳健方案]
- 「产品需求」「技术方案」depends_on: [策略定稿]

### 11–20s 高潮段帧级节奏

| 时段 | 持续 | 画面 |
|---|---|---|
| 11–13s | 2s | L1：「用户调研」+「竞品分析」+「技术趋势」3 节点同时 running（蓝脉冲 + 流式预览） |
| 13–13.5s | 0.5s | L1 三节点 completed（绿闪）→ 粒子**交叉分流**汇入辩论节点（展示交叉依赖） |
| 13.5–16.5s | **3s** | **辩论高潮**：正反方同时 running + 修订点线**双向粒子对射**（2–3 个来回），流式预览互相引用对方论点 |
| 16.5–17s | 0.5s | 辩论结束，两节点 completed → 粒子汇入「策略定稿」 |
| 17–18.5s | 1.5s | L3：「策略定稿」running，流式写"综合正反方…" → completed |
| 18.5–19s | 0.5s | 粒子分流到两条下游实线 |
| 19–20s | 1s | L4：「产品需求」+「技术方案」同时 running → completed |

## 八、工程结构

已落地于 [`apps/promo/`](/apps/promo/)（Remotion 工程，与 `apps/desktop` 平级），结构以代码为准。核心设计接缝＝**只读复用 desktop 渲染层的组件与样式**：共享 `globals.css` + 镜像 Tailwind、内嵌字体、预计算 ELK 坐标。

**为什么这么搭（留档理由）**：desktop 升级组件 / token 时宣传片**自动同源**重渲——这正是「全 B」相对截图方案的长期优势，也是「宣传片必然反复改版」前提下选它的根因。
