## 一、问题（摘要）

ReAct 唯一终止信号是模型自报 `done`；团队有验收结构、缺验收行为。典型事故：CEO 直答引用越界（`citations.out_of_range`）、worker 自报 done 无人回读产物。

## 二、已定策略（未全落地）

1. **交付前核验是团队分内职责**，非用户额外期望。
2. **责任留 CEO，动作下放团队**——CEO 读短结论，不亲自当 QA。
3. **两层**：轻层（产出者机械自检）/ 重层（独立审查 worker，仅高风险）。

触发：**信号决定论**——轻层宽触发（含角标、硬规格）；重层严触发（可运行物 / 关键数字 / 论证型成篇交付）。品味走 `ask_user`，不进审查。

## 三、未落地硬点 🗂️

| 硬点 | 说明 |
|---|---|
| 决定论触发 vs 现状 opt-in | `contract` 仍靠 CEO 在 `delegate` 时声明；需按产物信号自动注入校验 |
| 重层审查波次 | `WaveScheduler` 自动追加审查尾节点（要跑/重算/换眼睛/回源对照） |
| 分诊员 | 代码扫不出机械信号时，廉价 LLM 判轻/重/品味 |
| 核验呈现 | 审查节点可见、发现修正如实说、通过安静（§六 产品呈现） |
| 并行扇出拓扑 | 多 worker 并行时逐个核 vs 核拼装整体 |

## 四、启动触发

交付质量成为内测痛点；或评估体系量化「未核验缺陷率」显著。
