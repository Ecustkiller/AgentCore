2. **多模型执行地基**（OpenAI 兼容 + 路由）：
   - [`llm/openai_compatible.py`](/apps/server/agentcore/llm/openai_compatible.py) —— 通用 OpenAI 兼容 provider：**只发标准字段**（model/messages/stream/temperature/max_tokens/tools），不发 DeepSeek 特有 `thinking`/`reasoning_effort`（别家网关会 400）；usage 用标准 OpenAI 键、cache 拆分缺失记 0；带 `probe()` 连通测试。
   - [`llm/router.py`](/apps/server/agentcore/llm/router.py) —— `ProviderRouter`：按 `provider/model` 前缀分发，无前缀/未注册前缀回退默认（DeepSeek），模型名原样透传。本身实现 `LLMProvider`，可直接当回合 `llm`；`close()` 统一回收默认 + 所有厂商 client。
   - [`config/llm.py`](/apps/server/agentcore/config/llm.py) —— kimi/zhipu/doubao 三家 `*_api_key` + `*_base_url`；空 key = 不注册（路由回退 DeepSeek）。
   - [`llm/factory.py`](/apps/server/agentcore/llm/factory.py) —— `build_router()` / `build_router_around(default)` 据已配 key 自动组装；空注册时等价「只有 DeepSeek」，普通对话/委派**零行为变化**。

3. **核心串连**（让每方真用不同模型）。透传链全程贯通、已核验：
   `sides[].model`（schema 暴露 + [`parse_sides`](/apps/server/agentcore/tools/builtin/debate/schema.py)）→ [`DebateSide.model`](/apps/server/agentcore/runtime/debate/types.py)（`types.py:63`）→ `debater_task` 注入 → [`RunSpec.model`](/apps/server/agentcore/runtime/runs/types.py)（`runs/types.py:172`）→ 执行器覆写 `profile.model` → 路由器按前缀分发。回合级路由器在 [`pipeline/run.py:168`](/apps/server/agentcore/runtime/pipeline/run.py) 与 [`pipeline/resume/pipeline.py:88`](/apps/server/agentcore/runtime/pipeline/resume/pipeline.py) 经 `build_router_around(build_provider(creds))` 每回合包住，`router.close()` 统一回收。

4. **6 处提示词打磨**（纯 prompt 文本/构造，无契约/事件/数据模型变更）：
   - 主持人四步 [`moderator.py`](/apps/server/agentcore/runtime/debate/moderator.py)：`_frame`（形态感知 + 首轮挑「最承重」争议点）、`_judge`（clash 抽取强化、点出「谁让步/谁被驳」、clash 上限随参与方数放宽）、`_summarize`（喂上轮小结串连贯推进线）、`_brief`（形态感知 + 去水）；形态钩子 `_frame_form_hint`/`_brief_form_hint`。
   - 辩手两处 [`debate/prompt.py`](/apps/server/agentcore/tools/builtin/debate/prompt.py)：`round_feedback` 裁剪对手发言（防多方圆桌 prompt 暴涨）+ 喂上轮裁判「你被谁驳了什么」clash 命门 + `side_system`/`debater_task` 要求具体证据/推理链。

## 三、关键运行事实 / 操作配方（代码看不出来，最省后续 AI 力气）

### 3.1 DeepSeek key 的去向（曾反复踩坑，已实锤）
- DeepSeek 走 **BYOK**：每用户自带、AES 加密存 **Postgres**，按 turn 解密注入（[`llm/byok.py`](/apps/server/agentcore/llm/byok.py)），**不在 `.env`**。
- 后端**可加载配置**里 `deepseek_api_key` 与 `encryption_key` 实测**均为空**（只有 doubao）；`billing_mode=byok`。→ 正在跑的后端若能用 DeepSeek，是靠**启动 shell 注入的临时 env**（不持久、不在 `.env`/用户/机器级环境变量）。
- 后果：**新开的 `uv run` / 离线脚本 / `dev` 账号都够不到这把 key**。BYOK 模式下全局 key **不做回退**——无用户 key 即返回 `402 LLM_KEY_REQUIRED`。
- 让离线脚本能跑：把 `DEEPSEEK_API_KEY=sk-...` 写进 `apps/server/.env`（后端热重载），脚本即可用 `build_router()` 以全局 key 当默认 provider。

### 3.2 火山方舟（豆包）接入事实
- **一把 key（`ark-...`）+ 同一 OpenAI 兼容端点**托管：豆包 / DeepSeek-V4 / 智谱 GLM / 通义千问。`base_url` 默认 `https://ark.cn-beijing.volces.com/api/v3`。
- **model 字段必须传【接入点 ID（`ep-…`）或已开通的模型 ID】**——单有 key 点不到模型（与 DeepSeek/Kimi 不同）。
- 已开通：`doubao-seed-2-1-turbo-260628`（**深度思考模型**，答一句烧 ~500 reasoning token → 多轮多辩手偏贵偏慢，心里有数）。未开通：DeepSeek-V4-pro / GLM-4.7（方舟「开通管理」可免费开通、按量计费）。Kimi 不在方舟（需单独 Moonshot key）。

### 3.3 多模型辩论的 model 串格式
- 带前缀 → 路由到厂商：`doubao/doubao-seed-2-1-turbo-260628`。
- 无前缀 → 默认 provider（DeepSeek BYOK）：`deepseek-v4-pro` / `deepseek-v4-flash`。

### 3.4 怎么真跑一场（dev 工具，走正规 `/auth/token` + `/messages`，无旁路）
1. 后端 + 桌面 dev 已在跑（`uv run python -m agentcore`，`:8000` `readyz` 200）。
2. seed dev 账号：`uv run python scripts/seed_dev_user.py`（`dev`/`devpassword`）。
3. **dev 账号需先有 BYOK DeepSeek key**（`PUT /v1/users/me/llm-key` 或桌面「设置·模型配置」），否则发回合即 `402 LLM_KEY_REQUIRED`（**实测 dev 账号当前无 key**）。
4. 真跑并抓 SSE：`uv run python scripts/probe_turn.py "<诱导 CEO 发起多模型辩论的消息>"` → 事件存 `logs/probe_<ts>.json`，可 Read 复盘。
   - 诱导消息示例：让 CEO 用辩论功能、正反两方辩「大模型谁更聪明」，正方指定 `doubao/doubao-seed-2-1-turbo-260628`、反方 `deepseek-v4-pro`（CEO 是否照传 model 串有不确定性，可在消息里明确写出各方模型）。

## 五、被否决 / 决策留档

- **OpenRouter 聚合网关** → 暂不（用户要先连国内 kimi/智谱/豆包）；但「通用 OpenAI 兼容 provider + 路由器」地基对 OpenRouter 同样适用，将来可低成本接。
- **逐家官方 SDK**（Anthropic/Google 非 OpenAI 格式、多把 key）→ 否；统一走「通用 OpenAI 兼容 provider」一套。
- **人设模拟**（同一 DeepSeek 扮多角）→ 否；走 B·真·多模型（最有说服力、真杀手级）。
- **一上来 4 方** → 否；起步 2 方（豆包turbo + 原生 DeepSeek）先打通热路径，降回归面。
- **主持人/裁判用参赛模型** → 否；保持中立强模型（DeepSeek），避免「既当裁判又当选手」。
- **竖屏社媒** → 否（用户选横屏品牌片形态）。
