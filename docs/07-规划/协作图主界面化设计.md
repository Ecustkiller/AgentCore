# 协作图主界面化：聊天 ⇄ 作战室画布双视图

> 🗂️ **状态：讨论提案（07-规划）· 已按「双视图」重定**。把多 Agent 协作图从「聊天消息里内嵌的一个组件」（`InlineTeamGraph`）升级为可与聊天**平起平坐的第二视图**——一间「作战室画布」。**不再追求「图即唯一界面 / 无模式切换」**（原稿主张已撤，理由见 §二、§八）：改为 **聊天 ⇄ 画布双视图，一份数据两种渲染，用户显式切换、默认聊天**。
>
> **三句话定调**：
> - **默认聊天（决策甲）**：新用户 / 简单问答进来就是行业标准聊天，零门槛天然成立——不再赌「画布要像聊天一样轻」的试金石。
> - **画布是作战室（形态乙-1）**：opt-in 的「单张持久画布」——一个对话一张画布，每回合 CEO 组的队**在画布上跨回合视觉累积**、可平移、LOD 折叠。**仅前端渲染、不做 worker 实体化**：团队仍每回合临时组，「同一拨人」靠 `agentIdentity` 身份延续（真持久团队 = 乙-2，已否，见 §八）。
> - **显眼入口**：聊天里一起团队，回合就地开花成内联协作图（`InlineTeamGraph` 今已如此）+ 显眼「在作战室打开」+ 顶部按对话记忆的 `聊天⇄画布` 切换。差异化靠「团队在该出现处出现、一步进作战室」，不靠强迫所有人上画布。
>
> **保留的根**：「聊天 = 协作图的退化渲染」这条洞察仍成立，但只用在**数据层**——正因单 Agent = 只有 Captain 的退化 Team、运行时统一路径（[`Agent协作模式.md §设计哲学`](/docs/03-AI核心/Agent协作模式.md)），同一份「回合 + 执行」数据才能既渲染成聊天、又渲染成画布。**两视图同源（`projectExecution` fold），不动协议 / `turn_journal` / conformance。**
>
> **范围**：本文只管**单对话**内的「聊天 ⇄ 画布」双视图。跨对话 / 工作区 / 公司级的空间画布愿景**不在本文范围**（原『公司画布』上层提案已删除、其内容不再追求）。
>
> **现状**：阶段 0 已落地、藏在 `graphPrimary` 实验开关后（默认关）：单 Agent「1 节点图」`CeoNodeCard`、端点就地读答案、全屏画布命令栏雏形（见 §九）。其余阶段未落地。
>
> → 关联现状：[`前端UX设计.md`](/docs/04-前端/前端UX设计.md)（内嵌协作图 / 状态条 / `ProcessTimeline` / 检查点卡片 / 汇聚点）、[`Agent协作模式.md §设计哲学`](/docs/03-AI核心/Agent协作模式.md)（退化特例 + 统一执行路径）、[`编排器与CEO主Agent.md §四`](/docs/03-AI核心/编排器与CEO主Agent.md)（`ask_user` / `plan_review` 检查点）、[`手机端落地设计.md`](/docs/07-规划/手机端落地设计.md)（手机简版）。
> → 关联提案：[`职责晚绑定与动态再编排设计.md`](/docs/07-规划/职责晚绑定与动态再编排设计.md)（团队按任务自适应组队，约束乙-2）、[`前端展示完善规划.md`](/docs/07-规划/前端展示完善规划.md)（前端展示缺口，与本文正交）。

## 一、为什么做（产品论证）

**差异化在界面层被稀释。** 产品定位是「真正的 Agent 团队协作」、用户心智是「你是老板、掌管一支由 AI CEO 带队的团队」（[`前端UX设计.md §核心设计理念`](/docs/04-前端/前端UX设计.md)）。但当前协作图只在多 Agent 回合内嵌出现，主界面仍是单栏聊天——而聊天是单助手产品（ChatGPT / Claude）的母语，**只要界面长得像聊天，就在暗示「我是一个聊天机器人」**。

**但「砍掉聊天、强迫所有人上画布」是过度反应。** 简单问答用聊天天经地义；逼一个问「今天几号」的人去平移画布是负体验。真正要的不是「消灭聊天」，而是**当你真的在管一支团队时，有一间像样的作战室、且它一眼可见、一步可达**。

**结论（本次重定）**：聊天保留为默认视图；协作图升级为**可切换的第二视图——作战室画布**。差异化由「团队回合就地开花 + 一步进作战室」承载，而非「把整个 UI 变成画布」。

---

## 二、核心论点（已重定）：一份数据，两种渲染

原论点「聊天是协作图的退化形态 → 一张画布连续缩放、无模式切换」**已撤**（撤因见 §八）。新论点如下。

后端统一执行路径（[`Agent协作模式.md`](/docs/03-AI核心/Agent协作模式.md)）：单 Agent = 只有 Captain 的退化 Team，单 / Team 走同一代码路径。**这条洞察仍是地基，但只用在数据层**——它保证一份「回合 + 执行（CEO+worker DAG / journal）」数据可以**同时**喂两种渲染：

| 视图 | 渲染 | 读起来像 | 默认 |
|---|---|---|---|
| **聊天模式** | 回合 → 气泡 + 内联协作图（团队回合就地开花） | 行业标准 AI 对话 | ✅ 默认 |
| **画布模式（作战室）** | 同一批回合 → 单张持久空间画布（乙-1） | 一间作战室 | opt-in |

- **单一数据源**：两视图都从 `projectExecution` fold 投影，**不开第二条数据通路**——一份数据两种渲染、否决双写漂移（守单一数据源）。
- **切换 = 换视图、不换数据**：不动协议 / `turn_journal` / conformance。
- 这既兑现「作战室」差异化，又不赌「画布必须像聊天一样轻」（试金石），还把迁移风险降到「加一个视图 + 一个开关」，**聊天永不被删**。

## 三、画布模式要吃下的职责（沿用，范围收窄到「画布视图内」）

聊天今天承担的职责，**画布模式**要在自己视图内长齐（聊天模式维持现状即可）。逐条点名 + 现状：

| # | 聊天的职责 | 画布模式要长出的能力 | 现状 |
|---|---|---|---|
| ① | 输入框 / 下达指令 | 画布常驻**老板命令栏** | ✅ 雏形（`CanvasCommandBar` 在全屏图，待升为常驻底栏） |
| ② | 读 CEO 成稿答案 | CEO 节点就地展开读全文 | ✅ 已做（`EndpointReadingDrawer` / `GraphDetailPanel`，`graphPrimary` 后） |
| ③ | 单 Agent「思考·正文·工具」时间线（`ProcessTimeline`） | 搬进 CEO 节点（退化 1 节点） | ✅ 已做（`CeoNodeCard`，§九 第一刀） |
| ④ | 多回合滚动历史 | **跨回合在持久画布上视觉累积（乙-1）** + LOD 折叠 + 小地图/相机 | 远（本次重点，见 §六 阶段 2） |
| ⑤ | 检查点 / 发问 / 审批 / 续跑 / 云端任务 卡片 | 画布上就地交互（图上指挥，§四） | 中（卡片已在，但在聊天流里、未上节点） |
| ⑥ | 长文交付物阅读 | 节点展开 + 右侧面板作阅读面 | ✅ 近（`SidePanel` / `GraphDetailPanel` 已是阅读面） |

> 多数已有雏形或已落地（①②③⑥）；真正的硬骨头是 ④（跨回合持久画布累积 + LOD）和 ⑤（图上指挥，§四）。

## 四、图上指挥：画布模式必然是可指挥的

画布模式一旦成为你管理团队的地方，检查点 / 发问 / 审批 / 救火这些**老板权力**就必须能在画布上就地行使（§三 ⑤）——一个用来「掌管团队」的视图不可能是只读的。

- **图上指挥** = 把已散落在聊天流里的老板权力（[`CheckpointCard` / 救火行 / `ResumePrompt`](/docs/04-前端/前端UX设计.md)）搬到它们真正发生的那个**节点**上。
- 这件事**无论双视图与否都值得做**，且是画布模式成为「作战室」（而非「只读看板」）的前提。
- **聊天模式维持现状**：卡片仍在消息流里就地裁决，不动。

## 五、必须由人拍板的硬抉择（已更新结论）

### 5.1 ~~零门槛 vs 重画布~~ → 已由双视图化解
双视图后此矛盾基本解除：零门槛 = **聊天默认**；画布 opt-in，可理直气壮地空间化、不必假装像气泡。简单问答即便在画布模式也退化成竖排轻卡（乙-1 自动布局）。**试金石从「方案命根」降级为「画布模式内的体验细节」。**

### 5.2 回合历史形态 → 已定 乙-1·单张持久画布
原稿倾向甲（回合脊柱 filmstrip）。**人已拍板：画布模式走乙-1·单张持久画布**（一个对话一张画布、团队跨回合视觉累积、可平移）。甲不再作为画布模式形态。注意：乙-1 = **视觉累积**——团队实体仍每回合临时组，不做 worker 实体化（区别乙-2，见 §八）。

### 5.3 长文可读性（不变）
图唯一 ≠ 万物挤进节点：长文走节点展开 / 右侧 [`SidePanel`](/docs/04-前端/前端UX设计.md)。这条是「图主界面」与「图塞满一切」的分界，必须守住。

### 5.4 手机端（不变）
图在手机上难（[`前端UX设计.md §十五`](/docs/04-前端/前端UX设计.md) 列为待定）。桌面先行；手机以聊天模式为主，画布模式桌面专属或手机极简（不强求画布），详见 [`手机端落地设计.md`](/docs/07-规划/手机端落地设计.md)。

## 六、渐进迁移分期（已重定为「加视图」，非「砍聊天」）

聊天**永不删**，只是新增画布视图 + 切换。每阶段可独立合并、可回退：

| 阶段 | 目标 | 主要动作 | 风险 |
|---|---|---|---|
| **0 · 已落地** | 画布零件就位 | `CeoNodeCard`（退化 1 节点）+ 端点读答案 + 命令栏雏形（均在 `graphPrimary` 后） | — 已完成 |
| **1 · 画布壳 + 切换 + 显眼入口** | 画布能作为第二视图站住 | 顶部 `聊天⇄画布` 切换（按对话记忆）+ 聊天里团队回合「在作战室打开」做显眼 + 画布命令栏升为常驻底栏 | 中 |
| **2 · 持久累积 + LOD** | 画布成「作战室」 | 一个对话 = 一张持久画布、回合跨回合视觉累积、完成回合折叠成「回合摘要节点」、小地图 / 相机、简单回合自动竖排退化 | 中高 |
| **3 · 图上指挥** | 画布可指挥 | 检查点 / 救火 / 审批 / 续跑卡片搬到对应节点（⑤ = §四） | 中高 |

> 与原稿差异：删除原「阶段 3 · 收敛（移除独立聊天列）」——双视图下聊天是常驻模式、永不移除。

## 七、守住的既定决策（不跑偏）

「双视图」不等于推翻已定决策。本方案**显式守住**：

- **CEO 智能路由、不给用户选择器**（[`前端UX设计.md §十一`](/docs/04-前端/前端UX设计.md)）：画布只让你在 CEO 组好的团队上**行使老板权力**（指挥 / 裁决 / 止损），**不**给「手选 / 手搭团队」——指挥 ≠ 替 CEO 组队。
- **节点 ≤50 / ≥60fps**（[`前端UX设计.md §八`](/docs/04-前端/前端UX设计.md)）：画布模式靠 LOD（按缩放档折叠，Level of Detail）守住——完成回合塌成「回合摘要节点」、只有聚焦回合画完整 DAG、离屏虚拟化；不因「持久累积」就同屏堆节点。
- **节点 face 极简**（[`前端展示完善规划.md §3.1`](/docs/07-规划/前端展示完善规划.md)）：数字（model/token/¥）仍归 run 详情，主界面化不回灌节点。
- **独立 Arena 子系统仍否决**（[`Agent协作模式.md §7.4`](/docs/03-AI核心/Agent协作模式.md)）。
- **简单任务零噪音**（[`前端UX设计.md §三`](/docs/04-前端/前端UX设计.md)）：聊天默认 + 画布退化竖排，双重守住。

## 八、被否决 / 暂不做

| 方向 | 处置 | 理由 |
|---|---|---|
| **图即唯一界面 / 无模式切换（原稿主张）** | **撤** | 强迫简单问答上画布是负体验；且整方案命悬「画布像聊天一样轻」的试金石。双视图（聊天默认 + 画布 opt-in）零门槛天然、风险更低、聊天永不删 |
| **丙 · 自适应默认（按「有无团队」自动切模式）** | 否决 | 中途翻模式 = 错愕；「何时切」判据含糊 + 每对话模式偏好状态边界多；收益小（乙-1 简单回合本就退化轻卡）。改用「显眼内联入口」达成同等「画布在相关时出现」 |
| **乙-2 · 真持久团队（worker 实体化）** | 暂不做 | 「团队跨回合」的真需求 = 连续性 / 团队懂我，已由记忆模块 + CEO 跨回合记忆 + 共享工作区覆盖；worker 实体化撞「无选择器 / 每回合自适应组队」核心赌注（[`职责晚绑定与动态再编排设计.md`](/docs/07-规划/职责晚绑定与动态再编排设计.md)），是定位级（养成系）改动、非界面事 |
| 持久化「团队花名册」（跨回合固定团队） | 暂不做 | 同乙-2；身份延续由 [`agentIdentity`](/docs/04-前端/前端UX设计.md) 天然给到（同名角色稳定色 / 字），不立独立实体 |
| 执行前 plan 预审「拖拽改 DAG」画布 | 暂不做 | 触「用户手搭团队」红线（§七）；且 preflight 本是 ⏳ Phase 2（[`Agent协作模式.md §7.2`](/docs/03-AI核心/Agent协作模式.md)） |
