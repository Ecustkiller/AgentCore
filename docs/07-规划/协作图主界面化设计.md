# 协作图主界面化：从「聊天内嵌图」到「图即界面」

> 🗂️ **状态：讨论提案（07-规划）**。把多 Agent 协作图从「聊天消息里内嵌的一个组件」（`InlineTeamGraph`）升级为产品的**主界面**——聊天列逐步退化为「图的 1 节点形态」，最终用户主要在一张**协作画布（作战室）**上「掌管一支 Agent 团队」。提案拆两步：① 先把协作图**重新设计**到能独立站住（吃下聊天今天承担的「输入 / 读答案 / 单 Agent 时间线 / 多回合历史」等职责）；② 渐进迁移，把传统聊天列逐步收敛进画布。
>
> **从属**：本文是 [`公司画布主界面化设计.md`](/docs/07-规划/公司画布主界面化设计.md) 愿景的 **L1–L2 层**（单对话 → 回合脊柱）；工作区 / 公司（L3–L4）层与统一语义缩放空间见该文。两份非竞争提案，是同一愿景的不同缩放层。
>
> **核心论点**：聊天不是要被「砍掉再换成图」，而是**聊天本来就是协作图的退化渲染**。后端早已定「单 Agent = 只有 Captain、没有成员的 Team；运行时代码路径统一」（见 [`Agent协作模式.md §设计哲学`](/docs/03-AI核心/Agent协作模式.md)），前端只需把这条**如实画进 UI**：简单问答 = 1 个 CEO 节点（读起来 ≈ 今天的聊天气泡），团队任务 = 同一节点开花成 DAG。一张画布、按复杂度连续缩放，**无模式切换**。
>
> **未落地**：本文是方向提案；现状仍是「聊天为主、图内嵌」（见 [`前端UX设计.md §一/§三/§五`](/docs/04-前端/前端UX设计.md)）。迁移节奏见 §六。
>

## 一、为什么做（产品论证）

**差异化在界面层被稀释。** 产品定位是「真正的 Agent 团队协作」、用户心智是「你是老板、掌管一支由 AI CEO 带队的团队」（[`前端UX设计.md §核心设计理念`](/docs/04-前端/前端UX设计.md)）。但当前主界面是**单栏聊天区**，协作图只在多 Agent 回合内嵌出现（[`§一/§三`](/docs/04-前端/前端UX设计.md)）。聊天是单助手产品（ChatGPT / Claude）的母语——**只要界面长得像聊天，就在暗示「我是一个聊天机器人」**，「管理团队」的心智立不住。

**结论**：要兑现差异化，界面本身得是「作战室」，而不是「聊天框里塞了张图」。协作图应从**配角**升为**主界面**。

> 这不与「零门槛入门 / 简单任务零噪音」冲突——靠 §二 的退化特例渲染，简单问答仍是一张极简卡片，体验 ≈ 聊天气泡（见 §五.1）。

---

## 二、核心论点：聊天是协作图的退化形态

后端的统一执行路径已经定调（[`Agent协作模式.md`](/docs/03-AI核心/Agent协作模式.md)）：

- **单 Agent 是退化特例** = 只有 Captain、没有成员的 Team；
- 所有对话（单 / Team）走**同一条代码路径**，差异仅在「是否注入 `delegate` + 编排策略」。

前端今天**没有**对齐这条：单 Agent 回合走一条纯内联「思考·正文·工具」时间线（`ProcessTimeline`，[`§一B`](/docs/04-前端/前端UX设计.md)）、**根本不画图**；只有多 Agent 才内嵌协作图。于是同一套后端语义，前端裂成「气泡」与「图」两套表达。

**本提案 = 把这条统一律如实画进 UI**：

| 任务复杂度 | 画布形态 | 读起来像 |
|---|---|---|
| 简单问答（CEO 直答、无 `delegate`） | **1 个 CEO 节点**，思考/正文/工具时间线在节点体内 | 一张聊天气泡（零门槛不变） |
| 团队任务（CEO `delegate`） | 同一 CEO 节点**开花**成 worker DAG + 波次 | 一张作战室 |

同一组件、复杂度连续缩放、**零模式切换**。这既兑现「图即界面」的大胆愿景，又是把后端「退化特例 + 统一路径」**如实落到前端**，而非另起炉灶——**这是本方案能成立、且不跑偏的根**。

## 三、重设计命题：图必须吃下聊天今天的 6 件事

「只用协作图」的真正工作量，是让图**接管聊天今天承担的职责**。逐条点名（这也是重设计的缺口清单）：

| # | 聊天今天的职责 | 图必须长出的能力 | 现状接近度 |
|---|---|---|---|
| ① | 输入框 / 下达指令 | 画布上常驻的**老板命令栏**；用户提问 = 喂给 CEO 的输入端点 | 近（`EndpointNode` 的「用户输入」端点已是它的雏形，只差「能打字」） |
| ② | 读 CEO 的成稿答案 | **CEO 节点可展开**即正文全文 | 近（汇聚点已预览答案 + 点击跳转，差「就地展开读全文」） |
| ③ | 单 Agent 的「思考·正文·工具」时间线（`ProcessTimeline`） | **搬进 CEO 节点体内**——这是最大的一块：今天单 Agent 回合根本不画图 | 远（需让单 Agent 回合也成「1 节点图」） |
| ④ | 多回合滚动历史 | **回合脊柱**：每回合一张画布，纵向串成「回合 filmstrip」，滚动 = 穿越回合 | 中（每条回答已各持执行槽 `messageId`，缺统一脊柱 IA） |
| ⑤ | 检查点 / 发问 / 审批 / 续跑 / 云端任务 卡片 | **变成画布上的就地交互**（即「图上指挥」，见 §四） | 中（卡片已存在，但在聊天流里、不在图上） |
| ⑥ | 长文交付物的阅读 | 节点展开 + 右侧面板作阅读面（图唯一 ≠ 万物挤进节点） | 近（`SidePanel` / `GraphDetailPanel` 已是阅读面） |

> 读这张表能看出：**多数职责图已有雏形**（①②⑥），真正的硬骨头是 ③（单 Agent 也成图）和 ④（回合脊柱 IA）。⑤ 是独立的大件，见 §四。

## 四、与「图上指挥」的关系：单一界面必然是可指挥的

上一轮讨论提过「把图从**观测**升级为**指挥**」（节点上就地裁决 escalation、运行中插话改向、单分支重试/止损）。在「图即界面」的语境下，它从**锦上添花变成地基**——

**因为一个唯一的界面不可能是只读的。** 你一旦砍掉聊天，检查点 / 发问 / 审批 / 救火这些**老板权力**就**必须**落到图上（清单 §三 的 ⑤）。所以「图上指挥」不是被「图主界面化」取代，而是它的**前半程**：

- **P 阶段先做的「图上指挥」** = 把已散落在聊天里的老板权力（[`CheckpointCard` / 救火行 / `ResumePrompt`](/docs/04-前端/前端UX设计.md)）搬到它们真正发生的那个节点上。
- 这件事**无论是否最终砍掉聊天都值得做**，且为「图唯一化」扫清最大障碍。

## 五、必须由人拍板的硬抉择

大胆归大胆，这几处是真矛盾，**藏不得**（藏了后面必打补丁，违反 [`dev-process.mdc` 补丁绊线](/.cursor/rules/dev-process.mdc)）：

### 5.1 零门槛 vs 重画布（命根）
靠 §二 的「退化特例 1 节点渲染」化解：简单回合就一张卡、不开画布、视觉 ≈ 聊天气泡。**这条是整个方案能不能落地的试金石**——第一刀就要验证它的手感（见 §九）。若 1 节点形态做不到「像聊天一样轻」，方案需回炉。

### 5.2 回合历史的形态
- **方案甲·回合脊柱**（纵向 filmstrip，每回合一张图）：稳、保留聊天「线性速扫」的长处、迁移风险低。**倾向甲。**
- 方案乙·单张持久演进画布（同一团队跨回合累积）：更像「我的团队」，但「如何表达历史 / 跳回某轮」复杂度高。
- → **建议先甲**，乙作远期探索。

### 5.3 长文可读性
画布节点装不下 2000 字报告。**图唯一 ≠ 万物挤进节点**：长文走节点展开 / 右侧面板（[`SidePanel`](/docs/04-前端/前端UX设计.md) 已是阅读面）。这条是「图主界面」与「图塞满一切」的分界，必须守住。

### 5.4 手机端
图在手机上难（[`前端UX设计.md §十五`](/docs/04-前端/前端UX设计.md) 列为待定）。但手机端 ⏳ 未落地（[`手机端落地设计.md`](/docs/07-规划/手机端落地设计.md)），**桌面可先行**；手机走「回合脊柱化简版」（卡片流，按需展开图），不强求画布。

## 六、渐进迁移分期（呼应「慢慢去掉」）

每阶段可独立合并、可回退，**不是一次性豪赌**：

| 阶段 | 目标 | 主要动作 | 风险 |
|---|---|---|---|
| **0 · 重设计** | 图能「独立站住」 | 命令栏雏形（①）+ CEO 节点可展开读答案（②）+ 退化 1 节点渲染骨架 | 低（纯前端） |
| **1 · 共存** | 单 Agent 回合也成「1 节点图」 | 把 `ProcessTimeline` 搬进 CEO 节点（③），与聊天气泡**并行**验证手感 | 中（§五.1 试金石） |
| **2 · 反转** | 图成为回合容器 | 回合脊柱 IA（④）+ 检查点 / 救火等卡片上画布（⑤=图上指挥） | 中高 |
| **3 · 收敛** | 图即唯一界面 | 移除独立聊天列，命令栏 + 回合脊柱 + 画布成主界面 | 高（需 0–2 验证充分） |

## 七、守住的既定决策（不跑偏）

「大胆」不等于推翻已定决策。本方案**显式守住**：

- **CEO 智能路由、不给用户选择器**（[`前端UX设计.md §十一`](/docs/04-前端/前端UX设计.md)）：图主界面化只让你在 CEO 组好的团队上**行使老板权力**（指挥 / 裁决 / 止损），**不**给「手选 / 手搭团队」——指挥 ≠ 替 CEO 组队。
- **节点 ≤50 / ≥60fps**（[`前端UX设计.md §八`](/docs/04-前端/前端UX设计.md)）：不因「图变主界面」就堆节点（如每工具一节点，[`§五 已否决`](/docs/04-前端/前端UX设计.md)）。
- **节点 face 极简**（[`前端展示完善规划.md §3.1`](/docs/07-规划/前端展示完善规划.md)）：数字（model/token/¥）仍归 run 详情，主界面化不回灌节点。
- **独立 Arena 子系统仍否决**（[`Agent协作模式.md §7.4`](/docs/03-AI核心/Agent协作模式.md)）。
- **简单任务零噪音**（[`前端UX设计.md §三`](/docs/04-前端/前端UX设计.md)）：靠 §二 退化渲染守住。

## 八、被否决 / 暂不做

| 方向 | 处置 | 理由 |
|---|---|---|
| 持久化「团队花名册」（跨回合「我的固定团队」） | 暂不做 | 与「无用户选择器 + 每回合临时组队」张力大；弱化为「角色身份跨回合延续」（[`agentIdentity`](/docs/04-前端/前端UX设计.md) 已给同名角色稳定色/字，天然延续）即可，不立独立实体 |
| 执行前 plan 预审「拖拽改 DAG」画布 | 暂不做 | 触碰「用户手搭团队」红线（§七）；且 preflight 本是 ⏳ Phase 2（[`Agent协作模式.md §7.2`](/docs/03-AI核心/Agent协作模式.md)） |

## 九、第一刀（落地切入点）

**把 CEO 的「思考·正文·工具」时间线（`ProcessTimeline`）搬进 CEO 节点，让单 Agent 回合也渲染成「1 节点图」。**

- **为什么是它**：这是 §二「退化特例渲染」的**试金石**——单 Agent 1 节点图若能做到「像聊天气泡一样轻」（§五.1），整条路就通了；做不到则方案回炉，代价最小。
- **范围**：纯前端，不动协议 / `turn_journal` / conformance（时间线已是渲染层 fold，见 [`§一B`](/docs/04-前端/前端UX设计.md)）。
- **验收**：简单问答下，1 节点图与现聊天气泡**手感等价**（零门槛、零噪音、流式顺滑）。
- → 涉及代码：`components/graph/GraphView.tsx`、`components/graph/AgentNode.tsx`（CEO/captain 节点体内嵌时间线）、`components/chat/MessageBubble.tsx` 与 `lib/processTimeline.ts`（复用现有 `ProcessTimeline` 渲染）。

> 落地后续：阶段 0–1 验证通过，把「图主界面化」的现状行为迁入 [`前端UX设计.md`](/docs/04-前端/前端UX设计.md)，本文随阶段推进逐步退役。
