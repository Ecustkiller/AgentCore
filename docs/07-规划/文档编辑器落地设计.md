## 〇、决策摘要

| 维度 | 决定 |
|---|---|
| 内核 | **CodeMirror 6 源码编辑器**（非 TipTap / 非整页 contenteditable）。文本进、文本出，**字节忠实**——人存的字节即 AI 读的字节 |
| 所见即所得 | 用**内联 React widget 实时预览**换取「手感」：公式 / mermaid / markmap / GFM 表格 / frontmatter 就地渲染，光标进块自动还原源码编辑——**无 round-trip 有损往返** |
| 渲染复用 | split 预览与内联 widget 的渲染源**复用现有** [`Markdown.tsx`](/apps/desktop/src/renderer/components/chat/Markdown.tsx) / [`Diagram.tsx`](/apps/desktop/src/renderer/components/chat/Diagram.tsx)（mermaid/markmap/katex/vega 依赖均已在） |
| 落点 | 工作区面板 [`FilePreview`](/apps/desktop/src/renderer/components/files/FilePreview.tsx)：`.md/.markdown` 路由到编辑器，其余维持只读预览 |
| 源无关 | 编辑器对接 [`FileSource`](/apps/desktop/src/renderer/lib/fileSource.ts) 抽象，本地（IPC）与云端（REST）共用一套 UI；安全保存（CAS）按源能力分期硬化 |
| AI 改写 | L1 选区改写：选区 + 指令 → 后端 `POST /v1/files/assist/rewrite`（无状态、不落库）→ `@codemirror/merge` 逐块 ✓/✗ 评审 |
| 保存模型 | 防抖自动保存 + `Ctrl/Cmd+S` 即存；写前 **CAS**（baseline 版本，磁盘/远端被改即 `conflict`，绝不盲覆盖） |
| 新增依赖 | `@codemirror/*` + `@codemirror/lang-markdown` + `@lezer/highlight`（renderer）；后端 rewrite 端点（P3）。按 `dev-process`：**AI 提案 → 人确认** |

**一句话**：用 CodeMirror 做**字节忠实的 markdown 源码编辑器**，靠**内联 widget 实时预览**拿到所见即所得手感而不欠 round-trip 的债，靠 **merge 评审**让 AI 改写「人始终掌控落地什么」。

## 二、为何 CodeMirror 而非 TipTap

核心是 **markdown round-trip 有损**：TipTap（ProseMirror）编辑的是富文本文档模型，要在所见即所得里改 markdown 必须 `md → doc → md` 往返，而这一往返在本产品重度使用的内容上全是坑——

| 内容 | TipTap round-trip 风险 |
|---|---|
| KaTeX 公式 `$...$` | 高（需自定义节点保 `$` 不丢） |
| mermaid/markmap/vega 图 | 高（所见即所得里无法直接改图，只能退化为改源码） |
| 排版规范化 | 高：`*`↔`-`、有序列表重编号、换行/尾空格——**重排整文 → 巨大噪音 diff**，撞快照/三方冲突检测 |

参考实现把理由写在注释里：「**文本即典范，绝不隐式 reflow……人存的字节即 AI 读的字节**」。CodeMirror 路线的源是 markdown 文本本身，widget 只是**装饰**（光标进块即还原源码），故**所见即所得是「视图」而非「模型」**——既有手感，又零 round-trip 债，diff 干净。

> **被否决 · TipTap / 整页 contenteditable WYSIWYG**：round-trip 有损、math/diagram/clean-diff 全是坑、与「文本即典范」冲突；且其招牌的行内 mention pill / 斜杠命令在本项目要么已退役要么暂缓（见 [`前端UX设计.md §一`](/docs/04-前端/前端UX设计.md)），价值与代价不匹配。
>
> **被否决 · CodeMirror lang 之外另造 markdown AST 编辑**：无必要，源码 + 语法树 + 装饰已足。

## 三、架构与数据流

```
FilePreview(.md/.markdown)
└─ MarkdownFileEditor ……… 宿主：读/写/CAS/防抖自动保存/冲突裁决/视图切换（编辑·预览·导图）
   └─ MarkdownSourceEditor … CodeMirror6 内核（字节忠实，getValue/getView via ref）
      ├─ markdown(lang) + 主题(token) + history + lineWrapping + Mod-s 保存
      ├─ livePreview(StateField) → ReactBlockWidget …… 公式/mermaid/markmap/表格/frontmatter 就地渲染
      │     （渲染源复用 Markdown.tsx 的 Diagram / KaTeX / 表格）
      └─ AI 改写 L1：选区+指令 → rewrite() → unifiedMergeView 逐块评审（接受/拒绝/撤销）

读：FileSource.readForEdit(path) → { text, version, encoding, eol }
写：FileSource.writeText(path, { content, encoding, eol, baseline: version }) → WriteResult
     ├─ LocalRootSource → window.fsApi.writeFile（新增 IPC fs:writeFile + CAS on mtime）
     └─ WorkspaceSource → workspaces REST（P4：补 version/etag 条件写；P1 暂用现有盲 writeBytes）

AI 改写后端：POST /v1/files/assist/rewrite { selection, instruction, context_before/after }
            → { rewritten }（无状态、不落库，复用现有 LLMProvider）
```

## 五、与现有 AgentCore 的对接：复用 vs 缺口

**✅ 直接复用**：`Markdown.tsx`（预览 + widget 渲染源）、`Diagram.tsx`、`FileSource` 抽象与 `FileBrowser`/`FilePreview` 装配、工作区面板宽度与 keep-alive 机制。

**❌ 缺口（净新工作）**：

| 缺口 | 现状 | 需补 |
|---|---|---|
| 本地写盘 | `localRootSource` `caps.edit=false`、无 `writeBytes`；`FsApi` 只有 `readFile/rename/move/create/delete`，**无 renderer 可调的 `writeFile`** | 新增 `fs:writeFile` IPC + CAS；`readFile` 回 `mtime/编码/换行`；`localRootSource` 接 `readForEdit/writeText`、`caps.edit=true` |
| 云端写盘安全 | `workspaceSource` 已 `caps.edit=true` + `writeBytes`，但是**盲覆盖上传、无 CAS/版本**，`read` 不回版本 | P4：`read`/上传补 `version`(updatedAt/etag) 做条件写，防与 Agent 并发写互覆 |
| AI 改写端点 | 无 `/v1/files/assist/rewrite` | P3：新增无状态端点，复用 `LLMProvider` |
| CodeMirror 依赖 | 未引入 | `@codemirror/{state,view,commands,language,search,merge}` + `@codemirror/lang-markdown` + `@lezer/highlight`（pnpm 装最新 6.x，勿臆造版本） |

> **注意 · `WorkspaceOpName` 里的 `write` 不是这条线**：那是云端 executor 经 SSE 下发的 client-tool op（Agent 写本地），不是 renderer 可调的用户编辑写盘。二者别混。

## 六、关键契约

### 6.1 fs 桥：新增 `fs:writeFile`（本地 CAS）

```ts
// shared/ipc-contract.ts
FS_CHANNELS.writeFile = "fs:writeFile";

interface FsWriteInput {
  content: string;
  encoding: "utf-8";          // GBK 等暂只读不回写（参考实现策略）
  eol: "lf" | "crlf";
  baselineMtimeMs: number;    // 写前 CAS：与磁盘 mtime 不符即 conflict
}
type FsWriteResult =
  | { ok: true; mtimeMs: number }
  | { ok: false; reason: "conflict"; diskMtimeMs: number }
  | { ok: false; reason: "denied" | "locked" | string };

// FsApi 扩展
writeFile(rootId: string, relPath: string, input: FsWriteInput): Promise<FsWriteResult>;
// readFile 返回值补：mtimeMs / encoding / eol（供宿主存 baseline）
```

主进程 `fs-service.ts` 实现 CAS：写前 `stat` 比对 `baselineMtimeMs`，不符返回 `conflict`（带 `diskMtimeMs`，供「仍然覆盖」用），写成功回新 `mtimeMs`；落盘走「临时文件 + rename」原子写。授权根边界沿用现有 `realpath` 校验。

### 6.2 FileSource 编辑契约（源无关）

```ts
// lib/fileSource.ts（gated by caps.edit）
type FileVersion = { mtimeMs?: number; etag?: string };  // 本地用 mtime；云端用 etag/updatedAt

readForEdit?(path: string): Promise<{
  text: string; version: FileVersion; encoding: "utf-8"; eol: "lf" | "crlf";
}>;
writeText?(path: string, input: {
  content: string; encoding: "utf-8"; eol: "lf" | "crlf"; baseline: FileVersion | null;
}): Promise<
  | { ok: true; version: FileVersion }
  | { ok: false; reason: "conflict" | "denied" | "locked" | string }
>;
```

宿主 `MarkdownFileEditor` 只认这层接口，不分支本地/云端；CAS 的 `baseline` 由各源映射到 mtime（本地）或 etag（云端 P4）。

### 6.3 后端 AI 改写端点（P3）

```
POST /v1/files/assist/rewrite
  { selection, instruction, context_before, context_after }
  → { rewritten }
```

无状态、不落库；复用现有 `LLMProvider`，`scenario="file.rewrite"` 做成本归因。返回文本由前端套 `unifiedMergeView` 评审，**人逐块决定接受/拒绝**。

## 八、规则对接

- **配色 token**（[`color-tokens.mdc`](/.cursor/rules/color-tokens.mdc)）：`cmTheme` 与所有 widget **只用语义 token**（`background`/`foreground`/`border`/`primary`/`muted` 等），**禁硬编码 hex**——参考实现里 xlsx 预览残留的 `#374151` 之类**不照搬**，一律换 token。
- **桌面布局**（[`desktop-layout.mdc`](/.cursor/rules/desktop-layout.mdc)）：编辑器在 SidePanel 工作区 tab（宽 280–560px）。**split 预览在窄面板会挤**——建议「窄于阈值默认只编辑、宽面板才并排预览」，或预览作为可切视图（编辑/预览/导图段控，同参考实现）。字号/圆角/按钮档位遵守规范。
- **文件编辑安全**（[`dev-process.mdc`](/.cursor/rules/dev-process.mdc)）：禁脚本批量改源码；逐文件 StrReplace + Read 自检。新增 `@codemirror/*` 走 pnpm 装最新 6.x。

## 九、风险与边界

| 风险 | 缓解 |
|---|---|
| 内联 widget 大文档逐键开销 | 沿用参考实现：块只在 `docChanged` 重扫、光标移动复用缓存、遍历剪枝、超 `MAX_LINES` 退纯源码 |

| 关窗=隐藏到托盘不触发卸载 | 自动保存防抖 + `beforeunload` 尽力冲刷（参考实现已处理；桌面端关窗语义见 [`前端技术与架构.md §7.7`](/docs/04-前端/前端技术与架构.md)） |
