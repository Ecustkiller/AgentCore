# 执行级事件溯源落地设计（Turn Journal：展示级 → 执行级）🗂️

> **定位**：把 [`turn_journal`](/apps/server/agentcore/runtime/journal.py) 从「给人看的回放流」升级为「能重建引擎状态的事实流」，使**一个回合只剩一个真相源**。这是 [内核优化讨论 §A1](/docs/07-规划/内核优化讨论.md) 的 P1（最高杠杆），技术 backlog 见 [远期规划 §1.1](/docs/07-规划/远期规划.md)「执行级 journal 事实」。本文是该项的落地蓝图。
>
> **前置约束（2026-06 人确认）**：开发期、**不需要兼容层**、可积极重构。故本文**直奔单一真相源终态**——不做长期影子双写、不留 frame 旧格式兼容，以 conformance golden 测试作切换闸，绿了即删 `paused_turns.frame`。
>
> **状态**：🗂️ 部分落地。**Phase 1（执行级事实记录）+ 持久化切换 + `window_from_journal` 投影器已落地**，as-built 契约已迁入 [执行引擎 §18.3](/docs/03-AI核心/执行引擎架构设计.md)（现状文档）——`turn_started`/`round_boundary`/`llm_call`/`note`/`message_final` 5 类已记录并持久化，单一有序日志 `TurnFactLog` 已接替 sink 旧 journal 源，执行投影 `window_from_journal`（read-only，重建 captain LLM 窗口）已落地并有单元级 conformance。**ask_user 暂停 conformance golden 已立闸**（`test_pause_conformance`，驱真实挂起断言 `window_from_journal == frame.transcript`）。**§三两处已知边界已清**：已补 `tool_call` 全文事实（CEO 引用编号注解后记录，窗口改读它）+ `note` 带 `run_id`（多 Agent captain 中途注入归属）——纯加、零行为变更，故执行事实由 5 类增至 **6 类**。**resume 切换闸已齐备**：plan_review/delegate 暂停 golden（`test_pause_conformance` 驱真实 `DelegateTool` `checkpoint_after` 挂起，断言投影只留 captain 窗口、排除交织 worker 事实）+ 真实 DB 往返（`test_turn_journal_repo` 真库 `record→load`，断言 JSONB 无损且两侧折叠一致）。**resume 已改读投影（Phase 2 ④）**：`resume_chat_pipeline` 折 `suspension.journal_entries` + 回灌 history 重建 captain 窗口，**不再读 `frame.transcript`**；双向守护（投影闸 golden + 消费闸 `test_resume_window`）。**`transcript`/`history` 序列化已删（Phase 2 ⑤）+ `completed` 序列化已删（Phase 2 ⑥）**：`TurnSuspension.to_json()` 不再写 `transcript`/`history`/`completed`，`paused_turns.frame` 退为 resume 控制元信息（余 `tool_call_id`/`base_system_prompt`/`plan`）；窗口两端均从 journal 折出（云端 journal 自 `turn_journal` 表 + history 自消息库回灌，**sidecar 无库故本机帧自带 `journal_entries` + `history`**），已完成 worker 由新 **worker-head 事实**（终态 RunState 乘 `message_final` 记于 executor 收口点）+ `completed_from_journal` 投影 re-seed；journal 与内存 transcript 双缺才**显式抛错**（不再静默空窗口）。**本稿余项**：删 `plan` 序列化（从 `run_plan` 事实投影，含 `steer` 累积）+ deltas 退流（独立）（故下文措辞中，6 类执行事实 + 投影器 + golden + DB 往返 + 两处边界 + resume 读投影 + transcript/completed 退场 已是现状）。全量落地后本稿退役。本目录仅 `07-规划`。

## 〇、决策摘要

| 维度 | 决定 | 理由 |
|---|---|---|
| 核心动作 | journal 收编**执行级事实**，`paused_turns.frame` 降级为 journal 的一个投影并删除 | 消灭「展示流 + 执行控制态」两个真相源这一根因 |
| `llm_call` 存什么 | **只存输出**（content / reasoning_content / tool_calls / usage / finish_reason）+ 轮边界；**LLM 窗口靠 fold 前序事实重建，永不存全量窗口** | 无二次方膨胀，correct-by-construction（对标 LangGraph channel-delta / Temporal event-history） |
| deltas 定位 | `run_output_delta` / `run_reasoning_delta` **降级为纯 liveliness、退出 journal**（与 `*_tool_progress` 同类）；事实（`llm_call`/`message_final`）才是真相 | 今天 deltas 既当展示又当真相，是「展示级」的病根；拆开即「一切皆投影」落地 |
| 全文事实 | 新增 `message_final`（**只入 journal、不入 SSE**），承载每个 run 与回合的全文产出 | 展示要摘要、执行要全文；resume 喂回 worker 产物从此取自事实而非 frame |
| 两个投影 | 一份事实流 → `runs_from_entries`（展示，客户端 fold 契约不变）+ 新 `window_from_journal`（执行，重建 LLM 窗口 / 暂停帧） | 兑现 §18.6 把 Journal 做成一等端口 |
| 迁移闸 | conformance golden：对真实暂停回合断言 `window_from_journal(journal) == 当时实际 transcript`，绿后删 frame | resume 是最脆路径，静默损坏=丢回合，必须有机器裁判 |
| 节奏 | Phase 1 纯加事实（无损 journal，零行为变更）→ Phase 2 删 frame（resume 改读 journal） | Phase 1 独立解锁窗口重建/time-travel 且零风险；Phase 2 才碰 resume |

**一句话**：让 journal 记下「引擎真正做了什么」（输出级事实，而非摘要），把 LLM 窗口与暂停帧都变成它的**投影**；deltas 退回纯展示，frame 退场，单一真相源成立。

## 一、关键洞察：一个回合现在有两个真相源

这才是病灶——不是 journal 缺字段，而是**执行控制态根本不在 journal 里**：

| 真相源 | 存什么 | 服务谁 | 代码位 |
|---|---|---|---|
| `turn_journal` 表 | 展示流：团队图事件 + 工具卡 + 交互卡 + 单 Agent「思考·工具」步 + `turn_end` | 重载回放（客户端 fold） | [`journal.py`](/apps/server/agentcore/runtime/journal.py) `entries_from_runs`↔`runs_from_entries` |
| `paused_turns.frame` | resume 控制元信息：`tool_call_id` + `base_system_prompt` + `plan`（`transcript`/`history` ✅ Phase 2 ⑤、`completed` ✅ Phase 2 ⑥ 已退场——窗口与已完成 worker 均靠 journal 折出；`plan` 待投影） | resume 续跑 | [`suspension.py`](/apps/server/agentcore/runtime/suspension.py) `TurnSuspension` |

journal 今天是 [`EventSink.emit`](/apps/server/agentcore/runtime/events.py) 的副产品——只有落在 `_JOURNAL_EVENT_TYPES` 的 SSE 事件才进 journal。于是它对**执行**天生有损，三处缺口：

1. **`run_completed` 只发 `output_summary`（摘要），无 worker 全文**——resume 喂回 `delegate` 结果只能从 `frame.completed` 取全文。
2. **CEO 的 `transcript` 根本不入流**——它是 [`captain_transcript`](/apps/server/agentcore/runtime/suspension.py) contextvar，活在内存；journal 里没有任何 `llm_call` 记录真实 LLM 窗口。
3. **system prompt、注入的 NUDGE/FINALIZE user 消息、每轮 round 边界——都不是事实**。

所以「journal 是唯一事实源」目前只对**展示**成立，对**执行**不成立，缺口靠 `frame` 旁路补。§18.3 列的九类事实里，真正落地的只有 `run_event`/`tool_call`/`interaction`/`turn_end`；缺的正是执行级那几类。

## 二、九类事实 schema（落地定义）

`turn_journal` 主键 `turn_id + seq`（`turn_id == assistant message_id`），追加写。九类：

| kind | 入 SSE? | 载荷（要点） | 映射现状 |
|---|---|---|---|
| `turn_started` | 否 | `system_prompt`（**逐字捕获**，非重渲染）、`user_message`、`model_profile`、`history_len` | 新增。窗口 fold 的头锚 |
| `round_boundary` | 否 | `round_idx`、`run_id`、`role`(captain/worker) | 新增。`fold` 按它切轮重建暂停帧 |
| `llm_call` | 否 | `run_id`、`round_idx`、`content`、`reasoning_content`、`tool_calls`、`usage`、`finish_reason` | 新增。**执行保真核心**——只记输出 |
| `tool_call` | 否(执行专用) | `run_id`、`tool_call_id`、`name`、`arguments`、`result`(**全文 model-facing**)、`success` | ✅ 已落地。窗口工具源（在 CEO 引用注解之后记录）；展示卡仍走 `tool_use_start`/`tool_use_end` |
| `interaction` | 是 | `kind`(approval/ask_user/plan_review/…)、`interaction_id`、请求载荷、`resolution` | 映射现 `checkpoint_*`/`plan_review_*`/`question_posted` |
| `note` | 否 | `role`、`content`、`reason`(nudge/finalize/…)、`run_id` | ✅ 已落地。引擎注入的 user 消息，窗口 fold 按 `run_id` 归属 |
| `run_event` | 是 | `run_plan`/`run_started`/`run_completed`(摘要)/`run_failed`/`run_progress` | 现状保留（团队图展示） |
| `message_final` | 否 | captain：`run_id`、`content`(全文)、`reasoning`(全文)；worker run-final：`run_id` + **`state_to_json`(终态 RunState：phase/content/usage/cost/citations/…)** | ✅ 已落地。captain 重建回复；worker 版（带 `phase`）即 **frame.completed 的事实来源**，`completed_from_journal` 投影 re-seed |
| `turn_end` | 否 | `finish_reason` | 已落地 |

**关键拆分**：`run_output_delta` / `run_reasoning_delta` **退出 journal**，降级为纯展示 liveliness（live 流仍发、重载不靠它）。worker/CEO 的权威文本改由 `llm_call`（逐轮结构化输出，含 `reasoning_content` 与 `tool_calls`）+ `message_final`（全文）承载——deltas 与 `tool_progress` 从此同级（都不是事实）。

## 三、一份事实流，两个投影

兑现「一切皆投影」：journal 是唯一日志，下游全是它的纯函数投影。

```
                         ┌─ runs_from_entries  → 展示 runs 载荷 → 客户端 fold（契约不变）
turn_journal（九类事实）─┤
                         └─ window_from_journal → LLM 窗口 / 暂停帧（resume 读它，不读 frame）
```

- **展示投影 `runs_from_entries`**（改造）：消费 `run_event` + `tool_call` + `interaction` + `turn_end`；执行级事实（`turn_started`/`round_boundary`/`llm_call`/`note`）**忽略**。worker 全文从 `message_final` 投影成**一段 `run_output_delta` 等价块**喂给客户端 fold——**故客户端 fold 零改动**（重载仍见 run_output/tool/interaction 事件，只是合并成整块）。`tool_call` 的全文 result 在此**截断**为预览。
- **执行投影 `window_from_journal`**（✅ 投影器已落地，read-only）：`turn_started`(system+user) → 逐轮 fold `llm_call`(assistant 消息，含 reasoning_content 回灌) + `tool_use_end`(tool 消息，按 `tool_call_id` 配对) + `note`(注入消息)，按 `run_id` 切 captain 窗口，前置拼**历史投影**（caller 传入往轮消息；事实仅存 `history_len`），重建出与当时 `captain_transcript` **逐字一致**的 `messages`。已含单测 + 单元级 conformance（驱真实 `react_loop` 断言 `== 实时 transcript`）。暂停帧 = 在暂停那个 `round_boundary` 处的 fold 切面：`completed` ✅ 由 worker run-final 事实经 `completed_from_journal` 导出（Phase 2 ⑥）、`tool_call_id` 由事实导出；`plan` ⏳ 待投影。
  - **两处已知边界（✅ 已清）**：① `tool` 正文原取自 `tool_use_end`，但 CEO 路径在 emit 后才把引用编号折进 tool 消息 → 已新增 `tool_call` 全文事实（在注解之后记录），窗口改读它；② `note` 原无 `run_id`、按「当前活动 run」归属，多 Agent 下 captain 在 delegate 中途注入的 note 会漏 → 已给 `note` 带 `run_id`，窗口按事实自带 id 归属。守护测试：`tests/test_engine_facts.py`（驱真实 CEO 注解路径）+ `tests/test_turn_journal.py`（多 Agent note 归属）。

> **协议漂移**：改了 journal 入流集合 → 必重导 `packages/protocol-conformance` 向量 + golden，两端 fold 对齐到绿（见 [`protocol-conformance.mdc`](/.cursor/rules/protocol-conformance.mdc)）。

## 四、emit 路径：单一有序日志（as-built ✅）

> **较原提案的修正（已采纳）**：原设计「引擎直写 `Journal.record_fact` 端口、`EventSink._journal` 旁路删除、执行事实与展示流分家」**被否决**——展示事实（run/tool/interaction）与执行事实（llm_call/note/…）必须保持**同一发生序**才能正确 fold 窗口/快照，分两条流再归并是徒增对账。改为**单一有序日志**：sink 把展示事件**转发**进同一条日志，引擎把执行事实**直记**进同一条日志。

落地结构（[`runtime/facts.py`](/apps/server/agentcore/runtime/facts.py)）：

- **一回合一个 `TurnFactLog`**，绑定到 `current_fact_log` contextvar（`pipeline` 回合起点 `set`、`finally` `reset`；contextvar copy 进每个 delegated worker task，故 captain 与全体 worker 写**同一条**有序日志 = 每回合单一源）。
- **`EventSink.emit`**：够格展示事件（`_JOURNAL_EVENT_TYPES`）一边入 `_journal`（保留作**进程内 live 展示道**，仍喂 `_build_runs_payload` 的实时 `runs` 载荷），一边经 `record_turn_fact` **转发**进 `TurnFactLog`。
- **`engine.react_loop`**：每轮经 `record_turn_fact` 记 `round_boundary` → `_stream_llm_round` 后记 `llm_call`（只存输出）→ NUDGE/FINALIZE/circuit_breaker 注入处记 `note`；回合/子 run 收尾由 `executor` 记 `message_final`；回合起点由 `pipeline` 记 `turn_started`。（`tool_call` 暂仍乘 `tool_use_*` 展示事件转发入流，全文化随 Phase 2。）
- **持久化切换**：回合末 `pipeline._durable_journal_entries` 组合「fact log + process/turn_end 尾」→ `persist_turn_journal(entries=…)` 存库——**`TurnFactLog` 即耐久 journal 的单一有序源**，不再 `entries_from_runs(sink-built runs)` 派生。`EventSink._journal` **保留但降级**：只供进程内 live 展示，不再是持久化来源。
- **展示零变更**：`runs_from_entries` 对执行源 journal（凭执行事实判别）重套 surface gate + None-gate，对 legacy/resume/salvage 仍纯逆投影；纯聊天回合 `runs=None` → 不写 journal（存储与 None 行为不变）。
- 对齐 [执行引擎 §18.6](/docs/03-AI核心/执行引擎架构设计.md)：`Journal` 端口本已 Protocol 化，Sidecar 换本地实现即得本地执行级溯源。

> sidecar 本机暂停（[`LocalPausedTurnStore`](/apps/server/agentcore/sidecar/paused_store.py)）✅ 已同步收敛：本机帧文件 `frame` 只存控制元信息，窗口源 `journal_entries` + 历史 `history` 随记录另存（本机无库，此文件即对位云端 turn_journal + 消息库），resume 折 journal 重建窗口——云 / 本地同形不分叉。

## 六、解锁的四件下游（为何最高杠杆）

执行级 journal 一旦成立，[内核优化讨论 §A1](/docs/07-规划/内核优化讨论.md) 列的四件**同时**解锁——它们今天全被「journal 有损 → 必须 frame 旁路」这一根因卡住：

1. **真·窗口重建**：LLM 窗口 = 事实投影，correct-by-construction，不再靠搬运序列化 transcript。
2. **跨进程暂停**：任意进程读 journal 即可续跑（frame 不再是第二份必须随行的状态）。
3. **Sidecar 本地引擎**：Journal 端口换本地实现即得本地执行级溯源，frame 旁路这第二套持久化概念消失。
4. **time-travel 调试**：可把任一回合回放/折叠到任意轮——多 Agent 调试刚需。

并与 [内核优化讨论 §A2 长对话压缩](/docs/07-规划/内核优化讨论.md) 同源：历史重建一旦是「往轮 `message_final` 的投影」，压缩闸就有干净的折叠点。

## 七、风险与绊线

- **fold 必须逐字复现窗口**：DeepSeek 思考模式要求带 `tool_calls` 的轮回灌 `reasoning_content`（[`llm.mdc`](/.cursor/rules/llm.mdc) / §4.3），fold 漏一处 resume 直接 400。→ golden 测试**必须**覆盖含思考+工具的暂停回合（棘轮：发现 bug 先加复现向量再修）。
- **存储增长**：`llm_call` + `message_final` 全文长存。先随现有 TTL/级联清理（[执行引擎 §18.3](/docs/03-AI核心/执行引擎架构设计.md)）；大体积正文（read_url 整页等）按阈值卸载到 `ArtifactStore` 端口、journal 存指针（递指针不递全文，与现有预算基建同源）。
- **system prompt 必须逐字捕获**：[`prompt.py`](/apps/server/agentcore/runtime/prompt.py) 含动态内容（日期/能力目录），`turn_started` 存**当时实际串**，不重渲染。
- **补丁绊线自检**：若 Phase 2 发现需给 resume 加「兜底/对账」才不损坏，说明 Phase 1 事实仍不全——回到 schema 补事实，而非加补丁层。
