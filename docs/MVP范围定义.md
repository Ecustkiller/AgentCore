---

## 一、目标用户 ✅ 已确定

面向全量知识工作者：开发者、研究人员、写作者、分析师、小型团队等。不限定特定垂直人群。

> 详见 [DECISIONS.md §7](DECISIONS.md#7-目标用户)

### 决策理由

产品定位是"面向大众的 AI 工作台"，不聚焦单一垂直场景。通用场景才能验证 Multi-Agent 的核心价值——不同类型任务的协作分工。

| Day 1 必须 | Day 2 迭代 |

### 模块 4：工具接入

| Day 1 必须 | Day 2 迭代 |
|----------|----------|
| 网络搜索（Web Search） | MCP 协议支持 |
| 文件读写（本地文件系统） | 数据库查询 |
| 代码执行（受限 subprocess 沙箱） | 第三方 API 集成 |
| 工具调用结果展示 | 用户自定义工具 |

**代码执行沙箱策略（MVP）：**
- `subprocess` + `timeout` + 内存限制（resource.setrlimit）
- 禁网络出站（iptables 或 seccomp）
- 只写临时目录，执行完清理
- 接口保留 `SandboxProvider` 抽象，后续可升级 Docker/gVisor

## 五、竞争策略

### 差异化切入点

现有竞品（Cursor/Claude/ChatGPT）的弱点即我们的机会：

1. **真正的 Agent 协作** — 不只是单 Agent 派发子任务
2. **可定制的 Agent 团队** — 不只是预设角色
3. **跨场景通用** — 不限于编码
4. **可观测的协作过程** — 不是黑盒

- 第一版如何在一句话内说清与竞品的区别？

## 六、竞争定位与演进路线 ✅ 已确定

### 6.1 定位判断

AgentCore 与 Codex/Claude/Cursor 不在同一赛道。

| 产品 | 本质定位 | 核心用户 |
|---|---|---|
| Codex (OpenAI) | 自主式代码 Agent（异步任务、沙箱执行、PR 闭环） | 开发者 |
| Claude (Anthropic) | 通用对话 AI + 工具使用 | 泛知识工作者 |
| Cursor | IDE 内嵌交互式编码助手 | 开发者 |
| Devin | 自主软件工程 Agent | 工程团队 |
| Coze / Dify / GPTs | 低代码 Agent 构建平台 | Agent 创作者 |
| **AgentCore** | **AI Agent 生态平台（发现+使用+构建+运行时）** | **终端用户 + 创作者** |

AgentCore 更接近 **Coze/GPTs 的生态位 + Codex/Devin 的运行时深度**。

### 6.2 三维竞争壁垒

竞争力在三个方向的交叉地带——该交叉点目前无人占据：

| 壁垒 | 说明 | 竞品对比 |
|---|---|---|
| **Multi-Agent 原生架构** | 委派一等公民、层级编排、统一执行路径 | Codex/Claude/Cursor 本质单 Agent |
| **行业垂直深度** | 平台核心行业无关 + 垂直插件可插拔 | 竞品无行业垂直维度 |
| **生态平台闭环** | Tool/Skill/Rule/Agent/Team 五类资产市场 | GPTs Store 仅有 Agent 一类 |

### 6.3 关键差距

| 差距 | 说明 | 应对 |
|---|---|---|
| **底层模型能力** | DeepSeek vs GPT-4/Claude | Gateway 已抽象，切换工程成本低；预留多模型混合策略 |
| **代码执行 / Git** | 无 Docker 沙箱和 Git 闭环 | P2 规划，MVP 用受限 subprocess |
| **异步自主执行** | 断点续跑仅到存储阶段 | 渐进补齐恢复和 Fork |

### 6.4 演进优先级

| 时间段 | 方向 | 理由 |
|---|---|---|
| 短期（0-3月） | 多模型 Gateway + 核心体验打磨 | 消除模型短板，强化差异化 |
| 中期（3-6月） | 断点续跑 Phase 2-3 + 第二垂直行业 | 验证可插拔架构复制能力 |
| 长期（6-12月） | 开放 Agent 通信协议 + 代码沙箱 + 多表面统一 | 建立生态壁垒 |

**核心结论**：不在「通用 AI 助手」或「代码 Agent」赛道正面对抗，守住「多 Agent 原生 + 垂直深度 + 生态平台」交叉点做深做透。

## 七、行业趋势与技术判断

### 行业走向（2026）

1. **交互 + 自主双模共存**：交互式（Cursor/Claude Code）和自主式（Codex/Devin）不互斥，多数团队组合使用
2. **编排框架收敛**：LangGraph 是生产级主流（Klarna/Uber/LinkedIn 在用），但 AgentCore 自研以保持架构自由度
3. **协议标准化**：MCP（工具层）+ A2A（Agent 层）三层协议格局形成

### AgentCore 现有优势（保持并强化）

| 优势 | 行业对比 |
|---|---|
| Multi-Agent 原生（委派 + DAG/Sequential/Parallel + Arena） | 比 Codex/Cursor 更完善 |
| 统一执行路径（单 Agent 和 Team 走同一代码路径） | 架构干净 |
| Marketplace 生态（工具/技能/规则市场） | 有生态基础 |
| 基建完备（PG + Redis + NATS JetStream + MinIO） | 接入成本低 |

### 演进原则（不变）

渐进兼容、复用基建、Multi-Agent 优势最大化、先跑通再优化。

## 八、Day 1 验收矩阵

每个模块的 Day 1 最低交付标准。开发完成以此为准。

### 模块 1：基础聊天交互

| 验收项 | 验收标准 | 验证方式 |
|--------|---------|---------|
| 流式输出 | 用户发送消息后 1s 内开始出现流式文字 | 手动测试 |
| Markdown 渲染 | 支持标题、列表、代码块、粗体、链接的正确渲染 | 对照 CommonMark 规范 |
| 多轮对话 | 连续 5+ 轮对话上下文正确保持 | 手动测试 |
| 输入框 | 支持多行输入、Ctrl+Enter 发送、输入中禁止重复发送 | 手动测试 |
| 停止生成 | 点击停止按钮后 500ms 内停止输出 | 手动测试 |
| 会话管理 | 新建对话、切换对话、对话列表显示标题和时间 | 手动测试 |
| 空状态 | 无对话时显示欢迎引导 | 视觉检查 |
| 错误提示 | 网络断开/后端错误时显示可理解的错误信息 | 断网模拟 |

### 模块 2：多 Agent 执行

| 验收项 | 验收标准 | 验证方式 |
|--------|---------|---------|
| 串行执行 | A→B→C 三步串行任务正确执行并展示 | E2E 场景 |
| 并行执行 | 2+ Agent 并行执行，各自输出实时可见 | E2E 场景 |
| 辩论范式 | 正/反两方同时执行，编排器比较后给出结论 | E2E 场景 |
| 混合 DAG | 先并行再串行的组合拓扑正确执行 | E2E 场景 |
| 最大 10 并行 | 10 个 Agent 并行不崩溃 | 压力测试 |
| 检查点干预 | 用户可在检查点批准/调整/停止 | 手动测试 |
| Agent 输出合并 | 多 Agent 完成后输出正确合并为最终回复 | 手动测试 |

### 模块 3：动态角色分配

| 验收项 | 验收标准 | 验证方式 |
|--------|---------|---------|
| 自动分解 | 编排器能将复杂请求分解为多步骤多 Agent 计划 | 10 个测试 prompt |
| 角色分配 | 每个 Agent 有明确的角色名和 system prompt | 检查日志 |
| 工具集分配 | 不同角色的 Agent 获得不同工具子集 | 检查日志 |
| 单 Agent 透明 | 简单任务只用 1 个 Agent，UI 无任务卡片出现 | 手动测试 |
| 自适应 UI | 单 Agent→同 ChatGPT；多 Agent→展开任务卡片 | 手动测试 |
| 失败回退 | 编排器输出无效时回退为 single_agent 模式 | 注入错误测试 |

### 模块 4：工具接入

| 验收项 | 验收标准 | 验证方式 |
|--------|---------|---------|
| 网络搜索 | Agent 调用 web_search 返回有效搜索结果 | 手动测试 |
| 文件操作 | Agent 能读写工作目录内的文件 | 手动测试 |
| 代码执行 | Agent 调用 code_execute 运行 Python 代码并返回结果 | 手动测试 |
| 结果展示 | 工具调用过程和结果在 UI 中可见 | 视觉检查 |
| 执行沙箱 | 代码执行有超时限制（30s）和内存限制 | 触发超时测试 |
| 审批流程 | 高风险工具调用弹出审批请求，用户可批准/拒绝 | 手动测试 |

### 模块 5：任务进度展示

| 验收项 | 验收标准 | 验证方式 |
|--------|---------|---------|
| 任务卡片 | 多 Agent 任务在聊天流中显示任务卡片 | 视觉检查 |
| 实时状态 | 各 Agent 状态（规划中/执行中/完成/失败）实时更新 | 观察延迟 <1s |
| 图视图 | 可切换到图视图，显示 DAG 拓扑 | 手动测试 |
| 节点状态颜色 | 不同状态节点有不同颜色 | 视觉检查 |
| 节点动画 | 执行中的节点有发光/脉冲动画 | 视觉检查 |
| 依赖边 | 边正确表示步骤间依赖关系 | 对照计划验证 |
| 节点详情 | 点击节点可查看 Agent 详情（角色、工具、输出） | 手动测试 |
| 视图切换 | 聊天↔图视图切换延迟 <200ms | 手动测量 |
| 卡片折叠 | 已完成的任务卡片可折叠/展开 | 手动测试 |

### 模块 6：基础记忆

| 验收项 | 验收标准 | 验证方式 |
|--------|---------|---------|
| 会话持久化 | 刷新页面后对话历史完整恢复 | 刷新测试 |
| 上下文保持 | 单会话内 Agent 引用之前的对话内容 | 多轮对话测试 |
| 会话摘要 | 对话结束后生成摘要存储 | 检查数据库 |
| 用户偏好 | 跨会话保持用户偏好（如偏好语言、格式要求） | 新建对话后验证 |
| 新会话继承 | 新对话能读取并应用用户偏好 | 手动测试 |

### E2E 验收场景

除模块级验收外，以下完整场景必须可演示：

| 场景 | 描述 | 涉及模块 |
|------|------|---------|
| 简单问答 | "今天天气怎么样" → 单 Agent 流式回复 | 1, 3 |
| 研究报告 | "对比 React 和 Vue 的优劣" → 3 Agent 并行调研 → 汇总 | 1, 2, 3, 5 |
| 方案辩论 | "微服务 vs 单体架构" → 正/反辩论 → 编排器裁决 | 1, 2, 3, 5 |
| 代码任务 | "写一个快排算法并测试" → Agent 使用 code_execute | 1, 3, 4 |
| 检查点干预 | 多步骤任务中用户在检查点调整方向 | 1, 2, 3, 5 |
| 跨会话记忆 | 新对话中 Agent 引用上次对话的偏好设置 | 1, 6 |
