# 对外分享与开箱即用

## 结论

面向非技术用户，优先级是：

1. **签名并公证的 macOS DMG + 常在线后端**：双击安装、登录即用，最接近开箱即用。
2. **网页链接**：无需安装，但依赖同一后端，浏览器兼容与本地文件能力较弱。
3. **未签名 DMG / ZIP**：只适合内部测试，Gatekeeper 会拦截，不能作为公开分享方案。

不能只发客户端。桌面端只内置界面、本地执行与语音引擎；登录、会话、模型调度、账户数据仍依赖
`https://app.fashitianxia.xyz/api`。

## 公开分享的硬门槛

- 后端 `/api/readyz` 返回 `200`，且数据库状态为 ready。
- 新用户可完成注册、登录，并看到明确的模型/额度配置。
- macOS 安装包使用 Developer ID 签名并完成 Apple notarization。
- Windows 安装包使用代码签名证书。
- 客户端不包含服务端密钥、平台模型 Key 或其他用户凭据。
- 发布页提供版本号、系统要求、隐私说明、卸载方式和问题反馈入口。

## GitHub Release 凭据

稳定通道发布必须配置以下 Actions Secrets：

| 用途 | Secrets |
|---|---|
| macOS 签名 | `MAC_CSC_LINK`、`MAC_CSC_KEY_PASSWORD` |
| macOS 公证 | `APPLE_API_KEY_P8`、`APPLE_API_KEY_ID`、`APPLE_API_ISSUER` |
| Windows 签名 | `WIN_CSC_LINK`、`WIN_CSC_KEY_PASSWORD` |
| 跨仓上传 | `RELEASE_GH_TOKEN` |
| 下载 CDN | `DEPLOY_SSH_HOST`、`DEPLOY_SSH_USER`、`DEPLOY_SSH_KEY` |

`MAC_CSC_LINK` / `WIN_CSC_LINK` 使用 electron-builder 支持的证书内容或 base64。
`APPLE_API_KEY_P8` 是 App Store Connect API 私钥文本，CI 会写入临时文件并在任务后销毁。

发布 workflow 会先检查生产 `/api/readyz` 和 `/api/version`；后端不是 ready 时不会生成公开安装包。

## 当前推荐

### macOS 内部测试

发送签名后的 DMG，不使用 ZIP。签名前只能让测试者右键“打开”或执行
`xattr -cr /Applications/Nexus.app`，不属于开箱即用。

```bash
cd apps/desktop
pnpm build:mac
```

构建前需要安装 Homebrew 构建依赖：

```bash
brew install whisper-cpp ggml libomp
```

### Windows

发送 NSIS 安装器。必须配置代码签名，否则 SmartScreen 会拦截。

```bash
cd apps/desktop
pnpm build:win
```

正式发布也支持在 GitHub Actions 中选择 `platform=all`，一次构建 macOS arm64 与 Windows x64。
Windows 与 macOS 先各自上传 GitHub draft release，最后一个 job 统一下载并生成 CDN 清单，避免
`latest.json` 被两个平台并发覆盖。

### 网页体验

直接分享 `https://app.fashitianxia.xyz`。它仍连接同一 `/api` 后端，因此后端故障时同样不可用。

## 发布前探活

```bash
curl -i https://app.fashitianxia.xyz/api/readyz
curl -i https://app.fashitianxia.xyz/api/version
```

两个地址都必须返回 `200`。Nginx `502` 表示前端站点存在，但后端容器/反代目标不可用，应先恢复服务端，
而不是继续重装客户端。
