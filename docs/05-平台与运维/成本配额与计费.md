## 〇、为什么成本是产品而非基建

AgentCore 是 multi-agent，一条用户消息 = CEO + N 个委派 worker，**花销天然能按 Agent/角色拆开**——这是单 Agent 竞品（Cursor/Codex/Claude）做不到的「团队工资单」。别人只能说「这次花了 ¥X」；AgentCore 能说「CEO ¥0.03 / 调研员 ¥0.05 / 写作 ¥0.04」。所以用量可观测是**产品差异点**，台账的 per-run 聚合视图（由 per-call 明细推导）正是为这个差异点服务。（✅ run 级 ¥ 可拆（`agent_id`）；✅ 人设级拆账：明细/聚合行携带 `persona`，仪表盘按 `COALESCE(persona, role)` 分组，见 §三。）

## 〇·五、计费模式：BYOK 默认 + 每月免费额度 fallback（✅ 已落地）

内测期默认 **BYOK（bring-your-own-key）**：每个用户在「设置·模型配置」自备任意 **OpenAI 兼容端点**（`api_key` + `base_url` + `default_model`），每条对话跑在用户自己的上游额度上。计费模式是 **per-user** 的：`users.billing_preference`（`platform` / `byok`）优先，部署级 `config.billing_mode` 只作注册默认与兜底（`billing/preference.py::resolve_effective_billing_mode`）；用户可在「设置·模型配置」切换（`PUT /users/me/llm-key/billing-preference`）。

**为什么禁用而非删除平台付费**：平台付费整套（全局 key fallback + 配额防线 + 成本账本）是带 DB 列、带防线逻辑的资产；删了再加要跑破坏性迁移 + 反向重建 + 重测一整套计费。故**全部保留**——免费额度（下）正是靠这套资产直接开启。

**一道闸门收口（不撒补丁）**：所有用户向 LLM 调用（云回合 / file assist / sidecar 推理代理）共用 `billing/gate.py::preflight_llm_credentials`，按该用户有效模式分支：

- `byok`：解析用户凭据（`resolve_user_llm_credentials`，fail-safe 永不抛）→ 有 key 直接返回（**不查配额**）；无 key 时——若 `platform_free_tier_enabled` 且平台凭据已配 → **转入平台代付分支（免费档 fallback）**，否则维持 `BYOKKeyMissingError` → **402 `LLM_KEY_REQUIRED`**（开关关闭 = 与旧行为一致）。
- `platform`（显式偏好或免费档 fallback）：平台凭据缺失 → 503 `PLATFORM_BILLING_UNAVAILABLE`；否则过 §一 `enforce_quota`（byok 部署下用 `free_tier_*` 限额组，D7）后用平台 key。

**计费语义（call 级凭据来源，✅ 取代部署级开关算价）**：`calculate_cost` 按**本次 call 实际用的凭据来源**算价、不读全局 `settings.billing_mode`（`llm/pricing.py::resolve_credential_source`，来源标记在凭据/Provider 构造处打上并贯穿 `log_llm_call` / call meter / `_record_proxy_spend`）：

- **用户 BYOK key** → **记账恒 0**（用户自担上游账单，`cost_total_nano=0`），token 照常记入；✅ 另按三层价卡出一笔**估算金额**落 `cost_estimated_nano`（展示用，见下「BYOK 估算可见性」），估算永不进配额 SUM 与平台记账；
- **平台主 key**（偏好 platform / 免费档 fallback / 无 key 用户的后台调用）→ 真实算价入账；
- **厂商 extras key**（`doubao/` 等 `.env` 多厂商 key，恒平台的钱）→ 真实算价入账。

**BYOK 估算可见性（✅ 2026-07-15 落地）**：BYOK 用户此前 ¥ 恒显「—」（平台无权威单价，硬算误导）——现改为**诚实估算**：三层价卡 `resolve_price_card`（`llm/pricing.py`）按 `user_defined`（用户自填单价，挂 `/users/me/llm-key`，输入+输出必填、缓存命中价可选缺省=输入价）→ `estimated`（仓库内社区价目快照 `llm/pricing_data/community_prices.json`，`scripts/sync_community_prices.py` 手动同步自 LiteLLM，运行时零网络请求、模型名仅精确匹配不模糊猜）→ `unpriced`（都没有 = 不出数，**绝不回落 Flash 价**——user 路径乱猜比不猜危险）。`Cost.pricing_source` 全链路贯穿（台账 JSONB / SSE / REST），前端以「≈¥ + 估算」标注展示，与记账 ¥ 视觉隔离。platform/vendor 路径不变：curated 价卡 → 社区表 → Flash 回落 + `cost.pricing_fallback` warning（配额防线宁偏勿空）。

**后台场景降档（✅ 同日落地）**：`title` / `memory` / `compaction` / `followups` 的模型解析优先 `background_model`（用户级，挂 `/users/me/llm-key`）→ `platform_background_model`（部署级，默认空=跟随）→ chat 模型（`resolve.py::_model_for_purpose`）。凭据优先级不变（后台仍用户 key 优先，D6 反白嫖语义保持）——降的只是**模型名**，防 BYOK 贵模型用户被后台调用放血。

> 为什么不是 turn 级标记：同一 turn 可混用用户 key / 平台主 key / 厂商 extras key（多模型辩手），turn 级盖不住；维持全局开关算价则月成本帽形同虚设（平台代付 call 记 0）。

**后台调用（title / memory / compaction / followups）用户 key 优先**：`resolve_model_config` 的 byok 分支后台 purpose 与主回合同样**先用用户 key**、无 key 才落平台 key（吃免费档额度，单次标题生成 flash ≈ ¥0.0006，不做排除机制）。原「有平台凭据时后台无条件优先 platform 省钱」已反转——否则免费档一配平台 key 即激活，BYOK 用户后台调用翻到平台烧钱且有 key 跳配额 = 白嫖不设限，并破坏「有 key 用户零变化」承诺。→ 见 [`平台LLM接入.md` §二](/docs/05-平台与运维/平台LLM接入.md)。

**Key 管理面**：`/users/me/llm-key` GET/PUT/DELETE + `POST .../test`；三字段配置 + probe 连通性与 `supports_tools`；AES-256-GCM 加密落库，明文永不落盘。算法与 fail-closed/fail-safe 决策见 [`安全权限与治理.md` §七](/docs/05-平台与运维/安全权限与治理.md)。状态端点 `GET /users/me/llm-key` 下发 `free_tier_active`（该用户无 key ∧ 免费档开启 ∧ 平台凭据可用）——前端免费档信号**挂既有端点**，不造第二个状态源。

→ 见代码 `billing/gate.py`、`billing/preference.py`、`llm/resolve.py`、`llm/key_service.py`、`llm/pricing.py`、`api/routes/llm_key.py`

### 每月免费额度（平台代付免费档）

> 注册即可用「**每月 ¥1**」的平台代付额度跑真实回合（上游 DeepSeek Flash），额度耗尽引导接入自己的 key；配了 key 的用户一切照旧。动机：激活漏斗的头号摩擦是 BYOK 下发首条消息前必须先去厂商申请 key——免费档让「注册 → 亲眼看到团队分工协作」缩短到 30 秒；额度耗尽的 429 是天然的 BYOK 转化点；UTC 月初重置是回访钩子。对外文案诚实表述为「每月 ¥1 免费额度」，不说「送你 1 元」。

关键决策（2026-07-13 拍板，含被否方案）：

| # | 决策 | 被否方案 + 理由 |
|---|---|---|
| D1 | 额度语义 = **每月 ¥1 免费档**：复用月成本配额维，UTC 自然月重置 | 一次性赠送金（credit 账本）——商业模式未定，不为其预建新表/新 enforce 分支 |
| D2 | 覆盖**所有无 key 用户**；实现挂既有偏好机制的 fallback，不废除用户显式选择 | 「新用户」判定——多一个概念且行为分叉；「纯按有无 key 推导、废除 `billing_preference`」——该列已是完整消费链（注册默认→gate→API 下发→设置页切换） |
| D5 | 耗尽 429 用转化语义：专用 code **`FREE_TIER_EXHAUSTED`**（`FreeTierExhaustedError`，文案后端单一来源）+ CTA 直达模型配置；信号挂既有 `LlmKeyStatus` 端点 | 新造独立「免费档状态」端点/字段——`hasModelAccess` 已消费 llm-key status，双源必漂移 |
| D7 | 免费档专用限额组 `free_tier_*`（见 §一）；全局 `quota_*` 默认不动，留给 `billing_mode=platform` 全员代付模式（内部测试） | 直接改小全局默认——波及「有 key 但显式偏好 platform」的存量用户与内部全员代付模式 |

**开关与回滚**：`PLATFORM_FREE_TIER_ENABLED`（默认 false）；回滚 = 关开关。**注意**：call 级算价修复是无条件的——「关开关 = 与旧行为逐字节一致」的前提是部署未配平台凭据/厂商 key（配了则后台调用与厂商 call 从记 0 变为真实入账，这是修 bug 而非行为回归）。

**sidecar 路径语义**：推理代理配额是 **per-call** enforce——免费档本地引擎回合可能**中途被拒**（帽约束优先于回合完整性，对敞口反而更紧）；云回合维持「回合前一次、不腰斩」。代理对 `QuotaExceededError` / `FreeTierExhaustedError` 返回 **429**（曾误标 402，已修正——前端按 code 分流不漂移）。

**敞口（推算，无真实数据）**：flash 下单个典型多 Agent 回合 ≈ ¥0.03，¥1 ≈ 30 回合。单回合最坏（worker 硬顶 80k × 并行 8，「不腰斩」语义下配额只挡下一回合）≈ ¥0.65–1.5，可打穿月帽——故三维叠防：`free_tier_daily_tokens=200k` 把次日起单日敞口压到 ≈ ¥0.2–0.4。**每用户月最坏敞口 ≈ ¥2–3**；平台总敞口上限 ≈ 活跃注册数 × 该值（已拍板接受）。

**防滥用（复用既有，不新增面）**：注册 IP 限流 + 用户级消息滑窗限流 + `REGISTRATION_OPEN` 关闸 + admin 停用 + inference token 限流铸发（key 提不走，只能在产品内消费）；¥1/月/号的白嫖价值低于刷号维护成本。邮箱验证/设备指纹维持「有滥用信号再加」（[认证与会话](/docs/05-平台与运维/认证与会话.md)）。「先 BYOK 打满日 token、删 key 当日回免费档被日维锁」的边缘行为接受不改（反而防「配 key 烧量再删 key」套利）。

**明确不做**：credit / 余额 / 充值账本（商业化时另案）；新增注册验证；手机端 parity（免费档空态/耗尽 CTA）待桌面验证后另行下放（现状手机仅 `LLM_KEY_REQUIRED` 最小 parity + 契约类型连带适配）。

→ 单测 `tests/test_free_tier.py`；端到端探针 `scripts/probe_free_tier.py`（§八验收 2026-07-14 全过：无 key 真回合入账、耗尽 429 转化、BYOK 含后台零变化、proxy 429 非 402）

## 一、三层防线

三层正交：限流挡「刷得太快」，配额挡「用得太多」，计费只忠实记录、不拦截。

| 层 | 位置 | 管什么 | 失败行为 | 现状 |
|---|---|---|---|---|
| **限流** | 路由层（按用户）+ 中间件（按 IP） | **速率**——单位时间内的请求次数 | 超额拒绝（429 + `Retry-After`） | ✅ 已落地（默认内存单进程；`RATE_LIMIT_BACKEND=redis` 切多 worker 安全的 Redis ZSET 滑窗，含请求级 fail-open） |
| **配额** | 业务层（回合开始前） | **总量**——日 token / 月成本 / 日请求数 | 超额拒绝下一回合（429） | ✅ 强制已落地（含每用户覆盖 + admin `is_unlimited`） |
| **计费** | Finalize（append-only） | **记账**——每个 Run 的真实成本 | 失败 warning + 入落盘队列后台重试，不中断回合 | ✅ 已落地（详见 §三、§四） |

### 限流（速率防线，✅ 已落地）

两个互补的限流器（默认内存、单进程；配 `RATE_LIMIT_BACKEND=redis` 即切 Redis ZSET 滑窗，多 worker 安全）：

- **按用户限流**（✅ 路由层滑窗）：在消息发送 / 重新生成端点按已认证用户限频，挡单账号刷回合。因按用户需已认证主体，落在**路由层**（紧邻 `enforce_quota`）而非中间件；用**滑窗**（非固定窗口）避免边界 2x 突发；被拦的请求不记账。超额抛 `RateLimitedError` → 429 `RATE_LIMITED` + `Retry-After`。→ 见代码 `conversation/rate_limit.py`、`middleware/rate_limit.py`
- **按 IP 限认证端点**（✅ 中间件固定窗口）：限登录/注册/刷新端点（默认 10 次/60s），挡撞库；非 auth 路径与未登录请求放行。→ 见代码 `middleware/rate_limit.py::AuthRateLimitMiddleware`

回合开始前三道闸顺序：**限流（按用户）→ 所有权 → 配额**——限流最外，未过则不做资源级 DB 查询。

前端如何呈现「被拒回合」见 [`../04-前端/前端成本呈现.md` §7.6](/docs/04-前端/前端成本呈现.md)。

✅ 多 worker：`RATE_LIMIT_BACKEND=redis` 经 `RateLimiter` protocol 缝切到 Redis ZSET 滑窗（`RedisSlidingWindowRateLimiter`）/ auth 固定窗（`RedisFixedWindowRateLimiter`），调用点零改动。✅ **请求级 fail-open**：Redis 请求期报错→放行（fail-open）并记 `rate_limit.redis_fail_open`（warning，可告警）；只放松「速率」防线，DB 支撑的「总量」配额防线不经 Redis、不受影响；工厂构造期不可达仍回落内存。→ 见代码 `middleware/redis_rate_limit.py`

### 配额（总量防线，✅ 强制已落地）

> 此防线管**平台代付路径**：`billing_mode=platform` 全员代付，以及 byok 部署下的免费档 fallback / 显式偏好 platform（§〇·五）。**BYOK 有 key 用户不查配额**（用户自担上游账单）。

| 决策 | 内容 |
|---|---|
| 检查时机 | 回合开始前（`enforce_quota`），超额 → 429，不腰斩进行中回合（sidecar 推理代理例外：per-call enforce，可中途拒，见 §〇·五）；免费档路径超额抛 `FREE_TIER_EXHAUSTED`（转化 CTA），其余维持 `QUOTA_EXCEEDED`（等窗口重置） |
| 三维度 | 日 token / 月成本（USD）/ 日请求数；**0 = 该维度不限**。两组默认（D7）：全局 `quota_*` 2M / $5 / 200（platform 全员代付部署）；免费档 `free_tier_*` **200k / $0.14（≈¥1）/ 50**（byok 部署的一切平台代付路径）——月成本是主约束（≈30 个 flash 多 Agent 回合），日 token 是单日敞口硬防线，日请求防脚本刷（`config/quota.py`，起步假设按运营数据调） |
| 每用户覆盖 | `users` 表 `is_unlimited` + 三维度覆盖（NULL=继承所选默认组）；`scripts/set_quota.py` 或 admin API（`PATCH /v1/admin/users/{id}`，见 [`管理员后台.md`](/docs/05-平台与运维/管理员后台.md)）设置——覆盖列最优先，admin 特批机制不变 |

→ 见代码 `conversation/quota.py`（`QuotaLimits.for_user`）、`billing/gate.py`

### 计费记账（✅ 已落地）

每个 **LLM call** 落一行 `cost_calls`（权威明细）；每个 **Run** 在 `cost_events` 有一行物化聚合（产品面工资单 / 仪表盘 / 配额 SUM 读这里）。云回合 finalize 双写聚合；sidecar 经云代理按 call 记明细并物化聚合。详见 §三/§四。

## 二、用量/成本不变量

token 与成本在系统中有多种形态（SSE wire、持久化、API 响应、计费台账），下列不变量保证不会算出两套数、也不会跨用户串账：

1. **唯一原始来源**：单次 LLM 调用的原始 `TokenUsage` **5 字段**（`input / output / reasoning / cache_hit / cache_miss`；`total` 为派生属性），所有用量从它累加。→ 见代码 `llm/protocol.py::TokenUsage`
2. **唯一定价转换**：全系统唯一的 `calculate_cost(model, usage)` 把 token 折成钱（`input / cached / output` 三价分离，缓存命中按 ~50× 更低价计），任何地方要成本一律调它，绝不另算单价。钱一律**整数 nano-USD**（1 USD = 10⁹），杜绝浮点。**按 call 级凭据来源定价**（`resolve_credential_source`，不读部署级 `billing_mode`）+ **三层价卡**（`resolve_price_card`）：来源 `user` → 自填单价 → 社区估算表 → unpriced（记账恒 0，估算走 `cost_estimated_nano` 展示列，见 §〇·五）；`platform` / `vendor`（厂商 extras）→ curated 价目表 → 社区表 → Flash 回落。`Cost.pricing_source`（curated / estimated / user_defined / unpriced）随钱贯穿到台账与 wire。→ 见代码 `llm/pricing.py`
   - **记账与估算永分离**：`enforce_quota` 月成本、admin 全站统计只 SUM `cost_total_nano`；`cost_estimated_nano` 是纯展示列（BYOK 工资单/仪表盘），两列互斥非零（`_split_cost`，`runtime/costing.py`）。
   - **缓存拆分对账**：输入费按 `cache_hit/cache_miss` 拆价，但只要上游不返回 DeepSeek 专属拆分字段（BYOK `base_url` 指向代理/网关、换模型、字段缺失），裸用拆分会把「有 prompt 却无拆分」的输入静默记成 0。故按 `cache_miss = max(input_tokens − cache_hit, cache_miss)` 对账——原生路径（`hit+miss==prompt`）恒等无副作用，缺拆分时整段 prompt 按 miss 计，保证「被计价的输入 == prompt」永不落空。
   - **回落可观测**：未知/未配置 `model` 回落最便宜的 Flash 价（缺价绝不腰斩回合），但可能把 Pro 回合低估约 3×，故回落时打 `cost.pricing_fallback`（warning）而非静默，便于从日志发现漏价。

**真正的钱以 `cost_events` 台账为准**（不变量 #1）；`Message.usage` / `runs` 里的成本只是展示快照。新增任何成本展示点 → 复用统一定价函数，勿手算单价。

3. **会话归属不在写路径校验**：`cost_events.conversation_id` **无**指向 `conversations` 的 FK；推理代理写入不查「该会话是否属当前用户」。读侧一律按 `(user_id, conversation_id)` 收敛（`user_id` 来自鉴权令牌）→ **无跨用户泄漏**；伪造/错挂 id 至多把本人花销记到本人账本里无权的会话上。热路径不加归属 DB 查是有意取舍。→ 见代码 `api/routes/inference/proxy.py`（写头注释）、`db/models/billing.py`

## 三、台账：per-call 明细 + per-run 聚合（✅ 已落地）

| 决策 | 内容 |
|---|---|
| 粒度（②） | **per-call 明细（`cost_calls`，权威）+ per-run 物化聚合（`cost_events`）**。云回合与 sidecar（经云推理代理）同构：代理侧按 call 记明细并按 `run_id` 物化聚合；云 in-process 经 `log_llm_call` 入明细、finalize 双写聚合。明细携带 `role`（结构桶）+ `persona`（人设标签，如「调研员」）+ `run_id`/`agent_id`/`parent_run_id` |
| 货币（①） | 整数 nano-USD；冗余 `cost_total_nano`（记账）与 `cost_estimated_nano`（BYOK 估算，展示专用）双标量列供窗口 SUM，两列互斥非零 |
| 幂等 | 明细 `call_id` unique；聚合 `run_id` unique（finalize DO NOTHING；代理物化 DO UPDATE） |
| 写入时机 | 每成功 LLM call → 明细；turn finalize / 代理物化 → 聚合；与 assistant message 共享 `message_id`（背景调用 NULL） |
| 写入失败语义 | 同步写失败：warning + **落盘出队后台 drain 重试**（at-least-once）；回合正文已先提交，不因账本失败回滚 |
| 失败 run 计费 | 硬失败（worker `raise_on_error` 抛错、CEO/续跑循环崩溃）仍按**已完成轮**入账——`usage_sink` 把已计量 usage 从抛点带出，经 `calculate_cost` 折钱落 `FAILED` 行（token 已真花在用户 key 上，漏记 = 平台/用户白付）；用户主动取消（`CancelledError`）**刻意不记账**（`except Exception` 不捕 `BaseException`） |
| 真相源 | `cost_calls`（明细权威）；`cost_events` 为产品读侧聚合视图；`Message.usage` 仅展示快照。开发期无历史回填——老行可缺明细/`persona`，读侧 `COALESCE(persona, role)` 兼容 |

→ 见代码 `runtime/costing.py`、`db/repositories/billing.py::CostEventRepository`、`billing/attribution.py`、失败计费 `runtime/runs/executor.py::_priced_failure`

> **旁路解耦（重度并行止血 · ✅）**：共用落盘账本队列 `billing/cost_ledger_queue.py`——推理代理 `_record_proxy_spend`（`proxy.py`）与云 in-process call meter、主回合 finalize / handoff 同步写失败时一律入队。后台 drain 写 `cost_calls` / `cost_events`（at-least-once，`call_id` / `run_id` UNIQUE 去重），写库走 **telemetry 独立池**——与正文写 `primary` 池按 `DatabaseSettings` 分预算（`config/database.py` 双引擎）。故重度并行 debate 打爆连接池时，计费 / 审计 / journal / roster 等**遥测写永不饿死正文落库**（journal write-behind、audit / roster 回合内异步投递 + 回合末 flush，均走此池）。落盘队列**单进程**本地盘即可；**多 worker 化前须迁 Redis / DB outbox**（本地盘多实例会丢 / 双消费，代码注释已标）。→ 见代码 `billing/cost_ledger_queue.py`、`billing/proxy_spend_queue.py`、`config/database.py`。

## 六、成本预估 ≠ 实际记账

团队组建时提供启发式预估，与真实记账是两套东西，刻意如此：

- 预估用途是**比较不同团队组合的贵贱**（「三个 premium 模型会很贵」），不是预测真实账单
- 算法基于固定假设（Captain 跑 3 轮、队员各 2 轮，每轮约 3000 输入 + 700 输出 token）
- 假设串始终展示给用户，确保该数字永远不被误当成事实
