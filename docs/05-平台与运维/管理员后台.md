# 管理员后台

> **状态**：P0–P2 后端 `/v1/admin/*` + 独立 web 控制台 `apps/admin` ✅ 已落地。→ 见 §三 模块范围。

面向平台运营者（创始团队）的管理界面。与「设置 → 成员」（仅邀请码）不同，这里管控**跨用户**的账号与平台。

## 一、形态决策：独立 web 控制台（apps/admin）

**决策**：管理后台是**独立 web 应用**（`apps/admin`），**不**塞进桌面端（Electron）。

**为什么（按分量）**：

1. **架构契合**——admin 本质是「`/v1/admin/*` 之上的薄 CRUD 客户端」，不需要桌面端的 sidecar / 本地文件系统 / MCP / inference-token 机制；独立 web 是它最干净的形态。
2. **安全 / 运维**——admin 代码不下发到消费端桌面包；可锁在独立访问路径（内网 only / IP allowlist / 未来 2FA）；独立部署不受 Electron 自动更新滞后拖累；爆炸半径隔离。
3. **零浪费**——后端 `/v1/admin/*` 与前端形态无关，是真边界也是稳定面；独立形态不浪费后端工作，也省掉「从桌面端抽离」的迁移。
4. 与 `cross-platform-frontend` 一致——「各端全新建 + 只共享 contract-types / design-tokens」的又一「端」。

**被否**：A 扩「设置 → 成员」页（设置区窄列放表格挤、admin 代码混入消费端）；B 桌面内 `/admin` 路由（同样混入消费端、背桌面壳）。两者安全增益都只是「换个端口」——真安全取决于访问路径，而非源码放哪个目录。

## 二、鉴权 / 访问姿态（决策）

| 维度 | 决策 |
|---|---|
| 真边界 | 后端 cookie 会话 + `AdminUser`（`role==admin`）→ 403；前端只是客户端 |
| 登录 | **独立登录页**，cookie 限定在 admin origin（不复用桌面会话）|
| 网络 | **内网 only / 不挂公网反代**（独立形态安全价值的大头）|
| 加固 | admin 2FA / 单独凭据 ⏳ P1 |
| CORS | 后端按 admin origin allowlist + credentials |

## 四、后端契约（✅）

`AdminUser` 门控（401 未认证 / 403 非 admin）。

| 端点 | 行为 |
|---|---|
| `GET /v1/admin/overview` | 总览 Dashboard：今日脉搏 + 账号计数 + 近 7 日趋势 + 部署健康 + 近期错误 feed（`trace_id`/`conversation_id` 供下钻）。**纯读侧聚合** |
| `GET /v1/admin/users` | 全量名册，分页 + 子串过滤 |
| `PATCH /v1/admin/users/{id}` | 部分改 `role` / `status` / 配额。配额**三态**：字段缺省 = 不变 / `null` = 清覆盖回继承全局 / 值 = 设（0 = 该维度不限）|
| `POST /v1/admin/users/{id}/reset-password` | 生成一次性临时密码、改哈希并清锁定，同时**吊销该用户全部 refresh（强制登出所有设备）**；临时密码**仅在响应体返回一次**。复用 `AuthService`，未知用户 → 404 |
| `GET /v1/admin/users/{id}/detail` | 用户详情下钻：单账号 + 本人用量 + 最近会话 + 最近回合活动（`turn_metrics`）|
| `GET /v1/admin/usage/summary` | 全站用量看板：跨用户聚合；byok 下为各用户**自带 key** 花费之和 |
| `GET /v1/admin/observability/summary` | 运营观测：回合健康 + 趋势 + 近期错误 feed |
| `GET /v1/admin/observability/conversations/{id}` | 会话复盘：消息 + `turn_metrics` + `cost_events` + `turn_journal` spans **跨源合并时间线**；admin **跨用户**（任意账号会话）。无正文回合以「裸回合标记」入线（消息 ⟕ 回合 外连接），复盘绝不藏失败 |
| `GET /v1/admin/system` | 系统状态只读：计费模式 + 全局配额 + 健康 + 版本 |

路由与参数 → 见 OpenAPI / `api/routes/admin.py`。

**护栏（service 层）**：admin 不能改**自己**的 `role` / `status`（防自锁——账号不硬删，唯一通往「零 admin」的路径是最后一个 admin 改自己，故此一条即保证恒有 ≥1 active admin）。停用即时生效：被停用账号下次请求 `get_current_user` 复检 `status` → 401（无需吊销令牌）。

**P1/P2 复用既有聚合与基建，不另起炉灶**：跨用户口径 = `CostEventRepository.aggregate_*_for_window` 去掉 user 过滤（`user_id=None`）+ 新增 `aggregate_by_user_for_window`（join `users` 取展示名）；账本聚合 dict → cost/usage schema 的映射抽到 `api/cost_view.py`，与 `/v1/usage/summary` **共用一份**（账本已定价，只读不重算）；DB 探活 `database_ready` 下沉 `db/base.py` 成单一源（`/readyz` 与 `system` 同源），版本复用 `system.py::app_version`（与 `/version` 同源）。

**运营观测的数据源 = `turn_metrics` 表（DB），不是日志文件**：产品 AI 运行时日志（`logs/dev.jsonl`）是给 dev/cursor AI 排查的 firehose，且**生产默认仅 stdout**（`settings.log_file` 缺省空）、文件只追加无索引、不含消息正文——不适合在线给 admin 查。故在回合持久化尾（`conversation/service.py` 的 `chat.turn_complete` / `chat.resume_complete` choke point）**best-effort 落一行 `turn_metrics`**（与成本落账同一铁律：遥测写失败绝不炸用户回合），把回合已算好的结果/质量（status / finish_reason / rounds / duration / delegated / workers / tokens）写进库，看板用带索引 SQL 聚合。钱在 `cost_events`、正文在 `messages`，均以 `trace_id` 与 `turn_metrics` join（故复盘三源可拼，遥测行不重复存钱/正文）。

**tool/LLM span 级明细复用 `turn_journal` 投影，不另起 `span_metrics` 表**：span 事实（`llm_call` / `tool_call` …）**早已落 Postgres**（`turn_journal`，回放/热修的唯一事实源，按 `turn_id`=assistant msg id），故会话复盘的「执行明细」是对它的**读侧投影**（`load_map` 批量 + 压缩成 triage 用的 `ReplaySpan`，丢掉系统提示/完整结果等重负载），零新表零迁移。per-agent 花销/耗时也已在 `cost_events` 可聚合。**唯一**会让 `span_metrics` 扁平表成立的是「跨回合 span 聚合」（工具/模型健康看板：工具 X 的 p95 耗时、按模型错误率——对 `turn_journal` 的 JSONB 全扫不可扩展，同 turn_metrics vs 日志的理由）；该看板需求尚未提出，故暂不立表（YAGNI）。per-span 延迟当前未可靠落账（执行事实多无 ts），需要时是给 `ToolCallFact`/`LlmCallFact` 补 ts/duration 的小增强，非新表。

→ 见代码 `api/routes/admin.py`、`admin/service.py`、`api/cost_view.py`。配额维度语义见 [`成本配额与计费.md`](/docs/05-平台与运维/成本配额与计费.md)。

## 五、前端（apps/admin, ✅）

独立 web 应用：**独立登录页**，cookie 限定在 admin origin（**不复用桌面会话**）。五页（概览 / 用户 / 邀请码 / 分析 / 系统）由 `AdminShell` 侧栏 + 页内 active-tab / active-view 切换（用户详情、会话复盘为页内下钻，非 router），默认落「概览」。

**信息架构（去重为纲：每个明细事实只在一个页存在一次）**：

- **概览** = 枢纽：今日脉搏 4 个 KPI tile（点即深链：活跃用户→用户 / 回合·错误率→分析·健康 / 成本→分析·成本 / P95→分析·健康）+ 部署健康灯带（数据库 / 计费模式，点→系统）+ 近期错误 preview（5 行，点行下钻会话复盘，「查看全部」→分析·健康）。**不重渲染明细**——`/overview` 仍含 7 日数组，但趋势图只在「分析」渲染。
- **分析** = 用量 + 观测合并（两者同构：窗口卡 + 7 日趋势 + 表 + 会话复盘下钻，仅指标不同），顶部 `成本 | 健康` 分段切换，右侧常驻「会话 ID 复盘」框；**仅当前段拉取**对应接口（`/usage/summary` / `/observability/summary`），不一次拉两份。
- **用户 / 邀请码 / 系统**：名册（+详情下钻，详情页头部「重置密码」→ 确认→一次性临时密码弹窗，仅展示一次 + 复制）、邀请码（行内「撤销」，`active` 才可撤，确认弹窗 + 状态回填 `revoked`）、部署只读快照；账号计数的唯一家在「系统」。

→ 见代码 `apps/admin/src/pages/`（`OverviewPage` / `AnalyticsPage` / `UsersPage` / `InvitesPage` / `SystemPage`）、`apps/admin/README.md`
