# 对话日志分析指南

> **Why**：产品 AI 回合的结构化事件在 `logs/dev.jsonl`（JSONL），完整正文在 Postgres——查失败回合靠 **trace_id 全链路**，不是搜 Cursor 转录。
>
> **How（操作步骤权威）**：用户给出 32-hex / UUID / 排查包时 → **只读** [`.cursor/rules/conversation-logs.mdc`](/.cursor/rules/conversation-logs.mdc) CLI 开查。本文不重复 CLI；**单次贴 ID 勿整篇读本文**（词表 / Token 两口径 / 接缝深挖再开对应节）。
>
> **默认证据面**：`log_timeline` 人读与 `--json` = **`decision_spine`**；全量事件流用 `--raw`。现码 `spine_events` = **turn_spine**（会话 turn 目录），不是产品面。
>
> **排查包（P1）**：`--pack <dir> --trace <tid>` 写出可投递目录——必有 `decision_spine.json`（契约 v0）+ `timeline.jsonl` + `meta.json`（含 `schema_version` / traffic / jsonl 断档 / 导出时间）；有 join 时附 `turn_metrics.json` / `messages.preview.json`；显式 `--full` 才带 `messages.json`（无 LLM body）。另一会话只读包内文件即可复盘。
>
> **Dogfood 入槽（P2）**：出包后仓库根 `python evals/dogfood/fill_from_pack.py --pack <dir>` 写入空 `pending_label`（只填真实 id；三维分可选人工）。最短路径 → [`evals/dogfood/README.md`](/evals/dogfood/README.md)。

## 接缝（日志 ↔ DB）

| | 产品 AI 日志 | Cursor IDE 会话 |
|---|---|---|
| 位置 | `logs/dev.jsonl`（仓库根；20MB 轮转） | `agent-transcripts/`（与产品无关） |
| ID | `trace_id` = **32-hex 无连字符**；`conversation_id` = UUID | 文件名 = 带连字符 UUID |

- **全链路键**：`trace_id`（同一次用户交互，含进程内委派）；会话 → `conversation_id`；单次回合运行 → `attempt_id`；持久回合 → `message_id`（≡ journal `turn_id`）。
- **`chat.turn_start.via`**：执行路径 `sidecar|cloud`，与工作区 `location`（local/server）正交；decision_spine head 会抽取。
- **本地回合 spine**：sidecar 回写后云端认 `chat.local_turn_recorded` 为 decision_spine head+close 锚（**禁止**再冒充双写 `chat.turn_start/complete`）；工具失败粗码/工具名见 `chat.local_turn_tool_failures` → spine `decisions`（不发假 `tool.execute_end`）。
- **本机互斥拒**（横幅 `turn already running: <uuid>`）：事件 `sidecar.turn_already_running`；**不进** `pnpm sync:logs`——查安装机 `userData/logs/desktop.jsonl`（及本机 sidecar 日志），勿只 sync 云端空转。**冷 resume 已不再走这条**（撞宿主槽改 deferred，见 `resume.deferred` / `resume.deferred_started`），本事件现仅覆盖 `startTurn` 撞键。
- **DB join**：`messages` / `cost_events` / `run_sessions` 带 `trace_id`（assistant / 落账有值；user / handoff 常为 `NULL`）。键集合权威 → [后端架构 · Context 注入](/docs/02-架构/后端架构.md)。
- **不落完整正文**；`preview` / `reply_preview` ~200 字；`LOG_LLM_BODIES` 开时有截断脱敏 `llm.request`/`response`。
- **模块入口**：事件注册表 `observability/catalog.py`（`sync_log_event_registry.py` 生成）；查询层 `observability/query/`；CLI `log_timeline.py` / `log_stats.py`。新增埋点写 `logger.info("component.action", …)` 后 sync——**勿手改**下方事件表。

## Token 两口径（decision_spine vs turn_metrics）

复盘时 **`llm.*_tokens` ≠ `tail` / `turn_metrics` tokens 不一定是 bug**：

| 口径 | 来源 | 含义 |
|---|---|---|
| **llm**（spine） | 同 `trace_id` 全部 `llm.call` 合计 | **全 trace**（含 pause 前 / team_preview 前） |
| **tail / turn_metrics** | 收口折账（`turn_metrics` 优先，否则 JSONL close） | **本段结算**；`kind=resume` / `chat.resume_complete` 通常只有 resume 段 usage |

spine JSON：`llm.token_scope=full_trace`；`tail.token_scope=settlement` 或 `settlement_segment`（resume）；`health.token_accounting` 有短说明。人读 timeline 在两数不一致时会打 `Token口径:` 行。**勿把差值当计费漂移去改账**——先看是否 resume。
