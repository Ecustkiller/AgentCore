## 一、设计基线

| 维度 | 选择 | 理由 |
|---|---|---|
| 登录标识 | **用户名 + 密码** | `username` 唯一非空；`email` 可空，留作后期找回/OAuth |
| 令牌传输 | **httpOnly Cookie** | 前端 `credentials:include`、CORS `allow_credentials=True`；SSE/fetch 天然带 Cookie，前端 JS 拿不到令牌明文（抗 XSS） |
| 令牌载体 | **双 Cookie**：access（短）+ refresh（长，path 限 `/v1/auth`） | refresh 限定 path，减小暴露面 |
| 密码哈希 | **argon2id**（`pwdlib[argon2]`） | 规避 passlib+bcrypt≥4.1 兼容坑；salt + 参数内嵌于哈希串 |
| 注册开放性 | **邀请码**（`invites` 表） | 公网防滥用 |
| 暴力破解 | 失败计数 + 5 次锁定 15min | |

> **Schema 真相源**：本仓 ORM + alembic 是数据库 schema 的**单一真相源**。→ 见代码 `db/models.py`、迁移目录。

## 二、数据模型

四张表（→ 见代码 `db/models.py`）：

| 表 | 说明 |
|---|---|
| `users` | 账号主体；`role∈{user,admin}`、`status∈{active,disabled}` |
| `credentials` | 密码与锁定状态，与账号资料 1:1 解耦 |
| `invites` | 邀请码；一次性，用后置 `used_at`；admin 可主动作废置 `revoked_at`（终态，不可再注册） |
| `refresh_tokens` | 轮换 + 重用检测的载体；**库里只存哈希** |

设计约束：

- **密码只存哈希**：argon2id，不可逆，无明文列。
- **refresh 只存哈希**：明文（`secrets.token_urlsafe(48)` 高熵随机串）发给客户端，库存 SHA-256 摘要——高熵随机串无需慢 KDF，热路径用快摘要即可。
- 遵循数据建模约定（无 ForeignKey、UUID 主键、`server_default`），见 [`../02-架构/核心接口定义.md` §6.2](/docs/02-架构/核心接口定义.md)。

## 三、令牌模型

| 令牌 | 形态 | 生命周期 | 用途 |
|---|---|---|---|
| access | **无状态 JWT**（HS256，claims `sub`/`type`/`iat`/`exp`） | 默认 30min | 所有 API 请求，随 access Cookie 自动携带 |
| refresh | **不透明随机串**（库存哈希） | 默认 7d | 仅换新 access；随 refresh Cookie 带到 `/v1/auth` |

access 校验是纯本地 JWT 解码（无需查库）；任何无效/篡改/过期/类型不符一律抛 `AuthenticationError` → 401，调用方统一翻译。

## 四、端点契约

`POST /v1/auth/{register,login,refresh,logout}` + `GET /v1/auth/me`。响应模型与字段 → 见代码 `api/schemas.py`。

| 端点 | 失败（决策语义） |
|---|---|
| `register` | 422 邀请码无效/已用、用户名占用、弱密码 |
| `login` | 401 用户名或密码错误（**不区分账号是否存在**）、账号锁定 |
| `refresh` | 401 缺失/无效/过期/重用（并清 Cookie） |
| `me` | 401 未认证 |

**邀请签发（admin 专属）**：`POST /v1/auth/invites`、`GET /v1/auth/invites`、`POST /v1/auth/invites/{id}/revoke`（撤销未用码 → `revoked`；已用/已撤销 → 422，未知 → 404）；非 admin → 403。首个 admin 用 `scripts/create_admin.py` 引导（鸡生蛋问题）。

**用户管理（admin）**：含 `POST /v1/admin/users/{id}/reset-password`——生成一次性临时密码、改哈希并**吊销该用户全部 refresh（强制登出所有设备）**，临时密码仅在响应体返回一次。详见 [`管理员后台.md` §四](/docs/05-平台与运维/管理员后台.md)。

> **注入约定**：`AuthUser`（401）/ `OptionalUser` / `AdminUser`（403）。权限在 **service 层**校验。

## 五、刷新令牌轮换 + 重用检测

refresh 单次使用，every refresh 把旧令牌标 `rotated_at`，并在**同一 `token_family`** 内签发后继（仅 login 起新 family）：

| 场景 | 行为 |
|---|---|
| 令牌首次交换 | 标记 `rotated_at`、同 family 签发后继 |
| 已 `rotated`/`revoked` 的令牌再次出现 | 判为泄露/重放 → **吊销整个 family**（`revoke_family`），强制重登 |
| 令牌已过期 | 拒绝 |

> **与原设计的偏差**：原设计含「10s 并发宽限窗口」应对多标签页善意并发；**当前实现未做宽限窗口**——任何已轮换令牌再现即连根撤销 family。多标签并发刷新可能互踢，待 Phase 3 评估是否补窗口。

## 六、静默刷新与流式通道约束

> ✅ 前端已接 401→刷新→重放链（含 SSE 流式通道）。以下为静默刷新**必须遵守的约束**。

access 过期由 401 触发刷新 → 换新 → 重试原请求，对用户无感；refresh 过期才真正跳登录。重发安全：401 在认证依赖层抛出、handler 未执行、请求无副作用，可安全重发。

**关键约束——流式通道必须各自接入刷新**：聊天 SSE（发消息、恢复、异步委派流）通常绕过统一 HTTP 封装直接 `fetch`。这些通道**必须各自包一层 401→刷新→重发**，否则「读了半小时再发消息」会因 access 过期直接掉登录，而非无感续期。**新增任何绕过统一请求层的 fetch/XHR 通道时，都须接入此机制。**

## 七、Cookie、CSRF 与易踩坑

- **refresh Cookie path 坑**：当前桌面端直连 `/v1/auth/refresh`，故 path 限定 `/v1/auth` 可正常回传。**但若改为 web 与 api 同源、反向代理把 `/api/` 重写到后端**，则按 RFC 6265 浏览器实际请求路径需以 Cookie path 为前缀，否则 Cookie 永不回传 → 静默刷新 100% 失败（dev 直连测不出，仅生产触发）。改部署拓扑时务必复核此项。
- **CSRF**：当前仅靠 SameSite 兜底（默认 `lax`）。原设计的 **SameSite=Strict + 写操作校验自定义头（X-CSRF 双提交）未做**，归入 Phase 3。`lax` 为兼容本地跨端口 / Electron 自定义协议客户端；待客户端 Origin 固定后可收紧到 `strict`。
- **CORS 源可配置**：`CORS_ALLOW_ORIGINS`（逗号分隔）取代硬编码 localhost；凭证式 CORS 禁用 `*`，须逐一列源。CORS 中间件置于限流外层，故 429 也带 CORS 头。**Electron 生产包走 `file://`（Origin `null`），跨站无法带 Cookie 到远端 API**——仅放行 CORS 不够，需 Web 与 API 同站（反代）或改 `app://` 自定义协议 / Authorization 头模式；属部署架构决策，尚未实施。
- **排障口径**：「总是掉登录」先查刷新链路（Cookie path / SSE 是否接入刷新 / 轮换是否互踢），调长 access 过期时间只是掩盖、非根治。

Cookie 属性与实现 → 见代码 `routes/auth.py` `_set_auth_cookies`、`config.py`、`.env.example`。

## 八、资源隔离（IDOR 堵漏）— 全库权威

多用户上线必须与鉴权同期堵住越权直接引用。**本 § 为 IDOR 防护的唯一定详述点**；其他文档仅交叉引用此处。

| 决策 | 内容 |
|---|---|
| 作用域 | 受保护资源查询一律按 `user_id` 归属过滤（如 `conversations.py` 全端点注入 `AuthUser`） |
| 失败语义 | 非属主访问 → **404**（`NotFoundError`，不泄露资源是否存在） |
| 闸门 | `send_message` 与 interaction resolve 均先校验会话属主 |

IM 会话同理：非 `chat_members` 成员 → 404（见 [`消息IM.md`](/docs/05-平台与运维/消息IM.md)）。
