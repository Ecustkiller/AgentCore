## 总览

全 AI 并行开发，5 阶段推进，预计 3-4 周完成 MVP Day 1。

| 阶段 | 目标 | 时间 | 累计 |
|------|------|------|------|
| Phase 0 | 脚手架 | 1-2 天 | 2 天 |
| Phase 1 | 基础层 | 3-5 天 | 7 天 |

### 并行开发流（Development Streams）

全程使用 4 条并行开发流，分别由不同 AI Agent 负责：

| 开发流 | 职责范围 | 贯穿阶段 |
|--------|---------|---------|
| **S-Core** | `core/` `llm/` `orchestrator/` `engine/` | Phase 1-3 |
| **S-Agent** | `agent/` `tools/` `memory/` | Phase 1-3 |
| **S-Frontend** | `apps/desktop/` 全部前端 | Phase 1-3 |

## Phase 2：核心逻辑（5-8 天）

### 目标

端到端流程跑通：用户发消息 → 编排器生成计划 → Agent 执行（含工具调用）→ 结果流式推送到前端。单 Agent 和多 Agent 串行/并行都可用。

### 任务清单

#### S-Core 开发流

| # | 任务 | 具体交付物 | 测试要求 |
|---|------|-----------|---------|
| 2.1 | 编排器主逻辑 | `orchestrator/planner.py`：接收用户消息 + 历史 → 调用 LLM（fast 模型）→ 输出 `OrchestratorPlan`（plan_type, agents[], steps[], checkpoints[]）；含 system prompt 装配逻辑 | 简单请求→single_agent计划；复杂请求→multi_agent计划 |
| 2.2 | 编排器 Prompt | `orchestrator/prompts.py`：`SYSTEM_PROMPT` 模板（角色定义 + 输出 schema + 示例）；`build_planning_messages()` 函数（注入用户消息、历史、记忆上下文） | prompt 拼装结果符合 DeepSeek 格式 |
| 2.3 | 流式 JSON 解析器 | `orchestrator/parser.py`：增量 JSON 解析器，在 LLM 流式输出过程中逐步解析 `agents` `steps` 字段；解析到第一个 step 时即可返回，不等完整计划 | 部分 JSON → 正确解析已完成字段；畸形 JSON → 优雅降级 |
| 2.4 | 检查点审视器 | `orchestrator/reviewer.py`：接收原计划 + 中间结果 → 调用 LLM → 输出 `ReviewDecision`（continue / adjust / escalate）；adjust 时生成新计划片段 | continue/adjust/escalate 三种决策均可触发 |
| 2.5 | TaskGraph 数据结构 | `engine/graph.py`：DAG 数据结构，`add_step()` `get_ready_steps()` `update_status()` `get_dependents()`；支持拓扑排序验证无环；支持运行时添加/删除步骤（Hot DAG Modification） | 构建 DAG → 获取就绪步骤 → 更新状态 → 获取下一批就绪步骤 |
| 2.6 | 事件驱动调度器 | `engine/scheduler.py`：`Scheduler` 类，核心循环 `run(plan)` → 扫描 ready 步骤 → `asyncio.create_task` 启动 Agent → 等待完成事件 → 处理结果 → 触发下游步骤；含 `max_parallel` 控制（默认 10）；含 graceful shutdown | 并行步骤同时启动；串行步骤按序执行；失败步骤不阻塞无关分支 |

### 关键演示场景

```

  → 编排器生成调整后的新计划
```

## 风险与缓解

| 风险 | 影响阶段 | 概率 | 缓解措施 |
|------|---------|------|---------|
| 编排器 prompt 效果不佳 | Phase 2 | 高 | 先用硬编码计划走通端到端流程，再迭代 prompt |
| 流式 JSON 解析不可靠 | Phase 2 | 中 | 容错解析 + 超时回退到等完整 JSON |
| DeepSeek API 不稳定/限流 | 全程 | 中 | 指数退避重试 + 本地 mock 开发模式 |
| 图视图动画性能 | Phase 3 | 中 | ELK 布局计算异步化 + 限制动画并发数 + requestAnimationFrame |
| 2C8G 服务器资源不足 | Phase 4 | 低 | MVP 限制并行 Agent ≤ 10；内存紧张时降级单 Agent |
| 前端等后端 API 被阻塞 | Phase 2 | 中 | 前端使用 mock API 先行开发，API 就绪后切换 |
