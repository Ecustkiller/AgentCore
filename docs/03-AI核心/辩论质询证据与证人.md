# 辩论质询证据与证人

> **权威范围**：质询式交锋、证据台账；结辩 / 证人 = 冷冻回放（旧场 + 单测），产品开辩热路不探测、不接线。主干循环见 [辩论编排设计](/docs/03-AI核心/辩论编排设计.md)；前端 → [辩论室 UX](/docs/04-前端/辩论室UX.md)。
>
> **主循环归属**：随辩论归「**组**」+「**看**」；本文是其交锋质量面 → [主循环](/docs/01-产品/产品定位与品牌.md)。

## 一、决策：独白相递 → 质询式交锋

三支柱咬合：质询产出交锋事实 → 小结写清让步 / 仍争议 / 无据 → 举证让「无据」结构可见。复用 round / `continue_run` / SSE / 双产物，不重建引擎。

**否决**：① 只改辩手 prompt；② 独立 Arena / 独立 SSE；③ 质询 CX 全开（仅正反 DEBATE 走 CX）。

## 二、质询（P1）

- 主持人对各方发尖锐必答题；被质询方以 `continue_run` 在**自己的 transcript** 上答——非新辩手。
- 仅正反 DEBATE；回避由裁判读 Q↔A 裁定（诚实认输 ≠ 回避）；前端只渲中性 Q→A，不贴褒贬。

## 三、倾向怎么来（不再打分）

- 裁判直接写收场倾向 / 胜负手 / 把握；不把比分当产品中间步骤。旧场事件可带 `scores`，界面忽略。
- 无据判断仍按【来源等级】：一手/权威可撑结论；决定性事实仅靠单一二手即便【已核实】也只算弱。当场文案用已核实·待核实·二手·深读，不教「弱源/待评」。

## 四、举证（P3，方案 A 内联）

- 关键事实紧跟 `【已核实·#eN】` / `【待核实·推断】`；未标按待核实。
- 诚实标【待核实】不罚；把无据当已核实才点明。待核实/单一二手不得当既定事实定倾向。
- 场级台账：`#eN` 可溯；成稿 id 闸＝本方笔记引用集；不上 `citations_event`。
- **方案 A 而非 B**（结构化 `claims` 演进未上）。已核实=success 绿、待核实=muted 灰（禁用琥珀）。用户面徽章不叠域名档位（官方 / 弱源 / 待评）；来源等级只在裁判内部消费。

## 五、结辩（P4，方案甲）

- **冷冻回放**：只服务旧场磁带与单测。产品开辩热路不跑、不接线（`closing_enabled` 恒假）。
- 回放形态：短结辩、硬禁新论点/新证据；协作图一列=一轮（质询折进同轮节点；旧场若有结辩则「终章」列）。否决质询/结辩全独立成列。

## 六、两阶段成稿 + 来源账

- 检索笔记（不进 outputChunks）→ 无工具干净成稿；冷冻结辩 runner 不检索。否决靠 preamble 剥除治收工混入。
- 辩手检索顶与 worker 共用 `engine_worker_token_ceiling`（独立辩论档已并入）。
- 让步 / 仍争议 / 本轮新点写进该轮小结，对照前几轮已出现过的点判还有没有新论点。来源账（`#eN`）仍单独存在。旧场若带对局事件，结辩回放仍可读；新场续辩不再另注入一本对局账。

## 七、证人模式

- **冷冻回放**：只服务旧场磁带与单测。产品开辩热路不探测、不接线（不把调研员拉进场、不点名证人）。
- 回放路径：无透镜 session → 整场零行为；失败/空点名不阻塞。答问挂证人节点（不挂调研宿主）。
- **否决**全量续派转任辩手（冷起接线/图锚/RunSpec 契约硬墙 + 滤镜污染中立）。
