# 运行时三模型与挂起

> **权威范围**：Interaction / Turn Journal / Run 三模型、端口契约、一轮一网关。入口 → [执行引擎](/docs/03-AI核心/执行引擎架构设计.md)。
>
> **主循环归属**：「**拍**」的机制底座（挂起 / 恢复怎么做到不丢状态）；产品口径在 [检查点与开工卡](/docs/03-AI核心/检查点与开工卡.md) → [主循环](/docs/01-产品/产品定位与品牌.md)。

依赖：Interaction 最小独立；Journal 是 Run 的地基；Run 落在两者之上。

## Interaction（唯一挂起原语）

收编审批 / `ask_user` / 本地工具 / `plan_review` / `team_preview` / 委派授权 / 阻塞升级 / 逐轮辩论 / `stage_card`。热路 `POST …/interactions/{id}`；冷路 `POST …/resume`。`delegation_authorization` **半退役**（并入开工卡；kind 保留回放）。

| 决策 | 取值 |
|---|---|
| pending 真相源 | journal fold；**否决**新建 `interactions` 表 |
| 不答语义 | 默认无限等待；废除静默 auto-DENY / 超时回落 |
| orphaned | turn 终了 / sweeper / resolve 410 / abort·retry·stop；**断连 ≠ 失效** |
| 同对话并发 | 见下节 [同对话再发](#同对话再发steer--queue)；热挂起→409；冷 paused 可发消息 |
| 冷卡 × live | 见下节 [冷 resume 与 live 交叉](#冷-resume-与-live-交叉deferred)；**否决** busy 时 409 丢放行意图 |
| 跨端 | 补齐客户端；**否决**后端按客户端能力降级 |

⏳ 跨进程等待（Redis BLPOP）。

## 冷 resume 与 live 交叉（deferred）

冷 `plan_review` / `ask_user` / `team_preview` 与 D9「paused 可另开 live」交叉时的完整语义（✅ 定案）：

| 决策 | 取值 |
|---|---|
| 点继续 / 提交时仍有 live | **收下决策**：`prewrite` settlement 后同连接 SSE 先发 EPHEMERAL `resume_deferred`（`busy_reason=wrap_up\|live_turn`），槽空后再 claim + 同连接续跑；对齐「发送即有流」排队姿势 |
| `busy_reason` | `wrap_up`＝registry 上仍是本 `message_id` 宿主收口；`live_turn`＝其它回合占槽 |
| 与 FIFO | 槽空时 **冷 deferred 优先于** `turn_queue` FIFO；deferred 跑完再 drain 排队消息 |
| Stop | 只停 live，**不清**冷帧 / 不撤销已 prewrite 的放行；卸锁后 deferred 被唤醒 |
| 卡「取消」 | 与 Stop 正交；deferred **之后** settlement 已锁（D1），不可再改口取消放行——UI 改展示「已记下」 |
| 断连 | 同排队：等待中断连不丢已写 settlement；槽空后可 detached 续跑 |
| composer 旁路 | 发送 = **另开一轮**，**不**取消冷等待（禁「发送将取消等待」假文案） |
| 本地引擎（sidecar） | ✅ 与云端同语义：busy 时 prewrite 后经 `turn/event` 发 `resume_deferred`，槽空再 claim 续跑，RPC 应答延到跑完。**否决**本机互斥硬拒 `turn already running`——冷挂起帧可 claim 时宿主 task 常仍在 D1 hold 等 detached 工人，硬拒会让「补派与在跑队友并行」这一产品目的失效 |
| 重复提交 | 同 `message_id` **幂等 join**：共用同一 waiter，不重复 prewrite，两条请求共享同一次续跑结果；顶替（last click wins）只适用于同会话**另一张**冷卡 |
| **否决** | busy→409 丢意图；resume 自动 cancel live；有冷卡就禁发；发送清掉 paused 帧 |

→ 见代码: `api/routes/conversations/turns.py` · `runtime/turn/runs.py` · `runtime/turn/queue.py` · `sidecar/server_pkg/handlers.py` · 桌面 `ResumePrompt` / `composerPendingHint`

## 同对话再发（Steer / Queue）

用户在同对话再发消息的三种意图（**已定案**；P0 ✅ · P1 ✅）：

| 原语 | 意图 | 入口（产品） |
|---|---|---|
| **Steer** | 软插入当前回合，不硬停 | 空闲：Enter / 主发送；生成中：草稿旁「插队」次级钮 / Ctrl/Cmd+Enter（桌面）；已排队项「立刻插队」（取消该项 + 同内容 steer 重发，仅 cancel 确认才重发）；`delivery=steer` |
| **Queue** | 当前回合完整结束后再开新回合 | 生成中：Enter / 主发送「排队」（默认；图标文案与空闲发送区分，禁复用 Send 冒充发送）；`delivery=queue` |
| **Stop** | 硬打断 | 主槽停止**常显**（有草稿时与插队/排队并存，对齐手机；与发送解耦，**否决**发送默认=Stop&send） |

| 决策 | 取值 |
|---|---|
| 请求体 | `delivery: "steer" \| "queue"` **必填**；缺 → 422；**否决**缺省回落旧自动分流（开发期无兼容层） |
| 空闲 | 开新回合；客户端仍带 `delivery=steer` |
| 热挂起 | `approval` / `delegation_authorization` / 用户侧 `escalation`（`awaiting==ceo` 除外）→ **409**；Steer/Queue 均不可绕 |
| 协调活跃 + steer | 现 `user_interjection` → CEO；CEO 可智能升格为排队（仅 Steer 路径） |
| 协调活跃 + queue | **强制** FIFO（绕过 CEO 插话） |
| 经典 in-flight + queue | 现 `turn_queued` FIFO，同连接续流；drain 时新回合 sink 首帧 `turn_queue_started` |
| 经典 in-flight + steer | ✅ ReAct/工具步边界真注入（DURABLE `user_interjection`：`received`→`injected`；收口 leftover → `queued` + `turn_queued.degraded_from=steer`）；无 accepting 窗口 → 回落 queue（`degraded_from=steer`，不进插话生命周期） |
| 排队取消 | ✅ 按 `queue_id`（`POST …/queued-turns/{id}/cancel` + EPHEMERAL `turn_queue_cancelled`）；Stop/abort **≠** 取消排队 |
| 出队开跑 | ✅ EPHEMERAL `turn_queue_started`（`queue_id` / `remaining_depth`）；**否决**靠前端 `message_start` 猜出队 |
| 协调升 FIFO | ✅ `enqueue_and_ensure_drain(emit_live_queued=True)` → live sink `turn_queued`（条可见可取消） |
| 条内容权威 | ✅ `GET …/queued-turns` 进程内 FIFO 快照（`queue_id` / `content` / `position` / `interjection_id?`，后者标明该项由插话升格而来）；三个 EPHEMERAL（`turn_queued` / `turn_queue_started` / `turn_queue_cancelled`）降为「队列变了」信号。对账时机：开 / 切会话 · SSE 重连（含 204 无 live）· `turn_queued` 报了本地没有的 `queue_id`；**否决**轮询。**否决**只靠 EPHEMERAL 攒条（曾如此）——那只反映「本端某次连接收到过什么」，刷新即空条但队仍在跑、多端不同步、协调升队项永远进不了条因而无法取消。发送路径仍保留 ack 后即时 upsert（省一次往返），对账只做兜底与权威修正 |
| 队列耐久 | 进程内；重启丢队 → 对账发现本地项服务端已无时**一次**轻提示再清（**否决**静默消失）；**否决**本切片做 durable queue |
| 展示 | Queue → 仅 QueuedTurnsBar（条即反馈，不再 toast）；出队开跑再进主时间线用户泡；Steer（经典+协调）→ 共用 `user_interjection` 状态机（协调四/五态含 addressed；经典无 addressed，`injected` 即终态） |
| 插话状态机 | ✅ 协调 `received`→`injected`→`addressed`\|`queued`\|`failed`；经典 `received`→`injected`（终态）\|`queued`\|`failed`。`injected` = 内容真正写入模型上下文（协调：CEO 注入点；经典：ReAct 步顶 drain），是**结构化可证事实**，非启发式推断。同 `interjection_id` 保最新 |
| 时间线落点 | ✅ 插话在助手回合过程时间线上按**真实发生位置**落零宽 marker（`ProcessStep.kind="user_interjection"` + `interjection_id`，与 `team` / `ask` 同构；同 id 只在首次 `received` 落一次，正文与五态仍由旁路 `userInterjections` 按 id 查）。桌面 / 手机各自 fold 同构，过 conformance。**否决**统一挂在助手气泡末尾——插话发生在回合中途，堆到 footer「N 轮 · 用时」之下会造成**因果倒置**（CEO 正文已写「这就让他停下」，用户那句「让他停止」却显示在更下方）。marker 顺带打断 content 尾步合并，经典 steer 正文自然拆成「插话前 / 插话后」两段；纯文本回合的 process 也因结构 kind 而得以持久化。画布 / 协作图**不**表达插话（图只讲拓扑，无回合内时刻维）→ [协作图与双视图UX](/docs/04-前端/协作图与双视图UX.md) |
| 图内处置标记 | ✅ `addressed` 由编排工具汇合点（`execute_tools`）**统一**标：CEO 本步成功用过 `update_synthesis` / `cancel_worker` / `delegate` 任一 → 清 `pending_interjections` 并标 `addressed`（note 按工具区分）。**否决**各工具实现里逐个补标——曾因只有 `update_synthesis` 补，CEO 用 `cancel_worker` 响应插话后 pending 未清、收口被 `promote_pending_on_close` 误升格排队，用户白等一回合且同一件事被答两遍；逐个补属同一根因改多层，遗漏面随新工具持续扩大。**否决**把「只发正文、不调工具」算已处置（启发式）。已知误伤：CEO 无视插话却同步做了图内动作时会误标 `addressed`——取「结构可证的工具事实」优于「猜是否针对插话」。→ 见代码：`runtime/coordination/interjections.py:address_interjections_after_ceo_tools` |
| 事件退役 | ✅ `turn_steer_accepted`（EPHEMERAL 纯 toast ack）**已删除**——它承载的是一条用户发言却不落 journal，刷新即丢、历史重建看不到；统一到 DURABLE `user_interjection`。**否决**保留双事件（语义重叠 = 长期漂移源） |
| 向量顺序 | 经典 steer 向量必须把 `user_interjection` 穿插在 `message_start` **之后**（与协调向量同序）——插队定义上只发生在回合流式输出期间。**否决**客户端为迁就乱序向量加缓冲兜底 |
| 辩论掌舵 | 仍走独立 `/debate-steer`；与主框共用语言、**不**强制并控件 |
| UX 默认 | ✅ 空闲默认 `steer`；生成中默认 `queue`；强制 `steer`（插队）靠显式钮 / Ctrl/Cmd+Enter（桌面）；**否决**伪装「已插入」（插队 ack 只标 `received`，生效由 `injected` 说话；降级才 toast） |
| 状态文案 | 两端逐字对齐：`received`「已送达，等待主 Agent 读取」· `injected`「主 Agent 已看到」· `addressed`「已纳入本回合合成」· `queued`「将在下一条回复处理」· `failed`「未被处理」。徽章与服务端 `note` 是**两层**：note 讲具体原因（「未能排队，请重试或再说一次」「本回合已中止，这条插话未被主 Agent 读取，已丢弃」等），徽章只讲结果——`failed` 两种成因（Stop 丢弃未读 / 转排队失败）下插话都**已送达**，故**否决**「未送达主 Agent」这类措辞（曾用，与 note 自相矛盾）。`addressed` 仅证明 CEO 本步成功用过图内处置工具（见上行），**不**证明正文回应了用户 → **禁**用成功色（勿假绿）；**否决**加「是否先回用户句」的结构化门禁（属启发式判服从度） |

### 已知行为（真跑 · 平台 DeepSeek · 2026-08）

以下为**已验证、按现状接受**的语义（非缺陷清单；若要改须另定案，禁顺手补丁）：

| 情境 | 实际行为 |
|---|---|
| 单轮散文（无后续 ReAct/工具步） | 仍可立刻 `user_interjection(received)`；若本回合再无步顶可 drain → 收口 **leftover 升队**，live sink 再发 `user_interjection(queued)` + `turn_queued.degraded_from=steer`（诚实纠正）；用户补充常落在**下一回合** |
| 多轮 / 有工具步 | pending 在下一轮步顶 `drain` → `engine.turn_steer_inject` + `user_interjection(injected)`，**同回合**消化（真跑已见注入标记进同一条助手回复） |
| Stop 与排队 | Stop **不清** FIFO；当前回合结束后 **立即 drain** 下一项——此时按项 cancel 常已 404（项已开跑），属「不清队但会开跑」，**不是**「Stop 后冻结队列」 |

探针（维护者）：`apps/server/scripts/archive/probe_delivery_steer_live.py`（`--suite all`）。

现状：P0+P1 ✅；P2（账户默认 Steer/Queue、辩论文案对齐、队列重排）**未做、可选**。→ 见代码：`messages.py` · `runtime/turn/steer.py` · `runtime/engine/loop.py` · 桌面 `composerDelivery.ts` · 手机 `messageDelivery.ts`

## Turn Journal（唯一事实源）

执行事实与展示事件共用**单一有序日志**；**否决**执行流/展示流分家再归并。

| 决策 | 取值 |
|---|---|
| 落盘 | Append-on-Emit：SSE 送达前先落盘；writer 单消费者 write-behind；owner 终了前必 `flush` |
| process 车道 | 语义边界步落盘（非 per-token）；纯散文回合不扩 `process_*` |
| 流式投影 | token 不进 journal → `turn_stream_state` UPSERT；终态删 |
| seq | live 由 DB 原子分配；merge 保留显式 seq；**否决**无锁 MAX+1 / 主键改 ULID |
| settlement | 同 write-behind 插队必达；dedupe 键须携完整事件 kind |
| 暂停态 | 新增回合内累积态须声明挂起归宿与再水化点（`turn_paused`） |
| 审计 | `agent_audit_events` = 下游只读投影，**非第二事实源** |

投影入口：`TurnState.from_journal`；恢复原语：`recover_turn`（恢复前先 orphan 热路 pending）。

## Run（唯一执行单元）

执行形状是数据（`depends_on`），不是离散模式。辩论/审查 = 主持人确定性循环驱动普通 DAG（**非独立 kind / 无 Arena**）。

| 决策 | 取值 |
|---|---|
| CEO | 根 Run 节点（CAPTAIN）；**否决** `synthesis` 零成本伪 run |
| 嵌套 | `depth ≤ 3` 硬上限；depth=3 永不获 `delegate`；单 lead 扇出 ≤4 |
| RunSession | transcript 可恢复延伸；续派接缝见 [多轮编排与同人续派](/docs/03-AI核心/多轮编排与同人续派.md) |

## 引擎纯化与端口

- 效应模型 `Continue | Handoff | Interact`；显式 `ToolContext`；按能力位非工具名特判。
- 宿主端口契约镜像 `runtime/ports.py`（Journal / EventSink / ClientRequestBridge / ConversationStore 已端口化）。
- **一轮一网关**：Turn 最早解析 `effective_gateway`，整棵委派树同一把，防 split-brain。

⏳：Redis 租约与事件总线；写类工具幂等键；大正文卸 ArtifactStore。
