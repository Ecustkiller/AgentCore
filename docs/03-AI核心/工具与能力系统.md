## 一、能力域架构 ✅ 已确定（⏳ 后端未实现）

> **实现现状**：目标架构，后端尚无 `capability` 模块 / `AgentEntityBinding`。MVP 在 pipeline 固定注册内置工具，无 Skill / Rule 能力实体与绑定。

**四关注点**：能力域 `capability`（能力定义与绑定）/ 市场侧（发现与发布）/ 本地侧（已装+自建）/ 获取通道（安装动作）。

**两铁律**：① 运行时永远只读「本地侧」，不直接碰市场侧；② 本地侧不反向依赖市场侧（市场可整体下线而运行时照跑）。

**单源原则**：Tool / Skill / Rule 经统一 `AgentEntityBinding` 绑定到 Agent；能力曾是 marketplace 子模块——根因是「能力地基盖在了市场楼里」，须拆回能力域。

**逻辑本地先行**：当前本地侧 = 云后端 user 维度私有空间；物理本地（设备侧、离线）留演进，不为后者预建 provider 抽象——两条铁律担保将来只换「本地侧从哪儿读」。

## 二、Skill 架构 ✅ 已确定（⏳ 后端未实现）

> **实现现状**：未实现 Skill 实体 / `agent_entity_bindings` / `consult_skill` / Prompt 自适应注入。MVP 的 `assemble_system_prompt` 仅做默认 prompt + 时间 + 长期记忆 `<rules>` 注入。

**单源原则（否决双源内联+市场）**：Skill 只有「市场实体 + 绑定」一种形态——与 Tool/Rule 对称，消除重复注入；内联 vs 市场应是 `status` 位而非两套存储。

**Prompt 自适应**：技能数 ≤ 阈值全文注入；超阈值目录模式 + `consult_skill` 按名拉取（只能查本 Agent 已绑定技能）。否决：关键词匹配 trigger、embedding 预筛、LLM 预筛。

**Skill ↔ Tool**：Skill 永不自动注入工具——绑定建议返回 `suggested_tools`；运行时对未持有工具注入 `<note>` 软提示。工具集仍由绑定显式决定。

**质量度量（⏳）**：安装数 / 激活数 / 描述完备度 / 用户反馈有效性——细则见 [`../07-规划/远期规划.md`](/docs/07-规划/远期规划.md)。

**Skill 编写规范（⏳）**：五要素 `name` / `trigger` / `guidance` / `constraints` / `output_format`；面向 LLM 祈使句、500–3000 字、步骤明确工具名——完整 checklist 待市场落地后补。

## 三、表达形态 vs 创作产物 vs 受控能力 ✅ 已确定

### 3.1 区分原则

| 类别 | 通道 | 判据 | 示例 |
|---|---|---|---|
| **表达形态** | LLM 直写代码块 + 前端渲染 | 只影响呈现、无副作用、不留可编辑产物 | mermaid / markmap / vega-lite |
| **创作产物** | 用户编辑器 + Agent 工具共编 | 可持久化、可反复编辑 | 导图文档、画布、多维表格 |
| **受控能力** | 工具（Tool） | 读写数据、触发副作用、需审计/计费 | 文件读写、HTTP、代码执行 |

**铁律**：纯可视化表达 = 直写代码块 + 前端渲染，绝不包装成工具；需持久化可跨轮编辑则升级为「创作产物」。

> **表达形态层 ✅ 已落地**：聊天内 mermaid / markmap / vega-lite 三引擎渲染，流式先显源码、回合结束再渲染，失败回退源码。→ 见代码 `apps/desktop/src/renderer/components/chat/Diagram.tsx`

### 3.2 为什么直写优于工具（表达形态场景）

工具通路用于表达时有 4 个累积失败点：参数 JSON 构造 → 工具执行 → 模型原样复读结果 → 目标格式语法正确。直写代码块消除前三个失败点，且天然支持流式（半截大纲仍是合法大纲，半截 mermaid 是语法错误）。

### 3.3 文本为典范模型

当内容同时被人和多 Agent 协作创作时，**典范模型应为 Markdown 文本**（非富文本 JSON/AST）——LLM 输出文本、本地 `.md` 落盘是文本、AI diff 也是文本。由此推导：文本即真相、AI 协作一等公民、聊天与编辑器共享渲染核、绝不损坏字节。

### 3.4 创作工具：产物的两副面孔 ✅ 已确定

「创作工具」每个对应一种**产物类型**，与「动作工具」并列：动作工具执行确定性动作不留可编辑产物；创作工具产出可持久 artifact，同时有用户面（UI 编辑器）与 Agent 面（类型注册工具集）。产物统一进文件/产物体系，可被对话 `@` 引用。前端工具箱见 [前端UX设计 §十二](/docs/04-前端/前端UX设计.md)。
