# 检查点与开工卡

> **权威**：`ask_user`、`team_preview` / `plan_review` / `stage_card`。挂起机制 → [运行时三模型](/docs/03-AI核心/运行时三模型与挂起.md)；编排字段 → [编排器](/docs/03-AI核心/编排器与CEO主Agent.md)；前端卡 → [协作图 UX](/docs/04-前端/协作图与双视图UX.md)。

## 一、`ask_user`（通用澄清）✅

**定案（已落地）**：取消「开场 / 开工提案」产品位与场面账；`ask_user` 仅为 CEO 在 ReAct 循环中的**通用澄清步**（可与检索/读文件等任意穿插，可连续多次）。参照通用 Agent（Cursor / Claude Code 式），非垂直生成器式选项闸。

| 项 | 决定 |
|---|---|
| 开场仪式 / kickoff 味 UX / 提案体硬闸 | **取消** |
| 澄清方式 | 多轮短问；**Agent 自主**决定何时问、问什么；交付类建议选项写**桌上结果**（一页先上 / MVP 主流程 / 模块流水线等），不写编制名单；选档后由 CEO 填 `playbook_args.intensity`（→ [编排器 · 团队形态](/docs/03-AI核心/编排器与CEO主Agent.md)） |
| 「就这样开做」开场主 CTA | **不作为**产品主路径 |
| 场面账（`style_options` / `format_options` + 风格/演讲/自动化硬门禁） | **取消**；缺信息靠短问，错了再改。点名载体/手段次优时的顾问短问 ≠ 复活场面账 → [编排器 · 载体/手段顾问](/docs/03-AI核心/编排器与CEO主Agent.md) |
| `team_preview` | **不动**（组队确认 ∪ 能力授权，与 ask 正交） |

**统一机制**：单一 `ask_user` 工具；`blocking`（默认 true）= 模型判断是否冻回合。「该结束还是挂起」归运行时。`blocking=false` 须写明将采用的默认，否则拒调。阻塞检查点 = 挂起即收口，冷路 `POST …/resume`。浏览器需用户登录时 CEO 设 `browser_login=true`（强制 blocking；与 worker `escalate(browser_login)` 同形「需要你登录 / 已登录，继续」卡，**禁止**把完整 escalate 开给 CEO）。

**Live 出卡（桌面 ✅）**：可操作面只靠 ResumePrompt ← InteractionStore cold pending（时间线内联标记 ≠ 拍板面）。`*_required` 入 IX 后须能出卡；`serverMessageId` stamp 晚到则 rebind 立即补画——**否决**靠硬刷新 journal hydrate 才看见。第二轮 / 同会话再次冷挂起：新 host 上真实 `*_required` 可替换已结算墓碑；同 host 重放仍挡。手机 ResumeCard 各自实现（`coldInteractions` / `coldResume`），语义对齐。→ 见代码: 桌面 `stores/interactions/store.ts` · `services/resume.ts` · `ResumePrompt.tsx`；手机 `lib/coldInteractions.ts` · `lib/coldResume.ts`

**卡上 CTA（桌面/手机）**：冷卡（`ask_user` / `team_preview` / `plan_review` / `browser_login`）次要键文案一律「取消」。`ask_user`：主「提交」=`decision: continue`；次「取消」= 拒答（wire 仍 `decision: stop`）→ tool result 回灌 CEO 短续一轮（软引导收口 / 换假设；**不是**空 continue「按默认继续」；对齐开工卡取消与 OpenAI reject→resume）。取消结算桌面不占时间线「已取消」存根，问句回落为普通正文。`plan_review` 三键：继续 / 调整 / 取消。整回合协作停止（`user_stop`；界面「停止 / 已停止」）与此正交，不归本卡——**禁止**把后者 gloss 成取消。

**冷卡 × live（deferred）**：有并行 live / 宿主尚未卸锁时点继续 → 决策立刻 durability（settlement prewrite），SSE 先 `resume_deferred`，槽空后同连接续跑；卡面改「放行已记下…」。旁路发消息不取消等待。权威状态机 → [运行时三模型 · 冷 resume 与 live 交叉](/docs/03-AI核心/运行时三模型与挂起.md#冷-resume-与-live-交叉deferred)。

**何时不用**：简单问答直答；信息已够 → 直接干 / `delegate`；意图都复述不出 → 可先正文澄清，或短 ask——不搞开场提案墙。

**否决**：开场问题墙；独立 `kickoff` 工具；场面硬账门禁；ask 与 `team_preview` 并成超级卡；多步 Wizard。

**现状**：桌面/预览前端统一为通用澄清壳（`AskDecisionBody`）。后端普通 ask intent 默认 `decision`；场面账（`style_options` / `format_options`）**已退役**，不再出现在工具 schema / SSE / resume wire。建站无风格时 `design_prompt_block` 软注入 `s_default`（营销/工具台分域正向配方）+ copy「视觉 thesis / 信息架构」软验收；`web_quality_scan` 仍查 DESIGN.md「用户选定风格 id」。→ 见代码: `CheckpointCard.tsx` · `tools/builtin/ask_user/`、`runtime/runs/website_style.py`、`playbooks/build_site.py`

**建站品味（2026-08 复审）**：维持无场面风格卡。默认路径靠 `s_default` 配方 + thesis，不恢复 `style_options`/风格硬门（与上表否决一致）。若日后真实使用仍「同质化严重」，再议仅用通用 `ask_user` 的软短问（仍禁止场面硬账）。

## 二、检查点与团队预审

| 原语 | 触发 | 语义 |
|---|---|---|
| `ask_user` | CEO 关键岔路 / 信息不够 | CEO 工具效应（通用澄清，见 §一） |
| `plan_review` | step 标 `checkpoint_after` | 波间结构挂起；前置强制 CEO 把关摘要 |
| `team_preview` | `delegate`/`debate` fan-out 前 | 计划确认 ∪ 能力授权（公共 kickoff gate） |

**delegate 卡**：≥2 worker，或本地 `command=kickoff` 需能力授权 → 挂卡。动作：授权并开工（可嘱咐；可**单向收紧写盘**为仅文字＝`form=prose`，不硬卸写工具）/ 取消。**主文案**：wire `headline`＝交付档短标 + 预计人数（有 `playbook_args.intensity` 时如「MVP主流程 · 预计 3 人」；无则「预计 N 人开工」）；角色分工表为次要预览。旧帧无 `headline` 时前端按人数回退。队员行展示写盘能力标签（`可改文件` / `仅文字报告`，由 `deliverable.form` 推导）；模型身份**只读**（默认跟组合 Worker 槽；CEO/`tasks[]` 节点显式仍有效）。确认面**不提供**排除岗 / 人改模入口（`excluded_run_ids` / `model_overrides` 契约可保留，与产品确认面用法解耦——编制纠偏走嘱咐或取消回灌；改模 → [编排器 · Per-worker](/docs/03-AI核心/编排器与CEO主Agent.md#per-worker-模型覆盖abc-同一功能)）。对抗视角走独立 `debate` 工具与辩论开工卡；**不**再经 delegate task 的 stance/round 展示标记挂卡或画「辩论」徽章（该假通道已收口）。→ 见代码: `runtime/kickoff/summary.py` · `runtime/kickoff/team_veto.py` · `TeamPreviewCard.tsx`  
**debate 卡**：顶层一律弹；动作：授权开赛（可嘱咐）/ 取消。`research_first` 键已退役——「庭前取证内化」指质量前提（约定文档桥 / Evidence Pack / 发言期有界检索入台账），**≠** 庭前调查员舰队，勿再当开工前先调研关卡或代派取证员流程 → [辩论编排 §五](/docs/03-AI核心/辩论编排设计.md)。

**阶段推进卡 `stage_card`**：幕间一步授权（如「按此开辩」= 机制直起、`skip_kickoff`）。**否决**二步制与「发消息即 orphan」。→ 见代码: `runtime/kickoff/stage_card.py`

**跳过**（仅既有结构轴；勿新增「是否开工」意图启发式）：单 worker+`finalize`；含 `checkpoint_after` 时计划半边让位；`team_kickoff=skip` 放行两半边；嵌套/`light`/续跑不挂；`stage_card` / MLR preauth 等既有机制。`team_kickoff=always` 在仍该挂的场景总挂。**禁止**把同回合已确认的阻塞 `ask_user`（`checkpoint_resolved`）当作跳开工卡条件——与 §一「`ask_user` ⊥ `team_preview`」对齐：澄清卡与开工卡正交，同回合先 ask continue 再 ≥2 worker `delegate`/`debate` 仍会挂 `team_preview`（双卡是预期）。

**专用卡**（`card` 参数，不新增 kind）：`proposal_pick` / `risk_ack` / `organize_plan` / `daily_review`（站立任务·每日复盘勾选墙）；主拍板四选一通则在提示词层。权限三轴 → [安全 §三](/docs/05-平台与运维/安全权限与治理.md)。`plan_review`/checkpoint **不受**三轴影响。
