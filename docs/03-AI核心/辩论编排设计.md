## 核心定位与重设计动机

辩论是 MVP Day1 范式之一（见 [`Agent协作模式.md §一`](/docs/03-AI核心/Agent协作模式.md)）。旧设计把它压成 `delegate` 上的三个展示标记（`stance`/`group`/`round`，display-only）+ 一段教 CEO 手动展开跨轮 DAG 的 Skill 配方，执行器/调度器完全忽略这些标记。这在「形状是数据不是模式」的技术教条下是自洽的，但**从用户需求倒推，它牺牲了辩论真正的价值**：

| 旧设计的产品级缺陷 | 后果 |
|---|---|
| 「轮次」是技术概念泄漏到产品层 | 让 CEO（甚至用户）去管理「第几轮、谁依赖谁」，把实现细节当成了功能 |
| 产物缺失 | 跑完只有「正反并排卡 + CEO 一段简短概览」，再甩 `ask_user` 让用户**自己**在正反里选——辩论很热闹，却没为用户的决策负责到底 |
| 辩论质量无人把关 | 正反可能各说各话（没真交锋）、强度不对等、轮数到了却没收敛 |
| 二元 pro/con 过度简化 | 真实需求里的「红队单向批判」「多方圆桌」被硬塞进正/反两栏 |
| 老板插不上话 | 辩论一旦开打就是黑盒跑完，用户无法中途掌舵 |

**重设计主张**：辩论需要一个**有状态的主持人层**来承载「发起对抗 → 逐轮判收敛 → 裁决 → 产出过程与结论」。当初否决「独立 Arena 子系统」（独立 SSE / 状态机 / `arena` RunKind）否得对——那是过度工程；但连带把「辩论需要主持人」也否了，是把洗澡水和孩子一起倒了。本设计把主持人加回来，**但它不是独立执行引擎，而是 CEO 之下、辩手之上的一个编排角色**，底层仍用现有的并行委派 + 上游产物注入执行。

> **用户拍板的四条方向**（本设计的地基）：① 辩论的**过程本身也是一等产物**（不为出结论而降级过程）；② 引入主持人/裁判一等角色；③ 支持红队单向 + 多方圆桌（破二元）；④ 轮次由收敛自停、对用户隐藏（用户/CEO 永不设轮数）。

## 一、产品目标与三问

**目标**：用对抗性多视角思考，帮用户得到一个他能信、考虑过反面的**结论或决策**，同时让他能看懂**思想如何交锋**。

| 三问 | 答案 |
|---|---|
| 谁用 | 面向大众的决策者 / 学习者 / 方案作者 |
| 解决什么真实问题 | ① 帮我做决策（选 A 还是 B）；② 压力测试我的方案（红队挑刺）；③ 学懂一个有争议话题（多方观点光谱）；④ 娱乐性思辨（少数） |
| 产品上如何呈现 | 用户只抛「问题」或选一个「形态」，不碰任何参数；产出**过程（交锋叙事线）+ 结论（决策简报）双产物** |

**核心洞察**：用户要的几乎从来不是「轮次」这个过程指标，而是辩论的**产物**——更可信的结论 + 看得懂的交锋。「轮次」是手段，必须对用户隐藏、由系统自调。

## 二、支点：主持人（Moderator）循环

主持人是「**主持 + 裁判 + 书记**」三合一的有状态编排角色。一轮循环四步：

1. **定本轮议题**：首轮把用户问题拆成争议焦点（`_frame`，并产开场白）；后续轮优先采用上轮裁判
   `verdict.next_focus`（assess 兼产、真去重——裁判刚读完本轮发言判未收敛时已从「仍存分歧」压出下轮焦点，
   避免下一轮开头 `_frame` 再读一遍同材料），缺失 / 空串 / 坏 JSON 时才回退 `_frame`；用户掌舵
   `focus_override` 始终最高优先。
2. **派各方发言**：底层 = 一波并行委派（辩手 worker），自动注入对方上轮产物（复用执行器现成的「## 前置结果（来自 X）」注入，见 [`执行引擎架构设计.md`](/docs/03-AI核心/执行引擎架构设计.md)）。首轮另可注入 CEO 随 `background` 传入的**案件底料**（以主持人名义、双方共享，见 §7.1）。
3. **质询交锋 beat**（`_cross_exam*`，`thorough=True` 才开）：立论之后、裁判之前，主持人代表交锋向各方发**定向必答质询**（直指本轮最站不住脚 / 最缺证据 / 涉嫌谬误的点），被质询方走 `continue_run` 在自己 transcript 上**先正面回答再展开**。把交锋从「我猜你会说 X 于是先反驳」变成「你当面问、我当场答」——`real_clash` 不再靠首轮硬凑而是结构上必然发生。详见 §四之二·质询回合。
4. **裁判本轮 + 记分 + 写小结**（`_judge_and_summarize`）：一次结构化调用同产三件事——裁判（有没有**真交锋**？是否**还在产生新论点**？可否收场？）＋**逐轮记分**（论点强度 / 回应完整度 / 证据充分度三维 + 谬误·无据硬拗的罚分，读「立论 + 质询问答」一起判）＋本轮小结（争议焦点 / 已达成共识 / 仍存分歧，「过程产物」骨架）；未收敛时顺带把「仍存分歧」压成 `next_focus` 供下一轮直接采用。三位一体读**同一份本轮发言**，合并成一次调用去掉冗余 LLM round-trip（真去重，非节流）。详见 §四之二·记分裁判 / 举证责任。
5. **决策下一步**：收敛 → 出决策简报收场；未收敛 → 进入下一轮；遇关键分歧 → 可选请老板掌舵（见 §六）。

**收场前的结辩 beat**（`_closing*`，`thorough=True` 且对抗形态才开）：循环收敛后，主持人给每位仍在场的辩手一次 `continue_run` 的**结辩机会**——短而有力地收束自己的胜负手（回收本场最强论点 + 直面对方最致命一击），**禁止**再抛新论点/新证据、受更紧的阶段化长度预算约束。结辩与决策简报（`_brief`）**并行**（`asyncio.gather`）——二者互不依赖（简报只读 rounds，不读结辩内容），结果仍一并随 `DebateResult` 返回。这是「阶段化发言角色」（P4）：立论 / 质询作答 / 结辩三种发言承担不同修辞职能，让辩论像真人一样有起承转合的收尾，而非戛然而止。详见 §4-2.4·结辩收束。

> 「轮数」= 这个循环跑了几次，由第 4 步的收敛判断决定。**用户和 CEO 都不再声明轮数**——这是旧「CEO 一次 `delegate` 静态展开 2N 个节点」的根本性改变（旧法轮数先验固定、无法运行期收敛）。

**主持人 ≠ 通用语义裁判**：[`多轮编排与同人续派.md §九`](/docs/03-AI核心/多轮编排与同人续派.md) 决定「暂不做判『写得好不好』的通用 LLM 质量校验，沿用机械 contract」。本设计不触碰该决策——主持人的「裁判」是**辩论领域内的交锋质量与收敛判定**（判「是否针锋相对、是否还在产生新论点」），是辩论这个能力的固有职责，不是给普通 worker 产物做通用质量门。两者语义正交。

## 三、三形态统一模型（破二元）

参与方从 `pro/con` 泛化为「**立场标签**」（支持 / 反对 / 某视角名 / 红队 / 方案方），一套主持人循环参数化出三形态：

| 形态 | 参与方 | 交锋模式 | 收敛判据 | 产物侧重 |
|---|---|---|---|---|
| **正反辩论** | 正 / 反 2 方 | 对称攻防 | 无实质新论点 / 焦点已澄清为价值之争 | 简报先行 |
| **红队挑刺** | 你的方案（被审）+ 1~N 红队 | 单向攻击 → 方案方回应 | 风险挖尽 / 方案方已修补 | 风险清单 + 加固建议先行 |
| **多方圆桌** | 3~N 个视角 | 多边碰撞 | 观点光谱已铺满 | 过程 / 观点地图先行 |

用户只选「形态」（甚至只抛问题、由 CEO 自动判定是否值得对抗性论证），**永不碰参与方数量 / 轮数 / 依赖**。

## 四、双产物：过程与结论都是一等

辩论结束**交付两样，都做好，不分主次**（用户拍板第①条）：

### 4.1 结论产物 —— 决策简报

- 争议焦点（双方真正分歧在哪）
- 各方去水后的**最强论点**
- 主持人的倾向性判断 + **置信度**（如「基于事实反方更站得住；但若你更看重 X，则正方成立」）
- 给用户的建议
- **交接清单（handoffs）**：辩论没替用户解决的残留项，统一为单列表 `brief.handoffs[{kind, text}]`，按**解决路径**（谁/什么能把它闭合）分三类——`value`（只有用户的价值观/偏好能闭合）、`fact`（证据能闭合，AI 可接手查证）、`question`（当下闭合不了：等外部事件 / 预测验证 / 后续观察）。判别铁律单一来源（简报 prompt 一处定义，判序：证据能闭合→fact；用户拍板能闭合→value；都不能→question）；未答清的用户追问必须收编、不得石沉大海；关键事实的证据状态语内联在条目文本（§4-2.3 grounding）。条目写法：`value` **问句化**（每条 = 用户可直接回答的一个问句 + 一句「你的选择如何影响结论」）；三键均对齐 `strongest_points`「去水压成单句、只留命门」。
  - **前端呈现（「留给你的」）**：外层标题保留；按 kind 三种**异质形态**——`value` = 问句卡置顶（高光 +「回复拍板」→ composer 预填）、`fact` = 可查证任务列表（「派查证」→ composer 预填）、`question` = 脚注级次要文字。分类名词标签（需你定夺 / 事实分歧 / 待解问题）从 UI 退场，靠形态差异而非标签分组。**被替代**：三分组小节同质 bullet 列表 + 抽象分类名词标签（同形态平铺、靠文案区分，拍板/查证行动不可见）。
  - **落地形态（wire）**：LLM 输出接口保守——仍填三键 JSON（键名即分类指令、输出契约零膨胀），解析层规整为统一 `handoffs`；wire `DebateBriefInfo.handoffs` 单列表，坏 kind 容错归 `question`（不丢内容）。**被替代**：三个平行裸字段 `factual_disputes` / `value_disputes` / `open_questions`——桶间定义重叠矛盾（`open_questions` 曾定义为「需用户拍板」与 `value_disputes` 同义，前端却把它归「无需你定夺」组）、条目无结构承载不了元数据、前端「需不需要你」分组维度靠组件硬编码二次映射。

### 4.2 过程产物 —— 交锋叙事线（三层渐进披露）

这是「过程本身有用」的落地，不是旧的「正反两栏平铺」，而是被主持人组织过、带攻防关系的叙事：

| 层 | 内容 | 服务对象 |
|---|---|---|
| **L1 焦点小结流** | 每轮一句焦点 + 小结，串成一条「认知推进线」 | 速读者：30 秒看懂整场怎么演进 |
| **L2 逐轮攻防** | 每轮 = 本轮议题 + 各方发言 + 主持人点评（谁回应了谁、谁让步 / 新增了什么） | 理解者：看思想如何被攻击与捍卫 |
| **L3 论点级全文 + 交锋边** | 各方完整发言（按 `run_id` 取辩手节点）+ 论点级交锋边「谁驳谁」（裁判逐轮抽取的 `from→to` + 驳的要点，载于 `clashes`，前端据本轮 `sides` 解析成名字/身份色） | 深读者：较真细节、看清谁针对性反驳了谁 |

### 4.3 呈现顺序按形态自适应

- **决策类**（正反 / 红队）：决策简报先行，过程叙事线紧随其后可展开。
- **探讨 / 学习类**（多方圆桌、纯思辨）：过程叙事线先行，简报作为「小结」收尾。

前端落点见 [`前端UX设计.md §四`](/docs/04-前端/前端UX设计.md)。

## 四之二、质询式交锋：让辩论像真人（质询 · 记分 · 举证 · 结辩）

> **动机**：旧辩论的底层原语是「**并行独白相递**」——每方各写一篇独白、看对方上轮快照、再写一篇，交锋靠主持人**事后**从独白里抽 `clash`。真人辩论的内核是「**当面质询式交锋**」：你问我答、逼对方正面回应、举证责任在主张方、裁判据实际交锋记分。三支柱把「独白相递」换成「质询式交锋」，**相互咬合、缺一留漏**：质询（P1）产出「谁回避命门 / 循环论证当场被戳穿」的交锋事实 → 记分（P2）据此奖惩 → 举证（P3）让「无据」变成结构上可见、可质询、可罚。设计推导（『并行独白相递＝病根』的根因分析）已并入上述动机；原提案文档随本次落地退役删除，**被否方案留档**：① 只改辩手 prompt（加 hedge / 压字数 / 要求引用）——治标，症状是「独白相递」原语的下游、prompt 层按不住；② 给辩论造独立 Arena 引擎 / 独立 SSE——沿用 §八 既有否决（全部复用现有执行地基、只改交互契约）；③ 质询 CX 全形态全开——否，`thorough=False` 快速对碰跳过 CX、守轻量意图与延迟。
>
> **状态**：✅ P1+P2+P3+P4 均已落地并过测试（后端 prompt/记分/结辩契约 + 前端渲染 + conformance 金样 `multi_agent_debate` 双端绿）。复用现有 round 循环 / `continue_run` / SSE / 双产物骨架，未重建引擎。P4（结辩收束·阶段化发言角色）是「让辩论像真人」的收尾支柱：真人辩论以结辩定音，本产品此前却在末轮戛然而止。

### 4-2.1 质询回合（P1，契约①）

- **是什么**：§二循环第 3 步的质询 beat。主持人对各方发 2–3 个**尖锐必答问题**（`_cross_exam_questions`，可含「是/否」逼答），被质询方以 `continue_run` 在**自己的 transcript** 上先正面回答再展开（`cx_answer_feedback`）——不是新辩手、是原辩手带记忆答问（`run_started` 携 `continues_run_id`＝现场根 + 原 `stance/group/round`）。作答带**取证预算**：优先基于已有调研与辩论材料作答、确需补证至多 1–2 次检索、拿不出出处按【证据状态铁律】诚实标待核实——质询是逼当场表态，不是再开一轮研究（真实 trace 曾现单方答 3 问打 11 次检索的狂潮）。
- **门槛**：仅 `thorough=True` 开启；`thorough=False`（快速对碰）跳过，守 `QUICK_DEBATER_HINT` 轻量意图与延迟（不与延迟预算打架，见 §二）。
- **数据 / 落点**：`CrossExamExchange`（`runtime/debate/types.py`：`target`/`questioner`/`exchanges[]`/`answer_run_id`，每条交换为 `CrossExamQa`：`question`/`answer`（解析摘要）——**不设** `ok` / 辩手自评二元字段）；编排 `tools/builtin/debate/rounds.py` + `moderator.py`；提问/答问 prompt `tools/builtin/debate/prompt.py`（`cx_answer_feedback` 只要 `question_index` + `answer`）。逐条 Q↔A verbatim 进 `RoundResult.cross_exam`（`answer` 仅为解析摘要），**作答全文不入载荷**、随 `answer_run_id` 的 continue_run 事件走（同「发言全文靠 run_id 关联」的省体量原则）。
- **回避判定（裁判裁定，非辩手自评）**：是否正面回应 / 回避由记分裁判读 Q↔A 原文裁定——落 `engagement`（回应完整度）与收场 `brief.decisive`（胜负手自由文本可点名回避）；**诚实认输 / 让步 ≠ 回避**（正面接招但承认弱点不扣 engagement，论点让步由 `argument` 维体现）。前端质询区只渲染中性 Q→A + 客观状态（作答中 / 作答失败 / 未作答），不贴「正面回应 / 回避」褒贬徽章。
- **前端**：辩论室 `arena/CrossExamSection` 渲染「Q→A」对（作答按 `answer_run_id` 从 settledModel 取回）。

### 4-2.2 记分裁判（P2，契约③）

- **是什么**：裁判从「只判交锋 / 收敛」升级为**逐轮记分**——每回合给各方打**论点强度 / 回应完整度 / 证据充分度**三维分 + **罚分**（循环论证等谬误、无据硬拗），读「立论 + 质询问答」一起判（`_judge_and_summarize` 的 `scores`）。质询是否正面回应**由裁判裁定**（非辩手 JSON 自报）：答非所问 / 打太极压低 `engagement`，诚实认输不算回避；收场 `leaning + confidence` **由累计分推导**、`brief.decisive` **点名胜负手**（谁的哪点被 drop / 证伪 / 无据，或谁在质询中回避命门），不再收场一次性拍脑袋，也不再依赖已删除的 per-question `ok` 二元字段。
- **数据 / 落点**：`RoundScore`（`argument`/`engagement`/`evidence`/`penalties`/`note`/`total`）挂 `JudgeVerdict.scores: dict[side_key, RoundScore]`；`DebateBrief.decisive`。累计跨轮相加，前端据分渲染逐轮比分条 + 收场比分。
- **证据分按【来源等级】分级（grounding）**：`evidence` 维不只看「有没有标出处」，还对【已核实】的出处再分等级——**一手 / 权威源**（判决书 / 官方公告 / 一手档案 / 原始数据 / 财报）可给满；但一条**决定性事实**只靠**单一二手来源**（媒体转载 / 二手报道）撑着时，即便标了【已核实】也只算**弱证据**、`evidence` 封顶打低，除非有**多源交叉印证**才回补。防「决定性结论压在一条未经一手核实的二手报道上」（真实 trace 里「17 次驳回」这类正反都无法一手核实、却被当既定事实的形态）。落点 `moderator.py` 的 `_judge_and_summarize` scores prompt + `_ASSESS_SYSTEM`。
- **不违反「主持人≠通用质量门」**：记分判的是**论证有效性 / 证据 / 是否回应**——正是「辩论**领域内**」的核心裁判职责，是既有裁判的自然延伸，**不是**给普通 worker 产物做通用质量门（守 [`多轮编排与同人续派.md §九`](/docs/03-AI核心/多轮编排与同人续派.md) 决策，语义正交，见 §二末尾）。
- **前端**：`arena/JudgeNote` 逐轮净分 chip（并入主持人小结元信息行）+ `arena/Scoreboard` 累计比分与 momentum 微图。正反辩论另有**「双方一眼看」对照区**（`arena/brief/SidePointsGrid`：两边最强论点 + 累计净分并置；对标圆桌的「观点光谱」、红队的「风险清单」两个英雄区）。收场 `FinaleStage` 内 `FinaleScoreboard` 终盘比分条。
- **记分仅收场消费（设计决策，非缺口）**：live `debate_round` 事件虽携带 `scores`（与收场逐轮单元共用 `to_event_payload` 单一源），但三端 fold 的进行中叙事投影（`DebateNarrativeRound` → `debateRounds`）**有意不带** scores / user_interjections——比分条与计分板只在收场 `debate_result` 后渲染。理由：轮中亮分会把「进行中的裁判观感」当成定论呈现（分数在后续轮次会被翻转），且 live 孪生窄投影守恒「进行中只看焦点/小结/交锋」。

### 4-2.3 举证责任（P3，契约②，方案 A 内联标记）

- **是什么**：每条**关键事实主张**（数字 / 金额 / 日期 / 案号 / 引用 / 先例 / 统计口径）须**紧跟证据状态标记**，二选一——`【已核实·<出处>】`（真用 web_search/read_url 查到出处）/ `【待核实·推断】`（拿不出出处，只是推断 / 常识 / 估算）。未标记的关键事实一律按【待核实】对待。把「无据」从「靠 hedge 自觉」变成**结构上可见、可质询、可罚**。
- **三处咬合（一套标记贯穿）**：辩手**标** → 裁判**据标记记分/罚** → 前端**把标记渲成证据徽章**。辩手侧 `prompt.py:EVIDENCE_RULE` 放进 `side_system`（系统提示只发一次却全程生效，立论/续论/质询作答一律受约束，省 token、口径单一）；裁判侧 `moderator.py` 质询盯紧「标了【待核实】却当决定性论据」、记分把「关键事实标【待核实】/未标却撑结论」判证据弱、把「无据硬拗成既定事实 / 臆造出处」计罚。
- **证据状态继承到结论、收尾不得抹平（grounding）**：举证标记不止约束辩手，还贯穿到**裁决收尾**——`_brief` 与 `to_ceo_output()` 明令：若 `decisive` / `leaning` 依赖的某个关键事实在辩论里是【待核实】或仅【单一二手来源】，不得当既定事实来定倾向，要么在 `confidence` 里显式降级并标【需一手核实】、要么移入交接清单（`handoffs` 的 fact / question 项，§4.1）；结论文字引用这类事实时**保留证据状态词**（如「若 X 属实——目前仅二手报道、待一手核实——则…」）。CEO 据简报收尾时同样**不得把【待核实】/【二手来源】的关键事实写成板上钉钉**。根治真实 trace 的「辩手诚实标了待核实、收尾却抹平成既定事实」（宁可诚实降置信，不拿未核实事实当定论）——与上条【来源等级】记分（§4-2.2）一上一下夹击 grounding。
- **诚实存疑不罚，硬拗才罚**：辩手**诚实标注【待核实】本身不扣分**（诚实存疑是美德），只有「把待核实 / 无据当成【已核实】的决定性论据」才扣。这是关键的激励对齐——否则辩手会为避罚而**假装有据**（正是开发期 fake-IP 取证常失败时最危险的行为）。故本铁律是对取证层 P0 的**正交护栏**：取证坏时辩论**诚实标待核实**而非自信臆造；取证好时它照样有价值（区分「我查到」vs「我推断」是真人辩论基本功）。
- **前端渲染机制**（`remarkEvidence` + `EvidenceBadge`）：remark 插件把内联标记切成自定义 `evidencemark` 元素、渲成证据徽章——**已核实 = success 绿**、**待核实 = muted 中性灰**（绝不用琥珀：设计系统 warning 槽位已退役，且「待核实」是「尚未坐实」而非「错」）。载荷走 `data.hProperties`（`dataKind`）**而非** `cite:`/`evi:` 那种链接 url——后者会被 react-markdown 的 `urlTransform` 按非安全协议清空。**仅辩论发言 opt-in**（`<Markdown evidence>`，`arena/SpeakerBlock` 与质询作答），不扰其余 assistant markdown。落点 `apps/desktop/src/renderer/lib/remarkEvidence.ts` + `components/chat/EvidenceBadge.tsx` + `Markdown.tsx`（`evidence` prop）。
- **方案 A（内联）而非 B（结构化）**：先让「无据可见 + 可罚」跑通，改动小；结构化 `claims: list[Claim]`（可精确统计 / 驱动结构化证据条）作为演进，本期未上（辩手输出契约更重）。

### 4-2.4 结辩收束（P4，方案甲：结辩 beat + 阶段化长度预算）

- **是什么**：§二循环收敛后、写决策简报前的**结辩 beat**。主持人给每位仍在场的辩手最后一次 `continue_run`（在自己的 transcript 上，`continues_run_id` 续原辩手接续链、`round_no` 锚到末轮，UI 归入该辩手的接续链而非新辩手），让其**短而有力地亮胜负手**：回收本场最强论点 + 直面对方最致命一击 + 给用户一句可带走的判断。
- **阶段化发言角色**：一名辩手的三种发言承担**不同修辞职能与长度预算**——立论（铺论据、可长）／质询作答（正面接招、中等）／**结辩（收束定音、最短最紧）**。`CLOSING_LENGTH_HINT`（`schema.py`）给结辩约 150–250 字的紧预算，`closing_task`（`prompt.py`）**硬禁新论点 / 新证据**（结辩只许收束已辩之物）。这解决旧辩论「末轮说完就戛然而止、没有真人辩论那种收尾定音」的产品缺陷。
- **门槛**：仅 `thorough=True` 且**对抗形态**（正反辩论 `DEBATE` / 红队 `RED_TEAM`）开启；快速对碰、多方圆桌（`ROUNDTABLE`，本就为铺光谱、无「收束定音」诉求）跳过（`_closing_enabled`）。全员失败（`STOP_ALL_FAILED`）或无任何轮次时也跳过。
- **数据 / 落点**：`ClosingStatement`（`runtime/debate/types.py`：`side_key`/`side_name`/`run_id`/`ok`）挂 `DebateResult.closings`；`ClosingRunner` Protocol + `make_closing_runner`（`runtime/debate/rounds.py`）；编排入口 `moderator.py`（`run_closing` 参数，收敛后调用）；提示 `prompt.py`（`closing_task` / `closing_context_blocks`——`run_context` 首块 `channel=task` 逐字复用 `closing_task` 返回值、`closing` 块降级纯环节标记，见 §7.3「逐轮真实任务上 wire」）。**结辩全文不入载荷**、随 `run_id` 的 continue_run 事件走（同「发言全文靠 run_id 关联」的省体量原则），`to_event_payload` 只带 `key/name/run_id/ok`。
- **前端**：辩论室 `arena/ClosingBlocks`（结辩陈词分隔 + `SpeakerBlock` 结辩全文按 `run_id` 从 settledModel 取回、`evidence` 徽章照常生效；未产出则标「未产出结辩」）；模型 `model.ts` 的 `resolveClosings` 把 `DebateClosing` 载荷解析成带 `RunNode` 的 `DebateClosingView`。手机 `DebateView` 是**极简摘要视图**（brief + 轮次摘要，本就不渲染质询/记分等富 beat），故结辩同样不下沉手机，与 P1/P2 一致。
- **协作图 beat 折叠（✅ 2026-07 改版）**：协作图**一列 = 一轮**——质询作答（channel=`cross_exam`）不再独立成列，折进同辩手同轮的陈词节点（状态取轮内最差态、耗时/成本/token 合计、直播态状态条显「立论中 / 质询作答中」且输出预览跟随活跃 beat）；结辩保留独立「终章」列。角标口径：首轮陈词无角标、续轮陈词「第 N 轮」、结辩「结辩」；「第 N 轮·质询」随独立节点退场，收场轮节点状态行挂可点「含质询」标记直达该轮质询 run（质询失败时归因「质询作答失败」），beat 级明细仍由侧栏 RunRevisionChain 与辩论室 `CrossExamSection` 承载。wire 契约不变（仍复用既有 `cross_exam` / `closing` channel）；状态条「接续 N 次」照旧**不计**辩论 continue_run（仅 CEO 带现场续派 / redirect 热修）。**被替代**：初版「质询 / 结辩全部独立成列」——thorough 3 轮每方 7 列、卡片同质墙，且图上只承载「答」这半场、讲不了 Q→A 交锋（内容叙事归辩论室）。→ 见 [`前端UX设计.md §五`](/docs/04-前端/前端UX设计.md)。
- **方案甲（结辩 beat + 阶段化长度预算）而非方案乙（完整发言角色状态机）**：先加「结辩」这一最缺、最像真人的收尾 beat + 给各阶段套长度预算，改动小、复用 `continue_run`；把「开场陈词 / 自由辩论 / 交叉质询 / 结辩」全套角色状态机作为演进，本期未上（收益递减、辩手输出契约更重）。

> **测试与金样**（四支柱代码落点见上面各小节「数据 / 落点」，此处不重列）：`conformance/vectors/debate.py`（金样含质询 / 记分 / 证据标记 / 结辩；`multi_agent_debate_multibeat` 钉多轮×质询×结辩列与 channel）；`tests/test_debate_evidence.py`（P3 举证 + A+B grounding 分级 / 结论继承 / 收尾保留 + 查询铁律，15 例）、`test_debate_closing.py`（P4 结辩契约）、`test_debate_moderator.py` / `test_debate_tool.py`（P1/P2 + 边际递减断路器 + 结辩编排）、`test_conformance_projection.py`（金样进度 7/7 与 multibeat 11/11）、`apps/desktop` 图 helpers / 角标单测（质询折进轮节点、结辩列与徽标文案）。

## 五、收敛与轮次治理

**收敛完全由主持人逐轮自判**（§二第 4 步裁判的 `converged`）——没有任何「最小轮数」机械门槛强制多轮。**终止条件**（满足其一即停）：

1. **收敛**：裁判判定各方无实质新论点（开始重复）。
2. **焦点澄清**：分歧已归结为价值 / 偏好之争（AI 判不了，交用户）。
3. **红队耗尽**：无新风险可挖（红队形态专用）。
4. **安全上限**：达到 `max_rounds` 硬上限——纯保险丝（防失控的断路器兜底，**非目标值**，收敛永远可早于它发生）。

前三条都是裁判的判定结果；第 4 条是与内容无关的硬上限。

> **跨轮论点账本不变式（收敛的结构前提）**：终止条件 1「无实质新论点」要判得准，裁判必须**看得见跨轮**。但 `_judge_and_summarize` 天生只吃【当前轮】发言（`history` 仅定 `round_no` + 小结锚点），若不补救，辩手把老论点**换措辞重述**就会被误判成「还在产生新论点」→ 永不收敛 → 撞满 `max_rounds`（真实 trace 5 轮全 `converged=false` 的结构性根因，非 prompt 语气问题）。故裁判额外收一份 `_prior_ledger` 压出的【前几轮已辩论点账本】（focus + 小结 + 交锋要点，用已压缩摘要非全文、守延迟预算），`new_arguments` 据此判「相比账本是否还有**跨轮**新论点（换措辞重述不算）」。首轮 / 无实质前轮时账本空、退化为只看当前轮。校准见 [`evals/debate_converge.py`](/apps/server/agentcore/evals/debate_converge.py)（含 in-round 与 cross-round 两类金标场景）。

> **边际递减断路器（收敛的确定性下限）**：跨轮账本让裁判「看得见重复」，但裁判仍是 LLM、逐轮口径可能漂移。故在其上再加一道**确定性下限**——`_judge_and_summarize` 若判定本轮与上一轮**连续两轮**都无跨轮新论点（`new_arguments=false`），即便 LLM 本轮仍给 `converged=false`，也机械强制收场（`converged=true` / `stop_reason=STOP_CONVERGED`）。这落的正是终止条件 1「无实质新论点·开始重复」的定义，用已有的 `new_arguments` 信号把它兑成一个不依赖 LLM 稳定性的下限：与 `max_rounds`（条件 4）同属断路器，但更早、更省（真实 trace 3–4 轮已复述却硬打满上限）。只补下限、不改裁判语义——首轮 `history` 空恒不触发；逐轮交互下用户仍可在边界 `CONTINUE` 覆写（续辩优先，见 §六）。回归测试 `tests/test_debate_moderator.py::test_diminishing_returns_converges_after_two_stale_rounds` / `::test_single_stale_round_does_not_trigger_diminishing_returns`。

> **`stop_reason` 归一不变式**：`stop_reason` 只在【收敛】时有意义。`_judge_and_summarize` 对 LLM 返回的 `stop_reason` 做归一——未收敛（`converged=false`）强制留空；收敛时校验其落在词表（`converged` / `focus_clarified` / `red_team_exhausted`）内、否则回落 `STOP_CONVERGED`。杜绝「未收敛却带 `stop_reason`」的口径错位流入 journal / 前端（真实 trace 曾出现第 1 轮未收敛却标 `focus_clarified`）。回归测试 `tests/test_debate_moderator.py::test_judge_normalizes_stop_reason_to_converged_invariant`。

**收敛北极星 = 「在不糊弄的前提下，尽快把用户的决策交付出来」**（呼应用户第①条：要的是产物，不是轮次）。这不再靠「跑满 N 轮才许收」，而是内化进【定议题】与【裁判】两处的逐轮标准——

- **定议题：钻决定性分歧，不巡游维度**：后续轮优先用上轮 assess 兼产的 `next_focus`（从「仍存分歧」派生，真去重）；仅当缺失 / 空串时 `_frame` 兜底，盯住「真正决定用户问题的那个分歧」往深里逼（用更尖锐、更逼胜负的子问题推进），只有当它确已辩尽（被事实分出高下 / 见底成价值选择）才转下一个最影响结论的点。仍注入「已谈焦点清单」禁「换个说法重谈」（防冗余「修订 v2」），但旧的「每轮必须换一个正交新维度」——这条把决策辩论推成维度巡游、几乎必然撞满上限的过度约束——已去除。（多方圆桌例外：本就为铺光谱，可自然转新视角。）
- **裁判：价值之争见底 = 收场信号，不是继续信号**：`thorough=True`（认真辩透）≠ 把每个角度都辩一遍——盯决定性分歧往深里辩，一旦它被事实分出高下、或见底成「只能用户拍板的价值/偏好选择」即判收敛；仅当还能冒出「会改变结论」的实质新论点时才继续。`False`（快速）= 核心交锋一清晰即收。**旧「仍有未决关键交锋就别收」已废**：它与「分歧归结为价值之争即收」（终止条件 2）自相矛盾——价值之争天生就是永远未决的关键交锋，于是价值承重的题（法律 / 决策等本产品主场）每场都撞满上限、`focus_clarified` 永不触发。
- **第 1 轮（开场立论）默认继续**：各方此时通常只是各自亮出立场、尚未真正接火（`real_clash=false` 是常态），默认判「未收敛」以逼出下一轮真交锋；**仅当**命题空泛到开场就无新论点时才许收。
- **快速单轮**（`max_rounds=1`）：一次对碰即收，裁判不强求多轮。

这样绝大多数决策辩论自然收在 2–3 轮，`max_rounds` 回到「罕见兜底的纯保险丝」定位（本节开头的设计原意）。也根治了旧机械楼层病：trivial 命题被强逼跑满 N 轮 → 续写者输入几乎相同 → 冗余「修订 v2」节点。

| 形态 / 模式 | `max_rounds`（安全上限） | `thorough` |
|---|---|---|
| 正反 / 红队（认真辩透） | 5 | `True` |
| 圆桌（探讨型，铺光谱即可、略紧） | 4 | `True` |
| 快速对碰（任意形态，轻量意图） | 1 | `False` |

`thorough=False` 对**所有形态**（含圆桌）一律快速单轮——轻量意图不该被强制多轮。轮数永不暴露给用户设定：用户只选形态（或由 CEO 据意图判 `thorough`），收敛由主持人逐轮自调，`max_rounds` 只兜底。

## 六、老板可掌舵：ambient 非阻塞插手

用户是老板，应能在辩论中途介入（不微操辩手，只对主持人表达，承袭 [`多轮编排与同人续派.md §一`](/docs/03-AI核心/多轮编排与同人续派.md) 的心智）。✅ 已落地：**ambient 掌舵**——辩论默认自动跑、**永不硬停**；有活跃用户时掌舵恒可用，用户随时把「继续辩 / 加角度 / 追问 / 够了收」fire-and-forget 送进 steer 队列，主持人在**下一轮边界非阻塞**捞起应用（§6.1–6.5）。收场后若还不满意，用户自行在对话框对 CEO 说话、CEO 重开一场全新辩论（§6.6）；外加**用户侧**站队（会话内态，§6.7）。

> 心智模型：用户是「**带着倾向旁听、能随时插一脚的第三方**」——干预只作用**议程 + 价值层**，**绝不篡改事实层**（保 AI 裁决的中立可信）。前端呈现见 [`前端UX设计.md §四`](/docs/04-前端/前端UX设计.md)。

### 6.1 触发与门槛（有活跃用户即武装）

- **开赛前另有一道门（编排层开工卡 ✅ 2026-07）**：顶层 `debate` 在主持人循环启动前经编排层公共 kickoff gate 挂 `team_preview` 开工卡（`primitive=debate`：辩题 / 各方立场 / 轮次预算；辩手只读 → 能力半边恒空；`full_auto` 不弹；调整 = 用户改写辩题后开赛、立场保留）。与本节**中途**掌舵正交：开赛前 = durable 否决权，开赛后 = ambient 永不硬停。挂起 / 跳过规则单一源见 [`编排器与CEO主Agent.md` §五](/docs/03-AI核心/编排器与CEO主Agent.md)。
- 辩论**默认自动跑**（裁判逐轮自判收敛）。CEO **不再**传 `interactive`——该参数已从 `debate` schema 删除。
- 门槛 `ambient_armed`（= 服务端 `checkpoint_enabled`）：有活跃用户即武装 ambient 掌舵；自治 / handoff 不武装 → 纯裁判自判。与其它检查点共用「有活跃用户」总开关。
- **永不硬停**：掌舵不阻塞主持人循环；用户不插手时循环与旧「非交互」路径逐字同辙。

### 6.2 在哪生效、谁说了算

- 主持人**每轮小结后**走轮边界钩子（`Moderator.run` 的 `on_round_boundary`；与 emit `debate_round` 的 `on_round` 正交）——**非阻塞** `take_steers(execution_id)`。
- 空队列 → 回落裁判自动收敛；有 steer → 用户选择**覆盖**裁判：`continue` 即便裁判要收也续；`conclude` 即便裁判要续也在该边界收场（`stop_reason=user_concluded`）。
- **conclude 下一轮边界生效**：用户在某轮生成中途 fire conclude → 当前轮先跑完，到边界才收场（不腰斩正在生成的轮）。

### 6.3 掌舵动作（常驻输入，非挂起卡）

赛事页主列常驻 `SteeringPanel`（辩论进行中可见），fire-and-forget 提交后回显「已发送·下一轮生效」：

| 动作 | 语义 | 落到引擎 |
|---|---|---|
| 继续辩一轮 | 再来一轮（裁判要收也续） | `continue`，无 focus |
| 按此角度继续 | 给下一轮指定议题角度 | `continue` + `focus`（覆写下一轮焦点） |
| 够了，出结论 | 下一轮边界收场出简报 | `conclude`（`stop_reason=user_concluded`） |

**追问（叠加项）**：可选【追问文本 + 定向某方/全场】，与 continue/conclude 一并提交（`ask` + `ask_target`）。注入下一轮辩手 prompt（`round_feedback`）+ 终审交代是否被回应，verbatim 进 `debate_result.rounds[*].user_interjections`（conformance `multi_agent_debate_followup`）。

### 6.4 机制：复用 redirect 模式的 in-process steer 队列

- **通道**：`runtime/debate/steer_queue.py`（同 `runtime/runs/redirect_queue.py` 模式）——按 `execution_id` 排队的进程内 fire-and-forget 队列；API `POST …/debate-steer`（云）/ sidecar `debateSteer`（本地）。
- **载荷**：`{execution_id, decision∈continue|conclude, focus?, ask?, ask_target?}`。drain 时 last-wins 折成一条 `RoundBoundary`，折进现成的 `pending_interjections` / `focus_override` / `CONCLUDE`（辩/判/记分逻辑不动）。
- **摘除**：旧阻塞式 `InteractionKind.DEBATE_ROUND` + `debate_round_decision_required` / `_resolved` 事件 + resolve 路径——不再每轮挂起等用户。
- **被否**：① 再造持久化交互 / 新 journal 字段绕过；② 把 ambient 做成另一种阻塞（drain 必须非阻塞）；③ CEO 猜 `interactive`。

### 6.5 前端落点

掌舵**常驻**在赛事页主列 `arena/SteeringPanel`（非「暂停才冒出的挂起卡」）；记分牌有「掌舵」快捷滚到输入区。画布指挥台对辩论仍 `includeDebate=false`。呈现见 [`前端UX设计.md §4.3`](/docs/04-前端/前端UX设计.md)。

### 6.6 收场后再辩（用户对 CEO 说话 · 全新辩论）

用户选「够了，出结论」后若不满意，**不**复活已收场的协程，也**不再**走结构化播种续辩。产品决策（2026-07）：续辩专用链路整体下线——用户在对话框对 CEO 说话，CEO 重开一场**全新辩论**（无 `debate_seed`）。

**曾落地又移除**：结构化补轮（`SendMessageRequest.debate_seed` → …）——与「用户自己对 CEO 说话即可」重叠，维护成本不相称。

**否决（历史仍成立）**：① durable debate resume；② 会话内软撤销窗；③ 服务端自动取最近辩论结果作种子。

### 6.7 站队（用户侧 · 会话内态）

**站队**（倾向某 `side.key` / 未定）是**纯用户侧轻量标注**——仅你可见、**绝不写进 AI 裁决**。前端 store `debateUserTake.ts` + 记分牌 `StanceControl`；终局 `FinaleStage` 附「你 vs AI」软对照。呈现见 [`前端UX设计.md §4.4`](/docs/04-前端/前端UX设计.md)。

**会话内态、不持久化**：重载 / 翻页即重置。

**「用户拍板」(gavel) 已整体移除（2026-06）**：理由见历史——纯客户端标注不回灌 AI、与站队重叠、专用表过建。表由迁移 `f1d8c3a6b9e4` 删除。

→ 见代码：`stores/debateUserTake.ts`、`components/chat/debate/arena/Scoreboard.tsx`。

## 七、技术落点（现状）

### 7.1 主持人 = `debate` 工具内的确定性编排循环（非 LLM 编排角色）

辩论是 CEO 的一个**编排工具** `debate`（`tools/builtin/debate/`，`ToolCategory.ORCHESTRATION`，与 `delegate` 同类、非终结）。CEO 识别对抗性意图 → 调 `debate(motion, form, sides[, thorough, background])` → 工具内驱动主持人循环 → 交回双产物供 CEO 用自己的声音收尾。

- **开辩前对齐用户原意（忠于原框）**：CEO 拟 `motion`/`sides` 时须**如实覆盖用户点名的每一极**——用户已给出争议轴 / 具体两极（如「加重【还是】减轻」）时不得悄悄砍掉一极、或把它偷换成更温和 / 不对题的立场（如把「减轻派」换成「审慎派」）；辩论所**依赖**的关键指代模糊（如「最近很火的那个」未点名指哪件事）时，先 `ask_user` 澄清再开辩，仅小返工可平滑纠偏才按合理默认开辩并在正文标注一句。这条行为约束由 `debate_and_review` 系统 Skill（`runtime/skills.py`）承载，回归测试见 `tests/test_skills.py::test_debate_skill_teaches_intent_alignment_before_opening`。
- **案件底料（`background`，可选，✅ 2026-07）**：CEO 发起前若已调研，把已核实的【客观事实清单】（主体 / 时间线 / 金额 / 程序节点，尽量带出处；不放观点 / 评价 / 立场分析）随参数传入，首轮以「**主持人整理的案件底料·双方共享**」注入全部辩手（`prompt.py:_background_block`，头尾裁剪封顶）；注入块明令**引用底料事实沿用其出处标记**（不得把底料包装成新【已核实】来源）、**支持立场的证据仍需独立检索**（保对抗性）。治「一场辩论 6 个 run 重复检索同一批基础事实」（真实 trace：一场 50 次 web_search 零缓存命中——措辞漂移让精确匹配缓存兜不住，治本是让辩手不必搜底料）。空参零行为变化；仅首轮注入（后续轮 / 质询 / 结辩经 `continue_run` 自带 session 记忆）。

主持人 `Moderator`（`runtime/debate/moderator.py`）是一个**确定性 Python 循环**，不是自由发挥的 LLM agent：循环骨架（定议题 → 派辩手 → 裁判+小结 → 决策下一轮）由代码控制，每一步的判断（议题 / 裁判+小结 / 简报）各走一次 `provider.complete` 出结构化 JSON（坏 JSON 容错降级；裁判与小结读同一份发言、合并为一次调用去冗余 round-trip）。「怎么派一轮辩手」经 `RoundRunner` 协议注入（由 `DebateTool` 实现），主持人本身只管编排与判定。

- **为何是确定性循环而非 LLM 编排角色**（对蓝图初稿的修正）：初稿设想「主持人 = `can_delegate` 内置编排角色（depth 1 的 LLM agent），CEO 委派给它」。实现改为确定性循环——① 循环 / 收敛 / 轮次治理是确定逻辑，交代码比交 LLM 自由发挥更可控、可测（注入返回脚本化 JSON 的 fake provider，零成本测全流程 / 收敛 / 双产物）；② 省掉一层 LLM 编排 agent 的 token 与不确定性；③ 仍满足「主持人是 CEO 之下、辩手之上的一层」——只是这层是工具内的循环，不是图上一个 LLM 节点。
- **委派深度**：辩手是 `depth+2` 的叶子（CEO depth 0 → 工具内 `build_run_plan(depth=self._depth+2)`），仍卡在 `MAX_DELEGATION_DEPTH=2` 内（见 [`执行引擎架构设计.md §8.4`](/docs/03-AI核心/执行引擎架构设计.md)）。

### 7.2 复用现有执行地基（不重建）

| 能力 | 复用项 |
|---|---|
| 首轮各方发言 | `build_run_plan` 一波并行辩手 + `build_agent_executor` + `WaveScheduler`（执行器现成） |
| 辩手跨轮带记忆 | `RunSession` 留人 + `continue_run` 续写：`DebateTool` 按 `side.key` 留住每个辩手的 session，第 k 轮对同一辩手 `continue_run`，把对方上轮论点当 feedback 注入，辩手在**自己的 transcript** 上续写——根治旧法「每轮全新失忆 worker」（[`多轮编排与同人续派.md`](/docs/03-AI核心/多轮编排与同人续派.md)；辩论编排续写豁免 CEO 侧唤回闸，轮次上限归 `RoundPolicy`） |
| 用量 / 账目 / 引用 | `WorkerResultAccumulator`：辩手各记一行账、主持人自身 LLM 调用折一行账（role=主持人），经 pipeline 折回回合总账，与 `delegate` 一致 |
| 中途掌舵（ambient） | in-process steer 队列（同 `redirect_queue` 模式），`Moderator.on_round_boundary` 非阻塞 drain，见 §六 |
| 开赛前开工卡 | 编排层公共 kickoff gate（`runtime/kickoff`，与 `delegate` 同源同卡同 resume 管线），`primitive=debate`，见 §6.1 |

> 蓝图曾把跨轮续写写成「把改稿工具下放给主持人」；实现直接用底层 `continue_run`（带现场续派的同源原语），无需下放工具——`DebateTool` 自己持有辩手 session 并续写。

> **辩手不配团队便签墙**（`collaboration=False`）：`build_agent_executor` 的团队便签软协作层（`post_note`/`read_notes`/`amend_note` + 便签墙广播，见 [`Agent协作模式.md §波内共享上下文：便签墙`](/docs/03-AI核心/Agent协作模式.md)）是给**协作团队**（`delegate` 并行 worker 边干边对齐）的；辩手是对手不是队友，故首轮 `first_round` 传 `collaboration=False` → **不建便签墙、三件套既不授予也不 offer**（连无限制 worker 也被 `_registry_without` 剥掉，非仅最小权限 worker）。跨方信息只走主持人按轮喂的 `round_feedback`（§6.3）这一辩论正当通道，不走便签互读——否则正反方会经便签偷看对方立论、团队卡还冒出让用户莫名其妙的「团队便签」面板。→ 见代码：`tools/builtin/debate/rounds.py`、`runtime/runs/executor_agent.py`（`collaboration` 开关）；回归 `tests/runs_executor/test_agent.py::test_collaboration_off_denies_note_tools_to_restricted_debater`。

### 7.3 节点结构：CEO → 主持人 → 辩手（主持人为完成态节点）

团队图呈现三层、进度正确收尾：

- **CEO 不进图**（与 `delegate` 一致，CEO 是主气泡）。
- **主持人是一个完成态节点**：`debate` 工具 emit `run_started`（`parent_run_id` = CEO 的 captain run）→ 收场 emit `run_completed`（带耗时 / 成本 / 简报摘要 / role=主持人）。团队进度因此把主持人计入并正确收尾，不再有「永久 pending 的编排节点」。
- **辩手挂在主持人下**（`parent_run_id` = 主持人 run_id，续写 beat 亦然——接续锚另走 `continues_run_id`），逐轮声明。**辩手身份（`stance`/`group`/`round`）随 `run_started` 上 wire**——续写序号会与轮次脱钩，显式携 `round`（及 `stance`、`group=debate:{form}`）才能让三端 fold 把每轮续写稳定投到正确轮次 / 立场，并在协作图铺成逐轮接续链（接续投影见 [`多轮编排与同人续派.md §七`](/docs/03-AI核心/多轮编排与同人续派.md)）；老日志缺字段时从现场根继承兜底。`stance` 仅正反 2 方有意义（builder 只认 `pro`/`con`），圆桌 / 红队无 `stance`。质询 / 结辩同为该辩手的 `continue_run`（同 `round_no`、`continues_run_id` 恒指现场根），**发言角色**由紧随的 `run_context.channel`（`cross_exam` / `closing`）表达——协作图角标读 channel 区分「第 N 轮·质询」/「结辩」，避免同轮双列撞成两个「第 N 轮」（见 §4-2.4）。
- **逐轮真实任务上 wire（✅ 2026-07）**：每个续写 beat（第 2+ 轮陈词 / 质询作答 / 结辩）的 `run_context` **首块**为 `channel="task"` 的逐字任务块——body 与喂给 LLM 的 feedback（`round_feedback` / `cx_answer_feedback` / `closing_task` 返回值）是**同一字符串**（同函数产出、零二次改写，从构造上消灭「拼给 LLM」与「展示给用户」双源漂移），heading 即环节名（「第 N 轮任务」/「质询环节」/「结辩环节」，前端任务区直接用作区段标题）。`closing` 通道块保留作 beat 标记（前端靠 presence 判环节 / chip 标签），但 body 降级为纯环节标记短句、不再复述指令（原 `_CLOSING_CONTEXT_BODY` 浓缩指令孪生文案退役）；`round_focus` 回归本职（焦点短语，供角标 / chip），`cross_exam` 问题清单与 `opponent` / `challenge` / `interjection` 材料块照旧。前端详情面板任务区按轮读该块显示真实任务（见 [`前端UX设计.md §十`](/docs/04-前端/前端UX设计.md)）；向量 `multi_agent_debate*` 钉住续写 beat 的 task 块逐字契约。

> **决策：主持人作为完成态节点**（落地时定）。备选「主持人不进图、辩手直接挂 CEO」会让团队图丢掉「谁在主持」这层、且进度分母不含编排成本；现选「主持人补全生命周期」，图体现 CEO→主持人→辩手 层级、进度准确。

### 7.4 双产物与 SSE

- **数据模型**（`runtime/debate/types.py`）：`DebateResult` = `brief`（决策简报）+ `rounds`（叙事线逐轮单元）+ `narrative_first`（按形态调呈现顺序）。
- **给 CEO 的文本**：`DebateResult.to_ceo_output()` 渲染简报 + L1 焦点小结流（L2/L3 全文不塞 CEO 上下文，省 token）。
- **收场事件（journal 权威）**：收场 emit 一个 `debate_result` 事件（`runtime/debate/types.py` · `DebateResult.to_event_payload()`：form / motion / stop_reason / sides / rounds / brief），承载全量叙事线（逐轮 焦点 / 裁判 / 小结 + **质询问答 `cross_exam` P1** + **逐轮记分 `scores` P2**）+ 决策简报（含 **`decisive` 胜负手 P2**）；**各方发言全文与质询作答全文不在事件里**（体量大），靠 `rounds[*].sides[*].run_id`（发言）与 `rounds[*].cross_exam[*].answer_run_id`（质询作答）关联执行图的辩手节点取回。举证证据标记（P3）**内联在发言/作答正文里**、随全文走、前端 `remarkEvidence` 渲染（见 §四之二）。进 journal、可重载回放；契约过 conformance（`ProjectedTurn.debate` verbatim，桌面 / 手机两端 fold 对齐，见 [`protocol-conformance.mdc`](/.cursor/rules/protocol-conformance.mdc)）。
- **逐轮实时事件**：`Moderator` 每轮 emit 一对增量——`debate_round_started`（焦点定下、发言**前**）与 `debate_round`（裁判 + 小结**后**，携 focus / summary / verdict + 各方辩手 `run_id` + L3 交锋边 `clashes`，与 `debate_result.rounds` 逐轮单元同构）。三端 fold 累积成 `ProjectedTurn.debateRounds`，让用户进行中就看到逐轮焦点 / 小结 / 裁判（圆桌 / 红队无 `stance`、过去进行中是空白，尤其受益）。二者 **DURABLE 入 journal**（P2 事件处置重对账时由 transport-only 改耐久，单一源 `runtime/events/disposition.py`）：**重载契约** = 重载由同一 fold 从 journal 重建 `debateRounds`，与 `debate_result` 的全量叙事线互为印证。前端把进行中与收场逐轮当同构孪生**归一为单一 `DebateModel`**（live→收场 不卸载重挂、辩手按 `run_id` 跨相位复用；见 [`前端UX设计.md §4.1`](/docs/04-前端/前端UX设计.md)）。
- ✅ **老板中途掌舵（ambient）**：有活跃用户即恒可用（§6.1–6.5：继续辩 / 加角度 / 追问 / 够了收）+ 收场后再辩走用户对 CEO 说话重开全新辩论（§6.6）+ 用户侧站队（§6.7）。掌舵走 fire-and-forget steer 队列（`debate-steer` / sidecar `debateSteer`），轮次边界非阻塞 drain；旧阻塞式 `DEBATE_ROUND` 交互与 `debate_round_decision_*` 事件已摘除。

### 7.5 真·多模型辩手（各方由不同厂商模型独立驱动）⏳ Phase 3 未启用

**MVP 现状**：辩论辩手与 CEO / worker 共用用户在「设置·模型配置」配的**同一 turn model**（[`编排器与CEO主Agent.md §2.1`](/docs/03-AI核心/编排器与CEO主Agent.md)）。`sides[].model` 在 `schema.parse_sides` 仍宽松解析入库（`DebateSide.model`），但 **`debater_task` 不注入**、`debate_result` 的 `to_event_payload` **不对外发 `model`**——前端辩手徽章改从辩手 run 的**实际执行 model** 取，避免 roster 声称与实际不符。

**Phase 3 目标**（未落地）：各方由不同厂商模型独立驱动——透传链设计为 `sides[].model` → `debater_task` 注入 → `RunSpec.model` → 执行器覆写 `profile.model` → `ProviderRouter` 按 `provider/model` 前缀分发（回合级 `build_router_around` + `router.close()`）。model 串格式与 provider 路由见 [`平台LLM接入.md §多厂商 Provider 路由`](/docs/05-平台与运维/平台LLM接入.md)。

- **起步阵容 = 2 方**（豆包turbo + 原生 DeepSeek）：先打通热路径、降回归面，非一上来 4 方（见 §八）。
- **主持人 / 裁判保持中立强模型**（DeepSeek）、**不参与对战**——避免「既当裁判又当选手」（见 §八）。
- ⏳ **端到端真跑（豆包 vs DeepSeek）**：须 Phase 3 恢复 per-side 注入后再验；配套「谁更聪明」宣传视频（未启动）见 [`远期规划 §4.3`](/docs/06-规划/远期规划.md)。

## 八、被否决 / 决策演进

> 本节为**全局否决 / 演进总表**；另有**就地否决**散在各节上下文，不在此重复：§四之二（质询三支柱的被否方案）、§6.3（追问不另起 `InteractionKind`）、§6.6（可逆叫停 / 结构化补轮的否决与移除）、§6.7（拍板 / 站队的否决与移除史）。

- **独立 Arena 子系统**（独立 SSE + 状态机 + 阶段轮转引擎 + `arena` RunKind）——**仍否决**。主持人不是独立执行引擎，底层复用 DAG 调度；本设计只补回「主持 / 收敛 / 产物」的产品层。
- **旧法：CEO 一次 `delegate` 静态展开 2N 节点 + 手搓跨轮 `depends_on`**——**被替代**。理由：轮数先验固定（无法运行期收敛）、CEO 手搓交错依赖图易错、`round` 与 `depends_on` 无一致性校验。改由主持人逐轮推进。
- **`round` 展示标记**——从「CEO 预先拍、可能与依赖脱节的 display-only 字段」**降级**为「主持人逐轮推进时自然产生、天然与执行一致」的叙事单位。旧的「round/依赖脱节」根因随之消失。
- **机械「最小轮数」楼层**（`min_rounds`，达门槛前不许判收敛）——**被替代**为「主持人逐轮自适应收敛」（§五）。理由：楼层不看内容、把 trivial 命题也逼满 N 轮，续写者每轮输入近乎相同 → 产出冗余的「修订 v2」；「别过早收敛」的意图改由裁判逐轮标准承载（第 1 轮默认继续、`thorough` 调收敛松紧），`max_rounds` 仅留作纯安全上限。`RoundPolicy` 随之去掉 `min_rounds` 字段、新增 `thorough: bool`。
- **二元 pro/con 专属**——**被替代**为「立场标签」泛化模型（§三），支持红队 / 圆桌。
- **主持人 = LLM 编排角色（depth 1 的 `can_delegate` agent）**——**落地时改为**「`debate` 工具内的确定性循环 + 每步嵌入式 LLM 判定」（§7.1）。理由：循环 / 收敛逻辑确定化更可控可测、省一层编排 agent 的 token 与不确定性；「主持人在 CEO 与辩手之间」这一层由工具内循环 + 图上完成态节点表达，无需是图上一个 LLM 节点。
- **主持人调研 beat（主持人先自行取证产底料、辩手引用）**——**否决**（2026-07 取证层优化）。辩手的重复检索是**并行**发生的、墙钟被遮蔽；首轮前串行加一个调研 beat（带检索的 ReAct run，约 30–60s）反使首轮墙钟净增，token 减半不抵体验回退。现状 = CEO 传 `background`（CEO 常已为用户写过案件概要、零边际成本）+ 注入时**归主持人名义**（§7.1）；CEO 未调研时空参、辩手照旧并行独立取证（墙钟最优）。
- **辩论独立 SSE 通道 / 散乱事件族**——**仍否决**。收场全量叙事线由单个 `debate_result` 结构化事件承载（§7.4）；逐轮实时只补一对增量（`debate_round_started` / `debate_round`）——走现有 SSE、不另起通道。掌舵不另造决策事件族（§6.4 steer 队列无 SSE）。
- **逐轮阻塞挂起（`DEBATE_ROUND` + `debate_round_decision_*`）**——**被 ambient 掌舵替代**（§六）。旧病：CEO 猜 `interactive` + 每轮硬停 babysit。现状 = 有活跃用户即武装、fire-and-forget steer 队列、轮次边界非阻塞 drain；旧交互 kind / 决策事件 / resolve 路径已摘除。
- **可逆叫停 = durable resume / 软撤销窗 / 服务端自动种子 / 结构化补轮（`debate_seed`）**——**否决 / 已下线**；现状 = 用户对 CEO 说话重开全新辩论（§6.6）。
- **站队/拍板**——**拍板已整体移除、站队降为会话内态**（§6.7）；曾落专用表 `debate_user_takes`（d4e9f2a1c7b6）持久化，因「没人消费的便利贴 + 与站队重叠 + 基建不相称」由迁移 `f1d8c3a6b9e4` 删除。原「存 `messages` metadata / `conversation` JSONB map」备选亦否决（违物理隔离 / 并发易覆）。
- **真·多模型辩手用「人设模拟」（同一模型扮多角）**——**否决**；走真·多模型（各方真由不同厂商模型驱动，§7.5），最有说服力、避免同源模型自导自演。
- **真·多模型一上来 4 方**——**否决**；起步 2 方（豆包turbo + 原生 DeepSeek）先打通热路径、降回归面（§7.5）。
- **主持人 / 裁判用参赛模型**——**否决**；保持中立强模型（DeepSeek），避免「既当裁判又当选手」（§7.5）。
