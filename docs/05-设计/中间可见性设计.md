> 来源：从 [产品AI协作优化复盘](../07-规划/产品AI协作优化复盘.md) §四 P0「中间可见性」拆出。

> 对照 §四 P0「中间可见性」。**结论：后端 `run_output_delta` 与前端 `outputChunks` 已接通**；缺口主要在可发现性、审查预警、跑一半改方向。

## 9.2 Phase 1 — ✅ 已落地（纯前端）

| 改动 | 文件 | 作用 |
|---|---|---|
| 审查预警启发式 | `lib/reviewConcern.ts` | 解析 `7/10`、方向类措辞 → 节点「待关注 / 方向风险」 |
| 图节点徽章 | `agentNode/*`, `projectFlowGraph.ts` | 审查官打出低分/方向问题时亮灯 |
| 「查看进行中」 | `StatusStrip` + `InlineTeamGraph` | 状态条一键打开首个进行中 worker 侧栏 |
| 实时详情条 | `RunDetailBody` | 进行中时提示流式更新 +「记下改法」预填输入框 +「停止整轮」 |

**验收场景**：用 conformance `multi_agent` 或简介流水线向量回放；任一 worker `running` 时：

1. 状态条出现「查看进行中」→ 侧栏流式输出；
2. 节点卡片出现输出预览行；
3. 审查输出含 `7/10` 或「方向偏」时出现琥珀/红徽章。

## 9.3 Phase 2 — ⏳ 待后端（真正「跑一半改方向」）

| 能力 | 方向 | 依赖 |
|---|---|---|
| 单人中途 steer | 取消 running run + `replan.steer` 或 worker 内 `ask_ceo` | `delegate/drive.py`, 执行器取消语义 |

## 9.4 Phase 2a 实施切片：取消 + 重跑

> 产品决策：**先押 A（取消 + 重跑）**，不先做 live steer 注入。目标：用户侧栏点「立即改此人」→ 只停一个跑偏 worker → 带新方向重跑，并行队友与整轮不受影响。

### 9.4.1 用户故事

简介流水线：三个审查官并行，用户在侧栏看到「方向审查」输出已偏科普向 → 点 **「立即改此人」**、填「受众应是初学者，别写推导」→ 仅该审查官被取消并重跑；事实审查继续；整轮不 abort。

### 9.4.2 与现有原语的关系

| 原语 | 能做什么 | Phase 2a 怎么用 |
|---|---|---|
| `revise` | 唤回 **已完成** worker（RunSession） | 取消后若有 partial session → `continue_run` 同路径重跑 |
| `replan.steers` | 操舵 **未跑** 节点 | 不用于 running；可用于「取消后新插一个同角色节点」备选 |
| `WaveScheduler` cancel | 今日：单 task cancel → **整批** `CancelledError` | **要改**：单 run cancel 不拖死兄弟 |
| `stopGeneration` | 整回合 abort | 保留；与「改此人」并存 |

**关键接缝**：`revise` 今天要求 `RunSession`（跑完才留人）；running worker 取消时要 **salvage 部分 transcript** 成 session，或接受 v0「冷重跑同 spec + steer 块」（无现场记忆，但实现更短）。

### 9.4.3 建议技术方案（分步交付）

**Step 1 — 交互契约（不碰 scheduler）** — ✅ 已落地

- 新 interaction：`run_redirect`（或 `worker_redirect`）
  - `required`：`run_id`, `feedback`, `execution_id`
  - resolve 后写入 turn 级 redirect 队列（hub / DelegateTool 可读）
- SSE：`run_redirect_requested` / `run_redirect_applied`（journal，可回放）
- 前端：`RunDetailBody`「立即改此人」→ `POST …/interactions`（与 approval/checkpoint 同桥）

已实现：`redirect_queue.py`、`POST …/run-redirect`、sidecar `runRedirect`、`RunDetailBody`「立即改此人」；drive 仅 log。

**Step 2 — Scheduler 单人取消** — ⏳

- `WaveScheduler.run(..., cancel_run_ids: Callable[[], frozenset[str]])` 或共享 registry
- 单 task `cancel()` 后：**不** `raise CancelledError` 整批；将该 run 标 `SKIPPED`/`CANCELLED`，兄弟继续
- `drive.py` 轮询 redirect 队列，把目标 `run_id` 加入 cancel 集

**Step 3 — 重跑路径（二选一，建议先 B 再 A）** — ⏳

| 路径 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **B 冷重跑** | cancel 后 `plan.add` 同角色新节点（带 `steer`）或同 `run_id` 二次 dispatch | 接缝少 | 丢失已写一半 |
| **A 热续写** | cancel 时 executor `CancelledError` 分支 salvage `RunSession` → `continue_run(feedback)` | 保留现场记忆 | 需 executor + session 接缝 |

**Step 4 — 前端闭环** — ⏳

- `RunDetailBody`：进行中显示「立即改此人」（`reviewConcern` 亮灯时预填 feedback）
- 图节点：被取消 run → `cancelled`/`redirected` 态 + 子 revision 边（若走 `continue_run`）
- conformance 向量：`multi_agent_run_redirect`（并行二人，一人 running 时被 redirect）

**Step 5 — （可选）Step 3A partial session salvage** — ⏳

### 9.4.4 验收标准

1. 并行 ≥2 worker，redirect 其一 → 另一 **仍在 running/completed**，整轮 **不** `cancelled`
2. 被 redirect worker 出现新产出（revision 子节点或同节点重跑）
3. redirect 事件 journal 可回放；`#/preview` 可见节点态变化
4. 「停止整轮」仍 abort 全回合（回归）

### 9.4.5 风险与纪律

- **补丁绊线**：若需「scheduler + executor + interaction + revise」四层兜底 → 先停，复核是否应降为 **B 冷重跑** v0
- **与便签分工**：redirect 是硬约束；`post_note` heads_up 仍是软广播——简介审查「方向错了」两条线都要，不互替
- **CEO 不在环**：delegate `drive` 期间 CEO 阻塞；redirect 必须走 **interaction 桥**（用户直控），不能等 CEO 自己 `revise`

### 9.4.6 建议开发顺序

1. Step 1 交互 + 前端按钮 — ✅ 已落地
2. Step 2 scheduler 单人 cancel（单测 `wave.py`）— ⏳
3. Step 3B 冷重跑 + steer 块 — ⏳
4. conformance 向量 + `pnpm conformance` — ⏳
5. （可选）Step 3A partial session salvage — ⏳
