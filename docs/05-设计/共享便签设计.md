# 共享便签设计

> 来源：从 [产品AI协作优化复盘](../07-规划/产品AI协作优化复盘.md) §四 P0「团队共享上下文 / 便签墙」拆出。

> 对照 §四 P0「团队共享上下文 / 便签墙」与 §3.1「CEO 手写 task 成本高」。**结论：便签墙后端与聊天 UI 已落地**；缺口是 **简介流水线未用起来**、**跨波次共识仍靠 task 复制粘贴**；CEO 播种能力已在 Phase 2 实现。

## 10.1 用产品语言说清「共享便签」

**人话**：主 AI 派了多个人同时干活时，需要一块**大家都能看的公告板**——谁定了什么规矩、谁发现了什么问题、谁认领了哪块活，**写一次、全队可见**，不用给每个人复制粘贴同一段背景。

**和聊天区别**：便签是「贴事实、不要求回复」——不是群聊，避免你问我答烧 token。

**这次简介实测的痛点**：三个审查官并行时**互不知道对方在审什么**；主 AI 给每人写的 task 里重复背景，还**没用便签**广播「方向错了」这类重大信号。

## 10.2 现状（已有能力）

| 层 | 已有 | 限制 |
|---|---|---|
| 后端 `NoteWall` | `post_note` / `read_notes` / `amend_note`；推增量注入兄弟上下文 | **仅同一 `delegate` 波内并行兄弟**；辩论辩手 deliberately 关闭 |
| 便签种类 | `decision`（我定了）/ `heads_up`（提个醒）/ `claim`（我领了） | 每条约 200 字；整墙 50 条上限 |
| 前端 | `TeamNotesPanel` 挂在协作图下（展开/收起都可见） | 有便签时状态条显示「团队便签 N」徽章 |
| CEO 收尾 | `format_notes_for_synthesis` → 概览【团队便签】+ 合·对账 | 收工时才读；开局可通过 `seed_notes` 注入 |
| Playbook | `build_feature` 模板要求后端贴 API 契约便签 | 普通 `delegate` 无此约束 |

代码锚点：`runtime/runs/notewall.py`、`tools/builtin/post_note.py`、`TeamNotesPanel.tsx`、`ceo_format.py`。

## 10.3 与 P0 诉求的 gap

| 用户/AI 诉求 | 现状 | Gap |
|---|---|---|
| CEO 写一次「团队共识」全队共读 | `seed_notes` 可在执行前写入 `NoteWall` | CEO prompt 尚未强制「先贴墙再派活」 |
| 并行审查发现「方向错了」互相看见 | 便签墙支持；prompt 已要求审查官贴 `heads_up` | 简介任务实测**未触发** `post_note`；需 conformance 验收 |
| 写手 → 审查 两波之间共享 | 波 1 结束产物经 `depends_on` 传递；**波内便签不跨波** | 跨波共识仍靠 task 复述 |
| 减少手写 task 篇幅 | 便签可承载接口/命名决定 | CEO 不知道要先把决定贴墙再派活 |

## 10.4 Phase 1 — ✅ 已落地（prompt 层）

不改 `delegate` schema，靠 **prompt + 前端显眼化**：

| 项 | 做法 | 文件/位置 |
|---|---|---|
| CEO 派并行审查时强制便签 | 在 `team_orchestration_advanced` + CEO core 加规则：审查发现方向/致命问题时 **必须 `post_note`（heads_up）** | `runtime/skills.py`、`runtime/resolve/prompt.py` |
| Worker 并行审查专则 | `_WORKER_TEAM_NOTE_POLICY` 补充「先贴便签再写详细意见」 | `runtime/runs/executor_identities.py` |
| 便签面板更显眼 | 有便签时状态条显示「团队便签 N」徽章 | `StatusStrip.tsx` |
| 合·对账回归 | conformance 向量断言：并行 worker 贴便签 → `teamNotes` fold + CEO 概览含【团队便签】 | `multi_agent_team_notes_ceo_seed` |
| 简介流水线复跑验收 | 人工/录制：三审查并行时至少一条 `heads_up` 便签 | 产品验收 |

测试覆盖：`test_team_orchestration_skill_teaches_parallel_review_notewall`。

## 10.5 Phase 2 — ✅ 已落地（schema，减 task 复制）

| 项 | 做法 | 实现 |
|---|---|---|
| **`seed_notes` on `delegate`** | CEO 可选传入 `[{kind, text}]`，执行前写入 `NoteWall`（`run_id=__ceo_seed__`） | `delegate/seed_notes.py` + `drive.py` |
| **Turn-level `team_brief` block** | 写入 DelegateTool 回合态，每个 worker 开局 `_build_context_blocks` 多一节「团队共识」 | `executor_context.py` |
| UI 区分来源 | `TeamNote.source: ceo \| worker`；CEO 播种显示「主 Agent 播种」 | `TeamNotesPanel.tsx` + fold |

改动面：`delegate/schema.py`、`seed_notes.py`、`executor_context.py`、`TeamNotesPanel.tsx`。

## 10.6 Phase 3 — ⏳（与 §3.1 自动拼装联动）

- CEO 声明「共识键值」→ runtime 自动展开为 `seed_notes` + 缩短各 `task`
- 与 [`上下文注入统一性讨论.md`](../07-规划/上下文注入统一性讨论.md) 的 Provider 抽象汇合（可选，非 P0 阻塞）

## 10.7 建议优先级

1. **Phase 1 prompt**（零 schema，立刻改善简介类流水线）— ✅ 已落地
2. **Phase 2 `seed_notes`**（真正减少 CEO 手写 task）— ✅ 已落地
3. **Phase 2 `team_brief` 跨波**（写手→审查→修订全链共识）— ✅ 已落地
4. **Phase 3 自动拼装**（共识键值 → `seed_notes` + 缩短 task）— ⏳

与 [中间可见性设计](./中间可见性设计.md) 关系：可见性解决「看得见输出」；便签解决「看得见彼此的决定」——简介任务两个缺口同时存在，Phase 1 已并行推进。
