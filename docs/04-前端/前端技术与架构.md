## 七、客户端架构（桌面 + 手机）✅ 已确定

> **双端独立实现**：桌面（Electron）与手机（Vite SPA，Capacitor 套壳上架）共用同一后端。**手机端 = 桌面端 − 依赖 Electron 主进程 / OS 的能力层**（黑名单减法，非白名单新设计）。各端各自拥有 stores / services / 协议 fold / 组件，**零共享业务实现**；唯一共享 = 协议一致性规范 + 事件类型 + 设计 token（见 §十二·conformance、`.cursor/rules/cross-platform-frontend.mdc`）。

### 7.0 手机端定位与减法

**保留**（云端撑的，浏览器里照跑）：聊天 + 流式、多 Agent 协作与 run 下钻、审批 / 检查点 / `ask_user`、成本呈现、IM、对话管理 / 搜索、云端工作区文件浏览、attention（概念同桌面，传输改原生推送）。

**减去**（且仅这些）：本地文件工作区、本地 Markdown 落盘编辑、本地 MCP stdio、后台常驻 / 托盘、全局热键、自动更新（交应用商店）、OS 集成（右键分析、文件关联、taskbar badge）、本地 sidecar 引擎。手机端**直接不实现**——无需 `if(platform)`、无需共享 port 抽象。桌面本地能力 → §八 / §7.1。

**传输**：**web SPA → Capacitor 套壳**拿 iOS/Android 上架 + FCM/APNs 推送；手机 web（Cloudflare Pages）已作一等客户端。**否决** RN（弃 DOM 复用）、纯 PWA（推送 / 后台残缺，同 §7.1）。

**平台粘合**（新增、不算违反减法）：bearer-token 鉴权、原生推送 + 回前台拉 `/v1/attention`、响应式触控（≥44px、无 hover 假设）。→ [`认证与会话`](/docs/05-平台与运维/认证与会话.md) §十；原生壳 / 商店余项 → [`远期规划`](/docs/06-规划/远期规划.md) §3.2。

→ 见代码 `apps/mobile/`。

### 7.1 桌面价值主张（vs Web/PWA）

| 能力 | 网页天花板 | 桌面解锁 |
|------|-----------|---------|
| 异步任务 + 审批门禁 | 关标签即断 | 后台常驻 + 原生通知 + 审批闭环 |
| 全局热键召唤 | 埋在标签页里 | Spotlight 式悬浮窗 |
| 文件工作区 | 只能上传 | 本地文件直连 / Agent 读写磁盘 |
| MCP 工具层 | 浏览器跑不了 stdio | 本地 MCP 运行时（常驻进程池） |

被否决：PWA（无常驻/通知/文件）、全原生 UI（贵且漂移）、Tauri（团队无 Rust，WKWebView 有差异，备选）。

### 7.2 主进程架构

→ 见代码 `apps/desktop/src/main/index.ts`（窗口 + `app://` 协议 + `fs-service`）。⏳ 未实现：`connection-manager`、`mcp-pool`、`local-store`。

**已定**：renderer 本地加载；SSE 云模式直连后端、本地 sidecar 模式经 `/v1/inference` 代理（均不经 IPC）；组件策略 = **桌面独立演进、不共享 packages 业务组件**（与手机对称；域卡片等有手机消费者也**重建而非从桌面提取**，只共享 token / 类型 / 规范）。

- **本地回合 outbox 回写器（✅）**：本地 sidecar 回合的正文耐久性归主进程——读 `<userData>/sidecar/outbox/` → 纯 Bearer `POST .../local-turns` → 云确认删文件 → `outbox:synced` IPC 通知 renderer 对账（换权威 id / 翻同步态 `synced_pending→synced` / 刷标题）；启动扫盘 + 2s 轮询 + `before-quit` drain，**跨 renderer 刷新 / app 重启续传**。renderer **退出** HTTP 回写职责（不再内存重试 / toast）。→ 见代码 `main/outbox-writeback.ts`、`main/auth-client.ts`、`shared/outbox-contract.ts`；链路 + 服务端合并契约见 [双模式 §10.3](/docs/02-架构/双模式工作区.md)。
- **本地引擎刷新恢复面（✅）**：主进程 per-turn 事件缓冲 + `sidecar:recovery` / `sidecar:attach` IPC；renderer 投影未同步 outbox 后 attach 续看。决策与边界 → [双模式 §10.7](/docs/02-架构/双模式工作区.md)；水合序 → §12.1。

### 7.3–7.7 安全 / OS 集成 / 通知 / 更新 / 托盘

→ 见代码 `main/index.ts`、`main/updater.ts`、`main/fs-service.ts`。自动更新含远程熔断 `GET /updates/policy` ✅；灰度分桶 ⏳。macOS TitleBar（`titleBarStyle: hidden`、交通灯留白、`macTitleBarInsetClass`）✅；原生菜单栏 / Dock badge 等 → [`远期规划.md` §4.2](/docs/06-规划/远期规划.md)。

### 7.8 跨端实现策略（为何全新建 + 巡检）

| 层 | 处置 |
|---|---|
| 协议 fold（SSE→state、run 树、resume/审批） | **各端全新建**；须过 conformance（§十二） |
| 组件 / chrome / 布局 | **各端全新建** |
| 事件类型、`ProjectedTurn` schema、golden 向量 | **共享规范**（`packages/`，非实现） |
| 设计 token | **共享**（`@agentcore/design-tokens`） |
| 纯渲染叶子（Markdown / KaTeX 等） | 可机会性共享，非强制 |

**为 AI 并行开发的收益**：爆炸半径收束（改 `apps/mobile` 物理上动不了桌面）、上下文局部、零协调最大并行。**诚实代价**：契约变更仍改两套 fold；巡检 harness 成本 ≈ 共享薄 fold——选全新建的理由是爆炸半径 / 独立演进，非省事。

> **被否决 · 共享实现核**：共享 = 跨 app 耦合，对有界上下文 AI 比 drift 更难控。**被否决 · 一棵树降级**：分支税 + 手机沦为压扁桌面。

**决策启发式**：放手新建一切；唯一红线 = 协议 fold 必过 `pnpm conformance`；契约变更只走后端单一源。

### 9.2 Store 关键拆分

### 9.3 按 messageId 隔离执行态 ✅ 已落地

**核心决策**：执行态键控从 `conversationId`（每对话单槽）改为 `messageId`（每回答一槽）——否则同对话连发多回合会节点串台，且历史回合无图可回看。实时与回放走**同一 fold**（`projectExecution`），SSE 据回合 `conversationId` 解析 live assistant 消息 id 路由 run/tool 帧；`message_end` 持久化回合 journal（后端落 `turn_journal`，读取投影为 `runs` 载荷），刷新经 `hydrateFromJournal` 幂等回放——含辩论进行态（`debate_round*`）、协调预览（`team_synthesis_preview`）、预检警告（`turn_warning`，经 `toMessage`）。

**⏳ 已知限制**：历史执行槽内存回收未做（`byId` 随浏览深度累积，开发期可接受）。

→ 见代码 `stores/execution/`、`services/streamConversation.ts`

### 9.4 单一数据源、两层投影 ✅ 已落地

**核心决策**：inline 信号层（状态轨 + 协作图）与详情面板层同投影同一消息执行槽；面板 tab 只存 `{messageId, runId}` 引用。**节点高亮一面一源**（内嵌图与画布放大态都派生自面板当前激活 run-detail tab——放大态点 worker 走 `showRunDetail` 钉进同一 `sidePanel` store，无独立高亮源）。**否决**跨 store 反向 `selectRun` 对账（补丁绊线）。

布局与交互决策见 [`前端UX设计.md` §一/§十](/docs/04-前端/前端UX设计.md)。→ 见代码 `stores/sidePanel.ts`、`stores/execution/`

### 9.5 事件归属显式化

**核心决策**：回合归属在 SSE 入口一次性确定——dispatch context 携带 `conversationId`，chat 类写会话切片、run/tool 类解析 live 消息 id 写执行槽；无「可路由事件白名单」需维护。

→ 见代码 `services/sse/`（dispatch + handlers）

### 9.6 按 conversationId 隔离会话运行时（后台 turn 存活）✅ 已落地

**核心决策**：会话运行时按 `conversationId` 分片（非单一全局态）——切走对话不打断后台 turn，切回即见。闲切片（无生成中且无挂起审批）释放、忙片保活；所有写入按 turn **自身的 `conversationId`** 路由。

**被否决（旧行为）**：`switchConversation` 切走即 `abort`——与「后台干活」心智冲突。

与 §9.3 正交：本节按会话保活 turn；§9.3 按 messageId 隔离协作图。

→ 见代码 `stores/conversation/`、`stores/interactions/`

### 9.6.1 回合停止生命周期（turnPhase）✅ 已落地

**核心决策**：渲染层在会话运行时（键 = `conversationId`，与 abort 同槽；**不**进 messageId 键控的 `stores/execution`）维护回合停止状态机：

`idle → preflight → streaming → stopping → stopped|completed|failed`

三条派生规则：

1. **开流门禁**：发送管线各 await 恢复点（sidecar 探活后、sidecar `invoke` 前、云 `fetch` 前）检查 phase——`stopping` / terminal 直接终止不启动。`AbortSignal` 只负责物理断流，权威判断是 phase。
2. **事件门**：`dispatchSSEEvent` 入口按 phase 过滤——`stopping` / terminal 丢弃内容 / 工具 / 执行帧，只放行终态确认（`message_end` / `error`）与无害 meta（`turn_saved` 等）；`ensureStreamingAssistant` 仅 `streaming` 允许重建气泡。
3. **停止闭环**：点停止 → phase 进 `stopping` → 仍显式调 `/stop` 与 sidecar cancel（引擎「断连≠取消」不变）；确认或超时进 terminal；`/stop` 失败 toast 提示（不再静默）。

**UX**：乐观收口——点停止 UI 立即 `finalizeLastMessage` 恢复平静，`stopping→terminal` 幕后走，不做「正在停止…」过渡态。

**被否决**：仅靠 `AbortSignal` 门禁（预检 await 窗口与已 abort 仍 invoke 的缺口）；停止后迟到事件仍 fold（会把 UI 拉回生成态）。

→ 见代码 `stores/conversation/turnPhase.ts`、`turnPhaseActions.ts`、`services/sse/dispatch.ts`、`services/turns/stream.ts`、`stopTurn.ts`

### 9.9 错误处理与提示分诊（统一错误契约 → 分场景承载）✅ 已落地

### 9.10 Markdown 文档编辑器（CodeMirror 源码 + 内联实时预览 + AI 改写）✅ 已落地

> **被否决 · TipTap / 整页 contenteditable WYSIWYG**：round-trip 有损、math/diagram/clean-diff 全坑、与「文本即典范」冲突；IME 友好度亦劣于 CodeMirror。

### 12.1 桌面 SSE 设计约束

- **单一入口**：所有 SSE 事件经 `services/sse/dispatch.ts` 统一分发（`streamConversation.ts` 仅负责传输/重连），不在组件中直接监听
- **Store 最小更新**：每条事件只更新必需的 Store 字段，不做全量替换
- ⏳ **对账兜底**：`reconcileAllRuns()` **未实现**
- **乐观更新**：发送消息时立即在 conversation store 创建 user message 条目，无需等后端确认
- **打开对话水合** ✅：先采纳云端消息窗口（切片非空/生成中不覆写守卫不变）→ `loadRecovery`（桌面并行：主进程 `sidecar:recovery` + 云端 `GET …/recovery`，失败互不拖累）。
  - **本地分支**（主进程事实：`sidecarLive || unsynced.length > 0`）：先投影 `unsynced` → `sidecarLive && pausedCount===0` 时 sidecar attach（订阅暂存 → 重绑快照 → `setActiveSidecarTurn` → 专用 clear-then-fold → 回放续看）。**不调** `resolveSidecarRoot`（路由意向 ≠ 恢复事实；冷启动缓存空会误判）；**不走**云端 `attachOnOpen` / `rejoinLiveTurn`。冷路 paused 只靠帧续跑卡 + 投影补内容可见性。→ [双模式 §10.7](/docs/02-架构/双模式工作区.md)；代码 `turns/sidecarAttach.ts`、`turns/projectUnsynced.ts`、`resume.ts`。
  - **云端分支**（无本地事实）：末行启发式不变——`cloudLive` 门闩 attach（一律带 `Last-Event-ID`，无则 `0`）clear-then-fold / rejoinLiveTurn；死租约幽灵（`running` 但无 live/pause）→ 标 `incomplete` / 「已中断，可重试」。→ 代码 `ConversationPage.tsx`、`turns/recovery.ts`；后端 overlay → [执行引擎 §8.3](/docs/03-AI核心/执行引擎架构设计.md)。
  - **冷启动测纪律**：水合恢复单测禁止预填对话列表 / 工作区 React Query 缓存、禁止 mock 路由判定——必须在「刷新后缓存全空」前提下仍触发恢复面。

### 12.2 协议一致性巡检（双端 fold 对账）

**核心**：`fold(events[]) → ProjectedTurn` 是纯函数；两端对同一 SSE 向量须产出相同规范化 state。后端 oracle（`apps/server/agentcore/conformance/projection.py`）为裁判；向量 + golden 在 `packages/protocol-conformance/fixtures/`（`python -m agentcore.conformance.export` 一键重导）。

| 支柱 | 机制 |
|---|---|
| ① 向量 + golden | 后端导出代表性场景（单聊 / delegate / 审批 pause-resume / 错误等）；两端 fold 对 golden JSON |
| ② 共享类型 + `assertNever` | `@agentcore/contract-types` 判别联合；新事件类型 → 编译失败直到两端处理 |
| ③ AI 可操作 | 根目录 `pnpm conformance` 串联手机 tsx runner + 桌面 vitest；CI mobile job 门禁 |

**桌面适配器边界**：团队图复用真实 `projectExecution`；单聊 process 时间线复用 `@/lib/processTimeline`（生产与 conformance 共用，防 coalesce 漂移）。手机用生产 fold 直接对账。

纪律 → `.cursor/rules/protocol-conformance.mdc`。向量**两来源并存、同判**：手写 event builder（`agentcore/conformance/vectors/`，export 导出）＋ **真实录制裁切**（`agentcore/conformance/recording_cut.py`：EventSink 录制原片 → durable-face 过滤（`EVENT_DISPOSITION` 主轴，DURABLE+DERIVED 保留、EPHEMERAL 仅留有 fold 语义的显式白名单）→ 确定性时间戳（同录制重裁字节稳定）→ `project_turn` 生成 golden）。裁切产物 `recorded_*.json` 落同一 fixtures 顶层、被各端 harness 同等判定；`conformance.export` 清盘按 `recorded_` 前缀跳过，两来源互不误删。开发期无真实录制素材入库（`demos/recordings/` 不入仓），管道由合成录制单测锚定（`tests/test_recording_cut.py`）；真实裁切向量入库留后续。

### 12.3 离线预览与截图自检回路 ✅ 已落地

同一批 conformance 向量除当裁判外，还兼作**离线 UI 预览**：隐藏开发路由 `#/preview` 把每条向量经**真实** `dispatchSSEEvent` 回放进**真实** `ChatView`，复现每种 AI 态——零后端、零 LLM、零 token。因为用的就是巡检那批 golden 向量，**永不 drift**（后端协议改了重导一次，预览与巡检一起刷新；丢个新 fixture JSON 即自动出现）。解决「改完 AI 相关展示要跑真实 AI 才看得到效果」的痛点。

- **入口（人）**：路由不在导航里——命令面板（`Ctrl/Cmd+K`）搜「前端预览」直达；URL 可寻址 `#/preview?s=<场景名>`，可深链 / 收藏单个场景。
- **纯浏览器跑渲染层**：`pnpm -C apps/desktop dev:web` 用 `vite.web.config.ts` 把渲染层当普通网页起（端口 5199，开 `/index.web.html#/preview`）。渲染层对 Electron 的唯一耦合是 4 个注入全局（`fsApi/sidecarApi/updaterApi/windowApi`），由 `preview/browserStubs.ts` 打桩；同处设 `window.__WEB_PREVIEW__=true` 使 `AuthGate` 跳过认证 bootstrap 离线渲染——**此标记仅浏览器入口设置，Electron 构建里永不存在 → 真实认证零影响**。
- **截图自检回路（AI）**：`pnpm -C apps/desktop shoot [场景名过滤]` 用 Playwright 无头 Chromium 逐场景截图到 `shoot-out/<name>.png`（gitignore，不入仓；**须在 `out/` 外**，否则 electron-builder 会把 `out/**` 打进安装包）。AI 改完组件 → 跑 shoot → 读图核对，形成「改→截→看→迭代」紧回路。
- **CI 渲染冒烟门禁**：CI 的 frontend job 也跑 `pnpm shoot`——任一场景渲染崩掉（未捕获报错 / `#/preview` 挂不上）即非零退出、CI 变红，组件改动悄悄炸掉某个 AI 态会被当场抓住；失败时把 `shoot-out/` 截图作 artifact 上传便于排查。→ 见代码 `.github/workflows/ci.yml`（frontend job）。
- **流式中间帧 scrubber**：预览不止看终态——`#/preview` 工具栏有帧滑块，拖动即改 URL `?k=<n>`、只回放前 n 条事件（`replayFixturePrefix`），逐帧看「工具进行中 / run 起了未完成」等流式中间态，`data-preview-frame` 同步标记就绪。截图器 `SHOOT_FRAMES=N` 则每场景额外均匀采 N 个中间帧（`<name>.f<k>.png`），CI 设 3——**中间态也进门禁**。人拖滑块与截图器深链 `?k=` 落到同一帧。
- **回放 source 适配器（消费端 A = FOLD 直灌）**：`preview/source.ts` 读统一超集事件文档（conformance 向量 / 磁带 / 录制原片，旧 `kind`/`ts` 读时别名）、只产出 `FoldReplaySource`（类型 + 运行时双重拒绝 sink 源直灌，防同会话 A/B 双注入）；FOLD 路**永不**重铸交互 id（巡检 golden 与 `?s=` 深链依赖稳定 id）；缺 pacing（`t_ms`）等步忽略，帧滑块语义不变。服务端 B 路（sink 注入）→ [执行引擎 §二·录制与回放](/docs/03-AI核心/执行引擎架构设计.md)。伴生纯 UI 场景面（白板/首启/手册/会话管理）不走此路径。

> **被否决 · Storybook**：会引入平行工具链 + 各 Provider 重接，维护更重；「真实组件 + conformance 向量回放」已覆盖需求。**被否决 · 手写 mock AI 态**：AI 态是事件流 fold 出来的，手写折叠态又脆又会与真实 fold 漂移；回放真实向量走真实 dispatch，状态天然正确。**已退役 · dev 录制按钮**：标题栏「录制」曾把真实回合 tap 进 localStorage 作 scratch 预览；已删，新态统一走后端向量 + `conformance.export`。

→ 见代码 `pages/PreviewPage.tsx`、`preview/{replay,fixtures,source,browserStubs}.ts`、`scripts/shoot.mjs`、`vite.web.config.ts`。
