## 7.1 粒度开关（大众 / Power）

`usageDetail`（默认 `false`，持久化 `localStorage: agentcore:usage-detail`，状态在 `stores/ui.ts`）。

- **¥ 永远可见**，不受开关控制；开关只控制 **token / 技术明细** 与 run-detail「资源消耗」**默认展开**。
- **唯一入口**：MorePage「用量」页顶部的「用量明细 / Power 模式」开关。一处开关同时驱动：① 仪表盘「明细」是否展开；② 各 Agent run-detail「资源消耗」是否默认展开——两处读同一个 `usageDetail`，不再有第二套粒度概念。
- **省钱彩蛋**（power）：前缀缓存节省 = `cache_hit × (miss 价 − hit 价)`，后端 `pricing.cache_savings` 提供，前端在 run-detail「资源消耗」以「缓存省 $X」呈现（`cost.cached`）。

→ 见代码：`stores/ui.ts`（`usageDetail` / `toggleUsageDetail`）、`pages/more/UsageSettings.tsx`（开关 + 仪表盘）、`components/chat/detail/RunDetailBody.tsx`（`defaultExpanded={usageDetail}`）。

## 7.2 格式化与汇率

- 金额一律整数 nano-USD（1 USD = 10⁹）流转，前端**不写死汇率**：`cnyPerUsd` 单一来源 `useUsageStore`（由 `/usage/summary` 下发的 `cny_per_usd` 刷新，首屏前用后端默认兜底）。
- 格式化函数：`formatCost`（¥，大众）、`formatUsd`（$，power）、`formatCompact`（token 等大数）、`formatDuration`（用时）。
- **0 成本约定**（与 §7.5 同源）：0 / 无花销显「—」，绝不显「¥0.00」；有花销但折算 < 1 分显「<¥0.01」。

→ 见代码：`lib/format.ts`、`stores/usage.ts`。

## 7.3 四级呈现

落地决策③「大众可见粒度」（见 [`../05-平台与运维/成本配额与计费.md`](../05-平台与运维/成本配额与计费.md) §五）：钱人人可见、token 仅 power。

| 层 | 位置 | 大众 | power | 数据源 |
|---|---|---|---|---|
| 7.3A 回合 | 助手气泡下 / 团队卡 | ¥ + Agent 数 | + token / 缓存率 | `message_end.cost` / `run_completed` |
| 7.3B 工资单 | DetailPanel progress | 各 Agent 一行 ¥ + 占比条 | + model / tok / 用时（run-detail） | `GET /messages/{id}/cost` |
| 7.3C 对话累计 | 对话头 caption | 本对话 ¥ | tooltip：token 合计 + 回合数 | `GET /conversations/{id}/cost` |
| 7.3D 账户仪表盘 | MorePage「用量」 | 语义额度条 % | token/成本拆分明细 | `GET /usage/summary` |

**差异点**：Multi-Agent 可拆「团队工资单」（CEO ¥0.03 / 调研员 ¥0.05…），单 Agent 竞品做不到。

### 7.3A 回合成本行
- 多 Agent：并入团队计分卡（`TaskCard` 的 CompletedCard）一行；失败/停止卡照常显示「已花 ¥」（无 `message_end` 时回落到已完成 worker run 之和，下界但仍诚实）。
- 单 Agent：助手气泡底部极淡 caption（`MessageBubble`，仅 `executionId === null` 的回合，避免与团队卡重复）。
- 实时用 `message.cost`，回放回落到台账快照（`messageCosts` 缓存，hover 时按需拉取）。

### 7.3B 团队工资单（+ run-detail 资源消耗）
- progress 视图 roster 每行叠加 ¥ + 占比条（`primary` 中性，状态由行 ring 表达，占比按最大行归一）；CEO 行 = 回合合计 − 各 worker（同源定价，余数精确），合计已知（`message_end`）才显。点行进 run-detail——当 CEO 收尾被提升为 synthesis run 时，CEO 行下钻到该 run 的「汇总过程」，且该 run 从 worker 行中剔除（CEO 不重复出现）；synthesis run 自身零成本（显「—」），CEO 花销仍归 captain 行，不双算。
- **run-detail「资源消耗」是唯一全量原始数字处**：model / 成本三价（输入·输出·缓存省）/ token（命中·未命中·缓存率·推理）；默认折叠，`usageDetail`（§7.1）时默认展开；¥ 合计常驻折叠态头部。

### 7.3C 对话累计
- 对话顶部极淡 caption + hover tooltip（token 合计 + 回合数）；进对话从台账 seed（`fetchConversationCost`），每回合 `message_end` live 累加（`addTurnCost`），无花销不显。

### 7.3D 账户仪表盘
- 本月额度条 + 今日 token 条（语义 %）；≥80% 转 `warning`；0=不限则不显条。明细（token / 缓存命中率 / 今日·本月成本 / 请求数）由 §7.1 全局开关控制展开。

→ 见代码：`components/chat/TaskCard.tsx`·`MessageBubble.tsx`（7.3A）、`components/chat/detail/AgentRoster.tsx`·`RunDetailBody.tsx`（7.3B）、`components/chat/ChatView.tsx`（7.3C）、`pages/more/UsageSettings.tsx`（7.3D）。

## 7.5 边界与约定

| 场景 | 处理 |
|---|---|
| 实时 vs 回放 | 执行中 `run_completed.cost` / `message_end.cost` 点亮；回放从 `cost_events` 台账重建 |
| 流式期间 | 成本是**完成时事实**（usage 只在末 chunk）；未完成不显，完成即替换为 ¥ |
| 0 成本 | 显「—」，不显「¥0.00」（与 §7.2 同源） |
| 颜色 | 仅 `primary`（占比/进度条）/ `warning`（额度告警）/ `muted`（次要文本）；遵 `color-tokens.mdc`·`desktop-layout.mdc`（成本数字 `text-xs`，条 `rounded-full`） |
