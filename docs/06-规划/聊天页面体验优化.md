> **状态**：🗂️ 讨论提案
>
> 聊天页是产品核心交互面。本文基于当前已落地的聊天 UI（`前端UX设计.md` §一–§十四）和竞品 IM 参考，提出六个优化方向及优先级。

## 方向 1：消息密度分层

### 问题

多 Agent 复杂任务时，单条助手消息内嵌 ProcessTimeline（思考 + 工具调用 + 团队图 + 检查点 + 升级卡），可占好几屏，用户很难抓到核心结论。

### 方案

#### 1a. ProcessTimeline 完成态折叠

当回合 **不再流式**（`!isStreaming`）且含过程步骤时：

- **过程节点**（reasoning / tool / tool-group）折叠到一行摘要：`"思考了 N 步 · 调用了 M 个工具"`，点击展开
- **可见节点**（content / team / checkpoint / ask / plan_review）始终显示
- 流式中保持现有行为（全展开）

涉及文件：`ProcessTimeline.tsx`

#### 1b. InlineTeamGraph 完成态默认收起

当前非辩论回合默认展开协作图。改为：

- `status === "running"` → 展开（实时看团队协作）
- `status !== "running"`（completed / cancelled / failed） → 收起（只看 StatusStrip 摘要）
- 辩论回合保持收起
- 用户手动切换后以其选择为准（`expandedOverride`）

涉及文件：`InlineTeamGraph.tsx`

## 方向 5：全局协作感知

### 问题

Agent 团队的运行状态只在当前对话的消息流内可见（StatusStrip / InlineTeamGraph）。切到其他对话或滚动远离时，用户失去"团队在跑"的感知；任务完成/需要决策时也容易错过。

### 方案

#### 5a. 侧栏活动概览

在侧栏导航区与对话列表之间，增加一个紧凑的全局活动横幅：

- 订阅所有对话的生成状态 + 审批状态
- 显示 `"N 个任务执行中"` / `"N 个待审批"` / 两者
- 点击可展开活跃对话列表，再点跳转
- 无活动时不显示

涉及文件：新建 `sidebar/ActivityBanner.tsx`，修改 `Sidebar.tsx`

#### 5b. 跨对话完成通知

当用户**不在**某对话页面时，该对话发生关键事件（团队完成 / 团队失败 / 需要审批）：

- 弹出 Toast（`notifyInfo`），内容如 `"「XXX」的团队已完成"`，带 action 按钮一键跳转
- 复用现有 `lib/toast` 基础设施
- 不重复弹同一事件

涉及文件：execution store 订阅逻辑 + toast 触发

## 方向 3：动画与微交互

> P1，后续细化

- 消息入场动画（CSS transition slide-in + fade-in）
- 流式响应期间，输入框上方显示当前活跃 Agent 角色 + 状态动画
- CheckpointCard / ToolLine 状态转换加过渡效果
- 流式文字 2-3 字一组平滑追加（检查现有 `streamingMarkdown.ts` 实现）

## 方向 4：对话管理与检索

> P1，后续细化

- 侧栏对话 hover 时显示最后几轮摘要预览
- 对话自动标签（代码审查 / 研究 / 写作 / 分析）
- 对话内消息 bookmark → 侧栏"已收藏"
- `Cmd+K` 搜索结果支持上下文预览 + 按时间/工作区/标签过滤

## 方向 2：输入区升级

> P2，后续细化

- 空对话引导卡片网格（常用场景模板），替代纯文字提示
- 输入框上方上下文面包屑（已绑定的工作区/文件夹/指令上下文）
- 长指令 Shift+Enter 多行 + 简易 markdown 预览

## 方向 6：对话内协作

> P2，后续细化

- 决策点聚合视图（侧栏或顶部"待决事项"列表）
- Agent 产出选中 → 评注（类似 Figma 评论）
- 长对话自动插入"轮次摘要卡"
