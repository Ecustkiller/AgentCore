# 桌面文件整理工作流提案

> ✅ P1 MVP 已落地（2026-07-16）。产品形态 = **对话内工作流**（否决独立整理器入口——对话触发已覆盖场景，工具箱快捷入口可后置）。P0 文件原语先行；本提案覆盖 P1「整理桌面」端到端。同日经双路独立审计修订：organize 改显式 mode、防绕过表述改「定位如实」、补齐冲突/跨盘/撤销/多 grant 边界。
>
> **落地对照**：§四/§五 决策 → `ExternalMount.mode` + 桌面 dispatch 白名单、`grant_organize_folder`、`card=organize_plan`、`file_batch(organize_plan_id)` 方案绑定放行、`organize_journal` 撤销、`organize_folder` playbook。现状说明书 → [双模式工作区 §八·10](/docs/02-架构/双模式工作区.md)、[工具与能力系统](/docs/03-AI核心/工具与能力系统.md)、[安全权限与治理 §十](/docs/05-平台与运维/安全权限与治理.md)。

## 一、三问

- **谁用**：大众桌面用户（非开发者），桌面/下载文件夹长期堆积文件。
- **真实问题**：手动整理繁琐、不知从何下手；产品 AI 目前只能看工作区，但真实用户已在问「你能看到我的桌面吗」——期待与能力有落差。
- **产品呈现**：对话里说「帮我整理桌面」→ 一次目录授权 → AI 扫描后出可勾选的整理方案卡 → 一次确认、批量执行 → 执行报告 + 可撤销。

## 二、行业基线（2026-07 调研结论）

| 共识 | 代表 |
|---|---|
| 目录级授权 + 只读/读写分层 | Claude Cowork、Manus、MCP filesystem Roots |
| plan-then-apply：方案预览 → 确认 → 执行 | LlamaFS、Sortio 等专用整理器 |
| 删除硬闸 + 可逆（回收站/快照/undo） | Claude Cowork（永久删除强确认）、Sortio（apply 前快照） |

整理类体验的胜负手是**方案预览 + 可逆执行 + 删除硬闸**，而非工具是否覆盖 move。行业刻意避开的坑：全盘常驻索引、无预览的全自动 watch、经 GUI 控制（Computer Use 类）绕过文件权限检查。调研全文见会话记录 / git 历史。

## 三、现状地基

- 工作区内文件原语齐全；**区外只读授权（W3）已落地**：`ask_user` 的 `grant_readonly_folder` → 桌面文件夹选择器 → `external/<别名>/` 只读命名空间，仅本次对话、可撤销、不改工作区绑定（→ [双模式工作区 §八·10](/docs/02-架构/双模式工作区.md)）。
- **W3 只读语义的如实定位**：对文件工具是硬约束（路由层写拒）；对本地 `code_execute` 是**软约束**——`AGENTCORE_EXTERNAL_<ALIAS>` 环境变量已注入绝对路径，本地 `SubprocessSandbox` 非隔离边界。本提案的安全设计以此为前提（见 §五防绕过），不回改 W3 现状。
- 会话 `permission_preset` 三档（observe / workspace / full_trust）是会话权限模式；委派时另有**开工卡**（`team_preview`：计划确认 ∪ 能力授权）。两者与文件夹授权均正交（→ [安全权限与治理 §三](/docs/05-平台与运维/安全权限与治理.md)）。
- P0 已落地：删除默认可逆（本地系统回收站、云/sidecar 进 `.agentcore/trash` 软删区）、`file_copy`、`mkdir`、`file_batch`（≤50 项/批、清单式审批、部分失败不中断）。

## 四、产品设计

### 4.1 授权：organize（整理读写）档 = 显式 mode

- `ExternalMount` / 桌面会话根增加显式 **`mode: readonly | organize`**（per-alias）。**禁止复用裸 `readonly=false`**：桌面 dispatch 现把 execute / process_start / archive 与写 op 一并挂在 `readonly` 单布尔上，直接翻转会连带放开执行类。
- organize 能力白名单（按 mode + op 显式判定）：list / read / grep / stat + **move（含重命名）** / copy / mkdir + 回收站删除。**显式拒绝**：write / append / replace、execute、process_start、archive、permanent 删除。
- **区外 permanent 硬闸**：路由层命中 `external/…` 即拒绝 `permanent=true`，与 mode 无关（比工作区更严）。
- 生命周期同 W3：仅本次对话、可随时撤销（按 alias）、服务端不持久化、不改工作区绑定；仅桌面本地可用。同对话可多 grant 并存、各自 mode；同一 root 由 readonly 升 organize 必须重新弹授权卡。
- 授权入口：`ask_user` 新 action `grant_organize_folder`，授权卡文案明确「AI 可移动/重命名/复制/删除（进回收站）该文件夹内的文件」。

### 4.2 工作流：扫描 → 方案卡 → 确认 → 执行 → 撤销

1. **扫描（只读）**：按类型/日期/项目归类盘点；敏感文件走启发式（证件、密码、财务类命名）**默认剔除**，方案卡可手动勾回；文案明示启发式非安全边界。
2. **方案卡**：复用 `ask_user` 新增 **`card=organize_plan`**（沿 `proposal_pick` / `risk_ack` 先例，不新增 InteractionKind，避免类型重生与两端 fold 成本；若清单交互日后超出 ask_user 答复模型再升级独立 kind）。呈现「原路径 → 新路径」清单 + 总览「新建 N 个文件夹、移动 M 个文件、删除 K 项（进回收站）」；逐项可勾选剔除（MVP 不支持改目标路径）。
3. **确认执行**：方案确认即该批次能力授权——执行经 `file_batch` 按方案分批（每批 ≤50、顺序连续），携带**方案绑定**（plan 引用 + 范围校验：仅允许方案内条目），批次执行**不再二次弹审批卡**；逐项回报成功/跳过/失败，部分失败不中断整批。**冲突策略 MVP 钉死：目标同名 = 跳过并入报告**。
4. **执行报告 + 撤销**：完成卡提供「撤销本次整理」——**move / mkdir 自动逆回放**（按操作日志倒序；mkdir 只删空目录）；**删除项不自动还原**（系统回收站无可靠程序化还原路径，Windows 尤甚），报告中列出并引导用户去回收站恢复。撤销单次有效、仅当次会话内、部分失败继续并如实报告。

### 4.3 Multi-Agent 形态

MVP 用 **CEO + 单 worker**：CEO 负责授权与方案卡交互（只读工具边界不变），扫描与执行经 `delegate` 给整理 worker——该 worker **只装配文件工具**（不含 `code_execute` / `terminal`），既贴合任务也收窄执行类旁路面。Scout / Librarian / Mover 多角色拆分是展示协作差异点的后续演进，不设为 MVP 门槛。

### 4.4 非目标（本期不做 / 后置）

- 全盘/常驻索引、自动 watch 持续整理（除非用户显式开启且有 undo，远期再议）。
- 重复文件检测、按内容深度分类、整理规则固化（P2 增强）。
- 云工作区/移动端整理——场景绑定桌面本机；远程下发任务须桌面在线且已授权（对齐行业桥接模型）。
- 跨卷 move 回落（copy+delete）：MVP 假设桌面整理同卷，跨盘（EXDEV）按逐项失败回报。
- 冲突「自动加后缀」、方案卡改目标路径：后置。
- 「整理进工作区」（把桌面文件归档到某项目工作区）：后置，MVP 只在授权目录内部整理。

## 五、技术要点（提案级）

- **授权层**：`grant_store` / `ExternalMount` 增 `mode`；桌面 sessionOnly root 同步 mode；桌面 dispatch 由 `readonly` 单布尔改为 **mode + op 白名单**判定；能力图鉴与审批分级同步。
- **通道**：organize 写操作沿 W3 读路径同构扩展（LocalWorkspace op 通道 / sidecar 两条路都要通）。
- **方案卡**：`ask_user card=organize_plan`，走统一交互生命周期（登记→展示→答复→留痕→失效）；答复携带剔除项；`file_batch` 带方案绑定与范围校验。若审批体系无法承载「方案绑定放行」，属方案层问题，停下重议（不得静默退化为双闸）。
- **撤销**：整理执行落操作日志（会话内、journal 留痕），完成卡触发 move/mkdir 逆回放（同样经 `file_batch`）。
- **防绕过（定位如实）**：organize 目录**不注入** `AGENTCORE_EXTERNAL_*` env；整理 worker 不装配执行类工具；文件工具白名单是**唯一受支持**的区外写路径（审批、方案绑定、撤销日志都挂在这条路上）。残余风险如实标注：同会话其他委派仍可能持有执行类工具，本地 `SubprocessSandbox` 非隔离边界，绝对路径一旦泄漏（如 code_execute stdout）即构成写能力——与统一熔断层同定位（兜底非安全边界），OS 级保证归沙箱演进线（→ [远期规划 §2.1](/docs/06-规划/远期规划.md)）。

## 六、已定决策与遗留

- 方案卡编辑粒度：MVP 仅支持剔除条目（改目标路径后置）。
- 撤销窗口：仅当次会话内；删除项引导回收站手动恢复。
- 敏感启发式：默认剔除 + 可勾回，非安全边界。
- 遗留观察项：`organize_plan` 若超出 `ask_user` 答复模型再升级独立 InteractionKind；跨盘回落与自动加后缀视真实使用反馈再议。
