# 统一时间线二期：升级卡与热审批痕迹进时间线

> 🗂️ 已拍板开工（2026-07-16 一期收口时立项；同日双路审计修订、产品负责人放行，一期已验收、启动闸门已开）。

## 背景

时间线一期已落地（→ [前端 UX §三·统一团队时间线](/docs/04-前端/前端UX设计.md)）：时间线基准语义 = **用户可感知的出现顺序**；投影键统一（interaction 查询键 = `serverMessageId ?? id`）；废除底部堆叠回退，立不变量「有交互卡必有时间线标记」（reload 从 journal 补标记）；流式 key 稳定化。

一期范围外、结构上仍不满足「一条回复内所有块按可感知时序」的两类：升级卡全部挤在协作图 `team` 槽下、多次升级不分先后；热审批 / 委派授权 resolve 后气泡内无按时刻留痕。

## 二期范围与已钉死决策

| # | 决策 | 内容 |
|---|---|---|
| D1 | 标记时刻 = `*_required` | 升级 / 审批 / 委派授权的时间线标记一律在 `*_required` 到达 CEO 车道的时刻落位（与 `checkpoint` / `team_preview` 同模式）；resolve 只更新该槽渲染、不另发标记。reload 复用 registry 驱动的 journal 补标记路径。 |
| D2 | 升级卡整体迁槽、只改位置不改内容 | 今日在气泡内渲染的全部升级形态（阻塞 `pending` 可拍板卡、非阻塞 `raised` 轻提示、CEO 仲裁 awaiting 形态、resolved 态）一律改为按各自 `escalation_required` 时刻落独立标记；画布指挥台 `EscalationCards` 双挂维持现状。 |
| D3 | 热审批 / 委派授权 = 痕迹、非卡 | pending 期间仅决策区（dock）有操作面，时间线**不渲染**；resolved 后在其 required 时刻的标记槽显一条轻状态行（类「已授权开工」条）。操作面不迁移。 |
| D4 | 否决旧「执行级归属槽」叙事 | 原「队员升级是执行级时刻、不另发标记、随团队执行槽渲染」设计否决；落地后将 UX §统一团队时间线对应段改写为「按各自时刻落标记」现状。 |
| D5 | 不变量适用范围 | 升级卡纳入一期不变量「有交互卡必有时间线标记」；审批/委派痕迹**非**交互卡，适用弱式不变量「有标记必有 journal `*_required` 事件」，行渲染由 resolved 门控（pending 标记在、行不显）。 |

## 时序上限（已承认的边界）

新标记给出的是升级/审批相对 **CEO 车道各块**的先后（排在 `team` 标记之后、可与 CEO 后续正文/工具步交错）；**不做协作图内部 worker 步级交错**——协作图仍是单块容器。

## 改动面 checklist（必碰面清单，非实现草稿）

- **契约/Wire**：`payloads/process.py` `ProcessStep` 联合补三类标记 + `pnpm gen:types`。
- **三处投影同构**：`EventSink._accumulate_process` / `_marker_spec_for_required`；`conformance/projection.py`（approval 现为显式 pass，需实现）；桌面 live 盖章（升级 `sseVia: "execution"`，不走现有 interaction 盖章路径，需 execution 处理器盖章）。
- **前端类型链**：`TimelineProcessKind`、`stepIdField`（现仅 `checkpoint_id | ask_id`）、`appendMarkerStep`、registry `timeline` 行、`registryUi`、`ProcessTimeline` 解绑 `team` 槽下整包 `EscalationCards`。
- **挂起捕获**：`synthesize_required_marker`（G7）纳入新 kind，否则 pause 快照缺锚。
- **mobile**：升级从 `TeamView` 迁独立标记、fold 与桌面对齐。
- **golden 重导**：升级族（`conformance/vectors/multi_agent/escalation.py` 等）+ `approval_*` / `delegation_authorization_*` 族，`uv run python -m agentcore.conformance.export`。

## 验收

- 多次升级按各自时刻分先后（`multi_agent_blocking_escalate_multi` 等向量渲染序正确）。
- resolved 审批/委派在 required 时刻有轻状态行；pending 仅 dock、时间线无行。
- reload 后新标记与痕迹不丢（journal 补标记路径覆盖新 kind）。
- `pnpm conformance` desktop + mobile 全绿；`pnpm shoot` 升级/审批场景读图核对；一期投影不变量测试扩展（`TIMELINE_KINDS` 纳升级 + 审批痕迹弱式断言）。
