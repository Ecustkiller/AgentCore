## 一、问题与动机

### 1.1 病根：交锋拓扑与形态语义错配

三形态已共用一套 `Moderator` 确定性循环（`DebateForm` 参数化，非三条独立路径）——「是否合并」不是问题。问题是**形态差异目前只落在 prompt / 门槛 / 产物侧重这一层**（`_form_guidance` / `role_directive` / `RoundPolicy.for_form` / 简报 hint），而三种人类形态的**交互拓扑本质不同**：

| | 正反攻防 | 红队挑刺 | 多方圆桌 |
|---|---|---|---|
| 人类原型 | 竞技辩论 | 评审委员会 / 渗透复盘 / pre-mortem | 专家 panel |
| 交锋拓扑 | 二元对称 | **星型多攻一** | **多边串行对话** |
| 现实现 | 全员并行波 + 下轮摘要注入 | 同左 | 同左 |

「全员并行波 + 跨方信息只有主持人按轮注入的上轮对方发言（头尾裁剪，`_OPP_CLIP`）」对二元对称是**恰好合身**的：2 方时「下轮针对性回应」观感就是对话，质询/结辩 beat 再补足当面交锋。但同一套机制放到红队（1+N）与圆桌（N 边）上：

- **首轮结构上互不可见**（裁判 prompt 写死首轮各方独立发言、`clashes` 恒空），4 方时首轮就是四篇并列独白墙；
- 红队**并非没有 beat，而是共用了正反的 beat**：质询 / 结辩对 `RED_TEAM` 与 `DEBATE` 同开（`cross_exam_enabled` / `closing_enabled`），但质询是「主持人→各方」的对称问答，不是「红队攻击 → 方案方逐条回应」的星型时序——设计表格明文的「单向攻击 → 方案方回应」（[辩论编排设计 §三](/docs/03-AI核心/辩论编排设计.md)）没有对应的执行结构：方案方与全体红队同波并行，对本轮火力最早下一轮才看得见。红队与正反在执行层几乎无差别，这正是实测「2 方红队像普通辩论」的直接原因（本提案对红队是**替换**其现有质询原语，不是从零补时序）；
- 红队 `role_directive` 原文「单向施压，不需要你自己另提方案」，叠加 CEO 惯例按域拆红队（实测场：架构 / 成本 / 工程三路），放大独白效应；
- 圆桌把「不裁胜负」误做成「不用对话」——裁判明文允许「并非针锋相对」、质询/结辩刻意关闭，「铺光谱」被实现成「并列交卷」。

[辩论编排设计 §四之二](/docs/03-AI核心/辩论编排设计.md)自己已把旧病根写成「并行独白相递」并否决「只改辩手 prompt」——但质询三支柱主要补的是**正反攻防**的当面交锋（主持人→各方问答），没有补红队/圆桌的形态专属拓扑。

### 1.2 实测证据（开发期数据，样本 n=2）

两场红队实测（2 方、4 方）均在首轮取证阶段被用户手动停止，形态价值从未呈现。这同时暴露「取证阶段过程可读性/时长」问题——**已明确后置另案**（见 §七 刻意后置），本提案只治编排拓扑。

## 二、设计原点：三形态回答三种用户问题

正向推导（用户需求 → 产品设计 → 技术实现），三形态对应三种真实诉求与三种成熟人类协作形态：

| 形态 | 用户带来的问题 | 用户要带走的产物 | 本提案动作 |
|---|---|---|---|
| 正反攻防 | 「该不该做 X？选 A 还是 B？」 | 有依据的裁决 + 双方最强论证 | **零变更（回归基线）** |
| 红队挑刺 | 「我这个方案扛得住吗？哪里会崩？」 | 被打磨过的方案 + **每条都有下场**的风险清单 | 重设计（§3.2） |
| 多方圆桌 | 「这个问题的全貌是什么？各方怎么看？」 | **共识/分歧地图** + 分歧根源 | 重设计（§3.3） |

**人类红队评审的铁律**（安全渗透复盘 / 军演 / 设计评审 / pre-mortem 的共性）：

1. 攻击对象是**方案的具体部位**，不是主题作文；
2. **每一刺都有下场**——评审价值在 finding 台账（逐条处置：接受/缓解/反驳/挂起），不在发言记录；没被回应的刺等于白挑；
3. **复攻打的是防御本身**（「你说加重试就行——重试恰恰放大惊群」），深度来自这里；
4. 红队之间**不互驳**（分域挖洞是特性），但主席**去重合并**，防止多路红队用不同话术捅同一个点；
5. 收场是**门决**不是比分：有条件通过 + must-fix / 需重大修改 / 不可行。

**人类圆桌的铁律**（专家 panel / 编辑部圆桌 / symposium 的共性）：

1. **串行、有相邻性**——每个发言接着刚说过的话，对话感完全来自「看得见本线程已有发言」；
2. **分题点名**，不是人人每题必答——主持人拆子题轴，每个子题只请最相关的两三位；
3. **分歧被钻探而不是被裁决**——主持人追一层「你们的分歧是事实判断还是价值排序？」，挖到 crux 即止；
4. **产物是地图**：哪些点收敛（结论稳健）、哪些点分裂、分裂由什么驱动。

## 三、目标形态

### 3.1 架构原则：形态 profile 从「prompt/参数」升级为三元组

**形态 profile = 交互单元 + 轮内拓扑（phase 结构）+ 收敛/产物语义。**

- 共用引擎不变：`Moderator` 确定性循环、辩手 `RunSession` + `continue_run` 跨轮记忆、检索→成稿两阶段（§4-2.5）、证据台账/举证闸（§4-2.3）、对局台账（§4-2.6）、ambient 掌舵与开工卡（§六）、双产物与 SSE 骨架（§7.4）全部复用。
- 变化只有一处定位：「轮内全员并行波」从**引擎的唯一形状**降级为**正反攻防这一个 profile 的形状**；`RoundRunner` 按 profile 声明的 phase 结构派发（并行波 / 星型三拍 / 点名串行均由既有原语组合：并行委派 + `continue_run` + 材料注入）。
- 不新建执行引擎、不新起 SSE 通道（沿用 §八 既有否决）。

### 3.2 红队：finding 生命周期 + 星型三拍 + 门决

**交互单元 = finding（刺）**：`{id, 严重度 critical/major/minor, 指向部位（方案的哪个环节/假设）, 主张文本, 证据引用（#eN）, 状态}`。状态机：`open →（方案方处置）answered → （红队复核）closed / escalated / deadlocked`。

**轮 = 一个完整的攻防复核周期**（对准本轮 focus），轮内三拍：

| 拍 | 谁 | 做什么 | 复用原语 |
|---|---|---|---|
| ① 攻击波 | 全体红队**并行** | 检索→成稿，产出本轮 finding 列表（每条指向具体部位、带证据标记）；红队之间不要求互驳 | 现有并行波（首轮 `build_run_plan` / 续轮 `continue_run`） |
| ①′ 合并 | 主持人 | 跨红队**去重合并**重复 finding（宁少合并勿误合并），编排回应清单 | 主持人 LLM 判定（同 agenda/裁判嵌入式调用） |
| ② 回应拍 | 方案方**单独** | 看到本轮**全部** finding，**逐条处置**：接受 / 缓解 / 反驳 / 挂起（每条处置须给理由与证据） | `continue_run` + finding 清单注入（同 `round_feedback` 模式） |
| ③ 复攻拍 | 全体红队**并行** | 只针对方案方的**处置**复核（禁止重复原刺）：每条 finding 判 closed / escalated / deadlocked，escalate 须说明防御为何不成立 | `continue_run` + 处置材料注入 |

- **裁判/记分转 finding 口径**：逐轮裁判读台账状态变化；`escalated` 的 finding 自动进下一轮 agenda 优先位。记分三维语义映射：红队按「finding 质量」（具体性/严重度校准/证据），方案方按「处置质量」（正面接招/证据/不硬拗）；举证铁律（§4-2.3）与罚分照旧贯穿。
- **收敛 = critical/major finding 全部 closed 或 deadlocked**（`red_team_exhausted` 语义自然承接）；跨轮论点账本与边际递减断路器（§五）继续兜底。
- **质询 beat 在红队形态被三拍取代**——复攻拍就是形态化的质询（红队↔方案方当面交锋），不再走「主持人→各方」的通用质询（现网红队与正反同开该原语，本提案将其替换）；结辩在红队形态**移除**（O1 已拍板：`closings` 恒空、门槛收窄为仅 DEBATE）。
- **与既有两本台账的分工不变式**：finding 状态是**形态产物**（红队复攻主张 + 裁判裁定为权威）；`match_ledger` 照旧只收显式状态变化、喂下一轮行为约束（撤回 / 让步可由 finding 处置**派生**，不双写两本）；finding 主张文本照走 `EVIDENCE_RULE` + 证据台账 id 闸（`evidence_guard` 回炉 / 降级语义不变）。
- **产物 = 风险台账 + 门决**：`brief` 的红队形态从「风险清单 + risk_severities」升级为 finding 台账视图（刺→处置→复核全线程）+ 门决枚举（`conditional_pass` + must-fix 清单 / `needs_major_rework` / `not_viable`），must-fix 来自未关闭的 critical/major。`decisive` 保留（点名哪条 finding 定了门决）。**wire 迁移**：`DebateBriefInfo.risk_severities`（按方 high/medium/low）随之退役——严重度降到 finding 粒度；前端 `severity.ts` / `RiskBoard` 改读 finding 台账，旧载荷走「旧数据兼容」降级渲染。
- **前端**：红队英雄区从「按方分栏」改为**按 finding 线程**渲染（刺 → 回应 → 复核，状态徽章驱动）；对打感来自线程，不来自并排文章。手机端沿用极简摘要视图（同 P1/P2 先例，不下沉）。

### 3.3 圆桌：分题点名串行线程 + crux 追问 + 共识/分歧地图

**交互单元 = 线程 turn**：`{speaker, 回应目标（可空 = 开题）, 文本}`。

**轮 = 一个子题**：

1. **frame 升级**：首轮把命题拆成 2–4 个**子题轴**（现有「光谱维度轴」hint 结构化为子题清单）；每轮 = 推进一个子题。
2. **点名串行**：主持人按视角相关性点名 2–3 位**依次**发言——后发者注入本线程已有发言全文（非摘要），prompt 要求「先回应已说的、再补自己的」；未点名者可被邀请补一句或跳过（pass 语义见 O4）。被点名方发言失败 ⇒ 主持人跳过、改点下一位（线程降级不阻塞子题，对齐 `absent` 续赛精神）。
3. **crux 追问**：线程内出现实质分歧时，主持人追问**一次**（定向：「你们的分歧是事实之争还是价值之争？」），双方短答；挖到 crux 即止、不逼收敛。
4. **裁判转地图口径**：逐轮小结从「clash 抽取」改为该子题的「共识点 / 分歧点 / crux（分歧驱动因素：事实 vs 价值 vs 假设）」。
5. **收敛 = 子题轴铺满**（既有语义保留）；记分继续不驱动 leaning。
6. **产物 = 共识/分歧地图**：按子题组织——各方核心主张、收敛处（稳健结论）、分裂处（crux 标注）；`narrative_first` 保留强化。质询/结辩维持关闭（`_closing_enabled` 现状不变）。

### 3.4 正反攻防：零变更

作为回归基线：**行为与 wire 形状零回归**——共享调度代码允许因 profile 分派而重构，但 DEBATE profile 的并行波 + 质询 + 结辩 + 记分链路形状不变，正反金样（`debate_single` / `debate_multibeat` / `debate_followup`）必须持续全绿。

**兼容性核对（实施期验证，不是开放问题）**：ambient 掌舵与 conclude 语义锚定「轮边界」——新拓扑下轮边界仍存在（三拍收口 / 子题收口），steer 队列机制零改动；开工卡、检索预算（`engine_debate_token_ceiling`）、便签墙关闭（`collaboration=False`）照常。缺席轮语义（`absent`）**红队的攻击侧与圆桌照常**；红队**方案方**缺席是星型单点、需专门语义（见 O7）。

**墙钟代价（产品取舍，已知情拍板）**：红队三拍约为**现「并行波＋质询」单轮**的 1.5–2 倍（基线注明：比较对象是现拓扑，不是用户可忍受阈值）；圆桌串行线程墙钟最贵。且攻击波 / 复攻拍仍走 `research_then_draft`，检索时长主导墙钟——检索污染与时长治理已后置另案（§七），本提案不缩短取证、只让等待过程可读。设计立场：这两形态的用户在等「值得等的产物」（风险台账 / 分歧地图），且过程本身变得可读（刺被逐条回应、主持人点名追问）——过程可读性是等待体验的解药。快速档降级形状见 O3。
