## 一、动机（诊断摘要）

统一辩论室（IM 群聊）存在六个系统性问题，叠加成用户反馈的「不像成熟产品、像 AI 做的」：

1. **隐喻错位**：几百字的论证文章被塞进 85% 宽聊天气泡；立论/质询/结辩/终审等戏剧阶段视觉同质，读整场 = 翻超长聊天记录。
2. **芯片汤**：名字 pill / 模型徽章 / 状态 pill / 计数 pill / 置信 chip / 记分 chip 每行 2–4 枚，元数据与内容同权。
3. **高价值数据被藏、低价值常驻**：三维记分躺 tooltip、记分总览默认折叠、交锋边压成一行静态引用；而「7 个 Agent · 7/7 子任务 · <¥0.01」工程读数常驻入口第一屏。
4. **解释性 UI**：遍地 Info 图标 + 大段 tooltip + 「收场后呈现」类占位文案，用文案解释设计。
5. **没有舞台**：辩题无标题位、比分无记分牌、「VS」是侧栏一行小字、终审（产品 payoff）是又一个灰气泡。
6. **读法控件碎片化**：流式/并排全局开关 + 逐轮覆盖 + 结论锚 + 侧栏裁判台折叠，五套小聪明谁也发现不了。

根源：群聊隐喻天然表达不了「阶段 / 比分 / 裁决」，只能靠 pill 和右坞裁判台往回补，越补越碎。

宽度：记分牌横贯内容区（`max-w-7xl`）。剧本主列两种布局（记分牌「布局」开关切换、偏好持久化 localStorage）：**并排**（正反两方默认）＝占满 `max-w-7xl`，正方左 / 反方右两栏对照（**仅逐轮发言分栏**；轮头 / 质询 / 裁判札记 / 用户追问 / 掌舵仍通栏）；**单栏**（红队 / 圆桌恒用，正反可切）＝正文列 `max-w-3xl` 居中（长文阅读宽度）。上方剧本主列示意图为**单栏态**。

### 3.1 记分牌（sticky header）

- 行 1：**辩题**（`motion`，`text-base font-medium`，截断 + title）+ 右侧状态（live =「第 N 轮 · ×方正在立论」+ 身份色脉冲点；settled = 收场原因）+ 一枚**「这场怎么读」info popover**（收编质询/结辩/记分/举证等全部概念解释，全页其余 Info tooltip 一律删除）。
- 行 2 按形态变体（§四）：正反 = 左右阵营（身份色名字 + 驱动模型，模型徽章全页仅此一处）+ 中央累计比分（`text-xl tabular-nums`）+ **momentum 微图**（逐轮各方得分小条，身份色；无记分的轮 / 圆桌整体隐藏）。
- **阶段章节 chips**：第 1 轮…第 N 轮 / 结辩 / 终审，点击滚动到对应锚点；当前可视阶段高亮。
- **站队控件（仅正反 2 方）**：小 segmented「你站：正方 / 反方」，随时可点可撤，session-only（沿用 `debateUserTake`），不回灌裁决；逐气泡 `StanceVote` 移除。
- 掌舵挂起时：记分牌出「等你掌舵」primary 徽标，点击滚到掌舵面板。

### 3.2 剧本主列（transcript）

- **阶段分节头**：`text-xs` muted 标签 + 细线（「第 N 轮 · 焦点」「质询」「结辩陈词」），轮头挂滚动锚；焦点与辩题同文则省略焦点。
- **发言块 SpeakerBlock**（取代气泡）：左 3px 身份色轨；头行 = 身份色名字 + 阶段词（立论 / 续辩 / 答问 / 结辩）+ 仅异常/流式态（正在输入 / 发言失败）；正文全宽 `text-sm`（`Markdown evidence` + `CollapsibleSpeech` 折叠保留）；头行可点仍钻右坞 run 详情。**无头像圈、无名字 pill 胶囊、无模型徽章。**
- **反驳引用块**：块顶「回 ×方：要点」引用条，**可点击**——滚动至被驳方上一轮发言块并短暂高亮（交锋锚点）。
- **质询小节**：保留「N/M 正面回答」概览（圆点状态）+ 逐条 Q/A 手风琴，但拍平 chrome（去掉卡中卡双层描边），作答仍可钻 run 详情。
- **裁判札记 JudgeNote**（取代主持人气泡）：非气泡横带（⚖ 图标 + muted 底或上下细线）——本轮小结正文 + 信号词（真交锋 / 已收敛等，沿用 `describeRoundVerdict`）+ **逐方本轮得分内联直出**（如「正 +2 · 反 +3」，罚分以 destructive 小注记 + hover 明细），不再用 tooltip 藏三维分。开场白（`openingText`）是首条札记；小结空窗显示「主持人正在小结…」同带。
- **用户追问**：右对齐的用户块（transcript 变体），带定向对象与状态词（已发送 / ✓ 已被承接 / 未及回应）。
- **掌舵面板 SteeringPanel**（live 轮边界挂起时，流末全宽 primary 淡面）：裁判建议行 + 追问 textarea + 定向 chips + 加角度 + 三动作（继续辩一轮 / 按此角度继续 / 够了出结论）。逻辑与服务照搬现 `SteeringBar`（`decideDebateRound`，结算由 SSE 翻面）；重载后（`interactive=false`）显只读一行。`conversationId` / `interactive` 由 `CanvasZoomedTurn` **直接以 props 传入** arena 页（不再经 `debateRoom` 店）。

### 3.3 终审舞台（Finale，非气泡）

- 顶部强分隔进入舞台区：「主持人终审」头（模型徽章 + 收场原因 + 「裁决过程」钻取）→ **倾向 `text-xl font-semibold`** + 置信 chip + 胜负手 + 争点。
- 主体：双方最强论点对照格（身份色 + 净分）→ 需你拍板（价值之争）→ 建议 → **终盘比分条默认展开**（身份色填充，非 primary）→ 你 vs AI 站队对照 → 「还需厘清」保留折叠。
- 行动排：**换个角度再辩**（复用现 `Continue`）+ **回到对话**（关闭放大态）。不新造收场后追问通道。
- 结论生成中态沿用「结论简报生成中…」。

### 3.4 聊天入口卡（StatusStrip 辩论分支）

预告片文案取代工程读数：settled =「辩论完成 · 正反 N 轮 · ×方略占优」（占优取累计净分领先方，平分/无分则省略；红队/圆桌用形态词），live =「辩论 · 第 N 轮进行中」；Agent 数 / 子任务 / 耗时 / 成本从**辩论分支**移除（非辩论团队分支不动）。「打开辩论室」CTA 不变。

## 四、三形态变体

剧本主列语法三形态共用，仅记分牌行 2 与终审主体变体：

| 形态 | 记分牌行 2 | 终审主体 |
|---|---|---|
| 正反辩论 | 红蓝对垒 + 累计比分 + momentum + 站队控件 | 现 `DebateBrief` 结构重排（对照格 / 拍板 / 建议 / 比分 / 依据） |
| 红队审查 | 被审方案方 + 红队名册；settled 后高/中/低风险计数 chips | 现 `RedTeamBrief` 结构重排（风险看板 / 加固 / 方案方回应） |
| 圆桌探讨 | 视角名带（身份色点 + 名字），无比分无站队 | 观点光谱先行 + 简报小结（现 `RoundtableSpectrum`/`RoundtableBrief` 重排） |

进行中无结构化 brief 的槽位一律**直接不渲染**（honest gap），不出「收场后呈现」类占位文案。

## 五、视觉纪律（六条硬规矩）

1. **每屏一个主角**：记分牌看比分、正文看论证、终审看裁决；任何区块不同时强调两件事。
2. **层级靠字阶和留白，不靠嵌套边框**：禁止气泡套引用套折叠的多层描边；拍平到单一背景 + 字阶 + 间距 + 一条身份色轨。
3. **每条发言一条 meta 线**：名字 · 阶段 · （仅异常/流式）状态。模型徽章只在记分牌与终审头出现。
4. **tooltip 不当文档**：概念解释收编进记分牌「这场怎么读」popover；正文区 Info 图标清零。
5. **空态骨架化**：删除解释型占位文案；无数据的槽位不渲染。
6. **身份色只出现在**发言块左轨、记分牌阵营/比分图、终审对照格与比分条；状态色（primary/success/destructive）不与身份色混用（遵 `color-tokens.mdc`；正反恒 `--debate-side-pro/con` 红蓝 token）。

其余遵 `desktop-layout.mdc`（4 级字号 / 3 级圆角），终审倾向用 `text-xl` 在字阶内。

- **「统一辩论室 = IM 群聊」**（前端UX设计 §4.1，2026-06 拍板）→ 被赛事页替代：群聊隐喻表达不了阶段/比分/裁决，长文不适合气泡。
