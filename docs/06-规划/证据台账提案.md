## 一、问题与动机

用户看到的「已核实」徽章，目前**不能保证**对应一次真实检索结果。两条管线各管一段：

| 管线 | 用户可见形态 | 机械可校验？ |
|---|---|---|
| citations 角标 | 正文 `[1]` → 来源卡 | ✅ 编号 ∈ 本回合来源池（CEO 路径） |
| 辩论证据标记 | `【已核实·街访数据】` → 绿徽章 | ❌ 出处自由文本；结辩仅能拦「本场从未出现过的新标签字符串」 |

终态目标：**检索产出结构化台账 → 成稿只引台账 id → 校验/分级/徽章同源可溯。**

## 二、两套现状机制盘点

### 2.1 citations 角标（回合来源卡）

**覆盖范围**

- `web_search` / `read_url` 成功结果经 `merge_citations` 写入回合引用池（按 URL 去重，上限 24）。
- CEO 路径 `annotate_citations=True`：工具输出末尾注入 `[n]=url`，模型按号引用；`finish_guard.check_citations` 拦越界 `[n]`；出口 `reconcile_citations` 剥离悬空角标。
- Worker / 辩手检索：`annotate_citations=False`——只收集、不编号、不做角标校验（编号在汇入回合卡时会重排）。

**消费方**

| 消费方 | 行为 |
|---|---|
| `runtime/verify.py` · `finish_guard` | CEO 造引用回炉 |
| pipeline 收口 | `citations_event` + 落库；挂起快照带引用池 |
| 桌面 / 手机 `remarkCitations` | `[n]` → 可点角标，挂来源卡 |
| 辩论管线 | 辩手 research 的 `citation_sink` 会收集，但**不驱动**证据标记、不进裁判 prompt |

**盲区**

- 只管「角标是否指向存在的卡」，**不管**主张内容是否真被该 URL 支撑。
- Worker / 辩手成稿不用 `[n]`，与辩论证据标记零耦合。
- 契约字段仅为 `url / title / snippet / site`——无稳定 id、无日期、无来源层级。

→ 见代码: `apps/server/agentcore/runtime/citations.py`

### 2.2 辩论证据状态标记（方案 A 内联）

**覆盖范围**

- Prompt 铁律 `EVIDENCE_RULE`：关键事实须标 `【已核实·<出处>】` 或 `【待核实·推断】`（出处为自由短语，如「2024年报」）。
- 三处咬合（**同一字符串约定**）：辩手标 → 裁判据标记记分/罚 → 前端 `remarkEvidence` 渲徽章。
- 近期缓解（辩论域内，仍非台账）：
  1. **结辩材料注入**：`closing_task` 注入本方历轮论点 / 质询让步 / 对方 clash，禁新论据。
  2. **后置机械闸**（`evidence_guard` + `speech_pipeline`）：结辩**白名单闸**（成稿相对「本场本方已出现过的【已核实·X】全文」做字符串差集）+ 立论 / 续辩 / 质询作答**出处软校验闸**（出处须与本方检索语料宽松对应，只拦「凭空来源」、宁可漏报不可误杀）；违规回炉一次，**二次违规剥离标签、降级【待核实·推断】后放行**（O2 已拍板落地 2026-07，见 §七）。
  3. **裁判来源三级锚定**（prompt 软约束）：`evidence` 维按 司法文书/官方原文 > 权威媒体 > 自媒体/百科/转述 封顶；弱源须点名；简报/CEO 收尾不得抹平待核实/二手状态。

**消费方**

| 消费方 | 行为 |
|---|---|
| 主持人质询 / 记分 | 盯「待核实当论据」、按自由文本出处猜来源等级 |
| `remarkEvidence` + `EvidenceBadge` | 桌面辩论发言 / 质询 opt-in；手机镜像；徽章文案 = 出处原文，**不可点开 URL** |
| conformance / 磁带 | 正文内联标记随发言全文；金样钉契约字符串 |

**盲区（根因）**

- **出处对账只是宽松字符串匹配**：软校验闸只判「来源名在本方检索语料中有无迹可循」（归一化 n-gram 命中即过、宁可漏报），拦不住「检索过的来源被张冠李戴到它并不支撑的主张」；无稳定 id，无法机械溯源到具体 URL / 具体一次检索。
- 来源等级依赖裁判 LLM 读自由文本，无法机械分级。
- 与 citations 池并行存在：辩论 research 已有 URL 池，标记却不引用它。

→ 见代码: `apps/server/agentcore/runtime/debate/prompt.py`（`EVIDENCE_RULE`）· `evidence_guard.py` · `speech_pipeline.py` · `moderator_judge.py`

### 2.3 并列表（决策用）

| 维度 | citations `[n]` | 辩论 `【已核实·出处】` |
|---|---|---|
| 标识 | 回合内 1-based 序号 | 自由文本短语 |
| 机械闸 | CEO：越界角标回炉 | 仅结辩：新标签字符串回炉 |
| 前端 | 角标 → 来源卡 | 徽章 → 纯文案 |
| 裁判/汇总 | 不进辩论记分 | 进 evidence / penalties / 简报继承 |
| 跨域 | CEO 汇总主路 | 辩论域专有 |

## 三、目标形态（终态）

### 3.1 台账条目（检索产出）

每次成功检索（search hit / read_url）写入**结构化台账条目**（概念字段，非实现草稿）：

| 字段 | 用途 |
|---|---|
| `id` | 稳定短 id（成稿引用面，如 `#a3` 或台账序号） |
| `url` | 归一化 URL（去重键，对齐今日 `merge_citations`） |
| `title` / `snippet` / `site` | 展示与卡片（兼容现 Citation） |
| `date` | 来源日期（有则填；检索未给则为空，不编造） |
| `tier` | 来源层级枚举（与裁判三级对齐：官方原文 / 权威媒体 / 弱源）——优先规则表机械判定，LLM 仅补洞 |

台账作用域建议：**单场辩论 = 主持人树下各辩手 research 合并池**；CEO 直答回合 = 今日 citations 池升级为台账（合流，见 §3.4）。

### 3.2 引用面（成稿 · 汇总 · 简报）

- 已核实主张：**只许**引用台账 id（辩论先行格式建议 `【已核实·#id】`，见 §五）。
- `【待核实·推断】` 保留（无台账可引时的诚实出口）。
- 裁判简报 / CEO 收口：引用事实时带 id 或显式待核实语；禁止把无 id 关键事实写成定论（延续今日「不得抹平」纪律，改为可机械抽查）。

### 3.3 机械能力（替代软约定）

1. **校验闸**：成稿中每个 `【已核实·#id】` 的 id ∈ 本作用域台账；否则回炉（对称今日 `finish_guard` / 结辩白名单，但基准从「说过的字符串」改为「检索登记过的 id」）。
2. **evidence 自动分级**：记分 `evidence` 维优先读台账 `tier`（+ 多源交叉：同一主张挂多个 id），裁判 LLM 只解释、不臆造等级。
3. **前端可溯源**：徽章点击 / hover → 台账条目（URL · 标题 · 日期 · 层级）；与来源卡 UI 可共用组件。

### 3.4 与 citations 角标的合流路径

| 阶段 | 策略 |
|---|---|
| **先行（辩论强台账）** | 辩论成稿走 `【已核实·#id】`；CEO 汇总仍可走 `[n]`；两套 id 空间暂分域，但底层条目形状统一（Citation ⊃ 台账字段子集）。 |
| **合流** | 回合引用池 = 台账；CEO 正文 `[n]` 的 n = 台账展示序号；辩论标记的 `#id` = 同一条目的稳定 id（或约定 n≡id）。前端角标与证据徽章都解析到同一条目。 |
| **兼容** | 存量正文无 `#id` 的自由文本标记：渲染降级为今日徽章（不可溯源），新产出强制 id。 |

**产品判据**：用户点任意「已核实」都能落到一张真实来源，且系统能证明该来源曾被工具返回。

## 四、辐射面清单

| 模块 / 端 | 为何动 | 风险 |
|---|---|---|
| `runtime/citations.py` + 工具 `web_search`/`read_url` | 产出台账条目（id/date/tier） | 契约变宽；需版本/兼容字段 |
| `runtime/verify.py` · finish_guard | CEO 路径扩展「已核实 id ∈ 台账」或与角标闸合并 | 误报纪律：仍须近零误报 |
| `runtime/debate/prompt.py` · `EVIDENCE_RULE` | 改引用格式为 `#id` | 辩手遵从度；旧磁带文案 |
| `speech_pipeline` / `closing_guard` | 白名单基准改为台账 id 集（立论阶段即可闸，不只结辩） | 回炉次数 / 延迟 |
| `moderator_judge` / `moderator_brief` | evidence 读 tier；简报继承带 id | prompt 与机械双轨过渡期 |
| CEO 汇总 / `to_ceo_output` | 收尾不得抹平 → 可抽查 id | 与辩论简报字段衔接 |
| 桌面 / 手机 `remarkEvidence` + `EvidenceBadge` | 解析 `#id`、挂台账载荷、可点溯源 | 需台账随 wire/投影可达；跨端 parity |
| `remarkCitations` / 来源卡 | 合流后共享条目模型 | UI 统一或双入口 |
| conformance 向量 · 辩论金样 | 钉新标记 + 可选台账事件/载荷 | 双端 fold 对齐 |
| 存量磁带 / demo（含 lv-molihua） | 回放：旧自由文本标记降级渲染；不要求旧带重录除非宣传片依赖徽章可点 | 宣传资产预期管理 |
| 契约类型 `Citation` / SSE | 字段扩展或并列 `ledger` 事件 | 生成类型 + 两端消费 |

**刻意后置（非本提案必做）**：法律垂直「来源卡台账」、跨回合长期知识库、用户上传证据入库——可复用条目形状，但不绑本终态 MVP。

## 五、分阶段落地：辩论域强台账先行

### 5.1 先行段定义

**范围**：仅辩论辩手成稿（立论 / 续辩 / 质询 / 结辩）。

**格式**：`【已核实·#id】` + 保留 `【待核实·推断】`。

**闸**：research 阶段写入场级台账 → 成稿阶段校验 id ∈ 台账（结辩白名单升级为台账子集，且立论起生效）→ 二次违规沿用已拍板策略：剥离标签、降级【待核实·推断】（O2 已决，见 §七）。

### 5.2 可行性（基于现状）

| 已有地基 | 为何降低先行成本 |
|---|---|
| 辩手 research 已有 `citation_sink` | 条目源现成，缺的是 id 与成稿引用约定 |
| 结辩白名单闸模式 | 差集 + 回炉骨架可直接改基准集 |
| `remarkEvidence` 已解析 `·` 后 note | `#id` 可进 note；溯源需额外传台账 map |
| 裁判三级文案已落地 | `tier` 字段可逐步替换 LLM 猜等级 |

**主要依赖（前端联动）**

1. Wire：台账如何到达渲染层——随 `citations_event` 扩展 / 辩论专用载荷 / run 级附件（**开放问题 O1**）。
2. `remarkEvidence`：识别 `#id`、查询台账、徽章可点；无台账时降级纯文案（兼容旧磁带）。
3. 手机：若辩论室仍极简，至少 Markdown 证据徽章与桌面同构；溯源面板可桌面先行。

### 5.3 建议里程碑（决策用，非排期）

1. **M1 辩论强台账**：场级台账 + `【已核实·#id】` + 成稿闸 + 桌面徽章可溯源；裁判仍可读标记，tier 先规则表 MVP。
2. **M2 记分/简报锚定台账**：evidence 自动分级；简报/CEO 抽查。
3. **M3 与 `[n]` 合流**：**P1+P2 已落地**（共享核、回合 `#r` 台账、id 闸、独立 `evidence_ledger` SSE、主卡=成稿引用集、weak 可引用+弱源徽标）——现状见 [工具与能力](/docs/03-AI核心/工具与能力系统.md) / [执行引擎 · finish_guard](/docs/03-AI核心/执行引擎架构设计.md) / [前端 UX §一B](/docs/04-前端/前端UX设计.md)。**剩余**（P3 主张须证）→ [引用即出处提案](/docs/06-规划/引用即出处提案.md)。

## 六、被否方案与理由

| 方案 | 否决理由 |
|---|---|
| **只加严结辩白名单 / 更多 prompt** | 已落地仍堵不住「首轮编造 → 白名单洗白」；不解决可溯源与自动分级。 |
| **方案 B：结构化 `claims: list[Claim]` 作为辩手主输出** | [辩论编排 §4-2.3](/docs/03-AI核心/辩论编排设计.md) 已否为当期（输出契约过重）；台账是**检索侧登记 + 成稿引用 id**，不强迫全文 JSON claims。 |
| **独立 Arena 证据引擎 / 第二套 SSE** | 沿用辩论既有否决：复用执行地基与事件契约。 |
| **成稿强制 `[n]` 角标取代证据标记** | 角标无「待核实」语义；辩论记分/质询依赖证据状态二分；应合流数据模型而非消灭状态标记。 |
| **全站一次到位（CEO+辩论+法律+知识库）** | 辐射面过大；先行辩论可验证闸与徽章，再合流。 |
| **运行时回源对照正文（重层 verify）** | 成本高、误报难控；终态先做「id∈台账」轻层，回源对照另案。 |

## 七、开放问题（✅ 已全部拍板 · 2026-07-18）

| # | 拍板结论 |
|---|---|
| **O1** | **条目形状统一到 Citation（加可选字段 `id`/`date`/`tier`），载体走辩论双事件**：`debate_round` 每轮带本轮新登记条目增量（live 轮末徽章即可点）、`debate_result` 收场带全量（权威、重载印证）；**不动 `citations_event`**、不加新事件族。否决「citations_event 承载台账」：回合池 URL 去重 + 上限 24 + 汇入重排编号，装不下场级台账且毁 `#id` 稳定性，收口才发导致 live 全程点不开。辩手检索照旧汇入回合来源卡（零回归）。台账作用域 = 场级合并池（条目记登记方 `side_key`）；「按方分池」否决——挡掉合法引用共享底料。 |
| **O2** | **剥离 `【已核实·…】`（含残缺形态）、降级 `【待核实·推断】` 后放行**（2026-07-17 已先行落地，`evidence_guard.demote_verified_tags` + `speech_pipeline`）。降级比「放行+警告」诚实（不给假绿徽章）、比硬失败稳（不毁整段发言）。合流 CEO 后与 `finish_guard` 对齐时复核口径。 |
| **O3** | **规则表 MVP + unknown 档**，规则表放 citations 平台层（M3 复用）：法院/gov/裁判文书网/官方域名 → official、权威媒体白名单 → media、其余 → unknown。**unknown 不是弱源实锤**——记分只封顶「决定性事实仅靠单一弱源/未知源」，不惩罚 unknown 本身；LLM 只在裁判侧解释 tier，不进检索热路径；检索元数据留作后续增强。 |
| **O4** | **场内序号 + 前缀（`#e1`、`#e2`…）**：登记顺序 append-only、同 URL 去重返回既有 id。短序号 LLM 遵从度高、token 省；hash 易抄错。`e` 前缀与 CEO `[n]` 角标视觉隔离，M3 再议数字空间统一。标记格式（纯 `【已核实·#e3】` vs 出处短语+id 双写）交实施期成稿遵从度 eval 定。 |
| **O5** | **允许空**：UI 显「日期未知」，缺日期不单独当弱源依据；**绝不让 LLM 补日期**（编造日期正是本提案要治的病）。 |
| **O6** | **不重录**：旧自由文本标记降级渲染（今日样式、不可点）。M1 落地后**重跑一场 LV 案命题**作端到端回归——同场验证 P0 对局记忆 + 台账溯源，宣传素材也从新场出。 |
| **O7** | **手机 `#id` 徽章解析同期必做**（否则新场次手机显示原始 `#e3` 乱码 = 可见回归）；溯源面板桌面先行、手机后置。 |
| **O8** | **归裁判，不上机械闸**：「哪个主张承重」是语义判断，机械化必误报；机械闸守死「id ∈ 台账」单一职责、近零误报。 |

**拍板时补充的两个咬合点**：

1. **底料预登记**：现行「引用底料事实沿用其出处标记」在 id 制下会被闸判违规（底料标签无 id）——主持人注入底料时把其中标签**预登记**为台账条目（URL 允许空、tier=unknown、登记方=主持人），注入块改写为带 id。
2. **命名区分**：P0 已占 `match_ledger`（对局台账·状态事件），证据台账代码命名统一用 **`evidence_ledger`**，防两个「台账」混淆（分工见 [辩论编排设计 §4-2.6](/docs/03-AI核心/辩论编排设计.md)）。
