# 检索与交付约束前置提案

> **状态**：🗂️ v2 已拍板（2026-07-18 终审通过）· **§七 第 1–5 步已全部落地**（同日：检索面 A3/A4/A5/A6、契约面 B1/B2/B3 一期、预算面 A1、B5 归因文案、伴随 P0「协调终态漏投致 120s 空等」源头修复）。as-built 已迁 [编排器 §2.6/§2.6.1/协调不变量 C](/docs/03-AI核心/编排器与CEO主Agent.md)、[工具与能力系统 §联网检索](/docs/03-AI核心/工具与能力系统.md)。**仅剩数据驱动后置项**（§七 第 6 步：B3 二期自动闭合围栏、停用词归一、`escalate(kind=resource)`、会话语言参与 locale 默认）——待 A6/phase 观测数据支撑后另批评审；后置项收口后本文退役。
>
> **一句话**：检索预算与交付验收标准从「事后发现」改为「派单时写进契约 + 工具/交付边界机械 enforce」，事后闸只做兜底。两个用户体感问题（搜索久、交付被打回重写）是同一设计缺陷的两个面：**约束没有前置**。

## 一、背景与证据

用户反馈：① 产品 AI 搜索耗时长、判定链路疑似复杂；② 交付经常被按「交付规范」打回重写。

基于两条 trace 的日志调查（**均为开发期自用流量，非生产用户数据；结论以此校准，放量后需用 A6 观测复核**）：

| trace | 任务 | 关键事实 |
|---|---|---|
| `b56d5b89…` | HTML 宣传官网 | 全程 **0 次搜索**；慢在单轮 11k token HTML 生成（~68s）、CEO 规划长思考（~48s）、文案→设计串行 wave、**122s 无埋点空档**；批次验收被任务文案词「打开」推断成 `code_verified` → 整批 unmet |
| `d3adcca0…` | AI 产业报告（7 调研 + 1 写手） | **169 次搜索**、覆盖活跃墙钟 ~33%；峰并发 33 vs 后端硬顶 6 → 排队把单次拉到 10–20s；精确缓存命中 **2/168**、近义重复 query 占 29%；**86% query ≥7 词**（提示词「2–4 核心词」形同虚设）；写手在上游交付后仍自行搜索 11 次 |

**证据时效校正（v2）**：该对照 trace 观察到的「94% SERP 混日文域」是 locale 钉扎修复**落地前**的数据——`infer_search_language` 的拉丁→`en` 钉扎已于同日落地（代码注释即引用此会话）。批次验收侧，「结构化信号压过文案推断」半步同样已落地：**仍存活的失败模式 = CEO 既未显式声明 criteria、又未声明 `form`/`artifacts` 时的 `text_inferred` 分支**。

**两个反直觉结论**（不变）：

1. 搜索的「判定链路」（citation_tier / 域拦截 / 台账 / finish_guard）实测微秒级，**不是耗时来源**——砍判定层对墙钟零收益，不做。
2. 交付侧「过严」的不是 finish_guard 条款（刻意窄、近零误报），而是**批次验收被文案推断错判 + 标准从未告知 worker + 打回形态是整稿重写**。

机制现状参照：[编排器与CEO主Agent §2.6 completion_criteria](/docs/03-AI核心/编排器与CEO主Agent.md)、[执行引擎 §交付前核验](/docs/03-AI核心/执行引擎架构设计.md)、[工具与能力系统 §引用质量闸](/docs/03-AI核心/工具与能力系统.md)。

## 二、设计原则

1. **约束进契约**：检索预算、验收标准在 `delegate` 派单时显式确定，写进任务契约并注入 worker 上下文。**绑定性判定禁止运行时从文案猜**（如「打开」→`code_verified`）；非绑定的软警告（宁可漏不可错杀类提示）保留。
2. **机械规则在边界 enforce**：query 形态、预算余量在工具边界做确定性校验并给结构化反馈；不靠提示词恳求（86% 违反率证明恳求无效）。谓词必须机械可判（结构化字段 / DAG 形状），**禁止按 role 字符串等文案特征建规则**。
3. **事后闸只兜底**：finish_guard 保留为最后防线，但规则前置声明，让它不再是「模型第一次学会规则的地方」。
4. **引用纪律不放宽**：非法 `#rN` 维持「首次定向回炉、耗尽后剥离 + 观测」现状路径——防造引是产品底线，本提案优化时间成本，不动质量标准。
5. **流式一致性不破例**：任何对交付正文的引擎侧改写都必须走确定性 reset + 重推路径（live 气泡与持久化正文同步替换），禁止「只改落库、不改 live」。

## 三、Part A：检索作为受管资源

### A1 检索预算进委派契约（并入原 A2）

- `delegate` 任务契约新增检索预算字段（`web_search` / `read_url` 各自额度或合并额度，实现期定）。**结构化默认**：
  - 无上游依赖的节点（调研波）→ 默认额度 N（按日志分布校准）；
  - 有上游依赖 ∧ `form=prose` 的节点（合成波，对照 trace 中写手即此形）→ 默认 **0，且不装配检索工具**（复用现有 `tasks[].tools` 白名单机制）；
  - 其余下游节点 → 小额默认（下游深挖型调研存在，勿一刀切 0）；
  - CEO 显式声明恒优先覆盖默认。
- **enforce 点**：engine 工具执行层（有 run 身份处）新建 per-run 计数——与 `LoopController.investigation_calls` / `team_gate`（CEO-only 软 nudge）**正交，禁止挂接**。缓存命中不计入预算（不产生后端压力）。
- **用尽路径（v2 改写）**：预算尽 → `web_search` 返回结构化反馈「预算已尽：基于台账现有证据交付，并在交接中如实标注检索缺口」；worker 照常收尾，缺口经 handoff/debrief 与契约缺口块上浮；CEO 依缺口用 **`continue_from_run_id` 带现场续派并显式提高预算**（机制已有）。v1 **不新增 escalate 语义**——现网 `escalate.kind ∈ {normal, scope, dep}`，无资源申请通道；如未来需要 mid-run 申请追加，另案 `kind=resource`，属契约变更单独评审。

### A3 query 契约（工具边界校验）

- 拉丁文 query：未加引号部分限核心词数（≈6，按日志 P95 校准）；**CJK query 按字符长度上限**（whitespace 词数对中文恒≈1，无效）；**引号短语豁免**（搜报错原文、引文是合法长 query）。
- 超限 → 确定性拒绝 + 一句改写指引（与现有空结果提示的「>4 词裁剪」文案对齐），模型自行改写重试；**不做工具层静默改写**（隐藏机器、不可观测）。
- 已知代价：每次拒绝多一轮 LLM 往返——赌结构化错误提示一次改对；拒绝的调用不消耗 A1 预算。

### A4 缓存归一键扩展（v2 收窄）

**事实校正**：检索缓存**已是 conversation 级、全队 worker 共享**（正/负缓存均有）；证据台账同 URL 登记去重已返回稳定 id。2/168 的命中率根因是**措辞不重复**，不是不共享。本项只做一件事：

- 扩展 `_query_key` 归一化，第一期仅 **casefold + 拉丁词序排序**；**不去停用词**（否定词被抹会错命中错源），停用词归一先观测数据再议。
- **辩论 carve-out**：辩论 run 维持精确键现状、不吃归一共享——独立取证纪律不破；场级 `#eN` 与回合 `#rN` 双台账分流不变。
- 不做语义/embedding 缓存（错命中引错源，列远期观察）。A3 短 query 化是本项命中率的前提。

### A5 locale 钉扎验证（v2 重定性：修复已落地，本项是验证）

- 拉丁→`en` 显式钉扎、禁用 `default_lang=auto` 已落地。剩余工作：① 端到端验证 pin 不被引擎侧泄漏（中英混排 query、个别引擎忽略 `language` 参数的情形）；② 「会话语言参与默认判定」单独决策——与「中文调研合法地发英文关键词」场景冲突，需要裁决后才动。
- 若验证仍见污染，再评估结果域过滤，不预置。

### A6 阶段观测（v2 收窄）

- `queued / querying / fallback` phase 回调**已存在**（前端进度展示用），缺的是**结构化时长埋点**：把各 phase 时长写入日志，按 scenario 出「搜索次数 · 缓存命中率 · 排队占比 · 空结果率 · 占 wall%」画像。本次调查因缺 phase 时长只能靠常量反推。

### 明确不做

| 不做 | 理由 |
|---|---|
| 团队级新检索调度器 | 峰 33 并发是需求侧问题；A1/A3/A4 治理需求后，现有 semaphore + 限流够用 |
| 砍判定层（tier / finish_guard / 台账） | 实测微秒级，对墙钟零收益，只会回退质量底线 |
| 空结果重试特判 | 空后精确重试仅 ~1/9，不是主放大器 |
| 预算计数挂 `LoopController` / `team_gate` | 语义不同（CEO 治理 vs worker 资源），挂接即混层 |
| 按 role 字符串建默认表 / 谓词 | role 是自由文本，等于再造一层文案推断 |

## 四、Part B：交付验收进契约

### B1 废除文案推断（v2 精确化：只删 `text_inferred` 分支）

- `resolve_completion_with_source` 优先级链保留前三级（显式 > 结构化 `form=files`/`artifacts`→`files_written` > 全 prose→不强制），**删除第 4 级任务文案推断**。
- **省略语义维持 §2.6 现状「不强制」**——不新增「prose→内容非空」档位（那是另一次契约变更，本提案不做；worker 层契约已有非空兜底）。
- 软警告保留：`_BINARY_ARTIFACT_HINTS` / 执行类文案提示继续以**非绑定**警告形式随 delegate 结果返回（宁可漏不可错杀）。能力闸 `validate_execution_capability` 与收尾共用同一 resolver，自动跟随收窄。
- **补偿「打开软件」路径 A 安全网弱化**（对抗审计阻断项之三的配套）：
  1. skill / CEO 提示词把「真运行类任务必须显式 `completion_criteria=code_verified`」升级为硬要求；
  2. delegate 工具结果**回显 resolved 验收**（含「本批验收：未启用」），CEO 当轮可见可改；
  3. eval 棘轮：`delegate_run_app` 类向量守住「运行类任务显式声明验收」的行为。

### B2 验收标准注入 worker 上下文

- resolved `completion_criteria` 写进 worker「交付物规格」块（`describe_deliverable` 机制已有，扩字段）。
- **批次级语义注意**：criteria 是「至少一名 worker 满足」，注入全员会诱发冗余验证（7 人都去跑测试）。注入目标结构化圈定（持有执行类工具 ∧ `form=files` 的节点），细则实现期定。

### B3 finish_guard 规则前置 + 格式规范化（v2 分两期）

- **一期（随 B1/B2）**：共享基座提示词加一小块「交付底线」（围栏必须闭合、正文 `#rN` 必须在台账内）——现状是命中后才教；同时补 finish_guard 命中频率观测。
- **二期（数据驱动，仅当一期观测显示围栏回炉频率值得做）**：未闭合围栏自动闭合。**必须走确定性 reset + 重推路径**（先例：`apply_exit_ledger_ref_strip` 的 reset + 干净正文重推），并新增 `reason=normalize`——这是协议词表变更：conformance 向量 + 双端 fold + chip 折叠规则（「清气泡替换、**不**折『已按交付规范重写』chip」）需同批落地，显式标记为契约变更。
- **空语言块不自动删**（模型承诺了代码却没给，删块 = 静默改变交付语义）→ 维持回炉。
- 非法 `#rN`：维持「首次定向回炉、耗尽后剥离 + 观测事件」现状，不前移剥离。

### B4 批次 unmet 处理路径不变

- gap 回执 + 同缺口 2 次升级收口机制保留。B1/B2 落地后 unmet 只剩「真没做到」。

### B5 归因文案改版（v2 降级）

- 结构面已分（批次验收走 `DeliveryStatusCard`，finish_guard 走 rework chip），混淆在**文案心智**——降为文案/归因改版，可独立随时做；若动事件文案需跟 conformance。

## 五、有效性对账（对两条 trace 重放推演）

- `d3adcca0`：A1 预算封顶 + 合成波不装配检索（写手 11 次归零）+ A3 短 query + A4 归一键（29% 近义重复受益）→ 检索次数与排队同步下降，排队消失后单次回到 0.1–2s 主档；locale 污染已由既有修复覆盖（A5 验证确认）。
- `b56d5b89`：该委派若声明了 `form=files` 今日已不会误判；B1 堵住的是「既无显式声明又无结构化信号」的残余洞 + B2 让 worker 首次交付即对标。**单轮 11k token 长生成、串行 wave、122s 无埋点空档是另一问题，不入本提案**——122s 空档列独立 P0 排障（先加计时埋点定位，再谈修）。

## 六、代价与风险

| 风险 | 缓解 |
|---|---|
| 预算过紧饿死深调研（召回损失） | 用尽 ≠ 熔断：交付带标注缺口 + CEO 续派提额；默认值按 A6 观测校准 |
| query 上限误伤 | 引号短语豁免；CJK 单独字符上限；上限按日志 P95 校准 |
| A3 拒绝增加轮次 | 拒绝不耗预算；结构化指引赌一次改对；观测拒绝率回调阈值 |
| 归一键错配（错证据复用） | 一期只做 casefold + 词序；停用词归一观测后再议；辩论 carve-out |
| B1 后 CEO 漏声明运行类验收 | 三项补偿（提示词硬要求 / 工具结果回显 / eval 棘轮） |
| B3 二期动协议词表 | 显式标契约变更，conformance + 双端 fold 同批落地，数据不支撑就不做 |

**触点清单（实施验收面）**：服务端 `completion.py`（resolver + gap 文案）、`delegate` schema/tool、builder→executor 预算注入、engine 工具执行层计数、`search.py`/`search_cache.py`（A3 校验 + `_query_key`）、`resolve/prompt.py` + skills 文案；测试 `test_delegate_completion`、能力闸用例、search cache/query 单测、eval `delegate_run_app` 棘轮。**双端与 conformance 仅在 B3 二期 / B5 动事件文案时涉及**，其余不动 fold。

## 七、落地顺序（v2）

1. **观测与验证先行**：A6 phase 时长埋点 + A5 pin 端到端验证；（伴随独立 P0：122s 空档排障）。
2. **契约面**：B1（含三项补偿）+ B2 + B3 一期（提示词前置 + 命中观测）。
3. **预算面**：A1（结构化默认 + 工具装配联动 + 用尽/续派路径）。
4. **边界面**：A3 query 契约 + A4 归一键一期。
5. **随时可做**：B5 文案归因改版。
6. **数据驱动后置**：B3 二期（自动闭合围栏，契约变更）、停用词归一、`escalate(kind=resource)`。

每步独立可验收；conformance 向量与评测样本按现有 `conformance/vectors/`、`evals/` 机制补齐。落地后按文档治理规范：结论迁入 01–05 对应现状文档，本文退役。
