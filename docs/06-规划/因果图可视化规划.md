## 一、用一句话说清

**因果图**回答：多 Agent 一回合里，**谁的数据流进了谁**——不只是计划依赖（`depends_on`），还包括实际上游产出是否塞进了下游提示词（`inject`）。与审计「活动记录」同源。

## 五、接缝修复记录（2026-07-09）

**现象**：真库 `context.inject` 行 `source_run_ids` 均为 `[]` → 因果图无 inject 边 → UI 不显示「数据从哪来」。

**根因**：`run_context` wire 用 `blocks[].source_run_id`，`projector.py` 误读顶层 `source_run_ids`。

**修复**：`projector._context_inject_source_run_ids`；集成测改为真实 `blocks` payload。

**限制**：历史审计行不回填；修复后**新跑**多 Agent 回合方可验收。需重启 `agentcore`。

## 六、人工验收清单（pass_through · 需真后端）

> `#/preview` 无 audit API，不可用离线预览验因果图。

**Phase 1**

1. `agentcore` + 桌面 `pnpm dev` 已跑通
2. 发起多 Agent + 依赖链回合（pass_through 自动注入）
3. 打开**下游** run 详情 →「关系」→「**数据从哪来**」（默认收起）
4. 展开与「收到的上下文」`source_run_id` 一致
5. 「活动记录」含 `context.inject`，`source_run_ids` 含上游 run id
6. 打开**上游** run 详情 → 无「数据从哪来」
7. Network：同回合仅 **1 次** `GET …/audit?include_causal=true`

**Phase 2**（在 Phase 1 通过后）

8. 打开下游 run 详情 → 协作图对应 dep 边高亮，与「数据从哪来」一致
9. 无关边/节点变淡
10. toggle「显示审计数据流」→ 全回合 inject 路径可见
11. 若有仅 inject 无 dep 样本 → 橙色虚线补洞边可见
